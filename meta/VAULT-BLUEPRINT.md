# VAULT-BLUEPRINT — 知识库质量诊断与重建方案

> 诊断日期: 2026-08-29 · 范围: `~/wiki` (vault) + `~/wiki-book` (发布端) · 基于三路实测审计
>
> 一句话结论: **系统的病根是"只进不出、只存不炼、只连不选、只用不馈"**。
> 入口门禁真实存在但评分通胀，出口(成书)零过滤，库内没有代谢闭环，
> 链接是模板产物而非语义产物，使用侧没有任何反馈回路。
> vault 自己在 2026-05-18 的 REVIEW.md 里就承认: *"组织得很好的'已读'文件夹，不是智库"*。
> 四个月后，实体从 1,204 涨到 4,069，这个判定依然成立。

---

## 一、实测诊断（全部有证据，抽样可复现）

### 1. 规模与流速

| 项 | 实测值 |
|---|---|
| raw/articles/ | 4,016 md（wiki-book 侧另有 78MB 全量镜像） |
| entities/ | 4,069 |
| concepts/ | 161 · comparisons/ 32 · moc/ 45 |
| 入库速率 | ~25-30 篇/天（2026-05 至 08 灌入 3,000+） |
| 4 个月膨胀 | 4 倍（REVIEW.md 时点 1,204 实体 → 4,069） |

### 2. 门禁：入口真实、通胀严重、出口裸奔

- 入口: vxc≥49 + 域名门禁 + SHA-256 去重 + slug 相似度，是**真流水线**。
- 但评分**通胀**: 7 分 1,132 + 8 分 787 = 47% 落在 7-8 分；REVIEW.md 时代 90% ≥7 分，今天依旧。分数失去了区分度。
- 8 个实体评分越界（70/72/78/80/82/90，0-10 量表被写成百分制）；19 个 0 分文件不删；34% 实体根本没有 review_value。
- **book_compiler.py 对以上全部无感知**: `scan_entities()` 零质量过滤，按 tag 把 4,069 实体全量塞进 20 章；`book_blacklist.py` 是孤儿脚本，从未被引用。
- fallback 桶失控: **Ch01 收 1,643 篇（全书 26.5%）**，混入开发者工具盘点、风投分析、地缘政治预测等非 AI 内容。
- 僵尸页: sync 脚本 `rm -rf docs/ch0*/` 只清 ch01-ch09，**ch11/ch12 永不清理 → 2,898 个 stale 子页**（ch11 目标 2,816 vs 源 324），污染搜索索引、RAG 近邻图、rank-articles 计分。
- mkdocs 无 strict 模式，断链静默上线: PATH.md 在 GH Pages 上残留 **135 个未替换的 `{{BASE_URL}}`**，67 条 raw"延伸阅读"链接在两个域名上都是 404（sync 注释还声称拷 raw 是为了"不 404"——机制自相矛盾）。

### 3. 提炼：70% 实体是"带引文的复印件"

- 旁路脚本 `batch-score-ingest3.py` 把 `body[:3000]` 直接写进实体 → **2,840/4,069（70%）实体含 raw 存档 stub 签名**，108 个还保留 "Markdown Content:" 抓取残留。
- 12 篇随机抽样: **8 篇（67%）搬运/残缺**（逐句脚注中位数 14 个/篇，33% 实体 ≥20 个），3 篇有真提炼，1 篇是 `provenance_state: inferred` 的无源推断（**幻觉风险直接公开发布**）。
- 碎片: 68 个 <300 字 stub；**44 个 `-1/-2/-3` 副本**；13 个"腾讯研究院AI速递"每日残条；152 个 auto-harvested 标签实体。
- 重复家族: karpathy 同一场访谈两条实体（入链 213 vs 159）；harness-engineering 与 harness-engineering-framework 并存（147 vs 987 入链）；REVIEW.md 记录过 548 对近重复标题。

### 4. 连接：图谱统计失真，链接是模板不是语义

- 入链中位数 = 1；真孤儿 5.3%（216 篇）；**wiki-book 端 79.4%（5,162/6,504）子页零入链**。
- 极端头重: `harness-engineering-framework` 一个概念吸走 987 入链（全库 23%）；**762 个实体（18.7%）挂着同一句样板** `相关概念: [[concepts/harness-engineering-framework]]`——GB300 芯片、华语音乐模型、人类配额制全都机械挂上。
- top10 入链全部来自 harness/agent 同一话题圈；concepts/ 有 44% 只有 1-4 个来源、7 个零来源。
- 结论: 链接密度反映的是**模板管线**，不是知识语义。图谱在这个库上是失真的。

### 5. 代谢：更新机制存在过，全死了

- heartbeat 记录的 `wiki-p1-auto-expand`（停在 2026-06-30）、`wiki-batch-deepen`、`wiki-low-vxc-review` 三个 cron 全部死亡。
- 唯一内容级巡检 contradiction-scan（每 4h）只写 hot-context.md，**不回写任何文件**。
- 实体 `updated:` 字段 1,553 个停在"今天"、1,117 个停在 08-01——是脚本批量 touch 的痕迹，不是内容刷新。
- 淘汰只有"考古式大扫除"（05-18 删 314、quality-audit 归档 84），没有持续闭环。**新闻类内容半衰期以周计，却会永久沉淀并全量流入书里。**

### 6. 复利：价值单向流动，没有回路

- 数据流: 抓取 → 存 → 发布，到此为止。没有: 使用反馈（搜索零结果无人看）、合成产出（综述/对比/复现）、重温机制、复盘回路。
- `rank-articles.py` 只给仪表盘排序，且不在自动链路里（会漂移，历史 404 补丁可证）。
- 独有资产占比 ≈ 0：raw 谁都能抓，entity 是原文复印件，综述/对比/复现记录几乎不存在。**没有独有层，就没有护城河，时间越久贬值越快。**

### 7. 卫生问题（顺手可修）

- vault 根目录 5 个 `--score`/`--json`/`--results`/`--wiki-dir`/`--output` 垃圾文件 = 7 月 cron CLI 参数错位事故产物，至今未清。
- 数字口径漂移: 首页 4,087 vs 实测 4,069；course.md 称"5,000+ 篇"；STUDY.md 写 2,986；Dashboard.md 8,401 vs 表内 8,368——四套文档各说各话。
- raw 78MB 全量镜像每日 rsync+commit 进 wiki-book 仓库，但 `mkdocs exclude_docs: raw/` 构建即排除——git 历史与每日 diff 纯噪音。

## 二、重建方案：五个循环

价值公式：**V = 精炼度 × 连接度 × 复用度**。当前三者 ≈ 25% × 失真 × 0。
修复思路不是再加脚本，而是给系统装上完整代谢循环：

```
┌────────────────────────────────────────────────────────┐
│                    知识代谢系统                          │
│                                                        │
│  ①入口循环(已有)   ②代谢循环(缺·核心)   ③连接循环(失真)   │
│  抓取+评分+去重  →  每日check&eval     →  语义链接+合并   │
│       ↓                ↓                     ↓          │
│  ④输出循环(裸奔)   ←────────  ⑤复利循环(空白)            │
│  精选层出书+叙事      使用反馈→缺口报告→反向投喂→综述/复现   │
└────────────────────────────────────────────────────────┘
```

### ① 入口校准（改小，不是改多）

1. **评分锚点化**: score prompt 里给每个分值 1-2 个具体范例锚点；强制批内相对分布（每批 ≤20% 拿 ≥8 分）；字段升级为 `review_value_v2`，与旧通胀分隔离。清洗 8 个越界分。
2. **来源收窄**: 11 个公众号 + RSS 全量抓是"广撒网"。改为: 按过去 90 天"实际入库且 30 天后仍未过时"的来源做留存率排名，末位来源降频或停订。入库量目标从 25-30/天降到 **5-8/天**——量不是资产，留存才是。
3. **杀旁路**: 删除/禁用 `batch-score-ingest3.py` 与 `orphan-processor.py` 的 `create_entity()`。**实体只准由 llm-wiki 合成产出**；旁路只准建 raw。

### ② 代谢循环 = 用户要的"每天固定 check & eval"（核心新增）

新建 cron `daily-vault-checkup`（每天 04:30 固定）：

1. **指标采集**（脚本，秒级）: 孤儿率 / 中位入链 / 精炼率 / stale 率 / 重复家族数 / 僵尸页数 → 追加 `wiki/metrics/history.jsonl`（每天一行，可画趋势、可回归告警）。
2. **抽样复审**（LLM，K=40/天）: 优先级队列 = news 类超 TTL > 无分/低分 > inferred 无源 > 孤儿 > 最久未复审。每篇三裁: `keep / refresh / archive`。
   - archive 自动执行（移 `_archive/` + 更新 archive-index + 从书中摘除 + RAG 索引剔除）；
   - refresh 生成"过时点清单"挂进复审队列，由 llm-wiki 在窗期内重写。
3. **差异守护**: 与昨日 diff——新孤儿 / 新 stub / 新重复 / 新样板链接 → 当日日报邮件。

**时效分层**是代谢的前提: entity 新增 `half_life: evergreen | year | quarter | days`（入库时 LLM 判定）。
- `days/quarter`（新闻、榜单、版本发布）: 180/90 天强制复审，"当前价值分 = review_value × 时效因子"，排序用当前价值分。
- `evergreen`（方法论、原理、架构）: 永不过期，每年抽检一次。

**队列数学**: 40/天 × 5 天/周 ≈ 100 天完成全库 4,069 篇首轮复审，之后进入稳态滚动。
**原则: 归档不删除**——`_archive/` + archive-index.md 保底，随时可复活；淘汰的是"出现在书里、出现在搜索里"的资格。

### ③ 连接重建（缝合）

1. **合并家族**: 脚本识别（`-N` 副本 + 标题相似度 ≥0.85 + 同来源重叠）→ 生成 merge 提案 → LLM 合并为主条目（保留全部来源与差异点）→ 旧文件留一行 `已并入 [[主条目]]` 的重定向页防 404。首批: 44 个 `-N`、karpathy/harness 双条、548 对近重复。
2. **杀样板链接**: 找到注入 `相关概念: [[concepts/harness-engineering-framework]]` 的环节（provenance-enforcer / cross-link 批处理），改为**有语义依据才链接**（LLM 判断 + 在 frontmatter 写 `link_reason`）。宁可少连，不可假连。
3. **概念页门槛**: concept 存在的前提 ≥3 个实体来源；不满足的降级为 entity 的 tag。7 个零来源 concept 直接清。
4. **章节内聚**: split-chapters 时复用现有 TF-IDF 近邻图，把"近邻"排成"同节"，每节一 mini-MOC——让读者顺着语义走完一章，而不是顺着字母序翻 1,643 条清单。

### ④ 输出循环：书 = 精选 + 叙事，不是全量堆砌

1. **两层发布**:
   - **精选层**（nav 主路径）: 目标 ≤600 篇（每章 20-40 篇真精选），准入 = `review_value ≥7 且 provenance 完整 且通过实体契约 lint`。
   - **全库层**（参考库 section）: 其余页面保留可达但降权，页面标"参考存档"，不进主搜索权重。
2. **章节主编导读**: 每章 1,500 字叙事（这个领域是什么 / 主线争议是什么 / 按什么顺序学），由 LLM 从该章精选合成、人工终审——这是"精"在读者端的直接体现。试点章: ch04 agent_core。
3. **实体契约**（进 lint，不合格不许进精选层）: ≥3 条原创块（洞察/对比/代码/质疑）；正文为原文的 10%-60%（防截断搬运也防 AI 灌水扩写）；逐句脚注 ≥20 判搬运嫌疑进复审。
4. **构建硬化**: `mkdocs strict`（或 validation.links 降 error）；sync 脚本 `rm -rf docs/ch*/` 全前缀清理僵尸页；PATH.md 的 135 个 `{{BASE_URL}}` 在 deploy.yml 补替换或改 GitHub 永久链接；首页统计数字改为构建时实测生成，口径唯一。
5. **raw 镜像瘦身**: 只 rsync 被实体引用的 raw（现 ~4,016 全量 vs 实际被引用约 4,019 条 sources 对应的子集），或 raw 镜像迁独立 branch/LFS，停止主仓每日 78MB 噪音。

### ⑤ 复利循环（从 Vault 挖宝）

1. **周报合成 `weekly-synthesis`**（每周日）:
   - contradiction-scan 升级: 从"写 hot-context.md"升级为"生成观点冲突对比提案"（两方论点 + 来源 + 差异表），人工裁决后沉淀为 comparisons/——**矛盾是独有的知识资产，搬运永远给不了**。
   - 本周 RAG/搜索日志里的零结果 query + 低分 query → **知识缺口报告** → 反向调整 RSS 源与抓取关键词（投喂组合管理）。
   - 自动起草一篇 2,000 字主题综述（取当周最热主题的 top 实体合成），人工修订后进 concepts/ 或书附录。
2. **复现队列**: 给带代码的实体打 `reproducible` 标，learn/ 课程把编排成动手实验（checklist 制）；每月强制复现 2 个，产出笔记以 `type: project` 回写 vault。**复现产物是别人拿不走的一层。**
3. **间隔重温**: dashboard 加"今日重温"卡组——从复审产物 + 用户标记重点里每天抽 5 张。知识库从"查得快"升级为"记得住"。
4. **独有层占比**作为北极星: raw(任何人可抓) < entity 合成(半独有) < 矛盾对比/复现记录/主编叙事(独有)。每周统计独有层增量，目标每周 ≥2 件。

## 四、度量北极星（90 天目标）

| 指标 | 现状 | 90 天目标 |
|---|---|---|
| 精选层规模 | 无精选概念（6,509 全量） | ≤600 篇真精选 |
| 书内零入链页占比 | 79.4% | <30% |
