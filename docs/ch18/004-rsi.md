# RSI 与持续学习是两件事：智能复利的两个飞轮

> 📊 Level ⭐⭐⭐⭐ | 20.5KB

## 一句话结论

行业叙事常把"AI 自我改进"和"AI 自己学习"混为一谈，这篇的第一贡献就是把它们切开：**RSI 让生产智能的过程自动化、close the loop；持续学习让 AI 在交互中积累可泛化的能力**。两者受制于同一个瓶颈（好的 verifiable 环境），但需要的能力完全不同——**RSI 缺的是"实验能自动推进并被可靠验证"，持续学习缺的是"从少量经验中提取学习规则"**。作者的判断是：**持续学习大概率需要一次范式跳变，而 RSI 可能正是让这次跳变变得可行的前提**。

## 一、RSI 的操作性定义：不 scale people

论文里的 RSI 常被说成"AI 改进 AI"；这里的定义更可测量：**交付单位智能所需的 researcher 数量，不再随 compute 同比例增长**——"模型的提升 scale compute 和 intelligence，但不 scale people"。

支撑数据与形态：**OpenAI 2026 年 9 月内部数据**显示，每位活跃实验人员的实验量在 8 月达到 **2025 年均值的约 1.6 倍**（考虑到员工增速应快于算力增速，说明研究者正把更复杂、跨度更长的任务交给 Agent）；**Karpathy 的 autoresearch** 给出最小闭环——Agent 改训练代码 → 单 GPU、每次 5 分钟训练预算（不含启动/编译/推理）→ 固定评估决定保留还是撤销 → 下一轮，人负责研究指令与边界。

作者还强调，这里的进步要拆成两个量看：**每位研究员能管多少 GPU 小时**（自动化直接抬高它，让更多假设进入实验）与**每个 GPU 小时能产生多少有效成果**（要靠评估与研究方法的改善）。**真正的 RSI 要把更大的实验规模转化为更强的研究能力**，才形成复利；否则只是"实验更多了"。infra 也随之变化：训练系统除了给人用，还要**让 Agent 能操作、观察、纠错**——可调用的训练接口、可复现环境、独立评估，决定一名研究员能同时管多少条闭环。

## 二、两个维度构成的矩阵：Personalization × Self-evolution

| | 低个性化 | 高个性化 |
|---|---|---|
| **低自我进化** | 传统 LLM 范式（foundation model 隔代升级、定期 release） | Chatbot / Personal Agent（memory file、markdown 结构化记忆，像随身带笔记本的人） |
| **高自我进化** | frontier labs 的自动化、工业化训练（正从左下走向此处） | **持续学习**（两个维度的交汇点） |

这张矩阵的用处是给"自我进化"一个坐标：**现在多数所谓 self-evolving agent 其实停在左上角**（自动化了训练，但没有针对个体/环境的适应），而 Personal Agent 停在右下角（有记忆但不自我进化）。

## 三、公司映射：三类切入点

1. **RSI：AI 研究自动化** —— (a) **训练平台**（企业通过 API / RL fine-tuning 训练个性化模型，如 Thinking Machine 的 Tinker）；(b) **RSI 本身的研究**（实现 close loop 的闭环任务，如 Jeff Dean 创业的 Discover Loop）。
2. **Continual Learning：新范式突破** —— frontier labs 内部大概率已部分实现 RSI，**持续学习与算法效率是下一个最关心的问题**；visionary researcher 创业探索新范式**赔率更高但胜率更低**——甚至可能在现有范式下 frontier lab 用 RSI 就解决了持续学习。
3. **Domain Loops：垂直领域闭环** —— 越接近真实世界，实验越贵、越慢、越难复制，**RSI 能否带来复利取决于系统能否从每轮反馈中学到更多**（science discovery agent / automated lab；chip design 与材料发现则是"打造终端产品"或"沉淀数据与 RL 环境"两条路）。

## 四、四个研究瓶颈（RSI 实现之后最稀缺的能力）

**① 规模迁移。** 小模型上的 optimizer、数据配比或架构改动，能否在前沿训练里继续有效？作者举了反例：**Anthropic 的自动 alignment 研究已能自动设计并迭代，但最优方法移到 Claude Sonnet 4 生产训练时没有取得统计显著改善**——**便宜实验筛出的候选仍需要一定程度的 human in the loop**。

**② 好的 verifiable environment。** 科学上是 scalable oversight（任务多到人无法逐项检查、难到监督者不能直接判断时，如何仍给出可靠反馈）；工程上是 verifier 的质量–效率平衡。一个实用做法：**让 Agent 生成正确变体与错误干扰项，检查 verifier 能否区分**。

**③ 从真实轨迹重建环境。** 开源环境与 benchmark 多围绕"修一个 issue"这类单轮任务；真实工作是连续任务序列，文件、运行环境与用户目标都在变。三个具体难点：**文件与运行环境**（从轨迹恢复文件内容、拼文件树、让 Agent 补齐缺失、恢复语言/依赖/构建配置让它真能跑）、**任务边界**（从模糊 query 里识别任务区间，例如把"继续"还原成目标清楚、上下文完整的任务）、**任务验证**（**原始回复往往不是最优答案，verifier 应根据行为与真实状态变化判断任务是否完成，避免把"复现原回复"当成成功**）。

**④ 研究判断中的 taste 与资源分配。** 哪些问题值得做、哪些实验该加算力、何时该放弃——没有现成的短期分数，却决定实验能否留下有价值的发现。Anthropic 的内部观察是：**执行自动化越多，研究方向与 human in the loop 越重要**。

## 五、垂直领域 RSI：反馈越贵，复利越难

作者给了一个渐进顺序：**先在 frontier lab 内部形成闭环；再进入目标明确、反馈可验证的垂直领域**（AI for Science、robotics 已在找局部闭环）。

| 案例 | 数字 | 含义 |
|---|---|---|
| Anthropic 蛋白设计 | Claude 优化 **30+ 个**开源生物分子模型的推理代码与 GPU kernels，配合更简洁的 prompt、harness 与新模型 → **同等水平蛋白设计的 GPU 小时数为优化前开源模型的 1/100** | Agent 先是用工具，下一步是**反过来改进自己的科研工具** |
| Biomni × TusoAI（Phylo） | Agent 搜索数据与代码、检索文献、改写方法、训练评估候选，**一周测试 500 个候选**，得到结合多源 gene embeddings + 回归 + kNN 的基因扰动预测方法 | 模型研发的自动化已可产出可用方法 |
| Project Fetch 二阶段 | **Opus 4.7 完成五项接入与编程任务平均 12 分 7 秒**，上一轮用 Claude 辅助的人类团队用了 **264 分钟** | coding 能力正在压缩机器人研发中的软件工作 |
| RoboTTT（NVIDIA/Stanford/UT Austin） | fast weights 接入 VLA policy，压缩视觉与动作历史，**8K 时间步 context**、单次人类视频示范适应、长程装配在线纠错；**训练 context 变长时性能持续改善** | 让 **context length 成为机器人 policy 的新 scaling axis** |

作者的收束判断：随着计算环节变便宜，**瓶颈会更集中到真实实验反馈的质量与速度**；下一步垂直 RSI 要让系统**从有噪声的结果中提炼可信信号、建立新的 assay**，并据此改进下一轮的实验选择、工具与模型。

## 六、持续学习：定义、分级与最大难点

**定义**：系统在 interaction experience 中把新的知识与 entropy 转化为**能泛化到各种任务上的能力提升**。机制两步：**①获得新的 entropy**（从系统与环境获得新问题、新思路、新 tool，可由用户/环境提供，也可由模型自己产生）；**②把 entropy 转换成 learning**。

有一条判据极好用：**AI 得到新经历能立刻转化成 knowledge 才是 continual learning；如果需要先把经历收集起来、过一段时间再统一训练，那还是已有范式**——这一句直接否掉了大多数"定期微调"式的伪 CL。分级上，**第一级（也是最要紧的目标）是"一个任务能在 long context window 中持续学到信号并越做越好"**，而这正是当前范式很难做到的。

**最大难点是 sample efficiency**，作者用了一个好词 **grindability**：软件测试可以恢复环境、并行重跑，reward 密集且快（甚至 process reward），环境可低成本、并行、重置地反复尝试；**物理世界不 grindable 也不 verifiable，所以必须从更少的样本点里学到关键经验**。结论：**环境越难复制，越要从每次真实经验中学到更多**。

## 七、四条技术路线与它们各自解决什么

| 路线 | 解决什么 | 代表工作与要点 |
|---|---|---|
| **TTT / fast weights** | 记忆机制与在线更新 | 三个变化：可在线更新的 fast weights、learning 与 inference 同时发生、**memory 相对 context length 保持 O(1) 计算**。**TTT-E2E**（sliding-window Transformer 上做 test-time 更新并学习适合更新的初始化）、**In-Place TTT**（把 MLP 输出投影矩阵当 fast weights）、**REFINE**（next-sequence prediction + 序列级奖励训练 fast weights）、**Falcon**（fast-weight attention，归一化 delta rule 与滑窗更新）。尚未 scale up，关键可能是**数据**：训练序列要覆盖不同更新频率，并用长 trajectory 与后续结果教模型"哪些经验值得写入、如何控制干扰与遗忘、哪些状态该跨 session 保留" |
| **Adapters / Multi-LoRA** | 个性化与成本 | 冻结底座、只训低秩参数；把 adapter 当**可持久保存的局部状态**（用户/项目/领域经验各留一份，按任务选择或组合）。核心价值是控制 **stability–plasticity tradeoff**：把局部学习限制在**可路由、可删除**的 parameter space。三层级建议：**fast weights / task-local LoRA 存短期跨 session 状态 → slower adapter 固化稳定 skill → base weights 只吸收跨用户反复验证的通用能力**。挑战是把 adapter 数量 scale up（轻量训练 + 并发训练/路由/serving） |
| **Meta-learning** | 学习机制与 sample efficiency | 把"如何学会学习"变成训练对象：什么初始化更易适应、哪些层该更新、更新多少、什么信息值得留。**Nested Learning / Hope**（多嵌套、不同更新频率的优化循环，快模块适应当前 context、慢模块存稳定知识）、**SCoL**（按当前 context 生成自己的 update instruction，决定哪些层更新，再用 meta-RL 在连续 experience stream 上训练该策略）。它对应 TTT 未解的问题：**不是所有 fast-weight update 都该永久保留，需要一个 learned gate 决定哪些经验进入长期权重** |
| **Self-distillation / on-policy** | 学习信号密度 | **OPSD（on-policy self-distillation）**：把一个 session 中经历过完整过程的 "veteran" 模型蒸馏回 base student；**teacher/student 的 token 分布差异比终局 reward 提供更稠密的信号**；trajectory-refined distillation 从 student 自己犯错后的状态继续指导，减少 teacher forcing 的分布偏移。关键判断：**CL 的难点是新训练信号与模型当前 policy 的距离** |

## 八、架构之争：三个假设由弱到强

- **H1 现有范式够用**：更长 context + 更强智能 + 准备好的数据，可覆盖大部分需求。Dario 的公开讨论接近此派——在 coding 等**可外部化**领域，现有 Transformer + 长 context + RL + 工具系统可能已足以覆盖大量经济价值，CL 不是必须条件（他们做 skills 生态也印证这个取向）。
- **H2 Learning-rule hypothesis**：Transformer 留用，但需要 **meta-learned fast/slow update、distillation、memory gate** 等算法创新。
- **H3 Architecture hypothesis**：必须从底层设计可持续更新的架构与优化动态。反对派的论据是**attention 做 retrieve 本质是 shallow pattern matching**（按关键词找相似问题、把答案 copy 过来），**真正的学习应是把 100 道数学题压缩成核心逻辑再解新题**——这正是预训练有效的原因（compression 提炼共用逻辑进参数）。Sutton 的版本更根本：当前 LLM 从人类数据做 imitation，而非在持续 sensation–action–reward stream 中学 transition model，且梯度下降没有 good generalization 的保证。Dwarkesh 取中间立场：接受现有模型缺少高吞吐 experience learning，但不认为 imitation 与 experience learning 必须二选一——**LLM 可作强 prior，再靠 self-distillation 等机制逐步逼近 CL**。

架构备选与取舍：**RNN**（RWKV、xLSTM，紧凑状态省去不断增长的历史，但有限 state 丢细节、精确回忆难）、**SSM**（Mamba，结构化状态 + 输入相关选择控制写入与遗忘，压缩记忆与精确检索仍有取舍）、**混合架构**（Qwen3-Next 把 Gated DeltaNet 与 attention 结合，用递归记忆降成本又保留细节访问，代价是仍有 attention cache、系统更复杂）。

## 深度分析

### 把"自我进化"拆成矩阵，比争论定义更有用

RSI 与 CL 的混淆常来自同一个词被用在两个尺度上：一个在**生产侧**（造模型的过程自动化），一个在**使用侧**（模型在使用中变强）。矩阵的价值在于它同时否掉了两种常见误判——"我们有自动化训练流水线"不等于自我进化（缺个性化那一维），"我们有记忆文件"也不等于持续学习（缺自我进化那一维）。**判断一个 self-evolving 系统，先问它落在矩阵哪一格。**

### 规模迁移的失败案例，是整篇最该记住的数字

"小模型上有效、前沿训练里无统计显著改善"——这条来自 Anthropic 自动 alignment 研究的经验，直接戳破了"自动实验=自动进步"的乐观。**它意味着 RSI 的收益不是无限的：便宜实验能筛方向，但结论迁移到大规模仍需 human in the loop 兜一层。**任何以"小规模闭环 + 放大"为路线的团队，都该把这个反例当成验收清单的第一条。

### "立刻转化"是 CL 的判别式，也是它的技术难点所在

"收集经历→定期统一训练"被明确排除在 CL 之外，于是问题被逼到一个很硬的位置：**必须在交互过程中更新**. 这也解释了为什么四条技术路线都指向同一件事——**在线更新的稳定性**：TTT 靠 fast weights 提供 O(1) 记忆，LoRA 靠可路由可删除的参数空间控制 plasticity，meta-learning 提供 learned gate 决定什么进长期权重，OPSD 用 token 分布差提供比终局 reward 更稠密的信号。**四条路线各自解决"在线更新会崩"的一个侧面，而不是互相替代。**

### grindability 是个可复用的环境评估词

软件环境"可切碎、可并行、可重置、reward 密集"；物理环境三者皆无。**用 grindability 与 verifiability 两个轴给任务分类，就能预判某条 RSI/CL 路线在该领域能不能跑通**——这也解释了为什么 coding 一骑绝尘（两个轴都满分）、AI for Science 局部可行（verifier 可造但实验贵）、机器人在中间（仿真可 grind、真机不可）。

### 两个飞轮的关系：RSI 提供方法，CL 提供斜率

作者的收尾判断值得单独记：**RSI 已经在提高智能研发的效率，CL 有望让真实使用成为能力增长的来源；两者相互强化——自动化研究帮我们找到更好的学习方法，更善于学习的模型再加速下一轮研究**。而长期优势属于**"谁能持续提高经验转化为能力的效率"**——不是谁参数多，也不是谁闭环快。

## 实践启示

1. **先分清你在做 RSI 还是 CL**：前者优化"造模型的过程"，后者优化"用模型的过程"，瓶颈、指标与人才都不同。

2. **用"researcher 数是否随 compute 增长"当 RSI 指标**，比"AI 改了几行代码"可测得多；同时拆开看"人均 GPU 小时"与"每 GPU 小时产出"。

3. **小规模结论必须做迁移验证**：Anthropic 的反例提醒，便宜实验筛出的候选到前沿规模可能完全不显著，验收里要留 human in the loop。

4. **verifier 要能自测**：让 Agent 生成正确变体与错误干扰项，看 verifier 能否区分——这是最便宜的质量检查。

5. **重建环境时别把"复现原回复"当成功**：按行为与真实状态变化判断任务完成；任务边界要从模糊 query 里显式还原（"继续"也要还原成完整任务）。

6. **判 CL 只看一条**：新经历能否**立刻**转成知识；收集后统一训练仍是旧范式。

7. **按 grindability × verifiability 选领域**：两轴都高的先做（coding），verifier 可造但实验贵的做局部闭环（AI for Science），两轴都低的留给仿真。

8. **在线更新要配三层参数空间**：fast weights/task-local LoRA 存短期状态、slower adapter 固化稳定技能、base weights 只吸收跨用户验证过的通用能力——**用可路由可删除控制 plasticity**。

9. **别急着换架构**：先穷尽 H2（meta-learned 更新规则 + memory gate + distillation）；换架构是多年工程，收益未必先到。
