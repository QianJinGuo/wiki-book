# 快手电商智能补贴：大模型保覆盖、小模型保效果、Agent 保效率

> 📊 Level ⭐⭐⭐ | 17.2KB

## 快手电商智能补贴：三层能力与托管闭环

> 快手技术把「大促前怎么发券」拆成三个互补能力：**Uplift 专用模型保效果**（大预算核心场景）、**营销大模型保覆盖**（新场景冷启动）、**营销 Agent 保效率**（策略生产与全托管）。2026 年 818 大促消费券阶段复盘，智能策略在两个观察窗口的增量 ROI 都高于人工策略——但文中未给具体数值，作者也明确「不能据此判断收益会持续扩大」。

## 三个阶段：发得多不等于长得好

**粗放式（覆盖优先）**：2023 年年货节大促，10 天累计发券数十亿张、触达近亿用户、人均数十张——统一券包、统一门槛、集中投放，指标是发券量、领取率、核销率。**精细化（人群×场域×券档×时间段）**：按新客/回流/活跃区分补贴方式，结合直播、短视频、商城路径与类目偏好、价格敏感度调门槛面额。**智能化（目标驱动）**：以经营目标、预算上限、候选券档与业务约束为输入，预估不同动作的增量收益与成本，在钱效约束下选方案。

精细化阶段暴露的是**产能瓶颈**：一轮完整策略迭代涉及 **8 个阶段、30 多个环节、5 类以上角色，周期常超一个月，八成操作依赖人工**；历史策略分散难复用——2024 年前后做的 **8 次触达时机实验里，有 4 次因人员变动被重复开展**。所以智能化要同时提两件事：**决策能力**（要不要发、发多少、何时发）与**生产效率**（分析、配置、协同的成本）。

## 一个前提：四象限把「购买」与「增量」分开

同样一张券作用于不同用户，增量可以差很多。营销四象限：**营销敏感**（不发不买、发了才买）、**自然转化**（发不发都买）、**无动于衷**（发不发都不买）、**反作用**（不发会买、发了反而不买）。核销高不等于增量高——核销只说明券被用了，不说明这笔购买是被补贴促成的。

推论有两个：**购买概率高 ≠ 该优先补贴**（高概率用户本就大概率成交，补贴的边际作用小；低概率但可被推动的用户反而增量更高），**券面额大 ≠ 效果好**（用户在看 180 元商品时，满 200 减 25 可能因为凑单负担反而不如满 100 减 10）。

## 三类能力的分工

### Uplift 专用模型：在大预算场景深耕「补贴让谁变了」

传统模型判断「谁更可能买」，Uplift 判断「补贴让谁发生了变化」。围绕**用户—场景—候选券档**联合判断，回答三问：**要不要发**（相较不发是否有足够预计增量）、**发多少**（不同门槛面额各带来多少增量 GMV、继续加补是否划算）、**成本多少**（预期补贴成本是否满足钱效要求）。

一个容易漏的点：**补贴成本 ≠ 券面额**。同一张券发给不同用户，核销概率、实际抵扣金额、平台承担比例都不同，必须按业务规则估实际支出，再在预算约束下选动作。

### 营销大模型：两条路线解决冷启动

**路线一：LLM 语义表征 + Bandit**。LLM 把用户、商品、场景转成可复用决策特征，Bandit 在预算、准入、频控约束下选券档，兼顾利用与适度探索，按投放反馈持续调整——降低新场景启动成本，但增量与钱效仍要靠对照实验验证。

**路线二：奖励模型（RM）+ 策略模型（PM）生成个性化券**。RM 结合用户、商品、场景与领券核销行为，学习「什么券更适合这个用户」；PM 用这些评估反馈训练，在规则允许范围内生成少量个性化候选券；线上再由决策系统综合预期效果、成本与预算定最终方案——**大模型的用户理解通过轻量策略模型进入线上**，避免大模型直接上在线链路。

### 营销 Agent：把目标与约束变成可执行策略

模型解决单次决策质量，Agent 解决**策略从分析、配置、投放到复盘的生产效率**。运营给目标与边界（预算、人群、商品范围、门槛/面额/补贴率/频次规则），Agent 先理解目标与策略边界，再调用数据查询、知识检索、效果预估、预算测算等工具，分析历史策略表现、消费特征与商品价格，生成方案；**业务约束必须写进结构化策略配置，在方案生成与实际发券时统一校验**——不能只停留在给 Agent 的文字指令里。

执行由券投放系统承接（资格与预算校验、实验分流、发券），动态出价按请求实时算门槛面额；投放记录、效果数据与实验结果回流，**知识沉淀 Agent** 整理效果差异、适用条件与调整依据，更新知识库，形成「目标输入 → 策略生成 → 配置投放 → 效果评估 → 知识沉淀 → 策略迭代」闭环。

一句话概括协同体系：**大模型保覆盖，小模型保效果，Agent 保效率**。同一场景也可叠加：新场景先用大模型出初始策略、Agent 组织投放，预算与数据积累后再上 Uplift 专用模型深化钱效。

## 活动三段闭环与三个诊断式样

**活动前**回答三问：要什么增量、最多投多少预算、钱效底线是多少（例：预算上限内提升增量 GMV，且增量 ROI 不低于阈值），据此测算预期增量与预算需求、安排各阶段投入并留调整空间。

**活动中**是两层决策：**用户侧**先查资格、已领权益与频次，再结合用户状态、场景与候选券档的预期效果与成本，决定是否发、发哪档、何时触达；**全局预算**按阶段目标、实际消耗与新投入的预期回报滚动调整——扩量要看边际，避免「仅凭局部高 ROI 持续放量」。

**活动后**把转化链路与实验评估合起来看，三种典型式样给出明确诊断方向：**领取高、核销低** → 查券门槛与货盘是否匹配；**核销高、增量低** → 是否过多补贴了本来就会成交的用户；**扩量后钱效下降** → 分析新增人群/场域/券档的边际效果，识别策略适用范围与扩量边界。复盘结论要转成下一轮可验证的策略假设（调整方向、验证方式、判断标准），并把策略配置、适用条件、实验结果、调整原因关联沉淀。

## 工程底座：智能策略越靠近钱，越要可控

**数据链路**：围绕「业务场景 → 决策请求 → 曝光 → 转化 → 效果评估」建设，已沉淀用户行为、偏好、券、主播、商品等 **9 类以上维度数据集、1000+ 原子特征**，统一埋点覆盖直播、短视频、商城、店铺四大场域与 10 多个核心入口；关键约束是**只保留决策时实际可用的特征**（不能把事后信息混进决策特征），并统一数据晚到、延迟核销、退款回流的处理规则。

**策略管理**：人群规则、候选券档、出价规则、预算配置、模型版本统一纳管，记录每次调整的内容、原因、生效时间、覆盖范围；无论来自运营配置、模型优化还是 Agent 生成，都走同一套约束校验与发布流程；先实验灰度再放量，异常时可收敛新增投放或回滚到已验证版本。

**确定性执行**：资格、券档范围、门槛倍数、补贴率上限、发放频次、可用预算在实际发券时必须逐项生效；资金链路明确预算预占、核销扣减、到期释放、退款处理，靠状态管理、幂等控制与对账保障账实一致；跨场域还要做权益去重与互斥校验，防同一用户叠加领取。

**高峰与降级**：发券、预算、权益等关键链路做容量评估与压测，配限流、隔离、监控告警；降级按异常类型分档——**特征缺失/模型超时/推理异常** → 资格与预算校验通过后退回已验证的规则策略；**资金或资格状态无法确认** → 暂停相关发放；**预算消耗或效果异常** → 收紧投放，必要时停新增补贴。

## 四个坑

1. **核销高、购买概率高都不等于增量高**：一次实验里，叠加额外优惠投入更多补贴，但阶段性估计显示增量成交未同步提升、钱效反呈下降迹象——不能只凭核销与成交判断效果。
2. **单点模型优化要放回完整链路验证**：效果预估、成本预估、预算分配、实验评估需协同，单点提升不等同整体钱效提升。
3. **Agent 生成的方案必须满足业务约束**：约束要变成系统可执行规则并在两处校验，Agent 只负责在边界内组织策略。
4. **实验做过不代表经验留下**：8 次时机实验重复 4 次就是代价；复盘要连带保存配置、适用条件、结果与调整原因，让人和 Agent 都能理解「为什么有效、在什么条件下有效」。

## 现状与边界

「营销云舵」正在把这些能力整合为面向运营的托管平台，已围绕策略生成、效果分析、知识沉淀建多个专家 Agent，并在首个智能发券场景跑通「目标理解 → 策略设计 → 策略配置 → 投放执行 → 效果回收 → 分析诊断 → 策略迭代」最小闭环。当前分工是**运营定目标、划边界、把握关键决策，Agent 在授权范围内承接分析、配置、投放与复盘**；扩大托管范围要等稳定性与场景覆盖提升。

**证据强度要看清**：全文除规模类数字（数十亿张券、近亿用户、8 阶段/30 环节、9 类数据/1000+ 特征）外，**只有 818 大促「两窗口增量 ROI 高于人工」这个定性结论**，没有绝对数值、没有置信区间；作者自己写明需结合样本量与置信区间、策略版本、预算消耗与人群货盘节奏变化再验证，不能推出「收益会持续扩大」。

## 深度分析

### 四象限的本质：把「会不会买」与「补贴有没有用」拆成两个问题

传统运营只回答「谁会买」，四象限强行补上第二问：这笔购买是否由补贴促成。营销敏感与自然转化用户的购买概率可能一样高，但对补贴的响应完全不同——前者是预算的目标客户，后者领券只是转移利润。反作用象限尤其值得警惕：补贴可以是负增量，满 200 减 25 带来的凑单负担反而抬高决策成本。因此购买概率排序不等于补贴优先级排序；核销率只是执行链路指标，说明券被用了，不说明这笔购买是被补贴促成的。用核销率做优化目标，系统会系统性地把预算导向「本来就会买」的人。

### 「发得多」不等于「长得好」：三个阶段各自暴露的真问题

粗放式阶段数十亿张券解决的是活动感知与覆盖，发券量、领取率、核销率全是供给侧指标，没有一个度量补贴的真实效果。精细化把人群、场域、券档、时段拆开，效果改善但暴露产能瓶颈：一轮迭代 8 个阶段、30 多个环节、八成操作靠人工，8 次时机实验有 4 次因人员变动重复开展。智能化阶段才把问题落到增量收益与成本上。叠加额外优惠的实验给出反面证据：投入更多补贴，增量成交未同步提升，钱效反而下降——在错误的人群上加码，更多补贴是负优化。发券量是投入，增量才是产出，两者之间没有自动的传导。

### 三层能力是按预算规模分层的投资决策

大模型保覆盖、小模型保效果、Agent 保效率，对应三个正交维度：场景覆盖、单次决策质量、策略生产效率。分工的深层逻辑是边际收益：大预算核心场景里 Uplift 模型的精度提升值得专用建模投入；新场景样本不足，泛化能力比精度更稀缺，于是有 LLM 语义表征加 Bandit、RM 加 PM 两条冷启动路线；策略生产的瓶颈不在模型而在流程，由 Agent 串联分析、配置、投放与复盘。三层还能按场景生命周期叠加：新场景先由大模型出初始策略，预算与数据积累后再上 Uplift 深化钱效。值得注意的工程细节是大模型的用户理解要通过轻量策略模型进入在线链路——泛化能力必须降维成可低延迟部署的形态才能上线。

### 策略越靠近钱，第一性要求越从「聪明」变成「可控」

当模型与 Agent 直接决定资金流向，约束条件完全改变。业务约束必须写进结构化策略配置，在方案生成与实际发券两处统一校验，不能停留在给 Agent 的文字指令里；补贴成本不等于券面额，核销概率、实际抵扣金额、平台承担比例共同决定实际支出；特征只保留决策时点实际可用的，防止事后信息污染训练与评估；降级按异常类型分档——模型异常退回已验证的规则策略，资金或资格状态不明直接暂停发放，预算异常收紧投放。这构成一种职责分离：Agent 在边界内组织策略，执行系统守住资金与权益的确定性。可控、可查、可回滚不是锦上添花，而是智能策略进入交易链路的入场券。

## 实践启示

1. **优化目标设成增量，不要设成核销**：核销率会把预算系统性导向自然转化用户；先建对照实验度量增量 GMV 与增量 ROI，再谈放量。
2. **用四象限做预算迁移**：定期识别营销敏感人群并倾斜预算，自然转化人群降档或停发；对反作用人群做减法本身就是收益。
3. **按价格带设计券门槛**：面额要匹配用户正在浏览的商品价格，180 元商品配满 100 减 10 可能优于满 200 减 25，高门槛本身是决策成本。
4. **分层投资，不一步到位**：大预算核心场景上 Uplift 专用模型；新场景用大模型路线冷启动，数据积累后再升级；流程效率交给 Agent。
5. **用系统而不是提示词约束 Agent**：门槛、面额、补贴率、频控写进结构化配置，在方案生成与实际发券两处校验；Agent 方案与人工配置走同一发布与回滚流程。
6. **复盘沉淀假设而非结论**：把策略配置、适用条件、实验结果与调整原因关联存档，让人和 Agent 都能回答「为什么有效、在什么条件下有效」，否则实验重复的代价会持续发生。
