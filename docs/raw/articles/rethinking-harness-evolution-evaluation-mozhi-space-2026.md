# 智能体Harness自进化失效？重新审视其真实价值（附下载）

> 来源：模智空间（小智，解读 AI2《Rethinking the Evaluation of Harness Evolution for Agents》）| 2026-08-27 入库 | v=7 c=5 v×c=35 Raw only

背景：Harness 是包裹在大模型外面的整套运行系统（提示词、调用工具规则、记忆模块、结果校验逻辑、执行控制流程）。Harness 自进化（Automatic Harness Evolution）= 跑一批任务收集失败轨迹/执行得分 → 元智能体分析问题修改框架（改提示词/工具/中间件/记忆逻辑）→ 在基准任务上测试 → 迭代。核心质疑：这种自进化究竟是创造了更智能可通用的工具箱，还是仅仅让 AI 在开卷考试中通过反复刷题拿高分？

## 现有评测的两大致命漏洞
1. **漏洞1：不公平的比较**——Harness 自进化迭代消耗大量 token/运行轮次/反馈信号，但存在更简单方案 Test-time Scaling（不改框架、推理阶段多花算力反复生成答案）：并行采样（一次性生成多份独立答案选最好）和顺序迭代优化（基于上轮失败原地修改重试）。过去研究很少做这个公平对比，分不清性能提升是"打磨出更优秀框架"还是"花更多算力多试几次碰出正确解"。
2. **漏洞2：过拟合风险**——用来迭代优化 Harness 的任务和最后打分的任务完全同一批，元智能体会学到大量针对这批任务的专属小技巧/任务捷径，而非普适框架设计原则；换一批没见过的新任务性能可能打回原形。

## 公平竞赛规则
同等算力预算、同等反馈条件下对比四种方法：并行采样、顺序迭代、Harness 自进化、单任务 Harness Scaling（为每个具体任务动态临时修改工具箱）。同时拆分数据集——用一部分任务进化 Harness，另一部分完全没见过的任务做最终测试检验泛化。

实验用 Terminal-Bench 2.1（命令行代码智能体基准），测试 Claude Opus 4.6、GPT-5.4、GPT-5.4 mini，统一计算预算 K=5（最多 5 轮尝试）。

## 实验结果：Harness 自进化并没有想象中强大
- **场景1（无单元测试，模型自我判断对错）**：Harness 自进化平均效果甚至不如最开始的原始框架；对 GPT-5.4 进化后性能反而大幅下跌。仅靠模型自己反馈修改框架很容易放大早期错误越改越差。最简单粗暴的并行采样表现最强（多生成几份答案自我挑选收益稳定）。→ 没有外部客观校验信号时，让元智能体修改整套框架是高风险行为；直接多生成答案性价比更高。
- **场景2（有单元测试，客观对错反馈）**：即便有标准答案反馈，Harness 自进化依然打不过简单并行采样。pass@1：框架进化仅比原始框架小幅提升，远低于并行采样；pass@5：顺序迭代优化效果最好。Harness 自进化的收益大多来自"允许多次尝试"，并没有打磨出"跑一次就更容易做对难题"的框架。同样的算力花在迭代答案本身比迭代外层框架收益更高。
- **场景3（泛化：进化任务与测试任务完全分开）**：结论残酷——经复杂进化流程得到的工具箱在新任务上几乎毫无提升（仅平均提高 0.6 分）。说明现在的 Harness 自进化大多在记忆训练集任务专属补丁/特定命令/特殊边界条件，没有提炼出通用跨任务框架设计原理，极易过拟合。

## 为什么自进化会失效
- **记答案而非学方法**：AI 绝大多数修改是非常具体死板的打补丁（如"遇到任务A按顺序执行命令1/2/3"），而非提炼通用策略（如"遇到问题先检查依赖环境"）。
- **啃不动硬骨头**：补丁式修改只能帮 AI 解决"本就会做、只是容易出错"的简单问题；真正困难、需深度推理的核心任务，修改工具箱无济于事，瓶颈在于模型本身能力。

## 结论与启示
作者并非全盘否定 Harness 自进化，而是指出当前基准 Terminal-Bench 对 Harness 不敏感——该数据集上一套极简配置（仅 bash 工具+基础提示词）就能搞定大部分题目，性能瓶颈来自大模型推理而非外层框架。想看到 Harness 自进化真正威力，未来实验应选满足两个条件的基准任务：①任务难度足够高、现有智能体还有巨大提升空间；②任务高度依赖框架设计、必须靠专门工具/工作流/技能完成、大模型光靠自己推理做不到。

我们或许高估了 Harness 的作用，而低估了计算量和模型本身能力的重要性。类比：与其给学生设计花哨学习工具，不如让他多练习几遍（并行采样）或认真反思错题（顺序精炼）；真正的"学会"体现在能否举一反三解决从未见过的新问题。
