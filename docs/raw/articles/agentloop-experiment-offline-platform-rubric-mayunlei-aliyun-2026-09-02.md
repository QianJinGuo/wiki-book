# 实验：回测、离线实验平台与题目级 Rubric丨AgentLoop 数据飞轮实践（四）

> **来源**：阿里云云原生（马云雷，原创）
> **系列**：AgentLoop 数据飞轮实践 · 第 4 篇 / 共 5 篇
> **上一篇**：评估：从黄金指标到 Rubric（第 3 篇）
> **下一篇**：经验库 —— 自动挖掘经验资产

## 核心命题

发现 badcase、调优有了方向后，怎么证明一次优化真的有效？答案是实验：用数据集里的题目反复回测，用分数说话。实验能力回答三个问题：这次改动对这几道题效果如何（实验计划）？怎么安全地测到部署在内网的 Agent（离线实验平台）？怎么让分数稳定可信、并且知道分数为什么变（实验大盘 + 题目级 Rubric）。

## 01 实验计划：数据集 + 评估器 + 变量映射

创建实验计划时指定数据集，然后勾选评估器、配置变量映射。

**变量映射**解决"评估器用哪个变量"的问题——一边是实验的内置变量（input/output/轨迹），另一边是 dataset 里的原始内容（如 expected output）。除了内置变量，还可以加自定义变量标记实验上下文（版本号、实验记录 ID 等 KV 对）。版本号尤其重要——大盘上要对比"不同版本的分数差异"，没有版本标记就无从对比。

配置好实验后可获取本地执行代码——这是离线实验平台的入口。

## 02 离线实验平台：部署在客户内网

Agent 往往部署在公司内网，云端平台够不着。AgentLoop 提供离线实验平台，直接部署在客户内网，就近访问本地 Agent。

**架构分工**：
- **云端**：存储实验记录、展示大盘（记录提交到云端，平台侧随时可看）
- **内网平台**：负责执行——既能出网访问 AgentLoop 云端，又能在内网直接调用本地 Agent
- 数据不出内网，能力不打折扣

**平台配置步骤**：
1. 绑定 AgentSpace（配置要测哪个 AgentSpace、对应 region）
2. 配置 endpoint 与 VPC
3. AK/SK（建议申请专用 AK，权限专用、用途单一）

**连接本地 Agent**：新建连接 → 自定义调用代码（适配有状态 Agent：建 Session → 发消息 → 取响应）→ 单题测试验证连通性。

## 03 定时调度与 Launch History

单次实验验证改动效果，定时调度则把回测变成日常。演示中配成每 5 分钟调度一次（生产环境通常配每天回归）。

**Launch History** 记录每次触发，本地平台与 AgentLoop 控制台数据同步。回测结果直接在实验记录里看。评估过程能看到用了哪些 Rubric、逐项检查命中了什么、缺了什么。

## 04 实验大盘与分数分析

每个实验计划自动创建实验大盘：整体分数、变化趋势、明细，可按题目下钻查看单题分数变化。

为消除单次评估浮动，可按时间窗口计算均值（1 小时或 5 分钟窗口）。

**分数分析方法论（三步排查）**：
1. **分数变低要及时关注**——可能 Agent 真的退化了
2. **先排查 Rubric 定义**——同一版本多次评估分数频繁波动，多半是 Rubric 定义模糊，需优化评估器
3. **再看版本差异**——评估器没问题后，同一版本内分数稳定、不同版本间有差异，才是版本带来的真实差异

这套排查顺序避免最常见误判：把"尺子不准"当成"东西变差"。

## 05 题目级 Rubric：一个关键实践

在线评估用通用标准（用户问题发散，没法定具体 Rubric）。但实验不一样——badcase 抓出来后知道了具体用户问题，两道题的评估标准其实不同。如果用同一套 Rubric 评两道题，优化时就会失去方向。

**正确做法：把 Rubric 定义到题目级别，每道题绑定自己的评估标准。**

**四步改造**：
1. 整理每道题的 Rubric（细项、单项判定、概念边界、扣分项）
2. 数据集 schema 加列 rubric（text 类型），把每道题的 Rubric 写进对应题目
3. 评估器改造：新增 rubric 变量，按传入的 Rubric 评估，输出合法 JSON（rubric_id/score/reason/item_scores）
4. 实验侧绑定：Rubric 选项改为从 dataset 的 Rubric 读取

改造后每道题按自己的标准被评估，实验分数才真正有指导意义。
