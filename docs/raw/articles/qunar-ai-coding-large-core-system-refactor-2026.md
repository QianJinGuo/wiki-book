# 去哪儿网：AI Coding驱动大型核心系统重构实践

> 来源：Qunar技术沙龙（张培&薛锦泽）| 2026-08-27 入库 | v=8 c=8 v×c=64 NEW Entity

## 结果概览
| 维度 | 结果 |
|---|---|
| 交付效率 | 总工时约 100PD → 30PD（提效约 70%）|
| 性能收益 | 核心链路 P50 191ms→59ms、P90 644ms→195ms（下降约 70%）|
| 资源收益 | 机器资源成本节省约 45% |
| 上线结果 | 无 QA 介入，顺利上线无故障 |

核心方法：把大型重构变成目标可拆解、边界可约束、过程可验证、风险可回滚的执行系统，再让 AI 在系统里持续推进、反馈、沉淀证据。

## 一、大型重构的难点是系统级不确定性
- 从局部功能交付到系统行为控制：小需求改对一个功能点即可闭环；大型重构必须证明一整条主链路改造前后行为一致，异常/性能/资源/副作用可控。
- 四类不确定性决定成败：目标不清/边界不明/验证不足/AI 隐含假设补齐缺失信息。
- 传统重构成本高：工时投入大、系统认知不完整（依赖少数人经验）、测试覆盖不足、过程沉淀不足。
- AI Coding 前提：先把不确定性转化成工程约束——目标可拆解、边界可限定、验证可自动化、失败可回滚。

## 二、AI Coding 重构工程化方法论
### 1. Harness 和 Loop
Harness 解决"AI 能在什么边界内行动"，Loop 解决"AI 每一轮执行后如何反馈和继续"。没有 Harness，AI 在边界不清时自动补齐假设；没有 Loop，自动执行变成失控的连续改动。

### 2. 四阶段闭环
规划 → 设计 → 执行 → 验收。只有执行阶段进入高频 AI Coding，规划和设计用来把目标、边界、方案、验证条件对齐清楚。每一步有明确输入、输出、判断标准。

### 3. 人机分工
人负责方向与风险判断（目标定义/边界判断/架构取舍/风险接受/上线决策）；AI 负责高频执行与沉淀（代码扫描/方案辅助/代码修改/测试执行/Diff 分析/报告沉淀）。不能把方向判断和方案取舍交给 AI。

### 4. 任务拆解：先里程碑，再 Task
重构目标 → 里程碑 → Phase → Task。Task 至少要说明输入、输出、修改范围、不修改内容、验收标准、风险点和回滚方案。

### 5. Task 文件：先约束输入，再沉淀证据
Task 是 AI 可稳定执行的最小工程单元，必须提前定义执行输入、验证标准和风险出口。产物沉淀四类：Task 执行记录、验证结果、风险判断、产物链接（支持跨会话恢复）。

### 6. 项目总览文件与自动化执行
当 Task 变多，单轮对话承载不了全部上下文，需要项目总览文件作为文档导航页、状态页、上下文恢复入口、自动化执行入口。AI 按总览 + Task graph 找下一个可执行任务，执行完回写执行记录/验证结果/产物链接。项目总览文件 = 大型 AI Coding 项目的状态源（把"人脑记住的进度"变"机器可读、团队可复查、任务可接续"的工程资产）。

### 7. 发布级质量控制
Task 通过 ≠ 可全量上线。Task 级验证证明单次改动局部可控；发布级验证证明新流程在真实流量下行为一致、指标稳定、异常可回退。把"开发正确"推进到"生产可控"。

## 三、重构实践案例
近 15w 代码、高并发核心系统重构。约束搜索引擎系统约 10.5 万行（QPS 10k，IO+CPU 密集）、包装系统约 4.9 万行（QPS 1.6k，CPU 密集）、预定系统（QPS 80）。问题：三方数据源各自维护/业务逻辑高度耦合/数据口径不一致/报文大 IO 压力大。重构目标：合并搜索核心链路、三方数据源统一、性能优化（搜索 P50 190ms→120ms、省 30% 服务器资源）。

### 里程碑拆解：先一致、再优化、后收口
拆解顺序按"风险能否逐步收敛"而非"哪个模块好改"：先保证行为一致，再优化结构和性能，最后灰度收口。

### M1 目标与边界（四道护栏）
先让选举系统具备本地包装能力，通过一致性验证证明新旧链路行为可对齐。四道护栏：
- **修改范围护栏**：只改相关链路和实现承接，其他代码不动。
- **行为语义护栏**：请求/响应/异常语义不变，核心链路差异必须通过 Diff 收敛。
- **运行安全护栏**：影子双跑、灰度切流、自动止损控制发布风险，不做一次性全量替换。
- **副作用护栏**：影子链路不写 MQ/Redis/外部系统，新增验证不影响主流程稳定性。

### 执行路线：M1 = 9 Phase、34 Task
Task 之上加 Phase（一组共同目标的任务集合，作阶段性推进/验收单元）；Task 是 AI 可稳定执行的最小单元，分 MANUAL/CODE/CONFIG/VERIFY 四类（CODE 主要进 AI Coding，MANUAL 和关键 VERIFY 需人工判断）。执行按 Task 依赖关系推进，不随机挑选。

### Diff 闭环：真实流量差异是下一轮修复输入
影子双跑新旧流程对比，Diff 进入"拉取日志 → 聚类分析 → 问题定位 → 修复方案 → 人工确认"闭环。AI 参与线上差异分析和修复方案生成，但排障边界清楚：AI 辅助聚类/定位/建议，关键风险判断由人拍板。

## 四、总结
- AI 负责高频执行，人负责关键判断。约束越清楚，AI 产出越稳定；验证越充分，团队越容易建立对自动化的信任。
- 把复杂问题拆成可验证的 Task。好的 Task 说明为什么改/改到哪/如何验证/风险/留什么证据。
- 最终沉淀的是团队能力：任务拆解方式、项目总览文件、验证脚本、Diff 分析流程、发布检查项、风险处理经验，下次可复用。

**一句话**：AI Coding 在大型系统重构中的价值不是替代工程治理，而是把工程治理变得更细、更连续、更容易被执行。
