# 别让Agent什么都记 上交×腾讯提出 AdaMem

上海交大和腾讯合作的论文 AdaMem，解决一个被忽略的问题：LLM Agent 的记忆系统，是不是存得越多越好？答案是：不是。存太多反而会让 Agent 变笨。

## 问题：Memory Bloat

现在主流的记忆方案（比如 Mem0）基本是"来者不拒"——对话里所有事实性信息全存进去。短期没问题，但当你跟一个 AI 助手聊了几周甚至几个月之后，问题就来了：

- 无关的闲聊、随口一提的日程细节、重复的问候……全部堆积在记忆库里
- 每次检索时这些噪声会挤占有用的上下文窗口
- 结果就是 QA 准确率持续下降 —— 论文里叫 **Memory Bloat**

## AdaMem 怎么做

核心思路：不要记住一切，要学会记住什么。

它引入了一个叫 **Memory Policy** 的东西——本质上是一套规则，定义"对每个角色/场景应该记什么"。

这套策略是从反馈中自动学习的：每周跑一轮 QA 测试 → 哪些答错了 → 反思是"漏记了"还是"记多了" → 给策略打个补丁 → 如果补丁导致历史表现变差就自动回滚。

完全不需要重新训练模型，直接嵌入现有的 RAG 记忆栈就能用。

## 效果

在自建的 AdaMem-Bench 上测了 10 周：

- QA 准确率最高提升 +9.0%（85.2% vs 76.2%）
- 同时记忆量还减少了 9%
- 也就是说：更少的记忆带来了更好的效果

## 思考

1. "少即是多"在 AI 系统设计中的普适性：RAG 的检索裁剪、Context Window 的压缩、记忆写入控制，本质上都在解决同一个问题——如何在有限容量中放入最有价值的信息。AdaMem 把这个思路从检索端延伸到了写入端。
2. 从"记住一切"到"选择性记忆"，是 Agent 向认知智能迈进的一小步。
3. 工业价值明确：不需要重训练、可以嵌入现有栈、减少推理成本。
4. 明显局限：合成数据集上的验证、隐式反馈下策略推断只有 ~60% 准确率、评估规模偏小。
