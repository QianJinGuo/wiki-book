# 一文读懂 5 项 Harness 与 Agent 自我进化评测基准

> 原文：https://mp.weixin.qq.com/s/_u0xNsAzGZIwj96eyv8x9w

## 全文

同一模型、同一任务集，仅更换 harness（包裹模型的智能体系统层：提示词、工具接口、上下文与状态管理、恢复机制……），执行总分就能相差 **23.8 分**；让 LLM 自己去迭代改进 harness，最好的模型能提升 **16.6 分**，并在部分任务域超过人工设计的 harness。

这两个数字来自本文要讲的五项评测。它们共同确认了一件事：**Agent = Model + Harness**——当 LLM 以智能体形态工作时，性能不再只由基座模型决定，还取决于包裹模型的系统层；而"改进这个系统层"本身，正在成为对模型能力的新考验。

本文覆盖五份材料：**Harness-Bench**、**EvoAgentBench**、**HarnessOpt-Bench**、**Evo-Bench** 四篇论文（均已通读原文），以及 **RSI-Exam** 官方博客。先一览五项评测的定位：

| 评测 | 一句话定位 |
|------|-----------|
| Harness-Bench（北大 + 奇元科技） | 测量"换 harness"对真实工作流执行质量的影响 |
| EvoAgentBench（安徽大学 + EverMind 等） | 测量自我进化方法的经验迁移效果 |
| HarnessOpt-Bench（Scale AI） | 测量 LLM 优化 harness 的能力（受控优化协议） |
| Evo-Bench（人大高瓴 + BOSS 直聘） | 测量 LLM 固有的 harness 进化能力 |
| RSI-Exam（aiming-lab） | 测量模型–harness 系统的递归自我改进能力 |

**阅读方式**：第 1–5 节逐一解读五项评测，每一节按统一框架回答四个问题——这篇文章做了什么；它解决什么问题、为什么出现；评测对象 / 评测能力 / 评测协议是什么；评测发现与结论是什么。第 6 节把五项评测放在一起横向对比。

## 1. Harness-Bench：测量 Harness 对真实智能体工作流的影响

**Yilun Yao, Xinyu Tan, Chao-Hsuan Liu et al.**（北京大学、奇元科技）*Harness-Bench: Measuring Harness Effects across Models in Realistic Agent Workflows*

### 1.1 这篇文章做了什么

Harness-Bench 是一个**诊断型基准**：106 个沙箱化离线任务，在**固定任务环境、预算、超时和评测器**的前提下，让 6 个可配置 harness 与 8 个 API 模型后端做全因子组合执行（106 任务 × 6 harness × 8 模型 = 5,088 条轨迹），另将模型绑定的编码智能体 Codex 在同一任务集上单独评测（增加 106 条），合计分析 5,194 条执行轨迹。

### 1.2 解决什么问题、为什么出现

现有评测存在一个系统性缺口：静态基准（MMLU、GSM8K）抽象掉了执行；智能体基准（SWE-bench、WebArena、OSWorld、Terminal-Bench）评测的是完整提交的智能体系统；工作流基准（AgentBench、GAIA）则在**固定 harness 下比较模型**。结果是：**harness 本身从未成为主要评测对象**。

### 1.3 评测对象与能力定义

- **被测对象**：模型–harness 配置组合，记作 `Agent = Model + Harness`。
- **harness 定义**：组织上下文、工具、状态、权限、约束与恢复、把模型输出转化为外部动作的系统层。
- **评测的能力**：在真实端到端工作流中的**完成力、过程质量（鲁棒性/工具使用/一致性）、效率（token/轮数）、安全合规**。

### 1.4 评测协议

**任务集**：106 个手工审核过的沙箱任务，覆盖 8 大工作流类别（软件工程与代码维护 22、数据/BI/金融分析 14、工作区与工具操作 15、知识与证据检索 13、办公与商务沟通 12、垂直专业工作流 12、长时自治与状态适应 11、SRE/DevOps 7）。

**评分**：TaskScore_i = Security_i · Completion_i · Process_i，Process_i = (Robustness+ToolUse+Consistency)/3

**被测 harness 与模型**：OpenClaw、ZeroClaw、Hermes、Moltis、NullClaw、NanoBot 六个可配置 harness；claude-opus-4.6、claude-sonnet-4.6、gemini-3.1-pro-preview、qwen3.6-plus、glm-5.1、kimi-k2.5、gpt-5.4、deepseek-v4-flash 八个后端。

### 1.5 评测发现与结论

主结果（按 harness 聚合）：

| Harness | 总分 | 完成 | 安全 | 工具 | 一致性 | 鲁棒 | Token(K) | 轮数 |
|---------|------|------|------|------|--------|------|----------|------|
| OpenClaw | 52.4 | 60.0 | 100 | 79.5 | 74.0 | 70.9 | 82.1 | 5.0 |
| NanoBot | 76.2 | 81.6 | 100 | 93.8 | 93.7 | 91.7 | 68.7 | 7.3 |
| Hermes | 71.2 | 80.4 | 100 | 88.5 | 88.4 | 85.5 | 139.7 | 22.6 |
| ZeroClaw | 61.4 | 69.9 | 100 | 84.1 | 83.2 | 79.0 | 133.2 | 8.6 |
| NullClaw | 64.4 | 75.9 | 100 | 85.3 | 81.4 | 78.3 | 175.1 | 12.1 |
| Moltis | 68.8 | 78.4 | 100 | 86.3 | 87.3 | 84.1 | 134.9 | 8.0 |
| Codex（参照） | 80.4 | 86.5 | 100 | 92.4 | 93.9 | 91.6 | 86.1 | 5.0 |

1. **配置级差异很大**：最好的可配置 harness（NanoBot 76.2）与最差的（OpenClaw 52.4）相差 **23.8 分**。
2. **长轨迹不等于高性能**：NanoBot 分数最高且 token 消耗低于 Hermes/ZeroClaw/NullClaw/Moltis。
3. **harness 依赖性**：更强模型的均值总体更高、跨 harness 方差总体更小。
4. **失败症状分类**：契约/格式违规 36.4%、工具/恢复失败 24.6%、证据/接地不足 14.6%。核心概念 **execution alignment（执行对齐）**：失败轨迹的共同模式是"推理看起来合理，但与工具反馈、工作区状态、证据、可验证的输出要求脱节"。

**核心结论**：智能体能力应在**模型–harness 配置级**报告，而非归因于基座模型。

## 2. EvoAgentBench：以"能力迁移"评测智能体自我进化

**Xingze Gao, Chuanrui Hu, Hongda Chen et al.**（安徽大学、EverMind/盛大、东南大学）*EvoAgentBench: Benchmarking Agent Self-Evolution via Ability Transfer*

### 2.1 这篇文章做了什么

EvoAgentBench 评测技能式自我进化：把过往轨迹蒸馏成外部产物（技能、案例、工作流、进化提示词），再在求解未来任务时复用。它从多骨干执行轨迹中抽取"能力卡"（Ability cards），规范化为操作单元并构建能力图（Ability Graph），保证每个测试任务都有训练侧能力支撑。

### 2.2 解决什么问题

现有评测的共同缺口：任务中心基准只测"能否解开留出任务"，从不检验先前经验是否转化为可复用的程序性知识；记忆/长上下文基准止步于信息保留；技能类基准只在单个任务内部评产物质量，不测跨任务迁移。

### 2.3 评测对象与能力定义

- **被测对象**：自我进化方法 m。它只接收训练侧证据，产出进化状态 z_m。
- **评测的能力**：经验编码（extraction）、路由（routing）、吸收（uptake）三个环节构成的程序性迁移能力。

### 2.4 评测协议

三阶段构建流程：多骨干轨迹收集 → 能力抽取与规范化 → 能力图与切分。最终 528 训练 / 267 测试。

### 2.5 评测发现与结论

主结果（四域平均增益 Δ）：

| 方法 | Qwen3.5-27B | Qwen3.5-397B | Gemma-4-31B |
|------|-------------|--------------|-------------|
| Vanilla 平均分 | 37.5 | 49.2 | 36.7 |
| + Memento | −2.4 | +1.5 | −0.7 |
| + ReasoningBank | +3.6 | +2.4 | +0.4 |
| + GEPA | +1.2 | +3.5 | +5.7 |
| + Anchor†（诊断参照） | +7.5 | +10.5 | +5.8 |

1. **能力内容本身可跨模型家族迁移**：Anchor 在全部 24 个方法–领域–设置组合上均为正增益。
2. **当前自动方法在所有设置中都不稳定**：每种自动方法至少在一个组合出现负迁移。
3. **差距被定位到方法侧的抽取与路由**。
4. **单一设置评测不可靠**：Memento 在 27B 上最差但在 397B 上为正。
5. **成本与准确率解耦**：进化并不一致地降低成本。

**核心结论**：自我进化评测应从"聚合准确率比较"转向对经验编码 / 路由 / 吸收的细粒度诊断。

## 3. HarnessOpt-Bench：评测 LLM 的 Harness 优化能力

**Varun Ursekar, Apaar Shanker, Yash Maurya et al.**（Scale AI）*HARNESSOPT-BENCH: Evaluating LLMs at Harness Optimization*

### 3.1 这篇文章做了什么

HarnessOpt-Bench 把"harness 优化"定义成一个受控的优化问题：优化器 = LLM + 编码 harness，收到目标 agent 的种子 harness、带评分的开发/验证反馈和固定的目标评测预算；它编辑 harness、提名最终候选。评测了 5 个前沿 LLM 作为优化器跨 4 个下游任务。

### 3.2 解决什么问题

三个动机：1. 现有 harness 优化方法各自使用各自的目标、种子、预算，无法比较；2. 评测昂贵且含噪声的情形才是关键场景；3. 要让三个研究问题可回答，必须同时满足目标固定、最终评测全程留出。

### 3.3 评测对象与能力定义

- **被测对象**：优化器配置 = 优化器模型 × 编码 harness。
- **评测的能力**：在昂贵且随机的评测下的端到端 harness 优化能力——诊断、修改、预算分配、提名决策。

### 3.4 评测协议

交互协议：优化器在预算内向评测服务请求对候选在开发或验证分区子集上的评测；分级披露——开发分区揭示用例输入与逐用例结果，验证分区只给聚合分，测试分区全程不可见。

任务套件：OfficeQA、BrowseComp-Plus、Terminal-Bench、GAIA 四个下游任务。

### 3.5 评测发现与结论

主结果（归一化增益）：

| 模型 \ 任务 | OfficeQA | BrowseComp-Plus | Terminal-Bench | GAIA |
|-------------|----------|-----------------|----------------|------|
| claude-opus-5 (opencode) | 0.63 | 0.48 | 0.29 | 0.47 |
| claude-sonnet-5 (opencode) | 0.51 | 0.15 | 0.15 | 0.25 |
| gpt-5.6-sol (opencode) | 0.29 | 0.09 | 0.13 | 0.31 |
| gpt-5.6-terra (opencode) | 0.14 | 0.02 | 0.04 | 0.17 |
| kimi-k3 (opencode) | 0.41 | 0.16 | 0.12 | 0.28 |

1. **优化器模型的选择比编码 harness 的选择影响更大**：固定任务与 harness 换模型，增益平均变化 0.142；固定任务与模型换 harness，平均变化 0.079（约 1.8 倍差距）。
2. **原生 harness 没有一致优势**：20 个模型–任务组合中共享 harness 胜 11、原生胜 9、零平局。
3. **能分辨模型代际进步**：GPT 五代增益从 +0.03 单调升至 +0.49。
4. **过程分析**：探索过的维度比例与增益正相关（Spearman ρ = +0.34 至 +0.88）。

**核心结论**："harness 工程正在从基础设施变成一种模型能力"。

## 4. Evo-Bench：语言模型能否改进 Agent Harness

**Lisheng Huang, Chen Yang et al.**（中国人民大学高瓴人工智能学院、BOSS Zhipin）*EVO-BENCH: Can Language Models Improve Agent Harness?*

### 4.1 这篇文章做了什么

Evo-Bench 定位为首个评测 LLM 固有 harness 进化能力的基准。设置中有两个模型：被测模型（evolver）扮演工程师——查看验证任务集上的执行轨迹与分数、提出改进假设、修改"策略 harness"的代码；策略模型（policy model，固定为 DeepSeek-V4-Flash）真正去解下游任务。

### 4.2 解决什么问题

三个设计要点：1. harness 敏感性——任务得分必须对 harness 改进有响应；2. 跨切分泛化——验证与评测切分必须响应一致；3. 长时程进化——模型要能维持多轮迭代。

### 4.3 评测协议

任务领域：Search（BrowseComp、HLE）、Office（GDPval、APEX-Agents）、General（Claw-Eval）；160 个可见验证集 + 448 个不相交评测集。

两阶段 harness 引导构建：辅助 harness 生成 → harness 敏感任务选择。

### 4.4 评测发现与结论

主排行榜：

| 排名 | 进化模型 | Search | Office | General | Overall |
|------|---------|--------|--------|---------|---------|
| 1 | GPT-5.6 Sol | 44.5 (+32.8) | 41.6 (+3.2) | 59.4 (+11.0) | 46.3 (+16.6) |
| 2 | Claude Opus 4.8 | 46.5 (+34.8) | 39.7 (+1.3) | 56.3 (+7.9) | 45.8 (+16.1) |
| 3 | GLM-5.2 | 45.4 (+33.7) | 39.2 (+0.8) | 48.4 (±0.0) | 43.5 (+13.8) |
| 4 | Qwen3.7-Max | 36.3 (+24.6) | 37.8 (−0.6) | 59.4 (+11.0) | 41.5 (+11.8) |
| 5 | MiniMax-M3 | 33.6 (+21.9) | 41.7 (+3.3) | 56.3 (+7.9) | 41.4 (+11.7) |

- 基线 CodeAct 29.7，人工复合 harness 47.5

1. **前沿 LLM 确实具备自主优化可执行 harness 的能力**：最佳 +16.6 分，接近人工的 47.5 但未超过。
2. **增益高度依赖领域**：Search 最容易优化（Opus +34.8 接近人工水平）；Office 域改进最困难。
3. **早期饱和现象**：多数模型提前终止；AnytimeVal 高于最终分说明"先快速发现高质量结构、随后引入有害修改"很普遍。
4. **成本**：成本–性能的 Pareto 前沿呈陡峭的对数关系——GPT-5.6-Sol 超过 500 美元；DeepSeek-V4-Pro 不到 1 美元。
5. **跨策略迁移稳健**：进化出的 harness 对不同策略模型都有大幅提升。

**核心结论**：当前模型已能自主完成有价值的 harness 改进（General 域超过人工水平），但缺乏深层系统级优化。

## 5. RSI-Exam：递归自我改进研究循环的评测

来源：https://rsi-exam.ai/blog.html（aiming-lab）

### 5.1 这是什么

RSI-Exam 评测语言模型智能体**递归自我改进（RSI）**能力的基准。它测量的不是模型修改自身权重，而是：智能体能否在数小时的实验循环中持续改进一个可执行的研究工件。

### 5.2 为什么出现

四个设计原则：1. 长时程改进；2. 隐藏集重新执行；3. 领域原生评测；4. 可检查的研究轨迹。

### 5.3 评测对象与协议

- **被测对象**：模型–harness 系统。评测 9 个组合。
- **任务**：RSI-Exam 0.1 共 88 个任务（35 公开、53 私有），覆盖六个领域。
- **评分归一化**：起始工件固定为 0.00；理论上界固定为 1.00；前沿方案作为 0.60 锚点。

### 5.4 评测发现与结论

总体排名（88 任务平均归一化分）：Opus 5 0.464 第一；GPT-5.6-sol 0.433；GLM 5.3 0.403；Kimi K3 0.382；Grok 4.6 0.367。

1. **领域相对优势**：Opus 5 在系统与硬件（+1.31）、优化（+1.12）、金融（+1.07）优势最大。
2. **可见集到隐藏集的迁移下降**：所有模型隐藏集分数均下降，降幅从 11.7% 到 24.7%。
3. **资源消耗与分数不对应**：输出最多的排名最后三位之内。
4. **三个轨迹案例**说明了成功与失败的机理：TPU 内核优化 145 个版本达到 9.76 倍加速；数学后训练 41 个版本始终停留在 SFT 单一路线。

**核心结论**：持续实验本身不能解释成败——关键区别在于搜索是局限于单一方法，还是发展出结构上更强的方法。

## 6. 横向对比与总结

### 6.1 五项评测在回答什么问题

| 评测 | 被评测的对象 | 核心问题 | "进化/优化"的对象 |
|------|-------------|---------|------------------|
| Harness-Bench | 模型–harness 配置组合 | 同一模型更换 harness 后，执行性能相差多少？ | 无（harness 是被测因素，不进化） |
| EvoAgentBench | 自我进化方法 | 训练侧经验能否转化为可复用的"程序性能力"并迁移？ | 外部产物：技能库/案例库/进化提示词 |
| HarnessOpt-Bench | 优化器模型 | 前沿 LLM 能否系统性地改进一个目标 agent 的 harness？ | 目标 agent 的可执行 harness 代码 |
| Evo-Bench | 被测模型设计改进 harness 的能力 | 被测模型通过长时程迭代改进 harness，能把任务得分提升多少？ | 解题模型所用的 harness 代码 |
| RSI-Exam | 模型–harness 系统的递归自我改进能力 | 智能体能否在数小时的研究循环中持续改进可执行研究工件？ | 任意研究工件 |

### 6.3 相互印证的发现

1. **"配置级报告"已成共识**：不注明 harness 条件的智能体分数没有可比性。
2. **留出集上的泛化才是可靠依据**：可见集上的改进不能当作最终结果。
3. **"能够改进"不等于"善于搜索"**：当前模型擅长快速叠加显性能力与局部调参，缺少因果归纳与架构级重构。
4. **产出物的可迁移性确实存在**：限制不在内容，而在自动方法的抽取与路由。
5. **成本必须与准确率一起报告**。
6. **评测基础设施本身也需要审计**：防作弊设计已是基准的组成部分。
