# AI 时代的数据工程挑战：从复杂链路走向统一数据底座

> 来源：Databend（吴炳锡）| 2026-08-27 入库 | v=6 c=6 v×c=36 Raw only

## 问题：AI 系统的数据链路越来越长
AI 系统越做越多、迭代越来越快，但数据链路反而越来越长。传统链路：模型 API → Tracing → Kafka → 日志库 → 调度脚本 → Eval Dataset / BI。放入大规模业务环境后复杂度骤升：数据分散在火山云/阿里云/华为云等多厂商平台，需跨云、跨数据库、多套脚本搬运复制，同一种加工逻辑重复实现。问题不只是链路长/组件多/成本高，**数据口径的统一变得异常困难**——模型团队和数据团队都难获得可信、可复现的指标口径。

## 核心痛点：如何量化评估 Agent 链路改动
模型公司做 Prompt/Harness Engineering 时，如何证明某次调用链路调整有效？换模型后新模型性能提升多大？无法凭主观感受判断，必须量化评估。Databend 构建 Evot Demo（现已开源 https://github.com/evotai/evot）：记录 Claude Code/Pi/DeepSeek Agent 等主流 Agent 执行任务时对大模型和工具的调用轨迹，可视化每步执行过程、总耗时、步骤数、调用差异，支持 Agent 与模型能力迭代。

## 两大数据工程挑战
1. **数据量极为庞大**：Agent 进入生产后，单次复杂任务可持续数小时，单条 Trace 达 GB 级、Context Tokens 达百万级，每天近 100TB 数据持续入湖。类似工业机台数据——量庞大、形态相对单一，但必须持续稳定清洗供下游使用。
2. **JSON Schema 持续大变**：不同模型/同模型不同版本的 JSON 结构迥异，字段新增/缺失、数据类型漂移。如何兼容上下游变化、避免模型因结构变化报错，是现实的数据工程难题。

## 统一数据底座方案（Databend Cloud）
- 不同平台 Trace 汇入统一 Kafka → 持续写入 Databend Cloud。平台内依次完成：校验与解析、字段抽取、语义归一、Trace 聚合、质量检查、服务表刷新。
- **校验难点**：客户说"是 JSON"不一定是合法 JSON（Array 混入数字/字符串、多余大括号、字段格式不符），无法校验的标记交由人工。
- 抽取 Model/Prompt/Tool 等字段，把堆砌在单个 JSON 的数据展开成宽表，按聚合还原任务；语义层归一 + 敏感字段识别脱敏。
- **ELT 一体化**：数据在同一个湖仓内完成处理，简化链路；平台内置**数据血缘**（A 表来源、B 表生成逻辑、字段依赖上游字段可追溯）。
- **存算分离架构**：同一份数据按业务切分计算集群（摄入集群/服务集群/加工集群），负载隔离共享数据；计算节点无状态可自动扩缩容。服务集群按时间自动启停（8:00 开、20:00 无请求自动关）。

## 收益与量化
- 原本 3 名程序员加班维护 → 约 0.5 FTE + 一名实习生，人力约为原来 1/6。
- 每天近百 TB 数据持续入湖统一汇聚；多套数据链路/组件/接口由 Task 自动完成数据加工，异常自动提醒。
- 四阶段收益：接得住（JSON 原生类型承载，先写入再加工）、变得动（多集群隔离/按业务拆分）、Stream+Task 增量数据编排（无需额外开发增量识别和调度）、数据服务。

## 平台能力补充
- 内部部署类似 OpenRouter 的统一服务，提供多模型 + 内置 Harness Engineering 能力；对比内部方案与 OpenCode/Pi 等 Agent，评估 Harness 是否有效、有无不必要 Token 浪费。完整 Trace/成本/步骤数据可量化"Claude Code 说句 Hi 为何这么贵"。
- 细粒度权限管理和审计：谁连了数据库、执行什么 SQL、请求多少数据、消耗多少计算/内存，可从审计日志直接查询。

## 架构观点
- **Kafka 可能不再必需**：对象存储本身有 Notify 机制，应用直接写对象存储，存储通知下游增量变化，持续消费即可。链路少一层省组件和运维成本。对象存储全球写入不收费（某些 Kafka 公网流量 1GB 约 0.5 元，大数据场景成本可观），适合全球统一数据仓库。
- 面对结构持续变化的数据，先用 JSON 承接变化，再在平台内迭代加工逻辑；Task 做任务/DDL 编排，Stream 捕获增量，UDF 做自定义加工和分发。海外客户用它替换 Flink 做 Data Pipeline（如游戏结束匹配下一局队友的实时特征加工）。
- Multi-Cluster Warehouse 应对热点数据/并发突升，自动拉起更多计算集群。

## 客户案例
- **沉浸式翻译**（在线 App）：0.5 天 POC，次日成为正式客户；AI 数据分析、向量化记忆、长期任务跑在平台上。
- **基础模型/AI 企业**：持续处理大规模 Trace、构建 Evals、比较模型和 Harness 版本，数据用于训练和发布决策。
- **福建省大数据集团**：省级数据汇聚平台统一数据底座（数 PB 规模），Hadoop/MPP/Spark 等统一到 Databend，用统一 SQL 替代部分 Spark 作业。
- **中信信托**（金融）：统一归档和湖仓整合，冷/温数据逐步归档提供温数据层（千亿行级表长期放传统数仓成本高）。
- **工业制造**：机台每天约 50GB 数据持续加载，Raw 层"保真"（源端什么样进库就什么样=脏数据层），再通过 Task/Stream 增量自动加工分发。

## 定位
Databend 定位为"统一 SQL 访问 + 云原生简化数据工程"的一体化数据平台：承载结构化/半结构化/非结构化数据统一检索；用户无需显式考虑分区、手工设计索引，SQL 能表达需求优化器尽可能高效执行。目标是以云原生能力简化数据工程、减少人员和成本，为现代应用和 AI 工作负载提供简洁弹性的一体化数据平台。
