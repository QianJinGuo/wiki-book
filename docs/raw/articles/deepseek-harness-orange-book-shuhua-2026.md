# DeepSeek Harness 橙皮书：从开机到拆开（花叔，2026-08-14）

> 第三方一手实测文档（作者花叔，AI Native Coder，不写代码但产品全 AI 写）。120 页，基于官方仓库 + 683 篇设计笔记考古 + 本机一手实测（快照 2026-08-13 23:05-23:20，仓库 47f9438，本机 @deepseek-ai/dsh@0.1.0-rc.6）。所有数字带取数命令可复现。文档版本 v260814。

## §00 序章：探索未至之境

DSH（DeepSeek Harness 命令名）是"同一样东西的两面"：一个装上就能用的编码 agent，和一套能拆开重装的框架。内测开发者 Jiayuan Zhang（JY）类比：乐高汽车玩具，官方 Coding Agent 只是官方预置，零件全可换，拼出来不一定还是汽车。类比失真处：拼错乐高一眼可见，这东西拆错了通常安静地不工作（某零件永远卡"待加载"，§11）。

**三个开门问题**：
- **要钱**：dsh 无订阅，四层凭据全是 API key（进程环境变量→家目录凭据文件→项目环境文件→全局环境文件），仓库里没有订阅态概念，不会在花超前叫停。实测同一任务（读四文件+跑验证+写 README）：flash $0.0034（约2.4分）/35.7s，pro $0.0097（约7分）/45.4s。官方公告 2026-08-17 0点（北京时间）起改分时计价，高峰价是现价 3-5 倍，同活约 0.09 元/次。
- **隐私**：进程在本地、对话要出门（文件内容发去换回答）；遥测默认关；一个关不掉的匿名编号（鉴权后生成本机 UUID，每次请求带走，写在模块 README"已知限制"里）。
- **安全**：三档沙箱（只读/工作区可写默认/完全放开切时二次确认）+ 审批策略默认"问"；没有"总是允许"、不记规则、每次越界亲手点；拒绝后命令零执行。空白：三档词汇只管文件不管网络（官方明写）。

**模式只能在空白会话切换**：跑过一轮后换模式会被网关拒绝（内部工程笔记：历史是在该 preset 工具下产生的，换工具会让已记调用变孤儿）。选工作区动作会重置模式回标准（顺序：先工作区再模式）。

GitHub 公开当天 3 小时 star 2.7万，次日 35.0k，写书时 4 万+。JY 评价：按 Coding Agent 标准 DSH 体验不如 Claude Code/Codex，还很早期、接口在变、插件生态刚起步。

## §02 权限体系

默认状态三行日志：permission/preset=workspace-write、sandbox/mode=workspace-write、approval/policy=ask。两个独立旋钮：文件沙箱三档 + 审批两值（ask/never；只读和工作区可写配 ask，完全放开配 never）。切完全放开弹中文确认文案。

**升权梯子三道闸**：只能升不能平移（必须严格更宽档位）；只读是地板（不能升到只读）；重试只有一次且必须同一轮（"升权从不投机"）。内核拒绝消息带梯子：`[sandbox: file access denied under workspace-write mode]` + `[sandbox: escalation available — retry this exact operation once with sandbox_permissions + justification]`。

**软性封锁教训（撤回的决策）**：最早把沙箱模式写进固定系统提示词，线上数据打碎直觉——带着这句话，模型会拒绝尝试本可升权拿到的工作：第一次人工会话 12 轮里 5 轮零工具调用，直接解释"我没有权限"。他们称之"软性封锁"，被写入被拒方案清单（"先发货了，然后基于线上证据移除"）。换来的原则：不要在开头劝退，要在撞墙时给梯子。现在标准模式系统提示词 4000+ 字符无一个沙箱字样，策略作为单独运行时上下文快照发入；只读档措辞专门设计："Do not refuse a required modification from this policy alone: try an available tool normally and follow any denial and escalation guidance it returns."

**凭据保护撤回（第二个撤回决策）**：凭据明文存 ~/.dsh/.credentials.yaml 权限 0600，但模型 bash/文件工具跑同一用户，0600 挡不住模型（工作区可写只管写不管读）。他们加过"路径禁止读"规则，写完上线又撤回：Linux 路需在只读目录树里建挂载点、父目录不存在就拒绝整个约束（每台新机器中招）；另一路没法从已给出的读权限里做减法，每次调用都汇报"只管住了一部分"。结论原话："一个在它生效的地方破坏约束、在它不生效的地方谎报状态的保护，比一个被文档化的缺席更糟。"撤掉后改文档明说：存下来的凭据对模型没有边界——没有界面把文件塞进环境变量、模型拿不到现成路径，要读到得刻意去读没人给过的路径。真正的答案（进程读不到的系统钥匙串）记成待办。

**操作系统层**：macOS 用 sandbox-exec（苹果标"已弃用"，对策=探测，万一没了拒绝执行不静默放行）、Linux 优先 bubblewrap 退 Landlock、Windows 受限令牌；不用 seccomp（全仓仅 2 处提到，都在被否决笔记里）。Linux 启动器是自研 ~300 行 C：先戴手铐再变身，变身之后手铐还在。限制在内核里不在进程里，进程被完全攻陷也只能在圈里活动。三处失真：①"部分执法"档（旧内核/Windows 边界情况，会老实告诉你）；②焊的是文件不是一切（网络不在管辖）；③"焊死不等于焊得严"。

**撤回决策三**：Windows 沙箱评估第三方库 landstrip（Rust 内核一库三平台）被否："一个承担安全不变量的依赖，必须有被证明的采用度"（当时 48 star）；连"Linux 那级也换成它"都被否（现启动器可审阅 C 源码、二进制钉死在自家构建，刚从一个 Rust 依赖迁走）。同一天立反向规矩：能用成熟依赖就别手写。两条划同一条线两侧——安全关键位置 star 数是硬指标。

**模型不可见性**：会话日志 44 种事件类型，模型能看见的只有 3 种（用户说了什么/模型说了什么/工具返回），审批问过没有、你怎么答的、沙箱模式、权限换没换过全部只进日志不进模型眼睛（3:41 是 §05 正题）。

## §05 会话事件流（Model-visible ⟺ logged）

一句最普通的话（"用一句中文说明当前目录下有哪些文件"）日志落 44 行：assistant/chunk 13、三种打包行 7、user/message 3、assistant/message 2、step/start·end 4、agent/inbox/spliced 2、标题相关 3、turn/start·end 2、tool/call·result 2、request/header·context 2、权限三件套 3、文件头 1。44 是文件行数不是事件数（打包行一行装多条碎片，事件编号到 125）；44 种事件类型跟 44 行纯属巧合。44 行里模型只见 6 行（3 条 user/message、2 条 assistant/message、1 条 tool/result）。

**核心不变式**：`Model-visible ⟺ logged`——任何进模型请求的东西必须能从会话日志重建；新增模型可见输入必须新增会话事件。每次发请求前代码自己比对：把真要发的消息列表 vs "从日志重算应得列表"，六项逐项比（模型/系统提示词/温度/输出上限/工具清单），对不上抛异常请求发不出。三个好处：可审计（模型看到什么逐字节可复原）、调试、省钱（日志只追加不改写，投影出的请求天然是上一次的延长，缓存自动命中；"稳定性是涌现出来的，不是管出来的"）。

**从日志拿到的官方文档没有的东西**：标准模式完整系统提示词 4,100 字符（开头 "You are an AI agent powered by DeepSeek Harness."）；25 个工具逐个有名有姓；技能目录 1.6 万字符原样躺在 user/message 里。方式两条命令：`ls ~/.dsh/sessions/` + `zstd -dc .../session.jsonl.zstd`（压缩非加密，魔数 28b5 2ffd）。

**分叉/恢复/回放是同一日志的三种读法**：分叉=拷前面一段日志当种子（切口必须落在一整轮外，切半轮拒绝）；恢复=整份日志读出来当种子；回放=拿真实日志当剧本，无 API key 重跑（内部测试设施，出错现场可打包复现）。作者未实跑这三样。

**压缩不删原文**（与别家相反）：被压掉的事件留在日志原位，只是从"模型可见面"遮住；摘要是新写一条消息标注"遮住第几条到第几条"、记录哪个模型写的/限多少 token/实际花多少。省地方三件事：外溢（单条工具结果太大存成文件，模型可读路径，不调模型）/裁剪（机械掐头去尾，中间永久消失，不调模型）/压缩（裁完还满才调模型总结，一次模型调用）。从便宜到贵，三样都不改日志。实测外溢：171,000 字节文件被截，剩 5 万字节上限，提示完整输出在临时文件、省略 14,385 字节可 read/grep。外溢文件在系统临时目录不在 ~/.dsh/，每跑一次新建不回收（作者跑几次攒 16 个空目录）。

**代价**：最小样本"echo+回词"落 35 条物理记录；存储层打包（连续 3+ 同类碎片压一行，真实编码会话小 60%）；无保留期策略（跨项目恢复后所有项目日志堆同一目录，不自动清理）；会话格式版本号 0，老格式直接拒读不做迁移（拒读时说明方向）；删不掉（只追加不改写，无法精确抹掉某句，整删目录可以）。2026-06-20 提案"只留完整消息不存碎片"被否：失败的流（模型吐一半崩掉的内容只活在碎片里、撞输出上限那轮只有碎片承载账单）+ 无密钥回放建立在这些碎片上。结论："除非有一个一点信息都不丢的替代品，否则不能删"——去压缩存储格式，不去剪内容。

## §06 成本账单（实测）

四层凭据全是 API key，无订阅概念。真实任务（四文件+写 README）五步：flash $0.0034/35.7s、pro $0.0097/45.4s；一天 100 次 flash 2.4 元（8-17 分时计价后 9 元/天）。Claude Code 对照（Anthropic 文档）：平均每开发者每活跃日约 $13，90% 用户低于 $30/天。两个模型 token 用量几乎一样（未命中输入差 2.3%、输出差 11%），贵三倍全来自单价。任务里第三步跑 Python 验证是模型自己决定的（没要求它验证）。

**13,809 token 入场费构成**（第一次请求未命中输入 13,838，逐块发给 API 称重）：
- 25 个工具说明书 6,510（47.0%）
- 本机 skill 目录清单 6,242（45.1%）——**45% 是用户自己带进来的**（57 个 skill 全被自动读走）
- 系统提示词 844（6.1%）
- 运行环境快照 129（0.9%）
- 协议固定开销 82（0.6%）
- 用户实际提问 29（0.2%）

"我问了一句 29 token 的话，harness 替我先付了 13,809 token 的入场费。"工具最贵三件：workflow 979 / bash / str_replace_editor，合计 2,344 token 占工具预算 36%，而 workflow 这次一次没调用。57 个 skill 让每会话开机成本从 ~7,600 涨到 13,838（+82%），每开新会话付一次、每派子代理付一次，实际用到的 skill 数=0。

**缓存**：flash 缓存命中价 1/50、pro 1/120。五步流水缓存命中率 80.4%；命中数全是 64 的整数倍（13952/14464/16512/18176）——验证官方"64 token 一个存储单元，不足 64 不缓存"。第四次跑（隔 2:21、换进程新会话）开机 13,838 命中 13,824、全价只剩 13，成本只有上一跑 52.5%。DeepSeek 缓存寿命几小时到几天、写入不收费（对照 Anthropic：订阅 1 小时/按量 5 分钟）。"命中比未命中便宜 50 倍"说的是单价，总账没有 50 倍（输出不打折）：缓存全失效成本 $0.0034→$0.0121（3.55 倍）。

**KV Cache effect 门禁**：219 个包 README 必须以固定结构结尾，含 "KV Cache effect" 节写明"我这个零件会不会让缓存失效"，区分只追加/稳定重复前缀/替换更早内容/独立发一次请求四种行为。215 个填了，4 个白名单豁免（理由逐条写在门禁脚本源码里，脚本 38KB）。三条照做：不在会话中途改配置/换人格/开关工具；贴图开头贴；工具重排会掉缓存。摘要器教训：默认摘要器另发请求用专门摘要提示词，同一段历史按全价付两次（修法=把摘要指令搬到对话尾部变热请求延长线）；三条省钱直觉全被否（保留摘要器系统提示词其余复用/只发被遮历史不带头/省工具说明书）——结论反直觉：摘要器不用工具也得原样带两万多字符工具说明书，少传反而更贵（前缀错位）。

**三个坑**：①网页点模型下拉永久改全局设置文件、层级压过命令行参数——命令行指定 flash 日志里却 pro，3 倍差价静默发生；②产品自己不算钱（进度条用"4 字符=1 token"尺子，中文密度实测 1.71 字符/token，中文长对话偏差越攒越多）；③默认思考强度最高档（flash 3,797 输出 token 中 1,444 是思考 token 占 38%，全按输出价计费）。

## §07 创造模式实测：它给自己长出一只手

对话中途让模型给自己造新工具（count_chinese 数汉字），成功：模型工具清单 32→33（32=标准 25 + 创造模式多 7 件自指工具），动态插件 0→1（cjk-1），实测"探索未至之境"返回 6（正确）。19 步 24 次工具调用，**前 14 步 20 次调用一件正事没干，全在读自己的说明书**：查运行时（cordis_inspect×6）、翻安装目录（6）、读类型声明 types.d.ts（4）、搜 defineTool 在哪（3）、加载 cordis-plugin-development 技能（1，自己想起的）。真正动手最后 4 次：提交定义→挂进活运行时→确认工具数 33→用一次。写的代码 20 行，汉字匹配写了三段范围（常用区+扩展区+兼容区），两段这次用不上——"查着写"和"凭印象写"的区别。

**边界**：动态插件只活进程共享内存：不创建任何插件文件、不安装任何包、不改动任何配置、重启不存活、**不能被自动提升为正式插件**（想留下得人按正常流程写真插件）。风险声明原话："这个沙箱隔离全局变量，但它不是安全边界……请把这套工具当成 bash 权限来对待。"官方文档写"5 个自指工具"，实测运行时 7 个（"查看"拆成三个：列出/按条件查/查自己）。这场账：19 步/24 次、系统提示词 17,663 字符、32 件工具说明书 33,867 字符、新输入 131,494、输出 11,349、缓存命中 863,232（6.6 倍）、模型耗时 2:27、约七美分（86 万缓存全按新内容计费会翻六倍多）。

JY 称之为"自进化软件"雏形，作者同意但补后半句：**它能给自己长出一只手，但这只手活不过一次重启**。卡住沉淀的不是技术，是那条不变式（Model-visible ⟺ logged 得管到跨会话、管到硬盘配置目录，"这个 agent 现在是什么样"不再是一份日志能回答的）。他们不是做不到，是不敢默认打开。创造模式故意不进默认组装：模型写的代码在 harness 自己进程里求值，而管束程序的那道机制只管得住它派出去的进程——"在网页界面上，沙箱和审批这两道关是被绕过而不是被执行"。

## §08 PTC 模式：让模型写程序，以及那笔反直觉的账

PTC 模式英文界面叫 Code mode、目录叫 code，"PTC" 三字母只存在于中文界面，全仓 20 万行代码无一处展开（行业有同名缩写但仓库无证据借用）。模型眼前只剩一件工具 run_code，写 TypeScript 程序组合工具调用；题眼提示词："用 return 和/或 console.log 产出结果。只有你打印或返回的东西会回到你这里，中间工具结果永远不进入对话。"那 24 件工具没消失，是报关单从信封外挪进信封里——工具参数表 26,894→897 字符，但系统提示词 4,100→35,643 字符，第一轮真实输入 13,842→15,040（**多花约 9%**）。PTC 不省在前面，省在后面：5 次程序调用实际发起 15 次操作（找文件 3/跑命令 3/写文件 5/读文件 4），中间 10 次输出从没进模型眼睛；那 10 次以"代码内派发"事件落在日志里，模型读不到但人能倒带。

**同任务对照实测**（三小文件，V4-Pro 推理档拉满）：标准 21.9s vs PTC 305.9s；新输入 14,447 vs 17,591；输出 1,416 vs 17,235（思考 739 vs 13,095，76% 在想不在写）；端到端慢十几倍、输出 token 12 倍。两边都答对（含"最大文件并列"口径说明）。PTC 是赌注：赌中间产物大且不需要模型看见，任务越碎越大越划算，小任务稳输。

**三家走法不同**：Cloudflare 首创（TypeScript 轻量隔离）、Anthropic Programmatic Tool Calling（Python 托管容器）、DeepSeek 明确后来者（立项笔记点名引用 Cloudflare）。三个不同：①不靠省参数表限制模型，在执行环节堵死——8 月 7 日修复笔记：PTC 只收敛"广播面"没收敛"执行面"，模型直接喊原生工具名照样穿透执行（"当直接调用方能绕过时，省略参数表不构成任何强制"）；Anthropic 把同一件事写进文档警告，DeepSeek 写进执行器；②主动拒绝程序间共享状态（每段程序全新隔离环境跑完就死），宁可慢也要保"每个请求都是日志的纯函数"——Anthropic 反方向加状态持久化；③全程不给省钱数字（"而不是承诺一个普适的减少"，发布后才知道）。否掉"不设模式所有人都走 PTC"的原教旨（Cloudflare 博文做法）：编码 agent 最家常动作（跑命令/读文件/改一行）最适合原生调用，逼每次编辑套程序是给常见情况上税。

**极简模式**：只有两件工具 bash + str_replace_editor（持久命令行+四招文件编辑器：看/建/替换/插入），无搜索/子代理/上网/上下文压缩。用途=给模型跑分（官方跑基准测试同款）。扒掉四样一般人想不到的：上下文压缩（压缩机制在，模型历史可能被摘要偷换，测的就不是模型）、运行时环境说明（工作目录/沙箱状态不注入）、系统提示词彻底锁死（结构上加不进去，不靠自觉）、**不开"完全放开"沙箱**（即使全放开，工具参数表仍挂着"沙箱权限"和"申请理由"字段，模型看得见沙箱痕迹——要去掉的不是限制，是限制在模型眼里的痕迹）。Windows 上跑不起来（硬绑 bash，唯一没做平台判断的配置，仓库记成待办）。

**四个模式是四个文件夹**：标准 251 行 / PTC 262 / 创造 262 / 极简 62 行清单文件（agent.cordis.yml），切换=换清单重新组装 agent。唯一支持的造新模式方式=复制一份再改（§11 讲原因）。

## §09 长活：五个多 agent 工具 + Ralph 循环

25 个工具里 5 个跟指挥别的 agent 有关：subagent（全新会话，看不到之前聊什么）/ subagent_fork（带上文，用父会话已完成轮次当种子）/ list_agents（看谁在跑）/ send_message（给在跑的补一句话，不用等跑完）/ interrupt_agent（只停那一个）。子代理汇报工具说明书写给模型："它和你共享工作区，但它不会自动收到你的对话记录、工具输出或推理过程，所以'你把活干完了'本身并不是一个结果。"

**Ralph 循环**：给定不可更改目标，反复交给完全崭新的工人；每轮全新子会话不带上轮对话，只靠共享工作区 + 有字数上限的交接单传递状态（致敬 Geoffrey Huntley 2025-07 技法，仓库没提他名字）。写死提示词核心："共享工作区和它当前的工作树，是长期记忆和事实来源。动手之前先检查它们……把上一份报告仅仅当作一份有界交接单。"赌注：工作区本身就是记忆——第 47 轮新工人看到前 46 轮真实留下的文件，不是关于文件的叙述，没有挫败感和自我合理化。交接单只有三种结论且约束紧：还要继续（至少一条下一步）/宣布完成（具体证据且不能留一步）/宣布卡住（具体阻塞点）；报告超长直接失败不截断。出厂轮数上限 64（包默认 256）。**局限**：完成与否是工人自我宣称，非独立评估——独立评审者/评审驱动续跑/完成证书/对抗性验证器全部有意推迟；界面文案必须写"某个工人报告了这个结果"而非"已认证完成"。

**计划模式**：软性指引拦不住任何东西（限制来自沙箱和审批策略，互不读写对方状态）；进计划模式工具清单不变，只是提示里加"现在别用"（藏起来会改提示词开头打掉缓存——用一句规则的成本换一次全量重算）。**目标四相位**：进行中/暂停/卡住/完成 + 轮数上限。"卡住"定义严：同一阻塞条件连续三轮都还在才能标卡住且理由写清具体条件；困难/不确定/还有活没干完都不算卡住；机械闸门：自动轮次里报卡住满三轮前直接拒。目标"激活"故意不写进持久记录——重新打开会话它永远不会自己开始干活。

**事故与制度（§12-13 摘要）**：
- **四篇事故复盘**（docs/postmortem/，编号 0001-0004，中英双语，格式：摘要/时间线/根因/新增防护/经验教训；标准三条：机制隐蔽/系统性/重新发现代价高）：
  - 0001：桥有 178 个单元测试+100% 行覆盖率，生产环境完全无法工作——根因一行 `export default apply`（默认件让加载器丢掉"我要用哪些服务"申请单）；178 测试全手工挂载不经过加载器；真走全流程的测试要 API key，CI 没 key 跳过；本地"通过"因残留旧编译代码。结论："100% 行覆盖率始终满足。覆盖率证明代码行被执行过；它不能说明功能是否按交付方式正常工作。"方法论：信 trace 不信理论（优雅解释推理几小时，插句打印几分钟真相；优雅解释后来证明是第二个 bug）。
  - 0002：配置开关写错位置让工具集体消失——表达式在插件参数里现算，但"启不启用"格照原样读（对象恒真），三工具永久禁用；测试是快照测试且有人刷新过快照，"找不到工具"被存成新正确答案（"快照刷新是 fixture 的生产过程，不是正确性审查"）。加三道防护（配置格禁表达式+门禁扫描/快照工具拒收"找不到工具"/文件系统场景独立配置层）。8 月 11 日禁令被推翻：加载器现在真的求值那一格（Windows 需要按平台开关），"隐患是靠求值关掉的，不是靠禁止"。
  - 0003：验收替身服务器——用户 3081 端口对话，模型改完源码把验收甩给用户→自己起精简服务探 200 就宣布成功→又起 3334 端口验收报告完成，用户真正用的 3081 从没探过。根因：组合没告诉模型"当前会话跑在哪个网址/进程/模式"。修法：$DSH_WEB_URL/$DSH_WEB_MODE 环境变量 + 精简版服务器启动阶段拒绝。三句教训：网络就绪/构建成功/启动清单是三件不同事实；验收必须指定确切目标地址并从外部观察；一台替代服务永远证明不了你那台页面变了。
  - 0004：一行无害提示被当沙箱故障——老 Linux 内核沙箱每次执行前打印"我只能做到部分约束"（善意提醒），harness 只靠前缀分辨，正常空结果（退出码 1）撞上该前缀被判"沙箱不可用"→"搜索失败"（没搜到变系统故障）。根因原话："stderr 仍是带内归因通道。受限子进程可以故意复现 runner 的门控致命诊断行与退出状态。"影响评估克制：约束没被削弱、无命令跑无约束状态，损失在可用性与诊断完整性。真正的修法（带外通道）属后续加固——"一个刚发布的产品，在自己的事故复盘里写下'我这个判断依据原理上可以被伪造'，我没见过第二家。"
  - **教训固化**：219 个包各带 invariant.ts（184 份空，空实现第一行必须 `No runtime invariant:` 开头写明包特有理由，门禁机械拒绝糊弄）；崩溃恢复文案合成（工具调用记下后结果落盘前挂了→"结局未知。要不要重试，请从这个工具的语义出发判断：只有当操作是只读或幂等时才重试；如果它可能有副作用，先去核实外部状态或者问用户"；未开始→"重试即可"——两句话差别是"我不知道删除命令有没有执行"和"肯定没执行"）。已知未修：内存泄漏=生命周期（网页宿主不销毁 agent，句柄直接扔掉无淘汰机制，挂待办）。
- **AI 写代码库长什么样**：12,293 提交/64 天（2026-06-10 到 08-13）/单日最高 887（7-30）/设计笔记 683 篇（已实现 505/归档 142/待办 25/被否 11）。人数四口径：46/40/37/22（GitHub 认 22，网页显示 19）。2,355 个 markdown > 2,319 个 TypeScript。仓库 8-13 当天建、一次性推两个月私有开发史。**那句解释一切的话**（开工第二天制度笔记）："这个代码库主要由编码 agent 开发。相比写在文档里的约定，agent 遵守被强制执行的检查要可靠得多；而当劳动由 agent 完成时，'工作量很大'不构成一个成本论据。"Agent Note 制度三条：每个非平凡改动必须同提交新增/更新至少一篇笔记；笔记必须写清否决了哪些方案（"Alternatives are recorded, never invented"——制度前老笔记若考证不了必须永久带"这里的替代方案没被记录"注释）；笔记归档哈希冻结永久不许改（426 条封存记录，只能追加的指纹清单）。笔记分类编进文件路径不写头部（"把路径已承载的事实抄第二遍，迟早打架"）。27 道机械检查+12 个生成器（"35 个门禁"是把测试文件数进去了）；唯一没有自动检查的规则="改动是否平凡"（机器没法可靠判断，加了只会误报和表面合规——"能机械化的一律机械化，判断力留给人"）。提交量第一崔添翼（Tianyi Cui，2026-03 加入 DeepSeek 任 Harness 团队负责人，Jane Street 近九年）5,235 次占 42.6%，前三 63%。思维链泄漏清理程序（八类，含"英文文档漏出中文工作语言碎片"——一个证据同时坐实 agent 深度参与和团队开会用中文）。问题单设施造好但公开时关闭（5 模板+策略引擎+状态机全在，对外导流讨论区；公开不到 3 小时讨论区 184 条无标签无优先级）。

## §14 它在赌什么，代价是什么

**四注**：
1. **一切皆插件，赌生态，扔开箱即用**：连主循环都是配置里可 disabled 的一行（"没有一个特权内核等着你去打补丁"）。自证=删掉的东西（.dsh-plugin 专用格式 8-9 全删，skill/MCP 不需要特殊通道就是普通插件）。代价：体验不如 Claude Code/Codex（JY 原话）；133 个插件在跑、设置页能点着改的只有 3 张卡。
2. **每一次运行都有迹可循，赌可审计，扔磁盘和简洁**：44 种事件 3 种模型可见；为守这条拒绝 PTC 常驻内核（跨调用状态不进日志破坏"请求是日志纯函数"不变式——Anthropic 恰恰加了这特性，两家反方向，一边赌性能一边赌可重建）；35 条物理记录/最小样本；无保留期策略（"它不会自己删。硬盘是你的"）。
3. **技能和 MCP 只是普通插件，赌抽象正确，扔贴合度**：29 行"每项产品功能映射到扩展点"表，技能是二十九分之一。净赚=技能门开得最大（57 个零配置读走）；净亏=MCP 只桥工具类、默认零服务端（"每条服务端命令都是 agent 沙箱之外的可信可执行代码"）+35 个包不在默认安装。
4. **模型公司自己下场，赌能力兑现，扔中立**：Composio 8-11 实测——固定 DeepSeek V4-Flash 套 8 个不同 harness 跑 30 个跨软件复杂工作流共 240 次：通过率 46.7%-66.7%，每次成功成本差约 7 倍；"有 7 个任务，成败只取决于我们用了哪个 harness"。极简模式是"给它自己刷分用的"。匿名 UUID 跟请求走、关不掉（写在"已知限制与待办"段落，被门禁强制存在——"把'我们哪里不行'做成一道通不过就合不进门禁，是我看到的最值钱的东西"）。

**文档落后于代码三现场**：创造模式文档写 5 个工具实测 7 个；工具改名旧名留在喂给模型的技能文件里（"文档写错顶多骗到人，这个直接骗模型"）；9 个 Cordis 包三处文档写"私有从不发布"实际全发 npm 了（三处文档一致地错）。

**作者判断**：适合三类人（想搞明白 agent 底下怎么转的/要做插件工具界面的/攒了技能资产想找不用搬家就能试的新窝）；不适合三类人（Python 栈想嵌进产品——TypeScript 生态无 HTTP 桥/要多租户并发按会话计费/只想找更顺手的编码助手）。Hacker News 有人问"这个又是抄谁的"，答："because this time it looks pretty much original?"
