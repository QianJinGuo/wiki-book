# 在线蒸馏也会⼀步错步步错？Relay-OPD让教师关键时刻接棒

 2026-08-23 22:47 北京

别让错误滚成雪球

## 

学生推理一旦早早走偏，教师也可能被错误前缀带着走。Relay-OPD 选择在最值得纠偏的位置，让教师短暂接棒再交还学生。

随着⼤模型能⼒的持续提升，如何把强模型的能⼒⾼效迁移给⼩模型，正成为后训练阶段的关键课题。

相⽐让学⽣模仿教师数据的 SFT 与离线蒸馏，在线蒸馏（on-policy distillation，OPD）让学⽣在⾃⼰⽣成的轨迹上接受教师逐 token 的稠密监督，有效缓解了训练与推理之间的分布偏移，正逐渐成为将强模型能⼒迁移⾄⼩模型的主流范式。

但你是否注意到：学⽣⾃⼰⽣成的轨迹,也必然带着学⽣⾃⼰的错误。

在⻓链推理中，学⽣⼀旦在开头选错了⽅向，后续所有⽣成都会建⽴在这个偏差之上——此时教师给出的监督越来越不可靠，⼤量训练算⼒也被消耗在这些偏离正轨的冗⻓续写上。

为了解决这⼀问题，浙江⼤学联合阿⾥巴巴提出了 Relay-OPD（Relay On-Policy Distillation）：在学⽣⽣成的过程中，在线检测推理“跑偏”的位置，让教师像接⼒赛⼀样短暂“接棒”纠偏，随后再把⽣成交还给学⽣。

实验显示，该⽅法在⼋个数学推理基准上全部取得最优或次优成绩，较标准 OPD 平均提升 + 5.73%，同时将训练轨迹⻓度削减⼀半以上。

On-policy 不等于 On-track：前缀失败如何拖累在线蒸馏？

OPD 的核⼼优势在于：监督始终落在学⽣真实访问的状态分布上。然⽽研究团队发现，这⼀优势背后隐藏着⼀个被低估的问题：前缀失败（Prefix Failure）。

前缀失败指的是，学⽣在推理早期⼀旦选定错误⽅向，⾃回归⽣成会让所有后续内容都在这个错误前提下展开，滚雪球般形成⼀条冗⻓且“积重难返”的失败轨迹。

对这样的轨迹做逐 token 蒸馏，不仅监督信号愈发不可靠，还会⽩⽩消耗训练算⼒。

已有⼯作从不同⻆度尝试补救，但各有结构性局限：

  * 固定⻓度截断（ESR、FastOPD）：在固定位置⼀⼑切地截断 rollout，与推理实际在哪⾥失败⽆关；

  * 离线重写（TRD）：等整条轨迹⽣成完再由教师重写修复，⼲预时机太晚，且重写痕迹明显；

  * token 级混合（SKD）：依据师⽣分布的⼀般性分歧逐 token 切换，并没有“推理⽅向已经失败”的显式信号。




换句话说，现有⽅法要么“切得不准”，要么“修得太晚”，要么“换得盲⽬”。缺少的是⼀种既在线发⽣、⼜由推理状态本身决定⼲预位置的机制。

研究团队的突破⼝，来⾃⼀个有趣的观察：在同⼀个已经⾛偏的前缀上，教师和学⽣的“续写本能”截然不同——教师倾向于停下来、重新审视、转向，下⼀个 token ⼤概率是 Wait、But、However 这类反思词；学⽣则倾向于沿着原⽅向⼀路写下去。

论⽂中给出了⼀个典型例⼦：在某个⾛偏的位置上，教师以 74.4% 的概率想说 “But”，学⽣却以 50.6% 的概率想接 “So”。

这种分歧在⽣成过程中直接可观测，不需要任何 verifier、过程标签或奖励模型。论⽂将这样的位置称为交接触发点（handoff trigger）。

围绕这⼀信号，团队进⼀步开展了轨迹⼲预实验,得到两个关键结论：

  * 纠偏可以极其“局部”：只在每个触发点把那⼀个反思 token 替换为教师的选择——教师⽣成的 token 仅占全部 token 的 0.35%——准确率即可从 27.73 提升⾄ 34.96（+ 7.23%）；

  * ⼲预价值⾼度“前置”：保持⼲预⻓度不变,仅把⼲预位置从最早的触发点推后,准确率便从 41.99 跌⾄ 33.98、再跌⾄ 29.49。原因在于：随着前缀变⻓，教师也会被学⽣的上下⽂“带跑”，师⽣差距逐渐收窄，晚到的接管已⽆⼒回天。




此外，延⻓教师⼲预的收益会快速饱和：单次接管从 3 段延⻓到 6 段，教师 token 占⽐从 17.52% 升⾄ 28.52%，准确率却停留在 41~44 区间，与教师独⽴作答的 60.55 相去甚远。

这说明⼲预应当“点到为⽌”——既要趁早，⼜要克制。

Relay-OPD：让教师在关键时刻“接⼀棒”

基于上述发现,团队提出了 Relay-OPD。该⽅法包含三个关键设计:

1\. 免标签的交接触发器。预先定义反思词表 R（Wait、But、However 及其⼤⼩写、前导空格变体）。当教师在当前前缀上最偏好的下⼀个 token 属于 R，⽽学⽣的 top-K 候选中不含任何反思词时，即判定触发（主实验取 K = 5）。

2\. 接⼒预算（M, L）。整条轨迹最多允许 M 次教师接管；每次接管以触发的反思 token 起笔，继续⽣成 L 个⾃然段（以 \n\n 为界，平均每段约 23.2 个 token）——按“段落”⽽⾮固定 token 数计量，保证每⼀次接管都收尾于结构完整的推理单元。

教师接管段结束后，若预算未耗尽，学⽣从修正后的前缀继续⽣成；第 M 次接管结束时，整条 rollout 终⽌。与固定截断不同，⼲预位置与终⽌位置都由当前推理状态决定。主实验取（M, L）=（2, 3）。

3\. ⾯向接⼒轨迹的训练⽬标。设计⽬标前有⼀个关键判断：教师在接⼒轨迹上给出的指导，并不等于它在⾃⼰轨迹上的理想发挥——前⾯的⼲预实验已经显示，即便让教师接管近三成的 token，准确率仍远低于教师独⽴作答，原因是教师也会被学⽣写下的前缀牵着⾛。

既然这份指导并⾮处处可靠，学⽣就不应当照单全收。因此，Relay-OPD 直接在实际⽣成的接⼒轨迹上做 single-sample 蒸馏，有选择地吸收教师的纠偏信号，⽽不是拟合教师的完整输出分布。

后⽂的消融实验将证明这⼀选择的重要性。

⼯程实现上，Relay-OPD ⾯临⼀个现实难题：交接触发器要求在学⽣⽣成的每⼀个位置，都能拿到教师对下⼀个 token 的分布来做判定；教师与学⽣还要在同⼀条轨迹上反复交替⽣成。

如果为两个模型维持两套独⽴的推理引擎，就意味着每个位置都要跨引擎同步⼀次教师 logits，交接与收回时还要在两条流⽔线之间来回切换，调度与通信开销相当可观。

团队的解法，是把整个接⼒过程统⼀进⼀个投机解码（speculative decoding）引擎：学⽣作为 draft model，教师作为 target model。

学⽣⽣成段中，target 就是学⽣⾃身，draft 全部接受，等价于普通的学⽣解码；教师接管段中，则是标准的投机拒绝采样。

如此⼀来，教师本就要对学⽣的草稿做批量验证，验证中算出的教师 logits 顺带给出了触发判据，持续监测教师意图不再有任何额外开销；同时，由投机采样的正确性保证，单引擎产出的轨迹与“两个模型真实轮流⽣成”在分布上完全⼀致。

实验结果

⼋个数学基准全⾯领先，训练轨迹⻓度削减过半

团队以 Qwen3-4B-Instruct-2507 为教师、Qwen3-0.6B 与 Qwen3-1.7B（Non-Thinking）为学⽣，在 DAPO-Math-17K 英⽂⼦集上基于 verl 与 vLLM 训练。

全程不使⽤任何 verifier、过程监督标签或答案正确性标签，并在 AIME 2024/2025/2026、MATH500、AMC 2023、OlympiadBench、HMMT 2026 年 2 ⽉与 2025 年 11 ⽉共⼋个数学推理基准上评测。

结果显示，Relay-OPD 在两个学⽣规模的所有⼋个基准上均取得最优或次优成绩。以 1.7B 学⽣为例，平均准确率达到 46.96，较标准 OPD（41.23）提升 + 5.73%。

其中 AIME 2025、AIME 2026 分别提升 + 7.29% 与 + 7.19%；同时超过最强的轨迹⼲预基线 FastOPD（45.47）+ 1.49%。0.6B 学⽣趋势⼀致：较 OPD 提升 + 3.01%，并⼩幅超越 FastOPD（+ 0.62%）。

对⽐之下，⼏类基线的失败⽅式颇具启发性：

  * TRD 明显弱于标准 OPD，其离线重写的轨迹带有可⻅的修补痕迹，不像⾃然展开的解题过程；

  * SKD 难以打破学⽣已经形成的重复⽣成模式；

  * FastOPD 虽将训练信号集中于序列前段，却⽆法示范“如何从失败的前缀中恢复”。




效率⽅⾯，1.7B 学⽣的平均训练轨迹⻓度仅 2,296 token，较 OPD 的 4,658 削减 50.7%，也短于 FastOPD 的 2,709，且仅⽤ 35 步即达到最优 checkpoint（OPD 为 55 步）；0.6B 学⽣的训练轨迹⻓度较 OPD 削减 63.9%。

推理更短，答得更准

与 FastOPD 相⽐，Relay-OPD 在 AIME 2025、AIME 2026、HMMT Feb 2026 上的平均回复⻓度分别缩短 17.9%、14.2% 与 28.3%，准确率反⽽分别提升 + 2.39%、+ 4.17% 与 + 1.14%。

在不同采样预算下的 pass@k 也全⾯⾼于标准 OPD。这表明：学⽣学到的不只是答案，更是“在偏差滚成雪球之前主动转向”的推理习惯。

教师介⼊强度⾃适应衰减

训练动态显示，⽤满接⼒预算的轨迹占⽐从初期的 75%~85% 逐步降⾄ 50%~60%。

教师 token 占⽐从约 13% 快速回落，约 20 步后稳定在 2%~3%——随着学⽣能⼒增强,需要教师接棒的位置⾃然减少，⼲预强度⽆需⼈⼯调度即可⾃适应收敛。

此外，Relay-OPD 的策略熵始终⾼于 OPD 与 FastOPD：教师接管改变了学⽣访问的前缀与后续⽣成⽅向，客观上增加了探索。

消融：教师接管段与训练⽬标，缺⼀不可

教师接管段是否必要？同样限定 M = 1，“触发即停”（检测到触发点即截断、不⽣成任何教师 token）平均仅 43.48，补上 L = 3 的教师接管段后升⾄ 46.25（+ 2.77%）。

这说明收益来⾃被修正的上下⽂与局部推理示范，⽽不只是动态截断；

训练⽬标如何选？

在实际⽣成的接⼒ token 上直接蒸馏（46.96），明显优于改⽤学⽣的 draft token（44.56），也优于让学⽣去拟合教师完整分布的 forward KL（44.08）——后者会迫使学⽣⽆差别地吸收教师的全部输出，连不可靠的指导也⼀并照收。

敏感性分析进⼀步划出了⽅法的边界：L 从 0 增⾄ 4，平均准确率由 44.31 升⾄ 47.10，L = 5 开始回落；M = 2 最优（46.96），M = 4 反⽽降⾄ 44.01。

过⻓、过频的教师接管会使轨迹过度偏离学⽣⾃身的策略，反⽽削弱了 on-policy 蒸馏本身的优势——适度⼲预，正是这套⽅法的灵魂。

值得⼀提的是，Relay-OPD 的触发信号来⾃师⽣ logits 的直接对⽐，⼯程实现由投机解码引擎顺带完成，全程⽆需 verifier 与任何标注。

论⽂上线后，已有智能体蒸馏⽅向的后续⼯作沿⽤并扩展了这⼀交接机制（<https://arxiv.org/abs/2608.01953>）。⽬前，训练、消融与评测代码均已开源。
