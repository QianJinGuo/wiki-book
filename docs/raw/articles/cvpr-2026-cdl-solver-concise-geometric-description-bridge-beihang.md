# CVPR 2026 | 5.5k数据反超Gemini，北航用简洁描述打通几何推理

原创 让你更懂AI的 2026-07-31 11:04 北京

用简洁符号重塑多模态

平面几何问题求解（Plane Geometry Problem Solving，PGPS）一直被视为多模态大模型（MLLM）推理中极具挑战性的问题。解决一道平面几何题，既需要极度精确的视觉感知（看清线段平行、角度度数等视觉信息），又需要严密的逻辑推理能力。

传统的平面几何解题方法通常是将多模态大模型在庞大的训练数据上进行端到端的联合微调。然而，北京航空航天大学的最新研究指出：这种"既要画画又要推理"的联合优化，往往会两头落空。

为了打破这一瓶颈，北航团队推出了 CDL Solver —— 一个全新的几何求解范式。它不仅将数据需求量缩减了数十倍（仅需 5.5k 数据），更在多个几何基准测试中击败了 Gemini 2.5 Pro 等顶尖闭源模型！

Motivation：为什么以前的平面几何解题模型效果欠佳？

在审视现有方法时，研究团队发现了两个致命的"痛点"：

1. 视觉感知与逻辑推理的联合优化困境

当我们将多模态模型端到端训练时，模型需要同时学会"看图"和"解题"。但实际情况是，模型经常看错图（例如，在图 1(a) 中，多模态模型会将本是 的  错看成 ）。更糟糕的是，**过度微调多模态模型的视觉对齐，往往会损害基座 LLM 本身已经非常强大的逻辑推理能力**。

2. LLM 其实是个"隐藏的几何解题高手"

团队做了一个极具启发性的实验（见下表）：当不给大模型看图，而是直接提供完美准确的几何描述符号语言（GT CDL）时，大语言模型（LLM）的解题正确率飙升！

例如，Qwen3 30B 在拥有 GT CDL 的情况下，解题准确率直线上升到 88.4%！远超相当尺寸的开源模型（Qwen3-VL 30B）或强大的闭源多模态大模型（Claude-Opus-4.1、Gemini2.5-Pro）。

这说明：大语言模型本身的推理能力完全在线，只要能给它一座精确无损而精炼的"桥梁"，把图形翻译成它能看懂的语言，它就能完美解题。

方法与创新点

CDL Solver 放弃了让模型端到端优化的传统路线，而是采用了 "解耦" 的方式：让专业的模型做专业的事。它由两部分组成：一个负责把几何图形翻译成标准语言的"多模态解析器（MLLM Interpreter）"，和一个负责基于翻译结果解题的"语言模型求解器（LLM Solver）"。

2.1 核心桥梁：简炼几何描述语言

团队选择 CDL（Conditional Declaration Language）作为翻译几何条件的通用语言。CDL 包含三种核心声明：

- ConsCDL：定义图形的基本骨架，例如有哪些基本形状（三角形、圆形）、哪些点共线、哪些点共圆等。
- ImgCDL：从几何图中提取的物理/数值关系，如线段长度、角度大小、平行或垂直关系。
- TextCDL：从几何题目文本中提取的物理/数值关系。

创新的关键点在于"简洁性（Conciseness）"：相比冗长、口语化的自然语言描述，CDL 是一种高度结构化的符号语言。这种简洁性大幅收窄了模型的输出搜索空间，使 MLLM Interpreter 的训练变得更高效。

2.2 数据重塑：Formalgeo7k-Rec-CoT 数据集

为了解决原版几何数据集存在的数据标注错误、图文不匹配等质量问题，团队派出 4 位专家进行了严格的双盲人工校验，重构了 Formalgeo7k v2 数据集，并引入了高质量的 CoT 推导步骤，为几何学界贡献了高纯度的训练基石。

2.3 核心创新：两阶段训练与 "CDL 匹配奖励"

如何把一个开源的多模态模型训练成极度精确的 Interpreter？如上图（b）、（c），CDL Solver 设计了两阶段训练管线：

Stage 1：CoT 增强的监督微调

研究团队设计了一个 Python 解析器，将几何关系自动生成自然语言的思维链（CoT）推理步骤。训练时让模型输出 <think> 详细推理步骤 </think> <cdl> CDL 输出结果 </cdl> 格式，让模型在逐步思考，输出翻译结果。

Stage 2：基于"CDL 匹配奖励机制"的 GRPO 强化学习

传统的强化学习训练大模型解题，通常给 基于最终解题答案的惩罚（Solution-based Reward）：如果最终解题结果正确，就给 1 分，否则 0 分。但这种奖励信号太稀疏了（解题正确不意味读图结果全部正确；解题错误亦不意味着读图结果全部错误），在小样本下模型极难收敛。

CDL Solver 另辟蹊径，设计了 "CDL 匹配奖励函数"（CDL Matching Rewards）：

- 利用贪婪匹配算法，逐件对比模型生成的 CDL 与真实的 GT CDL。
- 精准计算生成结果的召回率（Recall）以鼓励信息的完整性，计算精确率（Precision）以惩罚错误和重复生成。下面公式以 ConsCDL 的奖励函数为例。

实验结果

在仅使用 5.5k 数据 进行微调的极低成本下，CDL Solver 在三大主流平面几何基准测试中展现出了令人惊叹的统治级表现：

3.2 几何求解准确率（Accuracy %）

在 Formalgeo 测试集上，CDL Solver（Qwen3-VL 8B Interpreter + Qwen3 30B Solver）直接拿下了 85.7% 的正确率！

- 超越闭源王者：在 Formalgeo 数据集上，CDL Solver 超越了 Gemini 2.5 Pro（81.8%）达 3.9%，比 GPT-4o（58.0%）高出了整整 27.7 个百分点！
- 超越专用模型：此前表现最好的几何模型 DFE-GPS 动用了 23.8 万条数据进行端到端联合训练，准确率仅为 75.3%；而 CDL Solver 仅靠 5.5k 数据（缩减了 43 倍！）就将成绩拉升到了 85.7%！
- 跨域泛化（OOD）：在完全没见过的跨域测试集 Unigeo（84.0%）和 MathVista（80.8%）上，CDL Solver 依然保持了极佳的性能，证明了其出色的通用性。

总结：CDL Solver 给未来大模型研发带来的启示

CDL Solver 的成功，不仅仅是一个学术榜单第一的诞生，它向多模态技术社区传递了两个非常核心的洞察：

1. "解耦"比"大一统"更优雅：与其试图用一个模型同时提升其视觉感知与逻辑推理，不如通过高质、简炼的结构化符号语言（如 CDL）作为中间桥梁，把两项任务解耦，从而最大限度地保留语言模型的推理优势。

2. 强化学习需要高密度的"过程奖励"：在数学、编程、几何等强约束领域，传统的二元（Right/Wrong）结果奖励效率极低。设计类似 "CDL 匹配"的精确过程匹配机制，能提供更充沛的信息流，让 GRPO 强化学习在极小的数据规模下依然能够爆发惊人的潜力。
