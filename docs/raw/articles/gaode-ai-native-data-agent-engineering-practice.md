高德信息业务覆盖十大核心业务域、千余张数据表。本项目构建了一套 AI Native 数据 Agent 体系，将数据消费完整链路交由 LLM 自主完成。盲测准确率从 40% 提升至 95%（线上灰度 90%），灰度覆盖业务方用户超百人。

## 技术选型

选择 LLM + 知识工程 + 工具执行 + 规约约束 路径，而非训练驱动或全量 Prompt。原因：业务知识变更频繁（表结构每周在变）、千张表规模元数据无法靠单次 Prompt 承载、需要可解释决策链路。

## 整体架构

三个专域 Agent 共享知识底座和执行基础设施：
1. 查数 Agent：NL2SQL，4 步漏斗选表
2. 波动归因 Agent：LLM 编排 + 统计工具执行
3. 找资产 Agent：意图分流 + 双通道处理

### Agent 三层架构
- 推理层：LLM（语义解析、选表推理、SQL 组装、结果校验）
- 知识层：SKILL References（表元数据、业务口径、枚举映射、SQL 规约）
- 执行层：数仓 Python SDK + SQL 安全沙箱（仅 SELECT）

## 核心能力

### 查数 Agent：4 步漏斗选表
1. 召回：关键词检索全域表索引（≤50KB），召回 3~10 张候选表
2. 精排：LLM 双维度打分（语义匹配 + 字段覆盖度）
3. 分层消歧：按数仓层级裁决（ADS > DWS > DWD）
4. 类型消歧：优先行业表，跨行业退选横向表

### 评测体系
- 评测集覆盖十大业务域
- 9 项前置标答检查，错误率从 15% 降至 3%
- 分钟级全并发流水线
- 三层结果保障：环境预检 → EXCEPT 全量对比 → AI 判定覆盖
- 6 大类根因分类体系

### 准确性迭代路径
- Phase 1 (40%→65%)：知识库补全
- Phase 2 (65%→85%)：规约体系优化
- Phase 3 (85%→95%)：精细化迭代长尾 case

### 波动归因 Agent
严格分离"理解"和"计算"：LLM 负责编排，统计工具负责精确计算。
异常检测方法体系覆盖 6 种方法（3-Sigma/IQR/百分位数/移动平均+标准差/环比同比阈值/STL 季节分解），根据数据特征自动选择。

### 找资产 Agent
意图分流：找表信号走漏斗选表，知识信号走业务知识问答。

## 工程化
- 选用 Claude Opus 系列作为推理模型底座（规约遵循能力最优）
- 三层服务架构：前后端分离 + Agent 服务化
- 团队全栈转型：SPEC 设计 → Agent 工程调优 → 前后端开发

## 落地效果
线上数据准确率 90%，灰度用户超百人，效果符合预期。
