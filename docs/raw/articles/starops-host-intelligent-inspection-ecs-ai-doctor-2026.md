# STAROps 主机智能巡检：给你的 ECS 请个 24 小时在线的 AI 医生

> 来源：阿里云云原生公众号（作者：陈诗雁）

## 核心主张

大多数故障都是慢性病累积而成的急症：内存使用率连续几天爬升直到 OOM 精准杀掉关键进程、conntrack 连接跟踪表悄悄逼近满载直到新连接成批失败、磁盘被日志蚕食直到数据库写不进去、光模块老化直到重传率飙升十倍。传统监控只在指标触顶时发告警，为时已晚；人工巡检受限于精力无法高频深度排查。

**主机智能巡检** = 自动体检 + AI 医生。它是阿里云全域智能运维平台 **STAROps** 的一项核心能力。STAROps 名字代表运维四层理念：全域感知（Sense）、目标导向（Target）、自主运维（Autonomy）、业务韧性（Resilience）。

## 能力架构

- 自动为每台主机做一次「全身 CT」：覆盖 CPU、内存、磁盘、网络、GPU、内核、硬件**七大领域、超过 50 个检查项**。
- 发现异常时不止报「有问题」，而是像医生一样给出「为什么会这样」和「接下来该怎么办」。
- **STAROps 与阿里云操作系统控制台分工协作**：STAROps 是统一入口和智能运维大脑（自然语言下发巡检/排障、编排流程、关联全域数据、生成分级报告）；操作系统控制台的运维组件 **SysOM** 提供底层诊断算子（memgraph 内存分析、diskanalysis 磁盘诊断），专治操作系统层疑难杂症。
- 调用关系：主机智能巡检发现异常 → STAROps 作为编排者并发调用 SysOM 底层诊断工具做深度定位 → 把内核级结论汇总进巡检报告。SysOM 是 STAROps 在主机场景下的关键能力提供方。

## 三大硬核优势

### 1. 覆盖广：探头伸进内核态和硬件层

普通监控只看 CPU/内存/磁盘「大众指标」，真正故障藏在更深处：

- **内核事件**：softlockup（业务线程饿死）、hungtask（进程僵住超两分钟）、RCU stall（内核死锁前兆）、conntrack 表满（新连接被悄悄丢弃）
- **硬件层**：处理器退化 MCE 错误、内存条即将失效 ECC 错误、硬盘濒临故障 SMART 告警、光模块老化丢包 CRC 错误

### 2. 诊断深：不只说「你有病」，还告诉「病根」和「药方」

以「业务突然变慢」为例，STAROps 给出一条完整证据链：

1. 发现异常：「iowait 持续偏高」
2. 自动定位：「通过诊断锁定 MySQL 进程频繁 fsync」
3. 深挖根因：「sync_binlog=1 让每次事务提交都要等磁盘」
4. 递上可执行方案

一次巡检 = 发现 + 定位 + 根因 + 方案，全自动。背后是 STAROps 的 AI 诊断引擎，把资深 SRE 几小时甚至几天的排查功力压进一次自动巡检。

### 3. 经验真：百万实例实战沉淀

- 规则来自生产数据（只有符合特定规律的持续性异常才是真问题，压制误报）
- 场景来自真实客户故障（conntrack 表满、RCU stall 等）
- 每条修复建议过线上验证，按紧急/中期/长期三步走
- 每项巡检配故障注入测试用例，确保 100% 准确检出

## 三个真实案例

1. **电商大促前夜 Slab 内存异常**：内核 Slab 内存（SReclaimable）异常升高占系统内存 30%。AI 诊断出是日志采集 Agent 遍历 /proc/*/fd 产生海量 dentry 缓存。调整采集策略后释放 8GB 内核内存，避开大促当天 OOM 风险（若无巡检，损失以数百万计）。
2. **微服务集群间歇性超时**：conntrack 表使用率 92%，dmesg 报「table full, dropping packet」。AI 判定是 K8s 大量短连接场景下 conntrack_max 默认值不足，调大参数并启用 keepalive 后超时彻底消失（人工排查网络设备要花几个小时）。
3. **数据库慢查询突增**：磁盘写延迟从 5ms 飙到 200ms，AI 诊断为 O_SYNC 写入叠加同盘混部引发的 IOPS 争抢。分离 WAL 日志盘与数据盘后延迟回落到 5ms（此前 DBA 已在 SQL 优化错误方向上折腾两天）。

## 使用方式

三种巡检姿势 + 「数字员工」：可直接对主机智能巡检说「帮我看看这台机器的内存情况」，自动跑内存全景分析、OOM 检测、Slab 检查，交完整报告。STAROps「数字员工」= 可自定义职责、权限和技能的专属 SRE 智能体。

## 真实演示五步流程

1. **用户下发指令**：对话框敲「/主机巡检，对当前 workspace 的所有 ecs 做一次巡检」——没有 UI 点选、YAML 配置、工单流转，一句自然语言就是全部指令。
2. **Agent 读取 Skill 与参数**：自动补齐 region、UID、workspace、time_range 上下文。
3. **执行异常事件查询**：调用底层 SLS 异常事件查询能力，扫描整个 workspace。演示结果：3 类 CRITICAL 异常、影响 102 台实例、累计 1380 个事件。
4. **触发 SysOM 自动诊断**：对内存偏高实例跑 memgraph 内存热点分析、磁盘吃紧实例跑 diskanalysis 磁盘分析，形成机器可读结构化诊断结论。
5. **分级巡检报告**：🔴 需立即处置（P0 严重问题 + 建议动作）+ 🟢 持续观察（P2 已恢复需关注）两级。

### 诊断示例

- **memgraph**：诊断结论「warning — 内存利用率过高，存在内存不足风险」，锁定具体进程，进一步指出某目录下 30 个 32MB 分片文件 = 2.72GB 疑似共享内存泄露——从「内存高」追问到「是谁、在哪儿、多大量」。
- **diskanalysis**：诊断结论「error — 磁盘使用率 91.7%，存在空间耗尽风险」，直接给出根因：31.6GB 测试填充文件，处置建议「立即删除该文件」。

这就是 Skill + Agent + SysOM 三件套的结果：从「帮我看看有没有问题」到「这几台机器要立刻删这个文件、那几台要排查共享内存泄露」，中间的排查、判断、诊断、汇总全被压进一次自动巡检。
