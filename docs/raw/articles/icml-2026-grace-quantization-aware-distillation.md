引言：先蒸馏再量化，错在哪里

视觉语言模型要落到手机、车机、边缘设备上，通常要同时做两件事：把模型变小（知识蒸馏，KD），把权重变窄（量化，Quantization）。

主流做法是把它们排成流水线：先用大模型蒸馏出一个小模型，再对这个小模型做训练后量化（PTQ）。这条路线在 8-bit 上还算稳妥，一旦压到 4-bit 就会明显掉点。

问题出在两个环节各自为战：

蒸馏阶段不知道后面要被量化。学生模型在全精度下学到的表示，可能分布尖锐、动态范围大、离群值多，恰恰是最不适合低比特表示的那一类。蒸馏优化得越好，量化时反而摔得越重。

量化阶段已经没有教师可用。PTQ 只有一小批校准数据和一个已经定型的学生，量化误差引入的表示偏移无法再被纠正。教师那边的知识此时已经用完了。

也就是说，两个阶段各自的最优解拼在一起，并不是整体的最优解。

针对这个问题，我们提出了 GRACE，一个把量化感知训练（QAT）与知识蒸馏在同一目标下联合优化的框架。

在 Qwen2-VL 7B→2B 上，4-bit 的 GRACE 学生模型八项基准平均分达到 68.0，超过 BF16 学生基线 4.0 个点，也超过此前最强的 4-bit 方法 SPEED-Q 5.7 个点，与 7B 全精度教师的差距压缩到 3.7 个点以内。

论文已被 ICML 2026 接收，代码与量化后的模型权重全部开源。

核心洞察：让学生在“戴着镣铐”的状态下学

GRACE 的出发点是信息瓶颈（Information Bottleneck，IB）视角下的一个观察：低比特权重限制了学生能够承载的表示复杂度，因此学生不应该去复刻教师的全部输出，而应该有选择地保留那些真正影响决策的信息。

由此引出三个具体的设计问题：

1\. 教师的哪些输出值得学？教师本身也会出错，在它自己都没把握的样本上强行对齐，学到的是噪声。

2\. 除了输出分布，还有什么值得对齐？视觉 token 之间的关系结构，在量化后往往比数值本身更脆弱。

3\. 蒸馏和量化的目标怎么配平？固定权重的多项损失加权，在训练不同阶段几乎必然失衡。

GRACE 的四个模块分别回应这几点。

〓 图2. GRACE 整体框架。学生在量化约束下训练，GDKD 负责置信度门控的输出对齐，RCKA 负责视觉 token 关系对齐，自适应 IB 控制器动态配平两者与任务损失。

方法

3.1 GDKD：按教师置信度给蒸馏信号打折

教师在简单样本上给出的分布尖锐可靠，在困难样本上则接近均匀甚至指向错误答案。GDKD 用教师输出分布的归一化熵构造一个门控权重：教师越确定，蒸馏权重越高；教师越犹豫，权重越低。

这个门控不是拍脑袋设的。Fano 不等式给出了条件熵与预测错误率之间的联系，熵越高意味着可达到的错误率下界越高。以归一化熵作为置信度代理，与"高熵样本的监督信号更不可靠"这一直觉在理论上是一致的。

在此基础上，蒸馏损失沿用解耦知识蒸馏的思路，拆成目标类与非目标类两部分分别加权，避免高置信样本上目标类概率主导整个梯度。

3.2 RCKA：对齐视觉 token 之间的关系，而不是数值

量化会扰动每个 token 的激活数值，但同一张图里 token 之间的相对关系结构相对稳定，也更接近模型真正利用的语义信息。

RCKA 在 LLM 倒数第二层取出视觉 token 的表示，计算 token 之间的 Gram 矩阵，用中心核对齐（CKA）度量师生两侧关系结构的一致性。

CKA 对表示的正交变换和整体缩放不敏感，正好适合学生维度低于教师、且数值被量化扰动的场景。

取倒数第二层是消融后的选择：更浅的层语义不足，最后一层已经过度贴合词表输出。

关系对齐带来的效果在注意力图上看得很直接。

对于“这个人在喂羊驼吃什么”这类需要定位交互对象的问题，标准 KD 训练出的学生注意力较为发散，而 GRACE 的注意力更集中在胡萝卜以及喂食这一交互区域上，视觉定位能力明显更强。

〓 图3. 多层注意力可视化对比。问题为"这个人在喂羊驼吃什么"，GRACE 相比标准 KD 更准确地聚焦在胡萝卜和喂食交互区域。

3.3 自适应 IB 控制器：不再手调损失权重

任务损失、蒸馏损失、关系对齐损失三者的权重如果固定，训练早期蒸馏项主导、后期任务项主导，几乎无法一次调好。

GRACE 把它写成一个带约束的优化问题：在蒸馏损失不超过阈值 τ 的前提下最小化任务损失，再用拉格朗日对偶上升动态更新乘子 β。蒸馏损失超出阈值时 β 自动上升，压紧对齐；已经满足约束时 β 回落，把优化预算让给任务本身。

需要说明的是，这一部分是 IB 视角启发下的设计，而非对 IB 目标的严格实现，论文附录对此有完整讨论。

3.4 分组 LSQ：量化不是训练后才发生的事

权重量化在训练中就以可微形式参与前向，步长通过 LSQ 学习得到，并采用对数空间参数化保证正性、用分位数初始化避免早期步长震荡。分组粒度为 128，支持 W8G128 与 W4G128 两档精度。

学生因此从第一步起就是在量化约束下向教师对齐，而不是先学好再被压缩。

4.1 主结果：4-bit 反超全精度基线

4.2 不止于仿真量化：真实 kernel 上的实测

很多量化工作只报告仿真量化（fake quantization）下的精度，即在训练框架内模拟低比特权重，并未真正部署。

我们在真实推理栈上做了端到端验证：INT4 使用 AWQ kernel，INT8 使用 GPTQ kernel，实测精度与仿真结果一致。

在 A100 上，我们进一步对比了 LLaVA-1.5 7B FP16 与 GRACE 7B INT4 的部署表现，覆盖显存占用、模型体积与推理吞吐三项指标。

INT4 版本在显存和体积上有数倍收益，同时因为 7B 规模的解码阶段以访存受限为主，权重位宽的下降也直接转化为吞吐提升。

需要说明的是，这一结论与模型规模有关。2B 量级的模型解码时更偏计算受限，量化的收益主要落在显存而非速度上。

〓 图6. A100 上 LLaVA-1.5 7B FP16 与 GRACE 7B INT4 的部署效率对比。（a）以 FP16 为 100% 基线的归一化指标；（b）INT4 量化带来的各项提升倍数。

总结

GRACE 的主张可以用一句话概括：模型压缩的两个环节不该分开做，因为它们优化的是同一个表示。

把量化约束提前引入蒸馏过程，让学生在低比特的表示预算下决定该向教师学什么、放弃什么，4-bit 的 2B 模型就能逼近全精度 7B 教师的水平。

整个框架不需要额外的教师微调，不依赖专有校准集，四个模块都可以单独插入现有的 QAT 或 KD 流程。

完整训练代码、评测脚本与量化后的模型权重已在 GitHub 与 HuggingFace 开源，欢迎试用与交流。
