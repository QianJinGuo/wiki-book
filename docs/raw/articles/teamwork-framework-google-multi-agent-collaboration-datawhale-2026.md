# Google重磅发布Teamwork，最新的多智能体研究！（Teamwork 框架解读）

> Datawhale 解读 Google 最近开源的 **Teamwork** 多智能体框架（antigravity.google/blog/teamwork-when-ai-becomes-a-research-partner）。核心：多智能体难的不在分工而在**组织**——让 Agent 互相挑战、在构建前找缺陷、把最强部分组合成解决方案。

## 一、多 Agent 难的不在分工，而在组织

常规任务用基础多智能体方法够用，但困难研究和工程问题中，松散组织的 Agent 会**很快偏离轨道**——一个 Agent 早期犯的错，其他 Agent 跟着认同，然后在有缺陷的想法上继续构建。核心矛盾不是"用几个 Agent"而是"怎么组织它们"。

Anthropic 实验对比协调 swarm vs 独立并行 agents 找软件漏洞：**协调 swarm 能找到更多漏洞，差距在复杂任务上更明显**。

## 二、Teamwork 如何让 Agent 互相纠错

把研究和工程问题通用结构具体化可配置：**生成候选方案 → 压力测试 → 把最佳想法组合成更强方案**。围绕循环三个关键设计：

1. **从生成方案到测试、组合、再进入下一轮**：不是简单任务分发，候选经测试后把好想法提取成更强下一轮候选。人类定目标+最终验收，Agent 执行整个迭代。
2. **把协作模式和 Agent 本身分开**：模式是规格不是可执行程序，不含编排代码；框架读模式后自动启动合适 Agent。专门的机制（对抗性批评循环）可跨领域移植不改代码。价值：协作逻辑和每个 Agent 干什么分离，编排策略可复用到完全不同领域。
3. **团队规模不预设、边做边调整**：框架根据任务需求动态决定生成多少 Agent；数量/结构运行时随问题展现改变。每次执行是活的过程不是固定管道。解决常见问题：很多框架要求事先想好用几个 Agent，但复杂问题结构往往做过程中才清晰。

## 三、五种问题，五种不同的协作方式

问题的结构决定怎么组织 Agent。五模式：

- **不可拆任务**：反复试错精炼，紧密的 Agent-测试-精炼循环，每测试结果直接反馈下一轮修改。
- **可拆任务**：扇出到多个并行工作者+批评者审查每个产出；编排器按问题定部署 Agent 数/轮数，核心角色固定但执行规模动态调整。
- **数学开放问题**：让不同候选路线先接受挑战，每个候选推进前必须压力测试（很多有希望方法最终失败，缺陷深入尝试后才可见）。
- **深度优先数学推理**：每走一步先验证这步是否成立，验证嵌入推理过程而非等完整答案后查。
- **审查论文**：用固定审查维度组织 Agent 批评意见。

## 四、失败的证明路线，也能留下有用的东西

长证明模式处理最难的开放问题，是完整的"**生成、对抗、综合、学习**"循环：

- **给每个候选方案安排一个专门的反驳者（伪造者）**：多个候选策略并行生成，每个配伪造者，唯一工作是打破此策略。综合树把候选策略和报告组合。**被驳倒的路线留在过程中，附带反对意见**——破碎路线可能仍含有用想法。
- **把长证明拆成带依赖关系子问题**：选定策略扩展成证明计划，子问题有明确目标+显式依赖关系；依赖图让独立子问题并行、依赖子问题按拓扑顺序执行。
- **让不同方案在锦标赛中逐层合成**：综合树每节点读候选+批评产生改进方案；综合失败则用累积反对意见重新运行——让失败变成有用信息而非丢弃。
- **这一轮踩过的坑，下一轮不再重来**：失败草稿保留；验证者发现提炼成**答案无关的陷阱注册表**（记录常见错误模式）；共享知识目录保存已证结果/失败方法/参考。

## 五、对做 Agent 的人的启发

- **多智能体核心是编排逻辑**：不是简单分任务，要设计压力测试机制、结果综合策略、跨轮学习机制。松散组织 Agent 互相强化错误（官方文档反复强调）。
- **一套协作模式可跨领域迁移**：编排逻辑和 Agent 描述解耦后，协作策略可移植到不同领域。
- **不要提前锁死 Agent 数量**：让数量/组织方式随问题动态调整；复杂问题结构难以预先预见。
- **必须有人专门提出反对意见**：Anthropic 研究发现多 Agent 面对相同情况会表现出比人类更高相似性——一个 Agent 错误决策被其他复制形成系统性失败（从众效应）。Teamwork 的伪造者机制/批评循环正是对抗这种从众，让每个候选推进前先独立压力测试。
- **小模型配好编排也能解决高难度问题**：日常 Flash 级模型+精心编排能解锁强劲性能。TCSBench 71% 得分里三个结果由 Flash-tier 模型首次产生博士级数学研究。不一定非用最大模型，关键是编排逻辑质量。

## 六、总结

多智能体未来不在堆更大模型，而在设计好协作机制。三个最值得参考的设计决策：**编排逻辑和 Agent 描述解耦、运行时自适应、把失败当有用信息**。Anthropic 多 Agent 研究提醒从众效应（互相强化错误），设计编排机制需特别考虑怎么避免。深入学建议重点看**长证明模式的锦标赛网络设计**（策略搜索/分解/跨轮学习）。
