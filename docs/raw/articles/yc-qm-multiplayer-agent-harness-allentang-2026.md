# 一文搞懂 YC-QM：面向企业的多人智能体平台（multiplayer agent harness）

> 架构师带你玩转AI / AllenTang | 微信公众平台
> 正文整理：YC-QM（yc-software 开源，MIT）multiplayer agent harness 架构解读

## 核心命题：从「个人助理」到「多人协作」

今天市面上的智能体，绝大多数是按个人助理设计的：一个人，一个对话框，一个助手。但你试着把它放进一家公司，问题马上就来了：老板想让助理读他的邮箱，但我不想让同事的助理读我的邮箱；一个项目需要多个人和多个智能体在同一个频道里协作；每个人的偏好、文件、凭据、定时任务全混在一起，谁也不敢动；今天选了 A 家的模型和框架，明天就被锁死。

QM 就是为了解决这件事而生的。它的一句话定义写在 README 第一行：A multiplayer agent harness for work. In Slack and on the web.（面向工作的多人智能体框架。在 Slack 里，也在网页上。）它由 yc-software（YC）以 MIT 协议开源。

QM 的世界观里有一个关键词：scope（作用域）。每个员工、每个 Slack 频道、每个群组、每个项目，都是一个独立的 scope。每个 scope 拥有自己的一整套：

- 记忆——它记得的是"这个人的事""这个频道的事"，不会串味；
- 文件——隔离的工作区；
- 凭据视图（keychain）——谁能用哪些账号、令牌，按 scope 授权；
- 权限——跨 scope 的读、写、投递都被拦截；
- 定时任务（crons）——每个人的后台工作互不打扰；
- Web 应用——可以给特定人群发布的内部小工具；
- 持久沙箱——后面重点讲。

这就实现了 QM 最关键的一对能力：个人性——每个人可以把智能体调教成"自己的"，装自己的技能、存自己的文件、配自己的凭据；共享性——同一个智能体又能出现在频道和项目里，和大家一起协作。个人定制和团队协作，在大多数产品里是二选一。QM 的答案是：靠 scope 隔离，两个都要。

## 它到底能干什么？

抛开概念，QM 落地的场景非常"公司日常"：

- 统一搜索：内部笔记、邮件、文档、数据库、互联网，一处提问，一起搜；
- 公司大脑检索：把散落在各处的组织知识找回来；
- 内部应用：现搭一个内部小工具，发布给对的人，还能持续保持数据新鲜；
- 邮件分身：从你过往的发件里学你的语气，然后定时替你分诊收件箱——打标签、写回复草稿一条龙；
- 代码仓库作业：在现有仓库里跑测试、开 PR、盯 CI、查系统日志；
- 项目跟踪：在共享频道里跟进项目，自动发进展和后续待办。

看一眼它自带的"种子技能"（skills-seed）就明白了：GitHub/GitLab、Google Workspace、Google Drive & Sheets、Dropbox、Linear、浏览器操作、"晨间摘要"（morning-digest）、"按语气起草邮件"（email-draft-in-voice）、应用发布（publish）……全是打工人每天要碰的东西。

## 架构：一个无头核心 + 一台"持久的电脑"

QM 的架构可以浓缩成一张图，几个值得划重点的设计：

1. **核心是"无头"的**。Core 本身不带任何界面。网页 UI、管理后台、公共门户都只是挂在 Core HTTP API 上的可选插件；Slack 是一个进程内插件，由 Core 启动并监管。这意味着界面形态可以随便长，核心能力不受影响。

2. **智能体的工具面刻意做得很小、很固定**。其中一个工具叫 execute——它把命令送进该 scope 自己的隔离沙箱里执行。这个沙箱被官方称为 scope 的"持久电脑（durable computer）"：装过的工具不会丢，重启、重新部署都在。它不是一次性容器，而是一台长期属于这个 scope 的机器。

3. **状态不落内存，落 Postgres**。会话历史、记忆、队列全部持久化。官方的工程文化里有一条铁律叫"Durable by default"：核心是蓝绿部署、多实例运行的，任何进程里的 Map、环形缓冲都会随部署被抹掉。凡是以后还要读回来的东西——审计、日志、解析后的配置、排队中的任务——必须进持久存储，绝不能只放内存。

技术栈也很朴素：TypeScript + Node 直接跑核心，HTTP 用 Fastify，Slack 用 Bolt，网页 UI 用 Vite 构建、Lit 渲染。

## 不绑模型，不绑框架

这是 QM 最值得称道的立场之一。很多团队今天选了某家的模型和智能体框架，就等于把整个系统的地基交给了供应商。QM 的做法是：智能体循环（agent loop）是一个可替换的底座，目前已经有四个适配器在跑同一套核心：Pi、OpenCode、Codex、Claude Code。

不只是模型层。官方的原话是：每一种"基质"（substrate）——harness、会话存储、沙箱、记忆——都躲在接口后面，生产实现只需要换一个接线文件（wiring file）就能整体替换。换句话说，QM 想做的是智能体平台的"操作系统层"：上层界面、下层模型和框架，全都可以换。

## 安全：智能体就是"你本人"

企业最怕的问题是：智能体到底以谁的身份、拿谁的权限在干活？QM 的答案和本地编码智能体（OpenCode、Codex、Claude Code）一脉相承：智能体以它所服务的那个人的身份行动，持其凭据、守其权限，所做的一切全程留痕审计。在此之上，组织选择一个统一的安全姿态（posture），而更窄的 scope 只能收紧、不能放松：

- Strict（严格）——每一次工具调用都暂停，等人工批准；
- Auto（默认）——一个分类器在外部数据和工具结果"抵达模型之前"做来源标记与筛查，部署方还可以把筛查指向自己的代理；
- Dangerous（危险）——不筛查、不暂停（你自己选的，后果自负）。

此外还有一层命令策略：预先声明的批准规则和硬性拒绝（比如递归删除、破坏性 SQL），在所有姿态下都生效，Dangerous 也不例外。

特别值得一提的是它的坦诚。SECURITY.md 里花了大段篇幅主动列举已知局限：命令策略可被混淆绕过、沙箱内凭据在使用中是明文、内容筛查是启发式的、管理员可以读取敏感内容（但全程审计）……它明确说自己还是"early, experimental software"，隔离设计"不是一个数据不会泄露的承诺"。在一个充斥着"我们的 AI 绝对安全"话术的行业里，这份诚实反而是一种专业。

顺带还有一个供应链层面的细节：新发布的 npm 包必须静置 7 天才能进入 lockfile——专门用来钝化"维护者账号被盗、恶意版本发布后数小时内被撤下"这类供应链攻击。

## 几个有意思的工程文化

翻它的 AGENTS.md（即 CLAUDE.md），能闻到一股很正的工程味：

- "修每一处，不只是被报告的那一处"——发现一个 bug，就全仓库 grep 同样的模式，一次改完；
- "修复应该让系统更简单，而不是更复杂"——能删代码就不加代码，能复用就不新建；
- "永不合并未经陌生上下文审查的代码"——写代码的那个上下文天然相信它是对的，所以必须派一个没看过你怎么写的独立审查者来"找茬"，改动越大、审查越深；
- "仓库里不留注释"——意图用命名、结构和测试表达，理由写进 commit message。

还有一个罕见的贡献政策：它收的是"人写的文字"，不是代码。你想改什么，在 adrs/ 目录里用大白话写一个 .txt 或 .md 描述清楚，官方认同了，由他们来实现。这在开源界几乎独一份——等于把"提案"和"实现"解耦，降低了贡献门槛，也守住了代码一致性。

## 总结：QM 想成为什么？

把上面的线索拼起来，QM 的定位就很清楚了：

- 它不是又一个聊天机器人，而是一个让"每人一个智能体 + 团队协作"成立的多租户底座；
- scope 是它的灵魂概念——记忆、文件、凭据、权限、沙箱全部按 scope 隔离，个人定制与共享协作兼得；
- 核心无头、基质可换——不绑界面、不绑模型、不绑框架，四个 harness 适配器已经证明了这一点；
- 它还很早期，官方自己也这么说。

但如果你正在思考"智能体如何真正走进一家公司，而不是停留在个人玩具阶段"，QM 可能是目前最值得精读的开源样本之一——不只读它的代码，也读它的安全模型和工程纪律。
