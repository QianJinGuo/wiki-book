## 引言

传统 BLEU/ROUGE 等文本相似度指标在 Agent 时代力不从心——Agent 是"理解意图、做出决策、调用工具、完成任务"的多步骤自主决策系统，而非"标准答案生成器"。

旧版评测（仅关注最终答案文本相似度）的六大局限：粒度粗、无法检幻觉、忽略中间过程、掩盖成本效率、缺乏多轮评估、与真实场景脱节。

本文解法三原则：
1. **评测面向架构**：Agent 由感知/规划/记忆/工具四大模块组成，评测按同样结构逐层拆解
2. **指标面向行动**：每项指标是一份"诊断报告"而非"成绩单"
3. **能力面向产品**：像监控告警一样可持续运行、可横向对比、可追溯演进

## 评测体系总览

### Agent 内部结构

商品中心 Agent 应用由四个模块协作运行：

- **感知模块**：接收用户输入，LLM 判断是否可被已注册的 Skill 处理，提供降级策略
- **规划模块**：基于感知结果制定执行策略（是否调用工具/检索知识库/存储记忆）
- **记忆模块**：短期记忆（滑动窗口维护多轮对话）+ 长期记忆（RAG 知识库）
- **工具模块**：MCP 协议自动发现注册远程工具 + 文件系统 Skill 管理（热更新下发）

### 为什么需要"质量 × 成本 × 性能"三维指标？

- **质量**：答案是否正确、完整、忠实于知识来源——底线但不是全部
- **成本**：每次请求触发几次模型调用、调用了几轮工具、消耗了多少 Token
- **性能**：首 Token 延迟和端到端延迟——直接决定用户体验

### 评测范围与数据集映射

预定义评测范围（15 种），自动装配对应的评测数据集和埋点指标：

| 评测范围 | 覆盖的数据集 | 覆盖的埋点指标 |
|---------|------------|--------------|
| 端到端评测 | 基础技能/知识问答/多轮对话/异常输入 | 模型调用次数、工具调用次数、Token消耗、延迟等 |
| 核心模块评测 | 全部 8 类数据集 | 同上 |
| 感知模块评测 | 基础技能/知识问答/多意图/模糊意图 | 意图识别延迟 |
| 规划模块评测 | 基础技能/知识问答/工具调用 | 规划决策延迟 |
| 记忆模块评测 | 知识问答/多轮对话/长对话衰减 | 记忆注入/检索延迟 |
| 工具模块评测 | 工具调用 | 工具调用延迟 |

## 评测指标体系

### 端到端：六项用户感知指标

1. **任务完成率**（北极星指标）：语义层面的完成度
2. **多轮对话完成率**：2-5 轮对话中的上下文连贯性
3. **指令遵循能力**：是否按照业务约束的格式回答
4. **幻觉率（忠实性）**：是否忠实于知识库原文/工具返回数据/历史上下文——只判断"忠实转述"，不判断"信息来源是否正确"
5. **异常输入处理率**：空输入、超长文本、乱码、Prompt 注入等场景
6. **用户满意度**：线上反馈收集

### 感知模块：六项指标

- 意图识别准确率/召回率/精确率（经典 IR 三件套）
- 多意图识别率：复合问题场景
- 模糊意图澄清率：追问>推断>答非所问>幻觉
- 降级触发准确率：超出 Skill 范围时是否正确触发知识库检索

### 规划模块：四项指标

- 路由决策准确率：Skill 调用 vs RAG 检索的选择
- 工具调用决策准确率：选对了工具种类？
- 知识库检索决策准确率：是否正确触发知识库检索？
- 规划路径评分：人工评估执行路径是否最优

### 记忆模块：四项指标

- 短期记忆保留率：多轮对话上下文连贯性（语义延续性而非字面匹配）
- 长期记忆检索精确率：检索返回的 chunk 中相关比例
- 长期记忆检索召回率：应检索到的知识点在回复中覆盖比例
- 记忆衰减曲线：按轮次统计记忆退化规律

### 工具模块：五项指标

- MCP & Skills 加载成功率：外部服务能否正确初始化
- 工具调用准确率：是否调对了工具？（多调/漏调/重复调用）
- 工具调用成功率：是否成功返回有效结果？
- 参数映射准确率：用户意图是否正确映射为工具参数？

### 成本指标

- 平均模型调用次数、平均工具调用次数、平均输入 Token 数、平均输出 Token 数

### 性能指标

- 端到端：首 Token 延迟、端到端响应延迟
- 模块级：意图识别延迟、规划决策延迟、短期记忆注入延迟、长期记忆检索延迟、工具调用延迟、热更新生效延迟

## 评测数据集

### 8 类数据集

| 类型 | 构建方式 | 规模建议 |
|------|---------|---------|
| 基础技能评测集 | 按 Skill 维度构造，Mock 隔离外部依赖 | ≥50 条 |
| 知识问答评测集 | 从知识库中抽取问答对（含正例+负例） | ≥100 条 |
| 多轮对话评测集 | 2-5 轮对话链，覆盖上下文引用/话题切换/指代消解 | ≥10 组 |
| 异常输入评测集 | 空输入/超长文本/乱码/特殊字符 | ≥20 条 |
| 工具调用评测集 | 按工具维度构造（正确/缺失/错误参数） | ≥20 条 |
| 多意图评测集 | 2-3 个意图的复合场景 | ≥20 条 |
| 模糊意图评测集 | 语义模糊、缺乏关键参数的问题 | ≥20 条 |
| 长对话衰减评测集 | 5 轮以上，关键轮次插入需引用历史信息的问题 | ≥10 组 |

### 评测用例构建规范

每条用例包含丰富标注字段，一条数据供多个 Judge Task 使用。关键设计：

- **E2E_MOCK 模式**：通过 mockDataId 注入 Mock 数据替代真实工具调用，评测结果可复现
- **E2E_REAL 模式**：走真实链路，适用于不依赖实时性分析的场景
- Mock 数据按工具维度组织，拦截器根据工具名查找对应返回值
- 知识问答评测集包含**负例**（如"IC的deleteAllProducts接口怎么调用？"——不存在该接口）

### 基于 LLM 的评测集自动生成

"Aone 文档知识工具集"输入语雀文档 URL → 按数据集类型 Prompt 模板自动生成结构化用例 → 人工审核 → 入库。

## Judge Task 设计

### 6 种 Judge Task 类型

| Task 类型 | 核心逻辑 | 适用指标 | 量化方法 |
|----------|---------|---------|---------|
| **二元判断** | 语义是否完成期望行为 | 任务完成率/多轮完成率/异常处理率/意图识别准确率等 | passed/total |
| **一致性判断** | 核查输出与参考标准的一致性 | 幻觉率/指令遵循能力 | faithful/compliant 样本数 / 总数 |
| **多标签匹配** | 对比期望列表与实际列表的交集/差集 | 多意图识别率/工具调用准确率/参数映射准确率 | matched 完全覆盖 expected 的样本数 / 总数 |
| **上下文保留** | 多轮对话中是否正确引用历史上下文 | 短期记忆保留率/记忆衰减曲线 | retained 样本数 / 总数 |
| **相关性判断** | RAG 检索结果质量 | 长期记忆检索精确率/召回率 | 相关 chunk 数 / 总数 |
| **行为判断** | Agent 是否执行了特定交互行为 | 模糊意图澄清率 | clarified 样本数 / 总数 |

### Judge Prompt 设计四原则

1. **单一职责**：一个 Prompt 只评测一个指标
2. **先推理后判断**：先输出 reasoning（CoT），再给结论
3. **负例引导**：包含典型的"通过"和"不通过"示例
4. **结构化输出**：严格的 JSON 格式，便于自动化解析

### 主指标设计

每种评测场景设定一个**主指标**，只看主指标决定 case 是否通过。其他指标不影响通过判定，作为质量维度单独衡量。例如端到端评测的主指标是"任务完成率"，感知模块评测的主指标是"意图识别准确率"。

### 路由错误时下游指标跳过

当期望路由 SKILL_MISS 但实际 SKILL_HIT 时，依赖 RAG 数据的下游 Judge Task 自动标记为 error 并跳过统计——路由错误只体现在"路由决策准确率"一项指标上，不污染其他模块的数据。

## 评测执行引擎

### 整体流程

1. 提交评测请求（指定 datasetType + evalMode）
2. 自动装配数据集
3. 并发执行评测用例（3 线程，单条 120s 超时，失败重试至多 2 次）
4. 单条用例执行：构造输入 → Agent 全链路 → 采集 EvalTrace → Judge Task 评分
5. 生成评测报告（质量 × 成本 × 性能）

### 运行时指标采集

轻量级 Trace 数据结构随 Agent 处理链路一起流转，各节点写入关键信息（命中 Skill、延迟、调用记录、Token 消耗等）。执行完毕后的 Trace + 最终输出一起交给 Judge 引擎。

### 多轮对话特殊处理

- 会话上下文共享：独立 session 标识符
- 轮次间同步：等待会话持久化（2 秒）再发起下一轮
- 指标累计：逐轮累加
- 整体评判：所有轮次输出拼接后统一评估

## 评测可视化

轻量级评测平台：
- 评测范围选择器 → 自动装配数据集 + 埋点指标
- 三维仪表盘（质量雷达图 + 成本柱状图 + 性能柱状图）
- 场景通过率进度条（按通过率从高到低排序）
- 用例诊断：详细用例结果表格 + 失败原因 + Agent 完整输出

## 方法对比

| 维度 | 旧版 | 新版 |
|------|------|------|
| 评测范围 | 仅最终答案质量 | 端到端 + 核心模块 |
| 评测方法 | LLM-as-Judge | Judge Task + Agent 埋点 |
| 指标数量 | 5 项（文本质量） | 35 项（质量 × 成本 × 性能） |
| 评测集 | 专项+通用场景 | 8 类分层数据集 |
| 评测结果 | 平均综合得分 | 细粒度诊断 |

## 未来方向

- **变更即评测**：嵌入研发流程，自动触发回归
- **趋势可追踪**：版本 A vs B 指标趋势对比
- **多模型 A/B 测试**：不同底座模型对比
- **评测集自演化**：线上 bad case → 结构化测试用例
