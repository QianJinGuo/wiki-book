# Claude Code 上下文管理机制

> 本地 PDF 编译整理稿（4 页，643KB，2026-08-12 提取，pymupdf 2250 字符）。信息来源：Claude Code 官方文档、ClaudeFast 指南。PDF 二进制 SHA256 见 frontmatter。

## 概述

Claude Code 的上下文窗口（Context Window）是其"工作记忆"，包含 Claude 在当前会话中能"看到"的所有信息：系统提示词、读取的文件、自身的响应、以及会话中产生的各种内容。默认上下文窗口为 200K tokens，部分计划支持 1M tokens（适用于 Sonnet 5、Opus 4.6 及更高版本）。

## 上下文窗口的组成（启动时自动加载）

| 组成部分 | 大约 Token 数 | 说明 |
|---|---|---|
| 系统提示词（System Prompt） | ~4,200 | 核心行为指令、工具使用和响应格式化规则，用户不可见 |
| 自动记忆（MEMORY.md） | ~680 | Claude 从之前会话中记录的笔记（前 200 行或 25KB） |
| 环境信息 | ~280 | 工作目录、平台、Shell、OS 版本、Git 状态等 |
| MCP 工具（延迟加载） | ~120 | MCP 工具名称列表，完整 schema 按需加载 |
| 技能描述（Skills） | ~450 | 可用技能的一行描述，完整内容仅在使用时加载 |
| 全局 CLAUDE.md | ~320 | ~/.claude/CLAUDE.md，适用于所有项目的全局偏好 |
| 项目 CLAUDE.md | ~1,800 | 项目根目录的 CLAUDE.md，包含项目约定和架构说明 |

## 会话过程中的上下文消耗

- 文件读取：每次读取文件都会将文件内容加入上下文（如读取一个文件可能消耗 1,000–3,000 tokens）
- 路径作用域规则（Path-scoped Rules）：当 Claude 读取匹配路径的文件时，相关规则自动加载
- 工具输出：如 npm test 的运行结果
- Claude 的分析和响应：Claude 自身的思考和回复
- Hooks 输出：通过 additionalContext 字段进入上下文
- 用户的后续提问：持续累积在同一上下文中

## 核心管理策略

### 1. 80/20 规则

永远不要在上下文窗口的最后 20% 进行复杂的多文件任务。当 token 使用率达到 80% 时，应退出会话并重新开始。
- 高上下文任务（80% 时停止）：大规模重构、跨组件功能实现、复杂调试
- 低上下文任务（可超过 80%）：单文件编辑、独立工具函数、文档更新

### 2. /compact 命令

将对话历史压缩为结构化摘要，释放上下文空间。

适合使用的时机：
- 完成一个主要功能后（开始下一个之前）
- 从研究模式切换到实现模式之前
- Claude 开始重复提问或与之前决策矛盾时

不适合使用的时机：
- 调试过程中（需要具体的错误信息和堆栈跟踪）
- 复杂重构中（文件级细节很关键）

可以通过 `/compact focus on the auth refactor` 这样的指令引导摘要保留特定内容。

### 3. 自动压缩（Auto-compact）

当上下文达到约 83.5%（~167K tokens）时，自动压缩会触发。系统保留约 33K tokens 的缓冲区用于此目的。

### 4. 压缩后的存活规则

| 内容类型 | 压缩后是否保留 |
|---|---|
| 项目根目录 CLAUDE.md | ✅ 从磁盘重新注入 |
| 全局 CLAUDE.md | ✅ 从磁盘重新注入 |
| 自动记忆（MEMORY.md） | ✅ 从磁盘重新注入 |
| 无作用域规则 | ✅ 重新加载 |
| 路径作用域规则 | ❌ 被摘要化，需重新触发 |
| 子目录 CLAUDE.md | ❌ 被摘要化 |
| 技能列表 | ❌ 仅保留已调用的技能 |
| 对话历史 | ❌ 被压缩为摘要 |

### 5. 子代理（Subagent）委派

将大量文件读取委派给子代理是最高效的上下文管理手段。子代理在独立的上下文窗口中工作，只将最终摘要返回主会话。

示例效果：子代理读取 6,100 tokens 的文件，仅返回 420 tokens 的结果，节省了约 5,700 tokens 的主窗口空间。

注意：子代理不继承主会话的对话历史或自动记忆，需要在任务提示中提供足够的上下文。

### 6. CLAUDE.md 作为持久记忆

CLAUDE.md 文件跨会话持久存在，适合存放：项目架构信息、当前冲刺重点、编码模式和约定。原则：保持精简，每个 token 都是从对话空间中借来的。

### 7. 战略性任务分块

将大任务分解为上下文大小的块：
- 先完成组件，再进行集成
- 先完成研究阶段，再进行实现
- 在会话之间创建交接笔记

## 监控上下文使用

1. 状态栏：Claude Code 终端底部显示 token 使用百分比
2. /context 命令：显示 token 的具体分配（系统提示、工具、记忆文件、技能、对话历史）
3. /memory 命令：列出本次会话加载的 CLAUDE.md 和规则文件

## 上下文耗尽的典型症状

- 产生与之前工作矛盾的代码
- 重复询问已经解释过的项目结构
- 丢失架构决策和命名约定
- 忽略几分钟前建立的模式

## 总结

Claude Code 的上下文管理核心理念是：提供有效执行任务所需的最少上下文。这同时最大化了性能、token 效率和成本效益。与其追求更大的上下文窗口，不如学会更小粒度地分解任务。
