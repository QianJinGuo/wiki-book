# CQ-SID：LLM 生成式检索在手猫搜索召回中的探索与应用（CIKM'2026）

> 来源：千问AI平台（朱建波/玄羿），阿里官方第一方。提出 CQ-SID（Category-and-Query Constrained Semantic ID），把 LLM 生成式检索定位于手机天猫搜索的召回阶段补充路，而非端到端生成。核心：类目约束+Query-Item 对比学习的 RQ-VAE 语义簇 SID + 四步渐进式训练（I2SID→Q2SID→(U+Q)2SID→对齐排序）+ EG-GRPO 专家引导强化学习。已在手猫线上全量部署。

## 背景与挑战

天猫 APP 搜索召回主要由三类构成：文本倒排索引（保证匹配准确性但受限于字符级精确匹配，难克服语义鸿沟）、向量检索（捕捉语义相似但有细粒度属性识别局限）、基于 Trigger 的 I2I 召回（依赖历史行为相似推荐，有相关性但新颖性多样性不足，易信息茧房）。生成式检索（Generative Retrieval）把"索引-检索"流程参数化到单个 LLM：把商品语义编码为离散语义标识符（Semantic ID, SID），LLM 自回归生成相关 SID 列表，把检索变成纯生成任务，简化系统架构。

落地电商搜索面临四挑战：①端到端生成可行性（快手 One 系列等是推荐场景端到端，搜索对准确/相关要求极高，上亿商品池能否充分建模/避免马太效应/覆盖长尾）；②SID 设计困境（主流追求"一物一 ID"降碰撞率，但划分过细需更多训练样本、Beam Search 需加大 Beam Size 导致 RT 和资源瓶颈，需在区分度与语义聚合间平衡）；③商品池动态演化（新品上下架频繁，索引编码在模型参数中增量更新难）；④召回与下游排序一致性（不仅检索被点击商品，还要展示下游排序可利用的高质量商品）。

从现实出发，把生成式检索定位于**搜索召回阶段的补充路**，而非端到端生成。具体：提出 CQ-SID（RQ-VAE + 类目感知 + Query-Item 对比学习的语义簇标识，在区分性与聚合性间平衡）；设计渐进式训练（Item2SID、Query2SID、(User+Query)2SID 逐步建立用户个性化 Query 到 SID 的映射）；提出 EG-GRPO（专家引导群组相对策略优化，向策略梯度组注入真实 GT 样本，在稀疏奖励环境稳定学习），将生成式召回与下游排序曝光对齐。

## CQ-SID 商品 SID 构建

SID 不追求绝对唯一性，视为**语义簇标识符**而非"单商品"标识符，满足三特性：语义聚合性（语义/属性相似商品可映射同一 SID，不追求低碰撞率，挂载数合理即可）；区分度保障（不相似商品映射不同 SID）；层次化结构（相似特征商品有相同或相近 SID 前缀）。

基于残差量化自编码器（RQ-VAE），引入类目约束与 Query-Item 对比学习，构建 CQ-SID，输入向量采用团队已有 Query/Item 多模态向量。核心结构：
- **类目引导残差量化模块**：三层残差向量量化，码本 K1×K2×K3=2048×1024×1024，第一级为类目感知码本。电商类目体系为 SID 层级划分提供天然结构引导；选取商品数大于阈值的二级类目体系（无则取一级），最终覆盖 1711 个有效类目。训练第一级量化索引时，已知类目商品强制用类目标签作索引、更新码本向量，其余沿用最近邻检索。
- **Query-Item 对比学习机制** 与 **联合训练目标**。
- **SID 后处理**：随机后处理分割大簇（同一 SID 下商品已高度相似，分割不过度破坏语义连贯），防止单 SID 挂太多商品、避免热门语义簇过大导致检索偏差，同时维持 SID 前缀层次化语义结构。

## Query2SID 检索模型（渐进式训练）

用 Qwen2.5-0.5B，四步：
- **Step1 Item-SID（I2SID）**：用商品标题→SID 映射数据 SFT（NTP-Loss），建立商品文本→语义标识符映射，得 M1，让模型理解商品文本与 SID 语义结构及码本层次关系。
- **Step2 Query-SID（Q2SID）**：用 Query-Item 关联数据构造样本，每个 Query 随机采样 N=3 个关联商品的 SID 作目标，得 M2，建立搜索词→生成商品 SID 能力。
- **Step3 (User+Query)-SID（UQ2SID）**：加入用户性别、购买力、近期点击的 Query 相关类目下商品 SID 序列等特征，得 M3，按用户历史行为生成个性化 SID 列表。
- **Step4 对齐精排的 SID 召回**：暴露 M3 用 GRPO 训练，奖励 R(o) 按点击/曝光/购买商品 SID 集合计算（Ppay/Pclk/Pexp，Svalid 为合法 SID 集合）。因点击购买远小于曝光、奖励稀疏，提出 **EG-GRPO（Expert-Guided GRPO）**：每批次生成的 Group 中随机采样加入实际点击/曝光的 GroundTruth 作伪生成结果，参与奖励计算与梯度更新，得 M4，在保证点击 Hitrate 前提下提升曝光 Hitrate、对齐排序。

## 在线推理与底池筛选

组装用户 Query 和特征 → Beam Search 解码生成 Top-K 候选 SID → 按预构建 SID-Item 映射表转商品列表。因 SID 对应语义相似商品簇 + 个性化特征，返回商品列表具备相关性/多样性/个性化综合优势，作为一路召回补充。

全量商品池作底池会召回相关差/效率低的商品（追求语义簇，同 SID 更多相似品而非相同品，细粒度匹配有 Gap；且召回是补充非替代）。从全量商品池按效率分筛选约 **2100 万商品**作初始底池，动态更新：每天按效率分将新晋高效商品推理挂载到相应 SID，保证时效与质量。

## 实验（手猫搜索真实业务数据）

评价指标：Hitrate；两个维度——相同 Beam Size（衡量相同推理资源消耗下的效率）+ 按商品效率分截断取 Top-1K（模拟线上 Quota 截断，衡量相同商品召回量下的效率）。基线为不实用类目约束和对比学习的标准 RQ-VAE。

**语义生成式召回（相同 Beam Size）**：RQ-VAE 0.0598/0.2579/0.5199（beam@1/10/100）；CQ-SID（w/o cate）0.0680/0.2870/0.5578；CQ-SID（w/o qi）0.0596/0.2691/0.5652；**CQ-SID 0.0758(+26.76%)/0.3161(+22.57%)/0.6181(+18.89%)**。类目约束与对比学习联合增强 SID 语义能力，beam@1 提升达 26.76%；消融证明两模块协同作用。

**Top-1K 截断（语义）**：RQ-VAE 在 beam=65 达最高 0.4275；CQ-SID 仅需 beam=30 达最高 **0.4422**（Beam Size 减 53.85% 仍相对提升 3.44%）。Beam 增大 Hitrate 先升后降（离线按效率分截断与线上链路差异 + 线上漏斗架构若粗排/精排对大量低质量候选区分能力不足会使优质商品被截断过滤）。

**个性化生成式召回（相同 Beam Size）**：beam@1/10/50/100 —— RQ-VAE 0.1359/0.4787/0.6912/0.7513；CQ-SID 0.1510(+11.11%)/0.5206(+8.75%)/0.7431(+7.51%)/0.8062(+7.31%)。**Top-1K 截断**：RQ-VAE beam=195 达最高 0.7607；CQ-SID 仅需 beam=160 达最高 **0.7984**（Beam Size 减 17.95%，Hitrate 提升 4.96%）。

**目标引导强化学习（对齐排序）**：表（clk@1/clk@10/exp@1/exp@10/pvr@10）——CQ-SID 0.1510/0.5206/0.5056/0.8693/0.4371；+GRPO(K=0) 0.1519/0.5196/0.5077/0.8702/0.4360；**+EG-GRPO(K=2) 0.1524/0.5221/0.5091/0.8703/0.4377**；+EG-GRPO(K=4) 0.1523/0.5219/0.5087/0.8711/0.4378。仅标准 GRPO 时 beam@10 点击 Hitrate 反而下降、曝光 pvr 降低——稀疏奖励导致模式集中效应（概率集中在少数高置信 SID，降低深层 beam 多样性、相似候选重复）。引入专家引导后点击/曝光 Hitrate 及曝光覆盖度一致提升（EG-GRPO 通过注入 GT 作策略梯度组高质量示范，优化精确目标同时保持召回广度，实现精确性与多样性平衡）。适度引导即有收益，K 增加出现点击与曝光跷跷板效应，但均优于不加专家样本（多目标帕累托改进）。

**线上实验**：生成式召回上线采用动态 BeamSize=[20,50,100]，平均总 RT 约 40ms，线上 **GMV+1.15%、UCTCVR+0.40%**，已手猫搜索线上全量部署；生成式召回路带重曝光占比 50.25%、点击占比 58.96%、成交占比 72.63%。

## 总结与展望

CQ-SID 在语义与个性化召回均显著优于基线，以更少推理资源实现更高召回命中率；EG-GRPO 在提升点击 Hitrate 同时更好对齐排序、曝光更多高质量商品。未来探索搜索生成式"召粗一体"范式减少漏斗损失，以及召回到曝光的端到端生成在特定垂类/长尾流量场景的落地。
