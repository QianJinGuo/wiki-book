# 清华混元 TRAJDEBUG：Agent 调试别看表面

> 作者：AI先声（小红书论文解读号）
> 清华、清华深圳国际研究生院、腾讯混元

## 核心问题

长程 Agent 失败时，真正麻烦的不是知道「任务没完成」，而是找出**哪一步把后面带偏了**。

一条轨迹里可能有很多局部错误：有些后来被修好、有些无关紧要、有些只是前面错误引出的症状。只看最后失败，或让模型通读整段轨迹下结论，很容易把责任归错。

TRAJDEBUG 解决长程 Agent 轨迹里**关键错误难定位**的问题。核心思路：**把错误当成一个生命周期来追踪**。

## 技术流程

1. **Multi-granularity history compression（多粒度历史压缩）**：当前步骤保留高细节证据，近邻步骤保留中等摘要，远处历史压成低细节进度。既能看长上下文，又不会被整条轨迹压垮

2. **Evidence-grounded error triggers（证据接地错误触发点抽取）**：不直接问「哪一步错了」，而是抽取每个触发点都必须能对应到明确证据的错误触发点——违反任务约束、历史观察、环境反馈、当前步骤内部自相矛盾

3. **错误实例合并与状态判断**：把相关触发点合并成 error instance，再判断状态——已经干净修复 / 修复但留下成本 / 仍然显性影响结果 / 仍活跃但没有终局痕迹。真正进入归因阶段的，是那些和最终失败仍有关的候选错误

## TRAJERRBENCH 基准

论文构建 TRAJERRBENCH：**486 条人工标注失败轨迹**，其中 400 条来自 τ²-Bench，86 条来自 SWE-Bench Pro，覆盖工具使用和代码任务。SWE-Bench Pro 平均轨迹长度约 **119.7 步**。

## 实验结果

- TRAJDEBUG 在多组关键错误定位任务上**宏平均准确率 34.11**，高于同底座直接提示的 25.69
- 把诊断转成任务指导后，重跑成功率平均提升 **10.80%**
- 把历史失败汇总成 failure memory 后，迁移到保留任务平均提升 **5.70%**

## 边界

- 仍依赖 LLM 做错误解释和最终归因
- 作为分阶段管线，前面漏掉触发点，后面候选集也会受影响
