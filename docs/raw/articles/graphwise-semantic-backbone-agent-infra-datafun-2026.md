# 资本开始买「语义层」了：Graphwise 获控股投资，AI Agent 的新基础设施正在成形

Graphwise 由 Ontotext 与 Semantic Web Company 在 2024 年合并而来，两家公司分别长期从事知识图谱、语义技术与知识管理。这笔交易对应的并不是一个新概念，而是语义技术在 Agent 场景中的新位置：语义层正在从 BI 上方的一层，向企业 AI 下方的基础设施扩展。

## 01 从 BI 的 Semantic Layer 到 Agent 的 Semantic Backbone

BI 时代的 Semantic Layer，核心任务是把底层表、字段和计算逻辑翻译成统一的业务概念。例如同一个 Revenue、GMV 或 Active User，由一套受治理的定义映射到底层数据，避免不同团队各写一套口径。

Agent 对语义的要求更宽。它不仅要知道一个指标怎么算，还要知道客户、订单、产品、供应商、组织和文档之间是什么关系，哪些规则约束这些对象，以及一条结论来自什么数据。Graphwise 因此把 Semantic Layer 进一步延伸为 Semantic Backbone：以企业知识图谱为基础，叠加可机器读取的 taxonomy、ontology 等治理模型，为不同应用和 Agent 提供共享的业务概念、关系与上下文。

## 02 Graphwise 的产品链路

大模型可以处理语言，但并不天然拥有一家企业内部稳定的业务语义。传统 RAG 能把相关内容送进上下文，却很难只靠相似检索表达跨系统的多跳关系、统一业务规则和数据血缘。对于 Agent，这些差异会直接影响后续推理和行动。

Graphwise 的产品链路围绕这一问题展开：Graph Modeling 用 taxonomy 和 ontology 定义业务逻辑，Graph Automation 连接企业数据，Semantic Analytics 为非结构化内容补充实体与元数据，GraphDB 保存可查询的关系网络，GraphRAG 再从这套受治理的知识基础上组装上下文。重点不再只是「找到一段相关文本」，而是先把企业中的对象、关系和规则组织成机器可以读取的结构。

## 03 市场信号：知识图谱重回 AI 基础设施中心

Graphwise 已有 200 多家蓝筹客户和 30% 以上的有机 ARR 增长，并非一家围绕 Agent 概念新成立的公司。Oakley 取得多数股权后，将重点放在商业能力、国际市场和战略收购上。

Semantic Layer 的功能边界也由此发生变化：过去主要解决「指标口径是否一致」，现在开始承担「Agent 是否理解同一个业务世界」的问题。知识图谱重新进入 AI 基础设施中心，不是因为技术本身突然变新，而是它的主要使用者正在从分析工具和知识应用，扩展到需要持续推理、协作和执行的 Agent。

模型提供语言与推理，RAG 提供外部信息，工具提供执行入口；企业 Agent 还需要稳定的业务概念、关系、规则和上下文。Graphwise 把这层称为 Semantic Backbone，Oakley 的交易则说明，这条路线已经开始获得大型私募资本的明确投入。
