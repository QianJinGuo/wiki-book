# 不止AutoResearch！策略与Harness共进化，EvoTrainer跑通自主闭环

原创 让你更懂AI的 2026-08-31 13:51 北京

训练系统也开始自进化

## 

自动跑实验只是第一步。EvoTrainer 开始让 AI 自己分析 Reward、Rollout 和失败轨迹，再反过来升级训练策略与 Harness。

EvoTrainer 是⼀种让⼤语⾔模型训练策略与 Training Harness 协同进化的⾃主训练⽅法。

它不只是在 Agentic RL 中⾃动跑实验、调参数，更关键的是让系统能随着模型变强，持续提升发现、诊断和解决训练问题的能⼒。

论文标题：

EvoTrainer: Co-Evolving LLM Policies and Training Harnesses for Autonomous Agentic Reinforcement Learning

论文地址：

<https://arxiv.org/abs/2606.03108>

代码地址：

<https://github.com/AlibabaResearch/DAMO-ConvAI/tree/main/EvoTrainer>

核⼼观点

传统⾃主训练中，Training Harness 往往被视为固定基础设施：Reward 定义、样本过滤、回测逻辑、诊断⽅式⼀旦设定，后续训练只是在这套静态框架内搜索更优参数或配⽅。

但在⻓程、多步、强交互的 Agentic RL 任务中，这种假设并不成⽴。

随着策略不断变强，原有 Harness 的局限会逐步暴露：

  * 原先有效的 Reward 可能失去区分度；

  * 原先⾜够的评估⽅式可能⽆法识别投机⾏为；

  * 原先粗粒度的诊断逻辑难以解释新的失败模式；

  * 原先的样本筛选机制可能⽆法持续提供⾼信息量训练信号。




因此，真正的⾃主训练不应只优化模型参数，⽽应让训练策略与 Training Harness 处于同⼀个协同进化闭环中：

  * 策略变强，暴露新的瓶颈；

  * Harness 感知瓶颈，升级诊断与回测能⼒；

  * 新的 Harness 再反过来为策略提供更可靠的优化信号。




EvoTrainer 的核⼼贡献，就在于将这种“训练决策系统本身也要持续进化”的思想系统化，并将其落地到 Training-Time。

相关⼯作

现有⼯作⼤致覆盖三条路线：

a. ⾃主训练：AI ⾃动提出⽅案并执⾏实验。

b. 推理侧 Harness 优化：优化模型推理时的⼯具、上下⽂和脚⼿架。

c. 优化 RL 算法：针对不同任务设计更合适的 RL 机制。

2.1. AutoResearch：⾃动化实验搜索 [1]

AutoResearch 证明了 Agent 已具备接管训练的能⼒，它通过“修改代码 → 启动训练 → 验证指标 → 决策保留/回滚”的闭环，实现了训练⽅案的⾃动探索。

然⽽，这种范式的本质仍是“基于静态标尺的快速试错”。

Agent 仅将验证集分数作为唯⼀的筛选依据，⽽承载评估与诊断功能的 Harness 在整个过程中始终保持不变。这导致系统缺乏对训练过程的深层理解：

  * ⽆法甄别信号质量：⾼分可能源于数据泄露或评估漏洞，⽽⾮真实能⼒提升；

  * 浪费失败样本价值：低分分⽀被直接丢弃，其中蕴含的诊断线索未被提取；

  * 缺乏能⼒沉淀：每⼀轮搜索都是独⽴的，训练中形成的排查经验⽆法转化为可复⽤的诊断技能。




换⾔之，AutoResearch 是⼀个⾼效的“实验搜索器”，但并⾮⼀个能持续提升训练理解能⼒的 “进化系统”。

它优化的是“找到下⼀个⾼分配置”的效率，⽽我们关注的是“升级发现问题与定义问题”的能⼒本身。

2.2. 推理侧 Harness 演化：Meta-Harness [2] 与 AHE [3]

Meta-Harness 与 AHE 共同确⽴了 “Harness 本身可作为优化对象”的重要范式，为 EvoTrainer 提供了关键的⽅法论基础。Meta-Harness 率先打破了 “Harness 即固定基础设施”的传统认知，通过 Agent 搜索并修改推理阶段的上下⽂组织与⼯具链代码，利⽤历史执⾏轨迹持续提升下游任务表现；AHE 则进⼀步系统化了这⼀⽅向，将 Middleware、⻓期记忆与 System Prompt 纳⼊可编辑范围，并明确引⼊可观测性信号作为改动有效性的验证依据，证明了⻓期⾃动改进必须依赖过程证据⽽⾮仅看最终结果。

然⽽，这两项⼯作的演化边界均严格限定在 Inference-Time。当我们将视⻆转向 Agentic RL 的训练场景时，会发现推理侧的演化逻辑存在根本性的信号断层：

  * 优化⽬标错位：推理侧追求单次任务完成率，⽽训练 Harness 需保障⻓期学习信号的稳定性与区分度；

  * 诊断维度缺失：推理侧关注输出正确性，却⽆法感知 Reward 失效、Rollout ⾏为崩塌或低信息量样本等训练动⼒学问题；

  * 经验⽆法跨阶段迁移：推理侧积累的 Prompt 优化或执⾏链路调试经验，难以转化为训练过程中对异常信号的审计、过滤与回测能⼒。




换⾔之，现有⼯作证明了 Harness 演化的可⾏性与过程证据的价值，但仍未跨越从“推理执⾏优化”到“训练策略协同进化”的鸿沟。

EvoTrainer 正是要将这种“过程感知 + 系统演化”的思想，真正移植到 Training-Time Harness 中，使其成为与训练策略双向驱动的协同进化对象。

⽅案

现有⼯作分别验证了 Agent 参与训练（AutoResearch）、Harness 动态演化（MetaHarness）以及过程证据驱动改进（AHE）的可⾏性，但尚未将这三者在 Agentic RL 的训练场景中统⼀。

EvoTrainer 的核⼼出发点，正是打破推理侧与训练侧的壁垒，⾸次实现 Training Harness 与训练策略的协同进化。

现实中的资深研发⼈员，在优化模型时，并不是仅盯着测评集上的分数去决策下⼀步的优化路径。

当⼀个版本结果异常时，通过 Reward 分布、Rollout 轨迹与版本 Diff 等⾼维信号综合诊断瓶颈来源。

然⽽，Agentic RL 的数据规模与噪声密度使这种分析难以⼈⼯持续执⾏。

EvoTrainer 的核⼼动机正是将这种碎⽚化的排查经验，转化为 Training Harness 中可执⾏、可积累的诊断程序——让 AI 不仅替代⼈⼯检查，更实现诊断能⼒本身的持续优化。

3.1. 训练策略与训练 Harness 的协同进化

EvoTrainer 将训练过程组织为⼀条可追踪的版本链：

它的关键在于：每⼀轮策略更新都会暴露新的⾏为模式、瓶颈和失效现象，⽽训练侧的 Harness 会据此调整⾃⼰的诊断⽅式；⼀旦诊断⽅式发⽣变化，后续版本的选择和搜索⽅向也会随之改变。

因此，EvoTrainer 关注的不只是“分数是否更⾼”，还包括：

  * 信号有效性：当前 Reward 是否仍具备⾜够的区分度以⽀撑梯度更新；

  * ⾏为稳定性：Rollout 轨迹是否出现分布偏移、模式崩塌或异常收敛；

  * 版本可⽐性：相邻版本间的性能差异是否能被现有诊断证据合理解释；

  * 评估鲁棒性：⾼分结果是否可能源于数据泄露、评估漏洞或随机噪声。




当现有证据不⾜以解释某次训练结果时，系统不会盲⽬推进下⼀轮实验，⽽是主动触发 Training Harness 的⾃我升级。

这种升级并⾮简单的参数调整，⽽是诊断能⼒本身的扩展，例如：

  * 引⼊新的⾏为分析器

  * 构造针对性的回测⽤例

  * 检索历史相似案例的诊断路径

  * 动态调整样本过滤策略




换⾔之，训练策略的演进与 Harness 的演进在同⼀闭环中交替发⽣——策略变强催⽣更精细的诊断需求，诊断升级⼜为策略突破提供更可靠的导航信号。

3.2. Memory & Skill：让EvoTrainer 具备持续进化能⼒

Memory + Skill 是 EvoTrainer 区别于“只会反复试配⽅”的关键能⼒。它不仅记录每次训练结果，还会沉淀失败经验、诊断⽅法和可复⽤策略，让后续版本的进化越来越“聪明”。

Skill：把有效⽅法沉淀成可跨任务复⽤的能⼒，这不是简单的经验总结，⽽是经过验证、可再次调⽤的操作能⼒，例如：

a. 分析器技能（analyzer skills）

b. 修复策略（repair strategies）

c. 训练流程模板（procedure templates）

3.3. 以 SWE 场景为例看 EvoTrainer 的进化过程

SWE RL训练的难点不在于最终 Reward 定义本身，⽽在于 SWE 它是⼀个⻓轨迹、多轮交互的操作任务。模型需要先定位代码，再理解上下⽂，再修改实现，最后通过测试验证修复是否成⽴。

因此，训练⽅案的演化，本质上是在不断回答⼀个问题：怎样把“成功修复”拆解成可学习、可⽐较、可优化的训练信号？

EvoTrainer 在整个过程中引⼊⾏为奖励、让⾏为奖励产⽣区分度以及加⼊ StdGroupFilter 让优化器看到⾼质量信号，最终达到最优效果。

3.3.1. 仅依赖最终正确性，⽆法⽀撑多步修复任务

最直接的做法是只⽤测试⽤例分数作为 Reward，但在 SWE 中，这种设计很快暴露出问题：

  * ⼤量失败轨迹共享同⼀个低分，导致信号极其稀疏；

  * 即使偶尔得分变化，也很难判断模型到底学到了更好的⾏为，还是只是碰巧命中；

  * 对于多步⼯具使⽤任务，单⼀结果分数⽆法反映过程质量。




也就是说，最终结果 Reward 能定义任务⽬标，却不⾜以塑造达到⽬标的过程⾏为。于是，训练系统开始从 Rollout 中寻找那些能反映“过程是否健康”的中间证据。

3.3.2. 引⼊⾏为奖励，把“健康过程”显式纳⼊训练信号

基于对 Rollout 的诊断，系统发现两个⾏为与成功修复强相关：

这两个信号的作⽤不是替代正确性，⽽是把原本只有“最终做对/做错”的 Reward，扩展为同时刻画结果质量和过程质量的复合信号：

在这个阶段，关键变化是：Reward 不再只回答“最后对没对”，还开始回答“这条轨迹是不是沿着更合理的修复路径在前进”。

3.3.3. 有了过程信号，还要让它真的产⽣区分度

但仅仅加⼊过程信号，并不能带来有效训练，系统进⼀步观察发现，如果过程奖励设计得过于对称，很多 Rollout 会得到相同或近似的附加分，导致 Reward Tie 增多。

这会削弱组内样本之间的排序差异，使训练难以判断哪种⾏为更值得强化，因此，问题从 “Reward 太粗”进⼀步变成了：Reward 虽然变细了，但还不够有区分⼒。

为了解决这个问题，EvoTrainer 没有继续堆更多 Reward 项，⽽是直接调整已有⾏为信号的相对权重。最终，ETT 被赋予略⾼于 SBE 的系数：

这样做的含义是：

  * SBE 反映的是修复前的准备⾏为；

  * ETT 反映的是修改后是否形成了“编辑—验证”的闭环；

  * 在 SWE 中，后者与有效修复更直接相关，也更有助于拉开 Rollout 之间的差距。




所以，这⼀步的核⼼不是“调参”，⽽是增强 Reward 的排序能⼒。

3.3.4. Reward 有区分度了，还要保证优化器看到的是⾼质量⽐较信号

即使 Reward 设计已经更细、更有区分度，GRPO 训练仍然依赖⼀个前提：同⼀组 Rollout 之间必须存在⾜够稳定的相对差异。

GRPO 的组内优势定义为：

如果⼀组 Rollout 的 Reward 都差不多，那么组内标准差会很⼩。此时会出现两种情况：

  * 如果 Reward ⼏乎完全相同，则也接近 0，优势值接近 0，⼏乎没有有效学习信号；

  * 如果 Reward 只有很⼩的随机差异，这些差异可能被较⼩的分⺟放⼤，形成不稳定的噪声信号。




于是，新的问题不再是 Reward 本身，⽽是：哪些 Rollout Groups 真正值得拿来做相对学习？

因此，EvoTrainer 最终加⼊了⼀个过滤机制，过滤掉降低那些缺乏区分度、⽆法稳定⽀持相对排序的 Groups 对训练更新的影响。

实验

在三类任务上评估 EvoTrainer，这三个任务覆盖了从单轮推理到⻓程⼯具使⽤的不同训练场景。

它们分别强调可验证推理、执⾏反馈以及⻓程 Agent-Tool 交互，覆盖了从单轮推理到复杂⼯具使⽤的不同训练场景。

整体结果表明，EvoTrainer 在三类任务上都稳定有效。更重要的是，结果不是来⾃⼀个固定的通⽤训练⽅案。不同任务最后需要的能⼒不同：

  * Math 更需要计算能⼒增强；

  * Coding 更需要 Reward Shaping 和 Filtering；

  * SWE 更需要⾏为敏感的训练路径。




这说明 EvoTrainer 不是简单找到⼀个万能配置，⽽是在根据任务瓶颈调整训练过程。

总结

综上所述，EvoTrainer 的核⼼贡献可概括为：将模型训练中的决策系统本身变为可优化的演化对象。具体⽽⾔，它在三个维度上实现了对现有⼯作的升级：

从“实验搜索”到“诊断决策”（对标 AutoResearch）：⾃动训练的瓶颈不在于候选配置的数量，⽽在于系统能否将每次实验转化为可积累的训练认知。

EvoTrainer 通过多维信号交叉验证与失败样本价值挖掘，使训练决策从试错驱动转向认知驱动。

从“静态基础设施”到“协同演化对象”（对标 Meta-Harness）：Agentic RL 的训练瓶颈具有动态性（从奖励稀疏到⾏为崩塌、从评估漏洞到低信息量样本），固定的 Harness ⽆法覆盖全⽣命周期。

EvoTrainer 使 Training Harness 随策略瓶颈持续重铸，成为与模型权重双向驱动的进化组件。

从“⼀次性调试”到“可迁移的认知资产”（对标 AHE）：失败案例、回测脚本与过滤策略不应被视为训练副产品，⽽是可复⽤的系统能⼒。EvoTrainer 通过结构化的记忆与技能库，使系统在跨任务场景中具备经验继承与泛化能⼒。

当然，当前 EvoTrainer 仍有⼏个限制。

  * EvoTrainer的推理、检索和回测计算成本较⾼；

  * 当前实验中的版本演化轨迹还不够⻓；

  * 系统表现仍然依赖较强的基础模型能⼒。




因此，下⼀步的重点不是简单扩⼤实验规模，⽽是让这⼀训练决策系统变得更便宜、更稳定、更可迁移。

总体⽽⾔，EvoTrainer 带来的收益并⾮源于实验数量的线性堆叠，⽽是来⾃ Training Harness 诊断能⼒的持续升级、回测机制的可靠性保障，以及诊断技能的跨任务复⽤——它让⾃动训练系统真正具备了“学会如何训练”的 Meta 能⼒。
