# Agent 数据飞轮平台的选型与接入：1688 宙斯接 AgentLoop 的七个步骤与五个坑

> 📊 Level ⭐⭐⭐⭐ | 19.0KB

## 起点：只看"这次输出对不对"，判断不了 Agent 的质量

用户向 Agent 提交任务，首要诉求是拿到正确结果；但研发与测试团队还需要回答三个问题——**结果是怎么产生的、偏差出在哪个环节、修完之后能否稳定复现**。Agent 的执行包含模型推理、工具调用与多轮重试，即使输入完全相同也可能走出不同路径；**验收只看最终答案，藏在执行过程中的风险暴露不出来**。

接入前三个痛点，构成数据飞轮要解决的清单：

- **偏差根因对应不到修改动作**：Prompt / Skill / 工具参数 / 读取策略多重影响，输出异常时现有信息不足以判断从哪切入，调整后也无法确认是否改对了地方——优化靠经验试错，且难以沉淀。
- **优化效果缺量化依据**：补 Prompt、调 Skill、改 MCP 配置后，少量用例通过只能说明局部改善，无法证明同类问题解决，也无法判断是否引入新偏差；没有统一评测标准与批量验证，版本质量靠人工抽查。
- **缺稳定回归机制**：失败请求、边界场景、判定标准散落在日志与沟通记录里，没形成可重复执行的用例；模型/提示词/工具配置一变就要重新人工验证，同类缺陷在不同版本反复出现。

## 选型：AgentLoop vs DeepEval vs EVA+

三个候选的定位差异被压成一张表，选型维度是**适配度、执行观测、回归评测**：

| 方案 | 主要特点 | 优点 |
|---|---|---|
| AgentLoop | 阿里云上的 Agent 观测与评估平台，连接线上 Trace、质量评估、数据集与实验 | 观测/评估/回归一体化，ARMS 探针无侵入采 Trace，接入成本低 |
| DeepEval | 开源大模型评估框架，用测试代码维护用例、指标与回归流程 | 开源、代码化、接入灵活，适合纳入 CI 自动回归 |
| EVA+ | 阿里内部评测平台，统一管理数据、任务与结果 | 一站式；部分应用免埋点或少量埋点；支持多类数据集、指标与实验对比 |

宙斯选择 AgentLoop 的理由不是"功能更多"，而是**它能在不改业务代码的前提下采到执行链路，且观测—评估—样本回归三件事连得上当前需求**。这个理由值得记住：选评测平台，先看"数据怎么进来"，再看"指标怎么算"。

## 观测：Session / Trace / Span

平台用三层结构组织调用日志：**Session 对应一段多轮会话，Trace 对应其中一轮请求，Span 记录该轮中的模型调用与工具调用**。沿调用链可检查各步骤的输入、输出、参数、结果与耗时，定位遗漏、误用、重复调用或性能瓶颈；平台还能把 Trace 加工成结构化 Agent 轨迹，按执行步骤展示模型与工具调用，供评估消费。

作者对"白箱"给了一个克制的定义：**白箱指可检查的执行记录，能看到多少细节取决于框架暴露与实际采集的数据**——所以接入验收不能以"控制台出现一条 Trace"为准，必须确认关键步骤是否齐全。

## 评估：工具调用成功 ≠ 任务完成

"工具调用成功"只说明某个执行步骤正常结束，不代表任务真正完成；评估还要判断**用户要求是否满足、关键结论是否有证据、最终结果是否完整交付**。平台把用户输入、模型推理、工具调用与最终输出加工成数据集，按准确性、任务完成度等标准给分并给出原因，快速定位低分样本。

三类评估器的分工（这是全篇最可复用的一张判据）：

- **Code Judge**：字段缺失、数值越界、格式校验、工具调用是否成功——规则明确、结果确定、零模型成本。
- **LLM Judge**：靠语义理解即可判断的（相关性、语气、是否答非所问）——配置轻、见效快。
- **Agent-as-a-Judge**：涉及业务知识与多步核验时，裁判可挂知识库 / 业务 Skill / MCP，**先查证证据再打分**——也就是"懂业务的裁判"。

评估结果直接进版本实验：用回归集设上线基线，对比不同 Agent 或优化前后版本；上线后继续从真实 Trace 抽样评估并告警，形成"观测—评估—优化—回测"循环。

## 回归：让失败样本成为下一次测试的输入

闭环的最小单元是**一个具体 Case**：从线上请求找到 Trace 与 Agent 轨迹 → 评估与人工复核 → 失败样本加入测试集 → 改 Prompt/Skill/模型配置 → **重新请求新版 Agent 取新输出与执行记录** → 按相同标准比较。

两个容易漏的前提：**必须重新请求新版本 Agent**（不能拿旧记录重打分），**必须保留必要业务条件**（避免数据或工具返回变化污染对比）。验收口径也很具体：能否根据请求找到完整记录、说明失败原因、把样本加入测试集、确认修改后同一问题解决；跑通后再扩样本与评估范围，线上覆盖不到的低频/异常场景再人工设计用例。

## 接入七步：探针级细节

宙斯是容器化 Java 应用（Pandora Boot + AgentScope2），选 **ARMS GenAI Java Agent 探针（jar 5.2.0-genai-1.0）**，以独立 AgentScope collector 运行。三条理由：**无侵入**（字节码插桩自动生成 `invoke_agent` / `chat` / `execute_tool` 语义 Span，业务零上报）、**部署层一次配置**（加启动参数挂载，与业务发布解耦）、**开销可控**（插桩开关收敛，只保留 AgentScope 链路所需数据）；探针向独立 SLS workspace 上报，与内部日志/链路体系隔离。

关键步骤与参数：开通 workspace 并写入 `ARMS_WORKSPACE`（生产/预发用不同应用命名区分）；启动参数含 `licenseKey`（环境变量注入，为空打 WARN 且不挂载）、`appName`、`workspace`。

**Trace 合格的三条口径**（比"有没有 Trace"更值得抄）：①**步骤齐全**——模型调用、每次工具调用都有 Span，输入输出可读；②**嵌套正确**——子代理/异步任务不丢父 Span，无孤儿 Span 或断链；③**染色正确**——业务相关数据在传播过程中不丢，且正确挂在对应 Span 上。

评估配置是一条五环节流水线，建议按序打通：**Agent 轨迹 → 数据处理 → 数据集 → 评估任务 → 评估器 → 评估结果**。数据处理做两件事（按时间/Agent/状态筛选日志；字段投影与变量映射），数据集两种来源（自动转化优先，人工自建用于冷启动/低频/关键场景），评估任务要素是"数据集 × 评估维度"（支持多维度并行，每样本生成独立评分），最后做变量映射。

## 五个坑（每一个都有现象—原因—解法）

1. **环境未隔离**：评估任务混入不同环境的 Trace，结果不可比较——生产与预发共用应用标识或 workspace；解法=各环境独立应用标识 + 任务内按环境筛选。
2. **插桩范围过宽**：低价值基础设施 Span 淹没业务链路，取数受干扰——解法=探针开关里只开 Agent 所需插桩，显式关闭数据库访问等非必要组件。
3. **用户标识未随链路上报**：`user.id` 只出现在入口 Span——原因是 Span Attribute 仅作用于当前 Span，异步中新建的 Span 不自动继承；解法=请求入口写入 OTel Baggage，并在异步上下文切换前完成捕获。
4. **多套链路上下文互相覆盖**：子任务挂错父 Span 或同一请求断链——多个追踪组件共用同一上下文并各自尝试恢复父链路；解法=每套链路独立的上下文键与父链路恢复逻辑，且用含异步子任务的请求验证父子关系。
5. **TraceId 不统一**：EagleEye 与 AgentLoop 各自生成 TraceId，排障时无法用单一 ID 跨系统检索——解法=入口与关键节点同时打印两个 TraceId 建立映射，排障时互为跳转。

## 三类用法与两个 Case

**线上巡检**（周期跑 Pipeline，从真实请求找低分与异常）→ **实验验证**（针对 Bad Case 提优化假设，固定数据集/评估器/变量映射，当前版本为基线组、一个或多个优化方案为实验组，逐题比较输出与评分，同时看完成度、证据支持度、工具选择、延迟、Token 与成本；**只改善单条 Case 却让其他题退化就继续调，不直接发布**）→ **发布准出**（回归集防历史问题复发、基准集看整体能力是否下降，核心指标达阈值且关键 Case 全过才进灰度）。

**Case A｜读了文档但没刷新**：用户要求重新读取钉钉文档并按最新内容回答，Agent 只凭对话上下文给出变化说明，**本轮根本没发起读取**——执行记录里只有请求与回答，缺"文档内容读取"。风险是文档已更新时把旧信息包装成最新结论。改进=遇到"重新读取/刷新/最新"必须触发本轮读取，答案与本次读取结果或文档版本关联，读取失败要明说。

**Case B｜子 Agent 结果未回传**：主 Agent 委派子 Agent 只读查询 6 个 Aone 工作项，子 Agent 6 次查询全部成功返回，但**结果未被提取汇总**；其摘要自相矛盾（说已开始查询又说没收到工作项 ID），主 Agent 直接采信，得出"6 项都没查到"的错误结论，任务完成度仅 **0.25**。教训：**只看"任务已完成""工具调用成功"发现不了"结果已返回但主流程未使用"**；改进=以结构化返回为准逐项核对查询数量与必填字段、比对摘要与执行轨迹、冲突时以可核验返回优先。

## 数据集分层：测试 / 回归 / 基准 / 后训练

作者把"数据集"从临时样本升成**按用途持续沉淀的数据资产**：测试集（问题复现与优化验证，含线上低分样本、低频场景、人工设计题，回答"能不能做对"）→ 回归集（已修复 Bad Case 与可能受影响的关键样本，上线前重复执行，作发布拦截门禁）→ 基准集（长期稳定、人工审核的黄金样本，用于模型切换/大版本/核心能力升级的全量回归与基线判断）→ 后训练集（高质量轨迹、专家标注、黄金答案与人工题，可用于 SFT/RL/行为对齐/经验迁移；**不要求唯一标准答案，也可含参考答案、偏好关系、过程标注或奖励信号**）。

流转路径清晰可执行：线上 Bad Case 先进测试集复现与验证 → 修复确认后进回归集防复发 → 长期验证的代表性样本沉淀为基准集 → 其中能提升通用能力的高质量样本加工为后训练数据；**实验里临时冻结的样本集合只是一次实验的数据切片，不该单列为长期数据集**。

## 量化结果

- **定位效率**：单次问题定位平均 55 分钟 → 15 分钟（约 **73%**）；一轮完整回归 1.5 人天 → 3 小时（约 **75%**）。
- **覆盖**：人工抽查约 200 条/轮 → 日均自动覆盖 **2000+** 条记录 × 5 个维度（约 10 倍）。
- **质量**：任务完成度 ≤0.6 的 2080 条记录中筛出 **72** 条候选，人工复核确认 **31** 个有效问题，其中 **26** 个修复并通过回归（**84%**）；固定回归集上完成度 **0.62→0.82**、证据支持度 **0.66→0.85**；历史问题复发率 **16%→5%**。
- **工作方式**：上线前发现问题比例 **30%→75%**，月均紧急排查 **8→3** 次，从"救火"转向"防火"。

## 深度分析

### 数据飞轮的启动条件不是"有平台"，而是"Trace 够用"

全篇最硬的约束在观测层：如果 Span 缺步骤、父子错挂、业务标识没染上，后面所有评估都在污染数据上打分。作者把验收口径写成"步骤齐全 / 嵌套正确 / 染色正确"三条，而不是"能看到 Trace"，这个区别就是**平台能不能用的分水岭**。

### 三类评估器是成本—可信度的分层，不是三种玩法

Code / LLM / Agent-as-a-Judge 对应三档"查证成本"：规则可判的用代码（零成本、确定性最高），语义可判的用 LLM（便宜），需要业务知识与多步核验的才上 Agent 裁判（贵但能查证）。**用便宜的评估器去判需要证据的维度，会得到"看起来对"的分数**；反过来用 Agent 裁判判格式，则是烧钱买确定性。

### 两个 Case 指向同一类失效：执行成功 ≠ 任务完成

Case A 是"该执行的动作没执行"，Case B 是"执行了但结果没被使用"。两者在最终回答层面都可能"看起来可信"，也都能通过"工具调用成功"的监控。**必须把"必要动作是否发生""远程结果是否被读取与消费""关键结论是否完整交付"写成独立断言**——这正是 Agent-as-a-Judge 相对 LLM Judge 的价值所在。

### 数据集分层是资产化，不是命名学

测试集 / 回归集 / 基准集 / 后训练集的区别在于**用途与生命周期**：测试集解决"能不能做对"，回归集解决"别再错"，基准集解决"整体有没有退"，后训练集解决"能不能更强"。四者之间的流转规则（Bad Case → 测试 → 回归 → 基准 → 后训练）让每条失败样本都有归宿，**这比任何"自动生成测试用例"的工具都更能减少重复缺陷**。

### 收益数据要看清分母

55→15 分钟是"单次定位"，1.5 人天→3 小时是"一轮完整回归"，200→2000+ 是"每轮/每日覆盖"，84% 是"31 个有效问题中 26 个修复通过"，0.62→0.82 是"固定回归集平均分"。**这些数字不能相乘，也不能当作整体效率提升**；它们的意义是把"接入前后"的差异钉在可复核的颗粒度上。

## 实践启示

1. **先定 Trace 验收口径**：步骤齐全、嵌套正确、染色正确；缺一条就先修埋点，别急着跑评估。

2. **探针选型看三件事**：无侵入（字节码/框架层）、部署解耦（启动参数）、开销可控（开关收敛）。

3. **评估器按查证成本分层**：Code → LLM → Agent-as-a-Judge，别让便宜的裁判判需要证据的维度。

4. **回归必须重跑新版本**：拿旧记录重打分等于自我确认；同时冻结业务条件。

5. **把"动作是否发生/结果是否被消费"写成断言**：这是 Case A/B 唯一能被自动发现的方式。

6. **数据集四分层并规定流转**：测试→回归→基准→后训练，临时实验集不单列。

7. **最小闭环优先**：一个高频可核验场景跑通"采集—检查—评估—复核—回流—回归"，再扩面。

8. **环境隔离与 TraceId 映射提前做**：否则评估不可比、排障跨不了系统。
