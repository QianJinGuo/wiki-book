# Agent 记忆的演进：从检索问题到治理问题

> 🧭 综合·演进 | 信源 7 篇

<!-- syn-slug: memory-evolution -->

把本章十几篇信源按时间排开，"记忆"这个词的所指换了三次。单看任何一篇都无法看出这条线——这正是综合页存在的理由。

## 四个阶段

**2023–2024｜向量库即记忆。** 把记忆等同于"存进去、查出来"：embedding + 向量库 + top-k。这一阶段的遗产是把"相关"做成了工程问题，代价是把记忆降格成了检索的别名。

**2025｜分层架构。** [记忆架构的回顾与前瞻](034-agent-memory)确立了短期/中期/长期三层分离（内存 <1ms、本地 DB、向量库 ~100ms）；[Claude Code 四层记忆方案](001-claude-code-agent)与 [七层记忆架构](025-claude-code)把分层推到更细的粒度。范式定型为"精简索引常驻上下文 + 全量按需加载"。

**2025–2026｜知识编译与治理。** 关键转折：自由文本记忆经 QA 化编译后，幻觉率从 30% 压到 5% 以下——瓶颈从"存取"变成"质量"。写入纪律、后台整合（去重/删旧/重组，记忆的垃圾回收）成为一等工程。

**2026｜记忆成为被评测的对象。** [AML 机制级评测榜单](002-aml-agent-memory-leaderboard-agent)让记忆方案首次可比较；[记忆注入五维框架](012-agent-5-4-memguide-stitch-ace-lost-in-the)（选什么/放哪里/怎么放/放多少/何时放）把设计变成结构化决策；[记忆评测全景](037-agent-memory)则提醒：评测口径本身还未收敛。治理化的标志不是"有最佳实践"，而是"有度量谁更佳的尺子"。

## 演进规律

三年里，记忆从**存储介质**问题，变成**分层结构**问题，再变成**治理制度**问题。2023 年问"用哪个向量库"的团队，2026 年应该问："我的记忆写入纪律是什么，谁来审计它，过期策略由谁裁决？" [MemOS 与 Hermes 的记忆插件化](042-memos-hermes)是这条线的最新一步——记忆开始以"操作系统组件"而非"数据库附件"的形态出现。
