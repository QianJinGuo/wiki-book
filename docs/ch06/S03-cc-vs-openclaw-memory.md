# Claude Code vs OpenClaw：两种记忆哲学

> 🧭 综合·对比 | 信源 4 篇

<!-- syn-slug: cc-vs-openclaw-memory -->

两个被拆解最多的编程 Agent，对"记忆是什么"给出了几乎相反的回答。对比它们不是为了分出优劣，而是因为**两者的分歧恰好铺满了记忆设计的决策空间**——你的任务落在光谱哪个位置，就该选哪种哲学。

## 四组对照

| 维度 | Claude Code | OpenClaw |
|------|------------|---------|
| 记忆的形态 | 围绕任务周期的自组织记录（四层递进：会话 → 项目 → 用户 → 组织） | 跨会话的结构化资产（文件即记忆，显式目录与命名） |
| 写入时机 | 任务结束时批量沉淀 | 过程中持续外化 |
| 一致性来源 | 分层覆盖 + 会话内自洽 | 显式规则 + 人工可审计 |
| 赌注 | 长任务足够少，会话内自洽够用 | 长期复利足够大，值得付治理成本 |

## 编者按

[源码级对比](013-claude-code-openclaw-memory-agent)最有价值的发现是：两者的记忆链路都没有向量库的关键路径——分歧在组织哲学，不在介质。[记忆架构总论](../ch04/263-agent-memory)提供的框架可以统一两者：**记忆设计的第一变量是任务连续性**。一次性任务选 Claude Code 式（轻、自洽、零治理）；长期演进的项目或团队选 OpenClaw 式（资产化、可审计、复利）。 [MemOS/Hermes 的插件化路线](042-memos-hermes)则是第三条路：把记忆哲学的选择权做成配置项——代价是复杂度转嫁给用户。

选择建议一句话：**先诚实回答你的任务有没有"跨会话的生命"，再选边。** 两边都上（很多团队的默认动作）通常意味着两边的治理成本都付了，复利却没拿到。
