# Personal Agent 记忆设计：六层记忆、五问筛选、三种遗忘与三种价值

> 📊 Level ⭐⭐⭐⭐ | 17.6KB

## 一句话结论

关于 Personal Agent 的记忆，多数讨论都在问"怎么存得更多、检索得更准"；这篇的起点是另一个问题——**如果自我是一份不断重写的叙事，那记忆系统该做的不是全部记住，而是维持一个"可以续写、可以修订、可以纠错、而且始终属于这个人"的自我叙事**。从这句话能直接推出三个工程要求：**连贯**（叙事得有结构 → 分层与整理）、**自由**（叙事可以改写 → 时间与失效）、**主权**（叙事专属于你 → 权限与归属）。

## 起点：两个故事指向同一件事

博尔赫斯《博闻强记的富内斯》里，主人公摔伤后记得一切——每一片叶子、每一道光影、前一天梦里的每张脸。博尔赫斯的判断是：**"我怀疑他并不擅长思考，因为思考要做的第一件事，是把不同的东西看成一类"**；思考就是遗忘差异、概括、抽象。

另一个方向是英国音乐家克莱夫·韦尔林：病后失去形成新记忆的能力，每次见到妻子都像第一次，热烈拥抱；几分钟后再见，又是一次；日记里反复写着同一句"现在，我终于醒了"。

**一个记得太多，一个记得太少，坏掉的是同一件东西：一个人还能不能把自己讲成一个连贯的人。** 这就是全文的问题意识——所以听到"AI 长期记忆"时该问的是：**我们要它记住的，到底是什么。**

## 论证链：记忆是什么、自我是什么

四组引证构成前提：

| 来源 | 判断 | 对设计的含义 |
|---|---|---|
| Richards & Frankland《The Persistence and Transience of Memory》(Neuron, 2017) | 记忆的目标是优化决策，原样保存只是手段；遗忘不是故障，能减少过时信息干扰 | 保真度不是指标，**未来决策质量**才是 |
| Anderson & Schooler (1991) | 频率、新近性、间隔模式能相当准地预测一条信息何时还会被用到；人忘掉的，大体是以后用不上的 | 遗忘可**预测**，不必凭感觉 |
| 控制论（Conant & Ashby, 1970） | 你想管住一个东西，手里得先有它的模型 | 要管理记忆，先有记忆的模型 |
| Locke / Hume / Tulving / Conway | 洛克：人格同一性在于意识延续，记忆是其证据；休谟：自我是一束知觉；图尔文：情景记忆要求"当时自己在场"；康威：自传记忆被**当前目标**驱动建构 | **自我是过程，不是东西**；记忆是成为自己的方式 |

一句话收束：**记忆是一份为将来写的摘要——写得好不好，不看它保真多少，看它能不能帮你在未来做对判断。所以遗忘不是记忆的敌人，遗忘是记忆的一半。**

## 为什么 Personal Agent 这两年才起来

三组观察：**①市场**——Appfigures 统计，2022 年底到 2026 年上半年，苹果与谷歌商店 AI 陪伴类应用累计下载 **1.65 亿次**、用户消费 **4.27 亿美元**，近**七成**用户向现实伴侣隐瞒使用行为；**②产品**——把角色做得"不听话"、有小脾气、会说错话就反驳，留存和活跃反而涨 **60%–70%**；**③判断**——百依百顺不行，因为人与人建立关系靠的是对方"是个谁"，而随时同意你的东西没有主体性。

"是个谁"拆成三样，全部指向记忆这一个底座：**可预测**（知道你会怎么反应，才敢依赖）、**连续性**（上周的你和这周的你是同一个人，关系才有厚度）、**有过去**（我们之间发生过什么，决定此刻是什么关系）。所以：**人设可以写进提示词，一段话就能改；人格改不了这么快，它长在记忆里**——这正是"用户模型、对话摘要这些技术早就有，personal agent 却这两年才起来"的原因：上一代解决"记住信息"，这一代想解决"成为一个人"。

**与任务型 Agent 的分野**：任务型记忆服务**任务复用**（上次怎么做的，这次接着用，做完可归档）；personal agent 记忆服务**一个人**（他是谁，他要什么）——后者很难用归档的方式处理。

## 核心机制一：六层记忆架构（自上而下）

这是全文最可落地的部分，用虚构人物"老周"（42 岁，做产品）逐层说明：

| 层 | 存什么 | 关键设计 | 老周的例子 |
|---|---|---|---|
| **L1 原始档案** | 原始材料：邮件、合同、长对话 | 原样存 + **来源指针**；冷存、可加密、可整体删除 | 十年前的邮件、搬家合同、和前同事的长对话 |
| **L2 工作记忆** | 当前任务的工作台 | 任务结束**就清空**；"别把工作台当长期记忆" | 今天让你改的那版周报 |
| **L3 情景记忆** | 事件（带时间、地点、人物） | 实时写、**衰减快** | 三年前那个雨天，他提了离职 |
| **L4 用户模型** ⭐ | **他现在是谁**：城市/工作/团队、偏好、厌恶 | 带**有效期与置信度**；"很多人把它做成聊天记录摘要——摘要记的是他说过什么，模型记的是他现在是谁" | 待过三座城市、两份工作、带一个团队；喜欢结论先行、讨厌被追问细节 |
| **L5 程序记忆** | 他做事的方式：写的风格、说话语气 | 从**反复成功的经验**里提炼；**改动前确认、可回滚** | 周报的写法、跟你说话的语气 |
| **L6 前瞻记忆** | 还没发生的事：承诺与约定 | **不衰减**，到期即触发 | 下周三答应给母亲回电话 |
| 横切元数据 | 时间、来源、置信度、敏感度、作用域 | 每层都要挂；**少一个，整层记忆就开始骗人** | — |

作者的用意很明确：**写得这么细不是为了系统显得完整，而是只有这么存，他这个人二十年、三十年，才讲得下去**——这是第一件东西：**连贯**。

## 核心机制二：五问筛选——什么值得记

一条信息去留与权重，用五个问题判断：

1. **以后还会用到吗？** 看出现频率、上次使用时间——Generative Agents 里"新近性"按小时乘 **0.995** 衰减，从上次被检索之后计算。
2. **会改变判断吗？** 一条信息值不值得留，看它对"你要回答的那个问题"有多少用（信息瓶颈视角）。
3. **出乎意料吗？** 真正值得记的是**让你改主意的信息**——**罕见不重要，改变才重要**（贝叶斯惊讶；原研究测的是注意力，不直接等于记忆）。
4. **关乎"我是谁"吗？** 身份、价值观、长期目标、重要关系，这类东西**忘得最慢**。
5. **是一个承诺吗？** 答应过别人的事不该淡忘，到点就该提醒。

**反例最见功力**：老周**每天刷牙**频率极高，但对未来判断几乎没用；他**搬过一次家**只发生一次，却改变了之后每次推荐、通勤与社交半径——所以"频率高"不等于"值得记"，**改变决策的才是。**

**节奏**：**白天轻写入**（记情景、抽事实、记承诺），**夜里重整理**（合并重复、提炼偏好、更新用户模型、检测冲突）。依据是脑科学的**互补学习系统（CLS）**理论——海马快速记具体经历、新皮层慢慢提炼结构、靠重放交错整合；sleep-time compute 的预印本还测算过，离线整理能在数学推理上把测试时算力省下约 **5 倍**（作者自报，单任务）。

## 核心机制三：三种遗忘——降权 / 失效 / 删除

"记忆系统最容易犯的错，是把过去的他当成现在的他。"所以每条记忆都该带**三个时间**：什么时候发生、什么时候记录、什么时候失效。遗忘分三种：

| 类型 | 做什么 | 数据 | 例子 |
|---|---|---|---|
| **降权** | 慢慢淡出检索 | **保留** | 他中学时喜欢的那个乐队 |
| **失效** | 标为失效、留历史 | **保留**（标状态） | 搬家后旧地址不该出现在"我现在住哪"，但得能回答"我以前住哪"；三年前说"从不喝酒"、现在喝一点 → 旧条目标失效而非删除，于是下次还能说"你以前是不喝的" |
| **删除** | 硬删 | **动数据** | 用户要求或合规要求（OpenAI 文档：关闭引用历史后，从聊天派生的记忆 **30 天内**删除） |

**三种里最难的是"失效"，因为它要求系统把"存"和"用"分开**：原始档案照存，回答问题时按预算与当下问题决定如何调用（率失真框架 RD-Forget 的思路）。由此得到一句很硬的判据：**遗忘首先是一个访问控制问题，其次才是删数据。**

配套的伦理判断也值得记：老周想删掉分手后那三年，系统**该给他这个权利，但不该替他把那段变成空白**——历史是他的一部分，哪怕那部分他不想再看；**删掉历史，你就没法回答"我为什么会变成现在这样"**。这是第二件东西：**自由**。

## 核心机制四：主权——记忆得属于这个人

记忆越长风险越大，四条底线听着像产品功能，其实是终身记忆的前提：**能看见系统记了什么、为什么用它**；**记错了能改**；**不想让它记的能关**；**想换地方能把记忆带走**。再加一条准入：网页、文档、别人转来的消息都可能带侵入风险（MINJA 证明**只用普通查询就能往记忆里注入恶意记录**），写进用户 Agent 前要过一道确认。

一句话：**一个人的一辈子，不能只托付给一家可能消失的公司。**

## 三类风险（原文明确点出的）

1. **注入**：MINJA 表明攻击者仅用普通查询即可写入恶意记忆条目——不需要特殊权限。
2. **记忆锚定**：把相关历史全用上，系统被过去困住，无法适应用户已改变的事实。
3. **用户自相矛盾**：今天说喜欢、明年说讨厌，系统该信哪个——这是"三种遗忘"要解决的核心场景，而非异常。

## 深度分析

### 把"记忆设计"从检索问题变成叙事问题

工程语境里的记忆通常被拆成存储、检索、压缩、调度四个技术问题；这篇的贡献是给出一个**验收标准**：记忆系统好不好，看它能不能让人**把自己讲下去**。这个标准一旦成立，很多默认做法立刻变成错误——比如"全部记住"（富内斯的失败）、"把聊天摘要当用户模型"（记的是说过什么，不是现在是谁）、"删除等于遗忘"（把留痕与淡出混为一谈）。**判据换了，架构才会换。**

### L4 用户模型是最容易做歪的一层，因为它要求"抽象"而不是"压缩"

摘要与用户模型的差别不在技术难度，而在**它们回答不同的问题**：摘要回答"他说过什么"（忠实于过去），用户模型回答"他现在是谁"（服务于将来）。摘要可以无损压缩，用户模型必须**有损且有判断**——要带有效期与置信度，要能失效。这与"记忆是为将来写的摘要"是同一个命题在系统层的落地。

### "遗忘=访问控制"是全文最可操作的洞见

把遗忘拆成降权/失效/删除后，最难的"失效"被证明**不需要动数据**——只需要在"用"的层面按当下问题决定调用什么。于是存储与使用解耦：**原始档案永久可追溯，检索面按情境收窄**。这把一个伦理问题（该不该删）转化为一个工程问题（何时不该用），同时也保护了"我为什么变成现在这样"的可解释性。

### 白天写、夜里整理：节奏本身就是一种架构决策

CLS 类比的价值不在"仿生"，而在**明确了在线与离线的分工**：在线要快、要轻、不能阻塞交互；离线要慢、要重、可以做合并去重与冲突检测。这与 Agent 系统里"热路径只做必要计算、冷路径做整理"是同一条工程原则，只是这里用睡眠做了锚点。**5 倍测试时算力节省**是这条原则的量化收益（单任务、作者自报，不可外推）。

### 主体性来自"会反驳"，这条经验对非陪伴类 Agent 同样成立

"不听话的角色留存涨 60%–70%"听起来像陪伴产品的怪癖，但它揭示的机制是：**关系需要对方是一个有边界的存在**。推广到工作 Agent——一个永远说"好的"的助手无法提供有效判断，因为它没有可预测的立场；而**可预测**恰恰来自"有过去"（记忆），不是来自提示词里的性格描述。

## 实践启示

1. **先定验收标准**：不是"记住了多少"，而是"能不能续写、能修订、能纠错、属于本人"。

2. **六层分开建**：原始档案 / 工作记忆（任务结束即清）/ 情景记忆（快衰减）/ **用户模型（带有效期与置信度）** / 程序记忆（改动前确认、可回滚）/ 前瞻记忆（不衰减、到期触发）。

3. **横切元数据是必需品**：时间、来源、置信度、敏感度、作用域——少一个，整层记忆就开始骗人。

4. **别拿摘要当用户模型**：摘要记"说过什么"，用户模型记"现在是谁"。

5. **用五问给记忆定权重**，尤其记住第 3 问：**罕见不重要，改变才重要**（刷牙 vs 搬家）。

6. **白天轻写、夜里重整**：合并重复、提炼偏好、更新模型、检测冲突——在线不阻塞，离线做重活。

7. **遗忘分三级**：降权（淡出、留数据）/ 失效（留痕、标状态）/ 删除（动数据）；**别把失效做成删除**，否则丢失"我以前是怎样"。

8. **把遗忘当访问控制**：存与用解耦，原始档案永久可追溯，检索面按情境收窄。

9. **主权四条**：可见（记了什么、为何用）、可改、可关、可带走；外部内容入记忆前必须过确认（MINJA：普通查询即可注入）。
