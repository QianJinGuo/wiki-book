# 速卖通选搭投：用自动驾驶分级做多 Agent 运营系统的成熟度标尺

> 📊 Level ⭐⭐⭐⭐ | 20.8KB

## 一句话结论

速卖通把大促运营从"**帮运营生成一张页面**"升级为"**替运营运营整场大促**"，并用**自动驾驶分级**给系统定坐标：L1/L2 是搭建助手（人是操作者）、**L3 是当前形态**（主 Agent 规划 + 领域 Agent 跨系统执行，人是安全员）、**L4 是终态**（促前中后形成可观测、可回放、可进化的闭环，人是审核者与策略制定者）。这句话是全篇的判据：**"生产级 Agent 的成熟度由模型能力和工程体系共同决定。"**

## 一、为什么借自动驾驶做标尺

作者的理由很实在：自动驾驶的演进必须依次解决**运行边界、风险控制、人工接管、持续学习**四件事，而选搭投一路遇到的问题几乎一一对应。于是每个阶段都能找到一个"人机责任"的定义：L1/L2 人全程负责、L3 人当安全员、L4 人当审核者。**这套分级真正的价值不是比喻好听，而是它逼你把"人在哪一步、负什么责"写清楚。**

四个建设维度也被写成了对照表（去年方案 → 痛点 → 今年建设）：

| 维度 | 去年的痛点 | 今年的做法 |
|---|---|---|
| **深度** | Copilot + Workflow 步骤写死，跨系统协同与异常分支即僵住，**无自进化** | ReAct 决策循环 + Plan Mode + 长期记忆，加**前置守卫**（角色权限/幂等/依赖校验） |
| **广度** | 各系统孤立、手工串联；"设计→搭→投→AB"信息断点 | 投放（站内运营位/PUSH/EDM）、AB、设计平台**三链路打通**；多 Agent **多协议**协同（同步调用/异步消息/**A2A**/定时调度） |
| **业务提效** | 只能基于已有知识搭页面，AB/巡检/修改靠人手工，**缺大促视角策划能力** | 促前规划 + 促中监控·AB 调优·**自动止损** + 巡检自动发现并修复；**人从执行者变审核者** |
| **自增长** | 知识散落个人，跨大促无法复用 | **三层知识库**（专家/案例/样本）+ 促后复盘归因自动反哺 |

## 二、整车架构：一个大脑、七个域控、三块底盘、一个车架号

- **主 Agent（统一控制面）**：ReAct 决策循环（观察—推理—行动）+ **Plan Mode**（长周期目标拆成可追踪、可暂停、可恢复的计划）+ 长期记忆（跨会话、跨大促可复用的事实与经验）。**"三个分别负责当前决策、过程控制、经验复用。"**
- **七个领域子 Agent（执行面）**：策划（目标拆解与 ROI/风险评估）、设计（主题包与主 KV）、选品（分国家选品与数据集）、搭建（编排 + 页面质检）、投放（多渠道下发与状态回收）、巡检（渲染/排期/选品/素材一致性 + 修复方案）、复盘（漏斗、归因、经验沉淀）。
- **三大底座**：Harness 与知识（计划、记忆、Hook、权限、恢复、专家知识）、数据与算法（画像/商品行业/大促历史/场域；分国家选品、楼层个性化、效果归因）、Agent 与工具集成（设计/选品/搭建/投放/审批；**人机交互、工具调用、跨团队 Agent 各用合适协议，不用一种 RPC 处理所有交互**）。作者判断："**缺任意一层，系统都只能完成局部自动化。**"
- **促唯一码**：贯穿策划→设计→搭建→投放→回流→复盘，让任务状态、上下文快照、领域产物都挂在同一主键下；并在促码之上派生**稳定的动作幂等标识**，把"同一场促"与"同一次动作"分开。**"主键是控制流、数据流与审计流得以统一的起点。"**

**边界纪律（很硬的一条）**：主 Agent **不直接生产业务实体**——页面、素材、数据集、投放任务都由领域 Agent 生产，主 Agent 只管理调用顺序、前后依赖与结果流转，**以此降低中心节点复杂度与故障影响范围**。

## 三、主 Agent 的状态管理：对话记忆与事实状态分离

这是与天猫国际那篇高度呼应的一条：**可压缩的对话记忆只用来保持交流连贯；Plan、任务状态、权限与幂等信息独立持久化**。好处写得直白——**应用重启后可从最近一次稳定检查点继续执行，无需让模型重读整段会话去猜任务进度**。

## 四、子 Agent 的三条协同原则（比"数量"重要得多）

1. **能力原子化**：一个 Skill 对应一个边界清晰、可独立验证的动作；
2. **领域资产归属清晰**：专业资产由所属领域生产，**主 Agent 不复制第二份事实**；
3. **结果契约化**：每次调用必须返回**结构化状态 + 领域产物引用 + 后续步骤可继续使用的上下文**。

作者的评断值得引用：**"多智能体系统是否成熟，要看编排、契约、状态与知识有没有形成闭环，Agent 数量本身说明不了太多。"**

## 五、Plan Mode：把"运行设计域"落到工具可见性

**动态规划**：请求先被路由为**创建 / 修改 / 投放 / 问答与诊断 / 数据分析**五类意图，再结合大促阶段、领域约束与历史状态生成结构化 Plan（步骤、依赖、所需上下文、执行 Agent、**人工确认点**）。每个步骤有明确状态（待执行/进行中/已完成/失败/等待人工确认）。**当领域结果或环境变化时，只重新规划受影响的后续步骤，保留已确认事实与已完成节点**（Re-planning）。分工一句：**"大模型负责理解意图与拆解任务，计划引擎负责约束执行顺序和推进状态。"**

**ODD（运行设计域）**：按当前阶段、前置依赖、用户权限、风险等级**动态决定本轮可用工具**——"搭建完成前，投放工具不会出现在模型的可选动作中"；必填缺失则转入信息补全；高风险动作标记为需人工确认。核心约束由**工具可见性 + 前置守卫 + 状态机**三者保证，**Prompt 只负责解释当前限制**。这与天猫国际的"状态→工具白名单"是同一手法，但这里多了一层**风险等级**维度。

## 六、Skill 四段契约：感知智能化，执行工程化

每个跨系统动作沉淀为原子 Skill，由四部分组成：**触发语义**（何时用）+ **输入 Schema**（模型要补齐哪些字段）+ **执行模板**（把字段编译成确定性报文）+ **结果 Schema**（向 Plan 返回状态与产物引用）。**模型只参与前两步，真正下发的报文由模板变量替换产生。**

三条共享约束，条条都是踩过坑的产物：

1. **执行模板不由模型自由改写**；
2. **传给下游的是业务值，知识库内部标识不出现在报文里**；
3. **字段超限或必填缺失时显式失败，不做静默截断和猜测性兜底**。

隐喻一句话收束：**"感知层可以处理复杂环境，线控层必须稳定、可验证。理解可以智能化，执行必须工程化。"**

## 七、HITL：目标不是"有人审"，而是"越审越少"

人工干预只放在**高风险、低置信、不可逆**节点：执行前检查权限/幂等/依赖、下发前确认关键参数、上下文缺失由人补充、上线前保留最终审核。交互层用**结构化确认卡**展示关键假设、参数差异与影响范围，用户可局部修改后继续。

**收敛机制才是关键**：首次出现且无法由规则或上游事实推导的信息，系统主动追问并**把确认结果回写知识库**；重复性确认**转化为规则或默认策略**；持续关注**人工介入率、人工改写率、升级原因**。判据一句话：**"只有人工干预随知识覆盖率提升而逐步减少，系统才能从'自动化操作界面'演进为具备自主性的 Agent。"**——这条把 HITL 从"兜底"改造成了"**知识采集入口**"。

## 八、促中：受控闭环与"故障语义三分"

纠偏闭环是 **观察 → 诊断 → 实验 → 执行**：巡检先产出**可复核证据**，诊断识别异常类型与影响范围，可验证方案先进实验或灰度，满足安全护栏后才扩大，**未达预期自动回滚并保留完整实验记录**。是否自动执行由三维度决定：**置信度、影响范围、可逆性**——高置信·低影响·可逆可自动；低置信或高影响进 HITL。

**"没拿到结果"≠"执行失败"**——可能是尚未受理、已受理未回传、远端异常、或本地查询暂不可用。系统在补偿设计里区分这些状态，并对重试次数、触发时机、并发范围设明确约束；**对有副作用的动作，优先依据可查询的结构化状态判断，无法确认则挂起转人工**。理由写得很实际：**"重复下发一次的代价远高于晚一点完成，所以我们不用激进重试去换取表面上的完成率。"**

**统一状态模型**：把各领域执行结果映射为统一任务状态、按促码聚合到同一视图，主 Agent 据此判断"哪些完成、哪些被拒、哪些仍在等待，下一步应补偿、追问还是人工介入"；**同步/异步、回调/轮询的差异全部收敛在适配层**。

**A2A 契约三条**：能力单入口暴露（渠道/场景分流由领域 Agent 内部确定）、请求带稳定幂等标识（重试不产生第二份业务实体）、同步受理与异步完成都映射到统一状态机。还有一条调用纪律：**主 Agent 调度相邻领域 Agent，不越过对方的路由、权限与知识层直接调末端系统**——多一跳，但保留了治理能力与独立演进空间。

## 九、促后：决策轨迹、Context 工程、长期记忆

**决策轨迹**：每次执行保存必要过程快照——**输入、结构化上下文、知识命中版本、计划状态、执行结果**。可以回看"Agent 在哪个时点看到了什么、选了哪条路、由谁确认并最终下发"。作者的因果链很清晰：**过程可解释 → 结果可归因 → 归因可信 → 经验才值得复用**。

**Context 工程**三件事：
- **按来源分类**：上游节点产出的事实数据 / 需运营维护的领域知识 / 可由确定性规则推导的系统信息——三类信息的进入方式、更新、校验、失效策略各不相同；
- **多维寻址**：`渠道 × 链路 × 促类型 × 国家（组）`，按 **国家 → 国家组 → 促类型 → 全局兜底** 逐级匹配；
- **装配与治理**：只按当前计划步骤加载必要信息，带上**来源、版本、优先级**；知识库有实例化/修改/审核/发布/回滚全生命周期；**任务快照 = 最小可回放单元**；下游统一从唯一事实源读取，看板只做聚合展示。

结论一句：**"Context 从普通参考资料升级为可寻址、可组合、可评估、可审计的运行时资产。"**

**长期记忆的三分**：专家规则 → 语义知识库；成功与失败案例 → 案例库；可复用参数与方案 → 样本库。**每类记忆都保留适用条件、验证证据与风险边界**；正向经验抽象为可复用策略，负向结论转成**失败模式与安全护栏**，尚无定论的问题进**后续实验队列**。当这些资产能在下一场促的规划阶段被主动检索、评估、引用，"执行—复盘—学习—再执行"才闭环。

## 十、四条工程原则（多场大促收敛出来的）

1. **结构化护栏**：运行阶段、工具可见性、权限校验、依赖关系、人工确认**都应由系统结构保证**——"模型偶尔忽略一条 Prompt 规则，代价可能就是一次错误投放"；
2. **确定性优先**：状态码、任务结果、固定规则**一律查结构化接口**，"不让模型从对话记录里推断"；
3. **Context 治理四件套**：**主键**（跨域对齐）、**来源**（评估可信度）、**版本**（追踪变更）、**快照**（还原决策现场）——"缺了主键无法跨域对齐，缺了快照就回答不了'当时为什么这样做'"；
4. **HITL 收敛**：固定审批流只是起点，目标是让人工干预率随知识覆盖提升而下降。

## 十一、L3 → L4 的三个待建方向

1. **促中主动运营**：从"执行既定计划"到"基于实时变化提出并验证调整方案"；
2. **促后效果学习**：打通结果归因与策略沉淀，让规划在模板与静态知识之外能引用**经过验证的历史经验**；
3. **运行域持续扩展**：在安全/稳定/可解释前提下扩大可自治的标准场景，非标准或高风险场景保留明确的人机协同边界。

## 深度分析

### 自动驾驶隐喻在这里不是修辞，是**责任分配表**

多数"分级"文章停在能力描述，这篇每一级都写了**人的角色**：L1/L2 操作者、L3 安全员、L4 审核者与策略制定者。责任一旦写明，工程要求就自动落地——L3 意味着"系统必须随时能交出控制权"，于是有了 ODD、前置守卫、HITL 卡片；L4 意味着"系统必须能解释自己"，于是有了决策轨迹与快照。**先定责任，再定能力，顺序反了就会做出"能跑但没人敢用"的系统。**

### "主 Agent 不生产业务实体"是一条被低估的架构纪律

它同时解决了三个问题：中心节点复杂度（不搬运大对象）、故障影响范围（主 Agent 挂了不丢产物）、**事实归属**（每个领域资产只有一个生产者，杜绝"两份真相"）。这与天猫国际"对话是入口，Task 才是业务事实"是同一条原则的两种切法——**都在把"谁拥有事实"从模型手里拿走**。

### Skill 四段契约，本质是给"自然语言 → 确定性调用"修了一道闸

模型只做"触发判定"与"字段填充"，**报文由模板编译**，且三条禁止（不许改模板、不许传内部标识、不许静默兜底）把常见事故一次性堵死。妙处在于它承认了模型的强项与弱项：**理解是概率的，执行必须是确定的**。这也解释了为什么"给模型一套 API 让它自己拼参数"在跨系统场景里注定不稳——**缺的不是模型能力，是那道闸。**

### 把 HITL 当知识采集入口，是"自主性"能增长的原因

固定审批流的宿命是"永远审"；这里把每次人工确认**回写知识库**、把重复确认**转成规则**，并监测介入率/改写率/升级原因。于是人工干预成了**一次性成本**而不是**永久开销**。这条思路可以推广：**任何需要人兜底的环节，都应该顺手产出能让下次不需要兜底的数据。**

### "故障语义三分"是异步系统最容易踩的坑

未受理 / 已受理未回传 / 远端异常 / 本地查询不可用——四种情况被压成一个"失败"，就会诱发盲目重试，而在投放这类有副作用的动作里，**重试的期望损失远大于延迟**。所以它的原则是"**以可查询的结构化状态为准，无法确认就挂起**"。这与天猫国际"异步副作用工具受理后禁止机械重提"、腾讯"隐性错误率"是同一族纪律：**宁可慢，不可重。**

### 三层知识库 + 适用条件/证据/风险边界，是对"经验复用"的祛魅

多数知识库只存"结论"，而这里的每类记忆都要**同时保留适用条件、验证证据、风险边界**。理由很明显：一条在大促 A 有效的策略，换国家/换品类可能反向。**没有适用条件的经验不是资产，是负债。**

## 实践启示

1. **先写"人在哪一步、负什么责"**，再决定技术等级；分级表的每一行都要有"人的角色"这一列。

2. **对话记忆与事实状态必须分家**：Plan/任务状态/权限/幂等独立持久化，重启从检查点续跑，不让模型靠重读会话猜进度。

3. **主 Agent 只规划调度，不生产业务实体**；每个领域资产只允许一个生产者，杜绝第二份真相。

4. **子 Agent 用契约而非约定**：结构化状态 + 产物引用 + 可继续使用的上下文，三样缺一不算交付。

5. **ODD 落到工具可见性**：按阶段/依赖/权限/风险动态裁剪可用工具；Prompt 只解释，不承担约束。

6. **Skill 四段式**（触发语义/输入 Schema/执行模板/结果 Schema），模板禁改、只传业务值、必填缺失显式失败——**不做猜测性兜底**。

7. **HITL 要能收敛**：每次人工确认回写知识、重复确认转规则，并把介入率/改写率/升级原因做成指标。

8. **故障语义拆四态**：未受理/已受理未回传/远端异常/查询不可用；有副作用动作优先查结构化状态，不确定就挂起转人工。

9. **纠偏按三维度放权**：置信度 × 影响范围 × 可逆性；自动执行前先灰度，未达预期自动回滚并留实验记录。

10. **跨团队协作走 A2A，不越域直调**：能力单入口、请求带幂等、同步异步统一状态机。

11. **Context 治理四件套**（主键/来源/版本/快照），装配只加载当前步所需；快照是最小可回放单元。

12. **知识条目必须带适用条件、验证证据、风险边界**，否则不是资产是负债。
