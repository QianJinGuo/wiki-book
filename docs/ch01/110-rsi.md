# 淘宝闪购店装选品的 RSI 系统：把「选法」做成可递归搜索的策略

> 📊 Level ⭐⭐⭐ | 18.0KB

## 业务对象：三个层次的选择，共享一份供给

淘宝闪购店铺装修里，海报挂品、橱窗、精选推荐共同构成进店体验。技术上它接收店铺上下文、商品候选池与装修素材，**输出不是商品列表而是带板块归属与展示顺序的组合**；跨板块共享有限供给，单个板块的最优列表未必是整店最优（一款热销咖啡适合多个板块，但每个位置都展示它，其他商品就失去曝光）。系统因此要分三步判断：单品是否合适 → 商品之间怎么搭配 → 整店组合预期效果。

三个难点决定了必须引入搜索：**跨板块选择相互影响**（容量、视觉匹配、去重约束下比较完整组合）、**经营环境持续变化**（新品/库存/偏好迁移让旧策略失效）、**验证成本有限**（大量候选无法逐一上线，只能离线筛再交线上）。

接入搜索后先撞上两个现象：**权重在变，橱窗里的商品却没变；商品换了，模型评分又几乎不变。** 前者说明参数探索没形成新决策，后者说明评价环节没提供区分信号——这两句话定了整套系统的设计目标：先让策略调整产生可比较的组合，再让模型识别组合差异，最后用真实业务反馈检验方向。

## RSI 的"自我"到底是什么

系统的自我改进对象有两层：**选品策略**（橱窗与推荐的权重、允许调整的组合规则）与**搜索状态**（采样分布、精英档案、步长、算子配比、经验偏置）。第一层改变"如何选商品"，第二层改变"下一次优先尝试什么选法"。作者反复强调边界：更新这些状态仍遵循预设算法与权限边界，**不等同于系统自主改写改进算法**。

Agent Loop 的六个环节被写成一张可核对的表：**观察**（数据窗口、基线策略、候选档案、评分趋势与历史经验）→ **决策**（选父代、变异算子、步长、允许调整的参数）→ **执行**（候选策略应用于选品器，落实容量/固定挂品/去重）→ **评价**（构造品槽特征，同一模型与数据口径下算适应度）→ **更新**（精英档案、搜索分布、调度状态、经验记录）→ **业务验证**（冻结候选、线上 AB、核对发布版本与效果）。判断是否算 RSI 的标准不是"大模型有没有参与"，而是**反馈是否改变了后续候选生成**。

两个时间尺度分工明确：**离线内循环**固定数据窗口与评估器、低成本比较多种选法；**业务外循环**冻结候选做线上实验、把效果证据关联到策略。评估器的训练与结构迭代是独立研发过程，**不属于已自动运行的递归更新环节**。

## 行动空间的三层与规模

**第一层商品组合空间**：橱窗与推荐的可变结果，海报与特型招贴作为固定条件参与约束与去重；仅换板块归属（商品集合相同）也可能产生不同评估输入。教学计算：100 件候选、橱窗 8 件、推荐 20 件、板块内不计顺序且禁止重复 → 约 10¹⁹ 量级组合（作者注明这是数量级示意，不是真实可行解数）。

**第二层策略参数空间**：仅权重部分就有 54 个独立自由度（扣除两个板块的归一化约束），若再开放 10 个幂指数与 2 个 MMR 系数即 **66 个连续自由度**，另加去重规则、种子等；四个品类分别维护策略与搜索状态，**不是所有店铺共享一套固定权重**。

**第三层搜索调度空间**：从哪个历史候选出发、用哪类变异/交叉、多大步长、是否迁移或重启。CMA-ES 按反馈更新采样分布；启用大模型调度时，LLM 只在规则基线上调整**步长倍率、预设算子组合、抑制允许范围内的离散动作**。三层共同的前提是：库存、固定挂品、板块容量与评估器都是外部条件，**改模型架构、造新特征、改写执行代码不在本轮动作空间内**。

## 搜索框架的选择与三条链路

作者比较了 ReAct、AutoResearch 与 Shinka 三种迭代方式，关注"如何记住试过的方案、如何用反馈决定下一步"，最终**借鉴 Shinka 的候选管理与分岛搜索**，把"程序修改"适配成"策略参数调整"：以选品策略为搜索对象、以咖啡/西餐/甜品/饮品为业务分岛、以约束后的整店组合效果为评价目标。这样业务约束留在执行层，每个候选都走同一条选品与评估路径。

运行上分三条链路：**在线选品**（店铺/装修资源/主题/当前策略 → 四板块商品列表）、**日更批量**（已确认策略 + 目标日候选池 → 确定性评分、橱窗与推荐重算、去重替补）、**离线进化/日滚搜索**（数据窗口 + 评估模型 → 候选策略、评估与经验记录）。三条链路通过策略产物连接：搜索提候选、实验与发布定版本、执行链路落地当日商品——**把线上响应成本与离线探索预算解耦**。

## 策略表示与评估模型

选品策略由商品评分（多样品偏好、图片质量等偏好转成数值参数）、多样性选择与 ILP 约束分配组成；在线链路是评分板块 ILP 分配 + 去重，日更批量另有独立执行入口，**三条链路须分别核对，不能统一描述为"全链路 ILP"**。

评估侧的核心问题是**候选区分能力**：早期诊断显示修复调整幅度与评分问题后，测试中的选品变化度从 0 升到 0.61、选品不变的店铺占比从 55% 降到 0%（作者注明这是测试场景恢复策略影响，不是业务收益）。模型侧包含品槽特征表示与**门控专家**设计（Slot Expert 第 0–7 轮自动调参使候选序准 69.82%→70.40%）；换品专项测试用 1,000 个店铺日、3,000 次替换，其中 2,754 次输入实际变化，校准后同分率 7.12%——**单调校准能修数值偏差，但可能把相邻分数映射成同分，校准前后换品同分率必须同时检查**。

## 进化与适应度：日更基线、联合反馈、归因难题

**CMA-ES 分布更新**以适应度排名为依据（取前 k 名更新中心），反馈时把候选实际权重重新转换为对数比值坐标，减小"投影前采样位置与实际执行参数不一致"；再用累积路径更新整体步长与对角方差。基于排名降低了对分数绝对尺度的依赖，**但无法解决大量同分**——所以模型分辨率是优化器生效的前置条件。

**适应度**必须处理"数据日期在变"：整体经营水平下降时，更好的策略也可能拿到比昨天更低的分数，因此引入**同日基线**，并把适应度与预测 P2、线上 AB 效应分别记录；启用动态差分评估时先比较候选与当日静态策略、再融合绝对水平。约束项包含价格带、新品覆盖与预测 P2 相对基线的下降，多样性用被选商品品类分布的归一化熵（前 20 代质量权重 0.80、之后 0.85）。

**联合反馈**（同一评分同时反馈给两个板块）能抓到跨板块效应——咖啡店例子里 A/B 的差别起于橱窗权重却经跨板块去重改变了推荐结果；但带来**归因难题**：各板块接收相同评分、未估计单板块边际贡献、未学习完整协方差，**所以这是工程成本可控下的联合策略搜索，不是对板块交互的完整统计建模**。

## 搜索调控：R1–R7 规则 + 受限 LLM

控制分两层：**生命周期控制**（今天是否启动、是否继续、候选是否适合进实验）与**逐岛调度**（每个品类下一代怎么搜）。作者明确"停止搜索、建议实验、批准发布是三个不同判断"，**逐岛模型输出的自然语言理由不能越过实验或发布门控**。

规则按 R1–R7 优先级检查、首个命中即决策：**R1 退化修复**（距峰值差距/短期下降/持续代数 → 重启分布并扩大探索）、**R2 震荡抑制**（大波动+趋势平坦+档案差异小 → 收缩步长、提高定向搜索）、**R3 早期收敛**（收敛跟踪器确认未进精调 → 提前精调）、**R4 档案停滞**（多代无优选更替 → 清理低效档案、强制探索）、**R5 迁移控制**（岛间排名/收敛/迁移接受 → 请求迁移或保护本岛）、**R6 预热转探索**、**R7 探索转精调**。

LLM 模式只允许输出**结构化参数**（步长倍率、预定义算子模式、可抑制动作），数值区间/枚举/动作白名单在代码里再次校验，**理由只用于审计**；适配器还检查预热阶段、调用间隔、运行内调用预算与服务可用性，不满足条件直接用规则结果，**候选打分不等待 LLM**——模型成本与候选评价次数解耦，LLM 不可用时搜索照常跑。

## 经验库：两种证据、双因子衰减

经验分两类：**离线评估经验**（变异方向、模型评分差、搜索状态——反馈密集但继承评估模型偏差）与**真实 AB 经验**（冻结策略、实验结果、范围与可信度——业务证据更直接但滞后、覆盖有限）。双来源方向汇聚：离线给方向、正向 AB 增加支持、负向或风险结果抑制方向；融合要考虑品类、策略变化、时效与可信度，**不能把不同店铺范围、不同实验协议下的反馈当可互换标签**。

置信度是**代际 × 幅度双因子衰减**（陈旧经验减弱 + 伴随大幅评分波动的经验降权），作者明确它是搜索启发式的可信度权重，**不是统计意义上的因果置信度，也不能代替线上实验**。容量与时效：岛级默认保留 50 条、店级 20 条，常规经验与 AB 经验半衰期分别 20 / 40 代。经验被保存为"板块 → 特征 → 调整量"的结构化方向，按衰减后权重汇聚为偏置供变异器消费。

## 结果与诊断：负结果也算结论

- **固定预算对照**：CMA-ES 在既定数据与评估条件下获得**更高的平均留出模型评分**——作者据此只支持"局部反馈更新有效"，不推论整套 RSI 更优。
- **一期线上 AB**：8 天有效观测，整套方案 **P2 相对提升 0.34%**；自动回灌与多轮积累仍待联调。
- **四层诊断**：其中"模型实际看到了新商品吗"要求逐维比较特征输入——商品 ID 改变不代表 642 维输入必然改变，特征相同、映射缺失或缺失值回填都可能让替换失去实际差异。
- **档案准入控噪**：普通新候选需同时满足"高于档案末位"与"配对改进置信区间下界大于零"才入档，历史最优另行保护；数据窗口或模型变化后历史分数不可原样复用。
- **负结果被保留**：旧结果里 Shinka 留出增量较高，但坐标下降不能代表完整 AutoResearch、旧评估器特征构造后来被修正、旧缓存缺完整店铺上下文——**三项解释性问题让该对比不能作为结论**。

## 深度分析

### 这套系统真正稀缺的是"可比较"，不是"会搜索"

工程上最难的不是加一个优化器，而是让"策略 → 组合 → 评分"三段可比：权重变了商品必须变（否则搜索是空转）、商品变了评分必须变（否则评价没信号）、评分变了要能归因（否则不知该往哪调）。作者用两道诊断把这条链钉住——选品变化度、换品同分率。**没有这两项，任何"RSI"都可能只是在参数空间里自我感动。**

### 明确"自我"的边界是可信性的前提

文章反复划界：改进只发生在策略与搜索状态层，评估器固定、更新规则预设、不自主改写算法；LLM 只能给结构化参数且理由不参与执行。这些限制看似削弱了"RSI"的成色，实际是把可验证性做出来了——**边界清楚，才能说清一次改进归因于哪一层**。对比许多"自进化"叙事把模型、提示、流程、评估混在一起，这里的克制反而让结论站得住。

### 同日基线解决的是"策略好"与"生意差"的混淆

经营大盘波动会让绝对分数失去可比性：一个更好的策略在淡日可能拿到比昨天更低的分数。引入同日基线（候选 vs 当日静态策略）把"相对改进"从"绝对水平"里剥出来，这与 A/B 的对照思想同源——**没有基线的分数只是天气**。

### 经验衰减是"记忆卫生"，不是统计置信度

双因子衰减（代际 × 幅度）刻画的其实是"这条经验还剩多少参考价值"，而不是"它有多大概率正确"。作者主动声明它不是因果置信度，这一点很关键：一旦把启发式权重当成统计证据，团队就会用它替代实验，最终得到一套自洽但与业务脱节的搜索。

### 负结果被完整保留，是这篇文章最像工程报告的地方

CMA-ES 在固定预算下更好、Shinka 对照因三项解释性问题不能作结论、AB 只有 0.34% 且仅 8 天、单种子结论不外推——这些"不够漂亮"的结论被原样写出，并配了各自的适用边界。对读者而言，可复用的是**验证设计**（同预算对照、留出评价、同日基线、置信区间准入、四层诊断），而不是某个数字。

## 实践启示

1. **先证明"改参数会改结果"**：选品变化度与换品同分率是搜索有效性的入场券，不是验收项。

2. **把"自我"限定在可验证层**：策略 + 搜索状态可改，评估器与更新规则固定，LLM 只输出结构化参数。

3. **同日基线 + 留出评价 + 线上 AB 三层分开**：分别回答"相对改进""泛化""业务收益"，不能相互替代。

4. **档案准入用置信区间控噪**：高于末位 + 配对改进下界 > 0 双条件，避免噪声反复替换。

5. **经验要能消费才叫经验**：结构化成"板块→特征→调整量"、带衰减与容量上限，否则只是日志。

6. **调度规则优先、LLM 兜底可选**：R1–R7 覆盖退化/震荡/早收敛/停滞/迁移/阶段切换，LLM 失败即回落。

7. **把负结果与解释性问题写进报告**：对照实验的结论强度取决于评估器与缓存是否可比。
