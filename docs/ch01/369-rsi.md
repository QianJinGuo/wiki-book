# RSI 的五种改进对象：求解栈 / 探索策略 / 模型权重 / 优化器代码 / 团队配置

> 📊 Level ⭐⭐⭐⭐ | 17.2KB

## 为什么这个分类有用

"递归自我改进"常被当成一个整体概念讨论，但读五篇 2026 年 9–10 月的论文会发现：**它们改进的根本不是同一个东西**。Meta^n 改求解栈，Dream-RSI 改探索策略，OPST 改模型权重，OPAL 改优化器代码，EAT 改团队配置。把它们并排放，才能回答工程上真正要问的问题——**你想让系统改哪一层？驱动这一层的东西是否需要固定？经验存在哪里？反馈从哪来？**

| 论文 | 改进对象 | 改进的驱动者 | 经验存哪里 | 反馈从哪来 |
|---|---|---|---|---|
| Meta^n | 求解栈（逐层包裹的预处理与函数库） | 固定的元操作 Ω + 进化档案库 | 执行记录与代码栈 | 基准评分 |
| Dream-RSI | 探索策略代码 | 探索策略开发智能体 + 回放模拟器池 | 发现树（可回放） | 回放目标（帕累托超体积减并行惩罚） |
| OPST | 模型权重 | 以特权信息为条件的 EMA 教师 | 跨轮继承的权重与教师 | 自生成数据上的蒸馏损失 |
| OPAL | 优化器代码（更新规则、日程、精度） | 循环中的智能体 | `analysis.py` 的探针与运行历史 | 训练动态本身（损失、梯度统计） |
| EAT | 团队配置（角色、协作、知识管理） | 监督者智能体 | 跨团队持久化文件系统 | 团队进度与行为模式 |

## Meta^n：把"改进改进者"从改自己改为改输入

**动机**：让系统改写自己的改进机制会带来不稳定，而冻结整个驱动层又限制改进深度。Meta^n 的解法是把递归**转向输入一侧**——固定一个从不改变的元操作 Ω，让它反复读取执行记录与已有代码，为求解器**逐层生成指导文字与辅助函数库**；层数不预先指定，由收敛条件决定。改进的是求解器外围的策略与工具，**不训练模型权重**。

**方法要点**：每层产出两类东西——针对输入任务的**指导文字**（如建议采用什么分析策略）与**辅助函数库**（如匹配罪名标签的 Python 函数，供求解器脚本调用）；停止条件有三种：Ω 不再输出代码、连续若干层未达改进阈值、达到层数上限。两种搜索模式：**线性**（沿当前链一直加层）与**进化**（维护多条候选链的档案库，优先但不只选高分链作父链，每条父链可生成多个新层，弱任务还可参考其他链的优秀记录）。

**关键数据**（明尼苏达大学 + 首尔国立大学）：

- **ARC-AGI-2 的"零与三百三十一"**：该基准被设计为无法靠精炼已有技能得分。两个基线几乎不动（OpenEvolve **0.003**、Gödel Agent **0.054**），Meta^n 最佳单链也只有 **0.123**，但完整元层栈在 GPT-5.2 基座上达到 **0.331**——**增益来自元层级而非更好的对象级搜索**。
- **总体领先**：GPT-5.2 上 CO-Bench 档案库最优 **0.870**（OpenEvolve 0.702、Gödel 0.527）、AlphaEvolve Math **0.917**（0.726 / 0.674）；**优势在失败方式最多的基准上最大**。
- **递归本身值多少**：去掉递归只留一层，Gemma 的 CO-Bench 从 0.845 降到 0.714（差 **0.131**）、GPT-5.2 差 0.080、AlphaEvolve Math 差 0.158，**底层求解器越弱差距越大**。组件分解：递归增益约 **72%** 来自层间传递的上下文字符串、约 **15%** 来自可调用代码库，其余来自搜索机制本身。
- **涌现的层角色**：无提示词规定角色，但对 596 次 Ω 输出做双评分者标注（只计一致者，Cohen's κ 平均 **0.59**）后发现——**回滚类角色在第 2 层严格为零、第 3 层才出现（代码基底占 55%）**（修正性角色要等"有东西可修正"）；战术原语第 3 层达峰 45%、第 5 层衰减到 17%，让位给专用函数库；纯提示词基底上提示工程每层都占主导，是代码基底的镜像。
- **差距来自结构而非算力**：Gödel Agent 把预算提 5×/10×，得分只从 0.502 升到 0.615/0.628，仍远低于 0.870；token 预算对齐后 Meta^n 仍领先；CO-Bench 上 Meta^n 的候选评估次数约为 OpenEvolve 的 **1/13（29 对 378）**。
- **不划算的场合**：AlgoTune 的种子脚本已把内核合约要求用满，Ω 的额外上下文反而**过度约束**（智能体式变体在该基准低于单次调用变体）；SWE-Bench 上种子太强，档案库最优就是**第 0 代候选**，Ω 从未触发。作者结论：**Ω 的价值随"种子到上限的空间"与"失败方式的多样性"同步增长**。

## Dream-RSI：把历史发现过程变成可回放的模拟器

**核心思路**：把真实搜索留下的历史变成一个**可回放的模拟器**，先在回放里低成本比较并改写探索策略（决定继续改进哪个方案、何时另开路线、如何并行、何时停止），再把选出的策略用于下一轮真实搜索。**改的是搜索规则而不是模型权重**。

五个角色分工清楚：**发现智能体**（读工作区与历史、生成新候选）→ **评估器**（评真实候选、返回得分）→ **探索策略**（一段可执行代码，决定从哪些位置继续、并行几次、何时停；不负责写具体实现）→ **探索策略开发智能体**（离线看回放结果、改写策略代码）→ **回放模拟器**（由真实搜索历史构成，按候选策略的选择逐步返回已记录结果）。

效果：智能体运行框架（harness）优化任务上，Terminal-Bench 2.1 从种子框架的 **0.7247 升到 0.8090**（Google、马里兰大学、Google DeepMind、弗吉尼亚大学）。**回放目标 = 帕累托超体积减并行惩罚**，即奖励"更好的前沿"同时惩罚"靠堆并行换分"。

## OPST：不用人工题和标准答案的后训练

**动机**：后训练通常依赖人工题与标准答案。OPST 让模型**按主题自己生成题目、解题理由与候选答案**，经**两级筛选**后用于训练——只知道题目的学生，去匹配**额外看到理由与候选答案的同源教师**的逐 token 预测分布；学生权重更新后，教师权重再按**移动平均**跟随学生。

效果：E2B 无思考模式下 MMLU 从 **37.5 提到 47.7（+10.2 个百分点）**（Google、乌尔姆大学）。注意其反馈性质：**用模型重答检查自身一致性，并非真实答案验证**。

## OPAL：在一次训练内部改写优化器

**动机**：训练前往往不知道合适的优化配方。OPAL 在目标模型的**一次训练内部**接入一个预训练智能体：它读取**损失、梯度等训练统计**，改写负责观察与参数更新的两段程序（`analysis.py` 与 `updater.py`），使优化方法随这次训练的实际情况变化——**闭环发生在同一次训练内**。

效果：在语言建模与图像生成的设置中多次达到或超过所比较的固定优化配方；**LightningDiT-XL/1 有引导 FID-50K 从 2.18 降至 1.83**（麻省理工学院）。代价是**反应式决策增加复现难度**。

## EAT：让监督者智能体重组团队

**思路**：多个编码智能体**共同优化同一个程序**；监督者智能体根据进展**重新安排成员职责、协作方式与经验交接**，团队配置逐版演化，代码与记录**跨版本持久化共享**。

效果：在控制推理预算的四项 GPU 内核任务上均优于单个 Claude Code 智能体；增加预算后，**MLA 解码内核相对生产版 FlashInfer 的平均加速比约 1.2 倍**；对已手工调优的 Flash-KMeans 仍取得 **1.71×** 加速比（加州大学伯克利分校）。

## 跨论文三点观察

**① 固定的驱动机制与可变的改进对象并存。** Meta^n 明确论证"改写改进者本身会带来不稳定、冻结驱动层又限制深度"，于是把递归转向输入侧；Dream-RSI、OPST、EAT 同样各保留一个固定设计（发现智能体与评估器 / "教师与学生同源、不引入更强外部模型" / 监督者提示）；OPAL 的智能体也是预训练模型，但它可改写训练中的 updater.py。**共同模式：让被改的部分可变，让驱动改进的部分冻结**——可复现性与递归深度之间的那条线，各篇画在不同位置。

**② 反馈的可信度与适用范围各不相同。** OPST 用模型重答检查一致性（不是真实答案验证）；Dream-RSI 回放的是**评估器曾给过的分数**，覆盖不到新分支；Meta^n 依赖任务评分器，档案库逐题择优也**不等于单链表现**。**这些信号能回答的问题不一样**——把"能涨分"当成"改进可信"，是这一领域最常见的误读。

**③ "没有调过配方的场合"是共同主战场。** OPAL 直接以此为选题（新语言、新架构、图像生成）；EAT 的 MLA/GDN/G+AR 起点都是朴素参考实现；Dream-RSI 的 Lasso 与 harness 任务同样没有现成配方。反过来，OPAL 与 Meta^n 都报告了"配方已精调"或"种子已很强"时收益缩水（OPAL 在 modded-nanogpt 原赛道、Meta^n 在 SWE-Bench 与 AlgoTune），**但 EAT 对已手调的 Flash-KMeans 仍有 1.71×**——作者据此谨慎表述：起始方案质量与可改进空间可能影响收益，但**这些结果不足以证明两者成正比**。

## 深度分析

### "递归"不是一个东西，五个对象对应五种失效模式

改求解栈的风险是**过拟合到单一任务家族**（Meta^n 在 AlgoTune 上被 Ω 过度约束就是证据）；改探索策略的风险是**回放与真实分布不一致**（回放覆盖不到新分支）；改权重的风险是**自我确认**（没有真实答案，只有同源教师的一致性）；改优化器的风险是**不可复现**（反应式决策难以重跑）；改团队的风险是**协作开销吃掉收益**（EAT 要用监督者压住重组成本）。**选哪种 RSI，等于选哪种失效模式去管理。**

### 冻结驱动层是这一代 RSI 的共同工程答案

五篇没有一篇让系统"改自己的改进算法"。它们都**冻结一个驱动者**（Ω、固定发现 Agent 与评估器、同源教师、预训练智能体、监督者提示），只让**下游对象**变化。这与"递归自我改进 = 改元层"的直觉相反，但从可复现性看是必然：**元层一变，历史结果就失去可比性**。真正被递归的是"经验向下一层传递"这条链，而不是"改进规则本身改写自己"。

### 收益与"可改进空间"强相关，这决定了推广边界

Meta^n 在种子已经很强的 SWE-Bench 上 Ω 从不触发、在 AlgoTune 上过度约束；OPAL 在原赛道收益缩水；而 EAT 在已调优内核上仍有 1.71×。合起来看：**RSI 更像"把粗糙起点推向良好"的放大器，而不是"把良好推向极致"的优化器**。这对落地判断很关键——先问起点离上限有多远，再决定是否上 RSI。

### 归档与回放，是这批系统的"经验基础设施"

Meta^n 的档案库、Dream-RSI 的回放池、OPST 的跨轮权重与教师、OPAL 的运行历史、EAT 的跨团队文件系统——**五个系统都有明确的"经验存放在哪"的答案**，且都不是"塞进上下文"。这与 agent 记忆系统的结论一致：**能被检索、比较、回放的经验才有复用价值，纯文本累积只会稀释注意力**。

### 二手解读的价值与风险

本文是个人精读号的联合解读，**数字与结论都来自原论文**，作者自己的贡献是那张横切表和三点观察——**而这恰恰是单篇论文不会给的东西**。风险也在此：横切表的归因（"改进对象/驱动者/经验存放/反馈来源"四列）是作者的分析框架，**不是论文作者们的共识**；引用具体数字时应回到原论文核对口径（尤其"档案库最优 vs 单链"、"平均 vs 单种子"这类差别）。

## 实践启示

1. **先选改进对象，再谈 RSI**：求解栈 / 探索策略 / 权重 / 优化器 / 团队，五者成本、可复现性、失效模式完全不同。

2. **冻结驱动者**：只让下游对象变化，否则历史结果失去可比性、复现无从谈起。

3. **把"经验存哪里"当成一等设计**：档案库 / 回放池 / 权重与教师 / 运行历史 / 共享文件系统，都要能检索、比较、回放。

4. **审反馈的性质**：一致性检查 ≠ 真实答案验证；回放分数覆盖不到新分支；逐题择优 ≠ 单链表现。

5. **判断起点离上限多远**：种子已精调时 RSI 收益常缩水；"没有配方"的场合才是主战场。

6. **算结构而不是算力**：Gödel 加 5×/10× 预算仍追不上 Meta^n；Meta^n 用 1/13 的候选评估次数取胜。

7. **可复现性是隐性成本**：反应式改写（OPAL 类）会显著提高复现难度，需要在设计时预留记录与重跑能力。

8. **谨慎对待横切归因**：分类框架是分析工具，不是论文共识；引用数字回原论文核口径。
