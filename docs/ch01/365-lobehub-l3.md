# 把噪音关进管道：LobeHub 的 L3 组织形态

> 📊 Level ⭐⭐⭐⭐ | 18.0KB

## 一句话结论

新智元用一份「AI 编辑部」日报做了 24 小时实测，验证 LobeHub（GitHub **8.4 万星**）那套组织形态：**主管 Agent 派活收稿 + 两个异构模型互相审稿 + 云端跑一整夜 + 早上人只看验收报告**。最有价值的不是"全自动"，而是三个**降噪与验收**的具体设计：**执行 Agent 只向主管汇报**、**每个人配一个 Personal Agent 过滤信息**、**Acceptance 把需求拆成可直接观察的检查项**。作者自己的结论也很克制：**"人只看结果"**，但普通用户**"中间还隔着几道门槛"**。

## 一、由头：DeepSeek 的那句判断

"10 月 31 日，DeepSeek Harness 团队发表长文《Super-agent 设计探索》"——文章讨论的困境是"**Agent 越用越多，人反而越忙碌**"；按 DeepSeek 的观察，"一个人通常只能同时跟进 **3 到 5 个 Agent 会话**"，于是有了那句判断：

> **"单任务的上限取决于模型能力，多任务的上限取决于人的注意力。"**

新智元抓住的另一句是"**相似的设计约束会导出相似的架构选择**"，于是去找已经上线的同类产品，找到了 LobeHub：**8.4 万星**，"过去大半年一直拿自己做实验，用自己开发的 Agent 平台组织自己的研发"；创始人文彬称团队"**三个月没在本地启动过开发服务器**，看完 Agent 交来的验收报告就直接合并，**开发速度提升了 3 到 5 倍**"。

## 二、实测设计：三人编辑部与"辩论到收敛"

编辑部三个成员：**主管 Agent**（派活、收稿）、**Claude**（主笔：搜集素材、列大纲、写正文）、**ChatGPT**（审稿：指出逻辑与视角漏洞 + 生封面配图）。

读者画像写得很具体："一位关注 Agent、基模、AI 商业化进展等话题的科技编辑，每天通勤时花五到八分钟，读完当天最值得关注的**五到八件事**，每条新闻都要有**一手来源和一两句判断**。"

**最值得抄的是"判断权归属"的设计**：

> "我们**刻意把判断权留给主笔 Claude**。GPT 可以提意见，Claude 也可以拒绝，只要讲得出理由，双方来回讨论，**直到 GPT 表示无重大异议，或者满四轮为止**。"

**六步流程，注意第 2 步与第 4 步的差别**：

1. Claude 搜集素材、撰写大纲 → ChatGPT 提修改意见；
2. Claude 参考意见、**自主决定**是否改大纲或补素材 → 再交给 ChatGPT，**二者辩论到收敛为统一意见**；
3. Claude 撰写初稿；
4. ChatGPT 给修改意见，**"这次不用辩论了，因为文字的可读性这块，Claude 比 GPT 强太多了"**，但撰稿思路可以帮忙补视角；
5. Claude 修改完毕后交给 ChatGPT，在可插图处（含封面）调用**GPT-Image-2.5-Sunburst**；
6. 交付稿件。

**这个"分级授权"很聪明**：在**思路层**允许对等辩论（因为需要不同视角），在**文字层**直接让主笔定稿（因为能力差距明确）。**不是所有环节都该民主。**

## 三、噪音治理：LobeHub 团队的三步演进

| 阶段 | 做法 | 问题/收益 |
|---|---|---|
| 早期 | **执行 Agent 直接在群里发言** | "几个 Agent 轮番汇报，**群里很快全是噪音**" |
| 第一步 | **执行 Agent 只向主管汇报，由主管统一对外** | 收敛信息出口 |
| 第二步 | **每个人配一个 Personal Agent 过滤信息**，"人只听自己的 Personal Agent，活由各个项目的主管 Agent 去派" | 把"人"从多路信息中解放 |

**主管 Agent 叫 Nasa**，"负责查看任务看板、分派工作和汇报进度"。

**主动响应实例（全篇最有画面感的一段）**："10 月 23 日晚上 8 点 24 分，创始人文彬在群里看到一张训练详情页的截图，随口评价'这个 UI 一眼看上去还是太 vibe 了，得想想怎么 refine'，发图的同事随后去吃饭，**55 分钟里没有人跟进**。9 点 19 分，一个**设计 Agent 在巡查频道时判断这件事和自己有关，在没有被点名的情况下接手**，指出页面上的**进度信息重复了三遍、框里套着框、最显眼的位置却放着空值**，当晚 11 点 52 分交出了改前改后的对比稿。"

作者的对照判断："DeepSeek 设想的主动响应，也是**先用规则过滤、再由模型判断是否介入**，两者的思路非常接近。"

## 四、深夜执行：300 秒限制逼出来的架构

**具体到什么分钟**："10 月 31 日凌晨 4 点 04 分，执行 Agent **Dario** 在 **PR #21852** 下回复了 **OpenAI Codex 审查机器人**的意见。这段代码来自主管 Nasa 派给它的任务 **T-1149**，Dario **运行了 31 步、耗时 1 小时 56 分**完成编写。接下来的 **18 分钟**里，它修复了四处问题，又针对另一条意见**给出理由，决定保留原来的写法**。"

**架构的成因写得很实在**："早期产品部署在 **Vercel** 上，**单次执行最长只有 300 秒**，团队便把 Agent 的**每一步拆分成一次独立的函数调用，用 Redis 保存中间状态，接力推进上千步的长任务**，工具调用则发往 **AWS 的沙箱或用户自己的电脑**执行。"

> "**Agent 察觉不到自己的思考和操作发生在不同的地方**，这和 DeepSeek 文中的'**计算、状态与环境分离**'属于同一个方向，如今每天稳定承载**几万次 Agent 执行**。"

**这是"约束塑造架构"的典型样本**：不是因为想到了分离才分离，而是 300 秒硬顶逼出来的——**限制反而成了可扩展性的来源**。

## 五、Acceptance：把"验收"做成可观察的检查项

> "Agent 交付之前，**先把需求拆成可以直接观察的检查项，到真实的产品里逐项运行，配上截图、录屏和日志**，人看报告决定通过还是打回，**已经通过的部分不用返工**。"

理由一句就够："**代码测试能证明程序可以运行，但还有很多细节需要像真实用户一样真正使用一遍才能发现。**"

两个闭环实例：

- **PR #21852**："最后也只等来一次人类操作，11 月 1 日中午，文彬按下了合并按钮，任务完成闭环"；
- **v2.2.21 发版**（10 月 29 日）："Agent 继续跟进各平台构建，晚上 8 点 26 分发现**桌面稳定版构建失败**，重新运行仍未通过，便**定位到一处依赖版本冲突，直接开出修复用的 PR #21910，只需请人点一个认可**。"

## 六、第一版日报的失败：一次"只看结果"的纠正

"文字部分结论看起来严谨性挺强，但**配图不明所以，标准的'美丽垃圾'**。"作者随即用语音输入给出一段极长的修改意见（要求按新闻利好利空把创始人肖像做夸张的艺术化处理），"我的 Agent 主管说，**是他的锅，他改**"。

然后是本篇最有态度的一句：

> "**我们人类用户只看结果，懒得点开弄清楚究竟是如何犯了这样愚蠢的错误，我们只需要表达 Yes or No。**"

"**人只看结果，正是 LobeHub 团队现在的工作方式。**"

第二天："Agent 终于记住了我们究竟想看到怎样的 AI 新闻……**其他部分也没有被不小心顺手改掉**，LobeHub 的 Acceptance 验收工具体现出了它的价值。"

## 七、RSI 的三个层面

"**记住用户的意见，只是 RSI 的第一步。**"（RSI=递归式自我改进，"系统利用自己运行中产生的结果持续改进自己"）

LobeHub 内部在做的三件事，恰好对应三个层面：

| 层面 | 做法 |
|---|---|
| **任务** | "将 Agent 执行时暴露的问题自动收集、归类，再转化成新的改进任务" |
| **运行框架（Harness）** | "让 Agent 自主优化运行时的 Harness，**并通过基准测试验证效果**" |
| **模型** | "探索如何利用真实执行轨迹进行垂直模型后训练" |

"LobeHub 希望把这些环节逐步连接起来，让系统能够利用真实运行中的反馈持续改善自身。"

## 八、L1–L5 分级与自评 L3

> **L1** 问一句答一句的应答工具 · **L2** 只服务个人的助手 · **L3** 人和多个 Agent 在同一现场协作 · **L4** Agent 之间自主接力、人只设定目标和边界 · **L5** 组织在运行中自我演进。

自评很克制：**"他们认为自己的团队处在 L3"**；而"上游项目的 Agent **直接向组件库 lobe-ui 的 Agent 提需求、对方加好组件自动发版再通知上游升级**"这类事，**"已经是 L4 的雏形"**。

## 九、底子与实测复盘

**底子**："从 2023 年开源的 **LobeChat** 起步，**Docker 部署超过 700 万次**"；"DeepSeek 发布爆火的 R1 时，也曾用 LobeChat 演示模型能力"。为什么这条路别人难追："**开源让它拥有现成的分发渠道，模型中立让各家模型都愿意接入，每天几万次执行沉淀下来的数据又能反过来训练模型**"。

**复盘（写得诚实）**："前前后后，我们被迫亲自上手了好几次，大多花在**第一次配置时的授权、额度不够了充值额度**等琐事上，真正和日报内容直接有关的，**只有前一晚交代需求和第二天退回的那一条意见**。" 且"目前实际体验下来，**离 LobeHub 自己团队那种只按一次合并键的状态，普通用户中间还隔着几道门槛**"。

**但价值判断很清楚**："节省下来的，是原本要在多个窗口之间来回切换、转述和比对的精力……**这份人类用户宝贵的精力并没有消失，而是被挪到了交代需求和判断结果这两头，用在了刀刃上**。"

收尾："**今天的 Agent 已经能接过中间的执行，起点的方向和终点的取舍，依然要由人来拿主意。**"

另引 **Gartner**："到 2028 年，**33% 的企业软件将内置 Agentic AI**，而 2024 年这一比例还不到 1%。"

## 深度分析

### 三步噪音治理，是一条可复用的组织演进路径

从"执行 Agent 直接在群里发言"到"只向主管汇报"，再到"每人一个 Personal Agent 过滤"——这三步解决的是同一个问题：**Agent 数量增长后，信息出口必须收敛，且收敛点要跟着人的注意力重新分配**。第一步把 N 对 N 变成 N 对 1；第二步把 1 对 N（人面对多个主管）变成 1 对 1。**这跟腾讯 Siboot 的 Topic 隔离是同一目标的两条路径**：Siboot 靠"切上下文"，LobeHub 靠"切汇报关系"。

### "思路层辩论、文字层定稿"是异构协作的正确粒度

他们没有让两个模型在所有环节都对等辩论，而是**按能力差距分级授权**：思路需要不同视角，所以允许来回四轮；文字可读性差距明确，所以直接由主笔定稿。这比"多 Agent 圆桌"式的浪漫设计务实得多——**异构协作的收益来自差异，成本也来自差异，所以只在差异值钱的地方引入辩论。**

### 300 秒逼出来的架构，说明"约束"是可扩展性的来源

Vercel 单次执行 300 秒上限，逼出"每步一个函数调用 + Redis 存状态 + 上千步接力 + 工具外发到沙箱"。结果是 **Agent 无感**，而系统获得了水平扩展能力。这与支付宝"单次变更 ≤800 行"、MNN"300MB 峰值内存"是同一种工程文化：**先把限制写死，再让架构去适配**——比"先设计理想架构再想办法压缩"更容易落地。

### Acceptance 补的是"代码测试测不到"的那一段

"代码测试能证明程序可以运行，但还有很多细节需要像真实用户一样真正使用一遍才能发现。"这句话点出了一个普遍缺口：**单测验证逻辑，端到端验证链路，但"产品是否真的可用、好看、说得通"只有用一遍才知道**。Acceptance 的做法是把需求翻译成**可直接观察的检查项**（截图、录屏、日志），于是验收从"看代码"变成"看证据"，且"已通过的部分不用返工"——**这直接把返工成本从线性降到增量**。

### "人只看结果"是一种权利，也是一种成本转移

这句话听起来很爽，但要看清它的前提：**Agent 必须能自己定位"为什么错"**。第一版日报配图失败时，主管 Agent 说"是他的锅，他改"——**这句话背后是 Agent 承担了归因责任**。如果 Agent 只会说"我改好了，你再看看"，人就得反复往返，"只看结果"就变成了"反复看结果"。**所以"人只看结果"的前提不是人懒，而是系统能自己闭环。**

### L1–L5 的价值不在分级，而在"用相邻级别的具体事件定义边界"

大多数成熟度模型是自我表扬的工具；这个分级的用处在于它给出了**可判定的例子**：自评 L3 的理由是"人和多个 Agent 在同一现场协作"；说"已是 L4 雏形"的理由是"**上游 Agent 直接向下游 Agent 提需求、对方发版后自动通知升级**"——**一次没有人类中转的跨团队交接**。这种"用事件定义级别"的做法，比任何描述性定义都更能指导判断。

### RSI 三层（任务/Harness/模型），和今天看到的其他家能对上

- **任务层**："问题自动收集归类 → 转成改进任务"，对应支付宝自进化、易点天下 AgentLoop；
- **Harness 层**："Agent 自主优化 Harness + 基准验证"，对应 SkillHone、HarnessPro；
- **模型层**："用真实轨迹做垂直后训练"，对应 MNN 的 SFT Loop Engine。

**三家独立团队都在往同一个三层结构收敛**——这比任何单点方案都更能说明方向。

## 实践启示

1. **收敛信息出口**：Agent 多了以后，先做"只向主管汇报"，再做"每人一个过滤器"。

2. **按能力差距分级授权**：思路层允许辩论（要视角），执行层交给强者定稿（要一致）。

3. **辩论要设收敛条件**：明确"无重大异议"或"满 N 轮"即停，否则两个模型会无限互评。

4. **给主管 Agent 明确三件事**：看板、派活、汇报——它是流程枢纽，不是执行者。

5. **允许"未被点名"的主动接手**：先规则过滤（频道/关键词/归属），再由模型判断是否介入。

6. **把硬约束当架构输入**：300 秒上限 → 拆步 + 外部状态 + 沙箱执行，反而更可扩展。

7. **状态与执行分离**：中间状态存 Redis/外部存储，工具调用发往沙箱或用户机器，Agent 无感。

8. **验收要产出可观察证据**：检查项 + 截图 + 录屏 + 日志，而不是"我看了一遍代码"。

9. **验收通过的部分不返工**：增量验收，把返工成本从线性变增量。

10. **让 Agent 承担归因**：它说"是我的锅"并能定位，人才有资格"只看结果"。

11. **RSI 分三层推进**：任务层（问题→改进任务）、Harness 层（自动优化+基准验证）、模型层（真实轨迹后训练）。

12. **成熟度用事件定义**：不要说"我们在 L3"，要说"哪一次交接已经没有人类中转"。
