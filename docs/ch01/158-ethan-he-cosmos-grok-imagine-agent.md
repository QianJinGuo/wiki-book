## 深度分析

### 缩放定律重排了人才与算力的流动
Ethan He 离开 NVIDIA 的直接动因，是在 Cosmos One 之后确认视频模型同样服从类似语言模型的缩放规律：模型要继续变强就必须扩大训练规模，而一旦进入这个阶段，算力就不再是基础设施，而是研究本身的上限。由此，顶尖研究员的择业逻辑从"谁的课题更好"改写为"谁给更多 GPU、更快迭代、更少资源约束"。他把迭代速度当作训练的第一指标：每天能做多少次迭代决定模型训练快慢，强基础设施与充足算力还为错误留出缓冲、为发现 bug 留出机会；而很多质量提升恰恰不来自新算法，而来自数据管线与训练管线里的小 bug 修复。随着编程模型把"实现新想法"从几周压缩到几小时，实验密度上升，算力反而可能重新成为迭代瓶颈。相关规律参见 [缩放定律](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/scaling-laws.md)。

### 从像素到潜空间：视频模型的训练管线
文章给出一条完整的工程路径。第一步是合成配对：互联网视频天然不与文本相关（山景配"我今天太开心了"式标题），必须用视觉模型为视频加字幕，且标注协议要求详细到"盲人听完能在脑内重构画面"。第二步是训练压缩器/分词器：1000×1000 图像即百万 token，无法直接在像素上训练 Transformer，必须经 VAE 把 patch 映射进潜空间再映射回来。第三步的 diffusion transformer 训练与语言模型几乎同构，只是输入输出换成视觉 token 并附加去噪过程。最反直觉的是"先图像后视频"的顺序约束：扩散模型对语言的理解纯粹来自语言-图像映射，若只训练千万级视频，语言 token 不足以支撑意图理解，因此视频模型必须从图像扩散模型启动。压缩上还存在实时性权衡：8×8×4 的时间压缩省四倍上下文但引入延迟，逐帧压缩换取流式交互；推理侧的少步能力则靠阶梯蒸馏获得——教师模型拟合的是整个互联网的复杂分布，学生只需拟合这个固定的教师，任务更简单（相关技术见 [模型蒸馏与压缩](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/model-distillation-compression.md)）。

### GPU 之外的账单：存储、特征与出口流量
访谈里对成本结构最陡的拆解是：十亿个 5MB 视频即 5PB 存储，VAE 的连续特征占用与视频本体相当，合计几十 PB；AWS 上 5PB 第五档出口流量约 23 万美元，甚至超过存储本身，且每次训练都要重新拉取数据，多次训练成本线性叠加——仅存储与网络两项每月就可能达到数百万美元，GPU 还未计入。推论是：用"GPU 小时×单价"估算视频模型成本会系统性漏掉 I/O 一侧；Cosmos 为此做了大量优化以避免训练被 I/O 限制。这种"token 背后的物理成本"视角与 [上下文经济学](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/context-window-economics.md) 互为补充。

### 视觉智能由语言智能驱动
Ethan 的核心判断是：扩散技术成熟后，视频模型的增益大多来自语言模型而非视频模型本身。机制证据在 Cosmos 架构里：7B 的视频模型配一个更大的 LLM 提示词重写器（Llama/Mixtral），把"一只猫"这类字面指令扩展成极详细的视频描述——视频模型对指令的理解非常字面，没写背景就给白底、没写动作就不动；且仅靠重写、无需联合训练即可显著提升观感。重写器已进化为智能体形态：生成"今日新闻"图像前会先抓取、消化、组织新闻再生成。生产级拐点的判断同样建立在语言侧：视频智能体本质是语言模型把扩散模型当工具调用，并组合 FFmpeg、视频编辑器等传统工具做迭代修改，而不是把所有能力塞进单一生成模型。通往 [世界模型](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/world-models.md) 的第一步也落在上下文问题上：视频延展携带全部历史上下文而非只有最后一帧，参考生视频实现"从历史中选择性取用上下文"；但 5 秒视频约 5-6 万 token，朴素塞入历史会让上下文很快爆炸，Frame Pack 式"越远越压缩"只是启发式，模型自动管理自身上下文才是终局方向。

## 实践启示
1. 选平台先看"每日迭代次数"与算力余量，而非算法口号——迭代带宽决定纠错与发现的速率，管线 bug 修复常常比新算法贡献更大。
2. 视频生成成本核算必须把存储、连续特征、出口流量计入，"GPU 小时×单价"只是下界；I/O 优化应作为一等工程问题而非事后补丁。
3. 生成模型对指令高度字面化，一个更大的 LLM 提示词重写器是性价比极高的增益来源，且不需要与生成模型联合训练。
4. 视频智能体的正确形态是语言模型编排工具箱（扩散模型 + FFmpeg + 编辑器），不要追求单一模型端到端包办生产级质量。
5. 先图像后视频的训练顺序不可跳过：语言理解来自语言-图像映射，图像配对不足则意图理解不成立。
6. 长时程问题的关键是"从历史中选择性取用上下文"而非无限塞历史；同样的上下文自管理需求很快会反向出现在 LLM 侧，值得提前布局。
