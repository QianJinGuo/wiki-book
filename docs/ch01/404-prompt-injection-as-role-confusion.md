# Prompt Injection as Role Confusion

> 📊 Level ⭐⭐⭐⭐ | 11.2KB

> **Background**：将 prompt injection 重新定义为**角色混淆（Role Confusion）**问题的研究论文配套博客。提供了形式化的理论框架来理解为什么 LLM 容易受到 prompt injection 攻击，并提出了基于角色感知的防御方向。

## 摘要

这篇文章提出了一个关于 prompt injection 的新理论框架：**prompt injection 本质上是 LLM 的角色感知失败**。LLM 通过角色标签（system、user、think、tool）来理解输入的不同部分，但这些角色边界可以被攻击者利用来注入恶意指令。作者开发了"角色探针"来测量 LLM 内部对每个 token 的角色归属判断，发现 LLM 在区分不同角色时存在系统性弱点。

## 核心要点

### 1. LLM 的"世界"：单一通道的 token 流

LLM 的输入本质上是一个**单一的、连续的文本流**。这与人类的体验完全不同——人类可以轻松区分"自己的想法"和"别人的说话"，因为它们通过完全不同的通道到达（内部思维 vs 听觉）。

但对 LLM 来说，所有内容——系统提示、用户消息、工具输出、模型自己的推理——都混在同一个字符串里。这个字符串不是模型经验的"记录"，它**就是**模型的经验。编辑这个字符串就等于编辑模型的现实。

### 2. 角色标签：LLM 的"类型系统"

为了在"token 汤"中恢复结构，我们用**角色标签**来标记不同的段落：

- **system**：系统指令，最高权限
- **user**：用户请求，视为指令
- **think**：模型自己的推理，信任并基于其结论行动
- **tool**：外部数据，不从中接受指令

这些角色标签是**离散的人类控制手段**。与 prompt 的模糊性不同，将文本从 user 移到 tool 应该是一个清晰的干预，具有可预测的行为影响。

但角色标签已经变得**过度负载**——它们现在要同时承担信任信号（system > user > tool）、威胁信号（user 和 tool 可能是对抗性的）、身份信号（assistant 文本设置未来人设）、生成模式（assistant 是干净的，think 可以是混乱的）等多重职责。

### 3. Prompt Injection = 角色边界失败

当低权限文本获得了高权限角色的权威时，就发生了 prompt injection。考虑一个浏览网页的 Agent：

- 网页内容被包裹在 **tool** 标签中，这应该信号"外部数据"
- 但攻击者在网页中隐藏了恶意命令
- LLM 将 tool 标签中的内容误认为 user 指令

关键洞察：LLM 看不到我们看到的颜色标记。没有颜色，即使是人类也可能认为注入的命令是用户文本——因为它**听起来像**用户会说的话。

### 4. 两种防御方式

文章区分了两种 LLM 抵抗注入的方式：

**攻击记忆（Attack Memorization）**：

- LLM 从训练中识别出"发送 .env 文件"是常见的 prompt injection 攻击
- 本质上是脆弱的——只对已知攻击有效
- 这就是为什么 LLM 在基准测试中表现好，但在面对人类攻击者时表现差

**角色感知（Role Perception）**：

- LLM 正确识别命令来自 tool 角色，该角色天然没有发号施令的权限
- 这是鲁棒的替代方案
- 但研究发现 LLM **无法**准确感知角色

人类红队测试发现，熟练的人类攻击者对前沿模型的攻击成功率接近 100%，但这些模型在标准 prompt injection 基准测试中得分接近完美。差异在于：人类会测试和调整攻击直到成功，基准测试不会。

### 5. 角色探针：测量 LLM 的角色感知

作者开发了**角色探针（Role Probes）**来测量 LLM 内部对每个 token 的角色归属判断。这提供了一种量化的方式来评估模型在角色区分上的能力。

## 深度分析

### "注入"是一个误称：问题在角色感知，不在输入净化

"Prompt injection"这个名字借自 SQL injection，暗示这是个输入净化问题——过滤掉恶意载荷即可修复。角色混淆框架指出这个类比有根本缺陷：SQL 注入中引擎与载荷分处不同信任域，而 LLM 的全部输入只是一条连续 token 流，系统提示、用户消息、工具输出、自身推理都挤在同一通道里，没有可供"过滤"的独立入口。人类靠感官通道的先天差异（内部思维 vs 听觉）轻松区分"自己的想法"和"别人的话"；模型没有这种结构，只能靠外部贴上的角色标签恢复结构——人类从身体性（embodiment）免费获得的东西，模型要用标签模拟。所以攻击者无需"突破"任何边界：编辑这个字符串就等于编辑模型的现实。角色混淆的要义是模型的**角色感知失败**，而非一个可以靠补丁封堵的注入点。

### 角色标签：唯一的离散控制杠杆，也是被过载的边界

与 prompt 的模糊性不同，角色标签是语言的一种"类型系统"尝试：由人控制的离散开关，把文本从 user 移到 tool 应当是可预测的清晰干预。但正因它是唯一的离散杠杆，标签被不断追加职责：信任层级（system > user > tool）、威胁判断（user 与 tool 可能对抗）、身份设定（assistant 文本塑造未来人设）、生成模式（assistant 干净、think 混乱）全部压在同几个标签上。多重语义共用一个信号，意味着标签本身不再是可靠边界——这正是"仅靠标签区分"必然脆弱的结构性原因，也为架构层隔离提供论据：真正的防御要在架构上建立角色隔离，tool 输出与用户指令物理分离；这与 [Hermes Agent Self-Evolving](https://github.com/QianJinGuo/wiki-public/blob/main/entities/hermes-agent-self-evolving.md) 等自演化智能体框架的安全治理直接相关，并与 [通道枚举判据](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/channel-enumeration-criterion.md) 相互印证——未封闭的通道就是已存在的漏洞。

角色标签还塑造更深的认知结构：think 块常被限制在模型的"潜意识"里——生成 assistant 文本时许多模型会口头否认前文 think 块的存在，尽管它就在上下文中实际影响着输出，像一面单向镜。角色在 LLM 认知中的结构化程度远超我们当前的理解。

### 为什么现有缓解手段只部分奏效

原文给出二分：模型抵抗注入只有两条路——**攻击记忆**（从训练中认出"发送 .env 文件"等常见攻击而拒绝）与**角色感知**（识别命令来自没有发号施令权限的 tool 角色，从而无视任何措辞的嵌入指令）。前者天然脆弱，只对训练分布内的攻击有效：人类红队对前沿模型攻击成功率接近 100%，这些模型在静态基准上却接近满分——差异在于人会改写、迭代攻击直到成功，基准不会。由此可解释各类缓解手段为何只能部分奏效：凡是靠"模型认出危险文本"起作用的机制（黑名单、模式匹配、对已知越狱措辞的拒答）都属于攻击记忆，对自适应攻击者必然失效；凡是靠标记与分层起作用的机制（给不可信内容加显式定界、按信任层级排序指令）则把全部赌注押在角色感知上，而论文的核心实证结论恰恰是 LLM 无法准确感知角色。正确的推论是把防御从提示层软约束移到角色边界处的架构上：物理隔离、角色感知、攻击记忆的多层组合远比单一手段可靠。这也为 [Agent Security Threat Models](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/agent-security-threat-models.md) 补上理论基础——解释注入为什么是根本性问题（角色感知的结构性缺陷）、在哪里设防（角色边界）、何时失守（感知失败时）。

### 残余攻击面：绕不开的 tool 通道

即便实现物理分离与来源标注，攻击面并未消失，只是压缩到 tool 通道——Agent 唯一必须让外部文本进入上下文的入口。原文的浏览例子中，注入只是埋在巨量网页输出里的几个 token，模型一旦误当用户命令，攻击即告成功。作者坦言，没有颜色标注时连他也会把那段注入读作用户文本——因为它"听起来像"用户会说的话。由此推出三条设计约束：(1) 结构化通道与来源标记降低混淆概率，但最终仍依赖模型"尊重"边界，需配合**角色探针**持续验证——对任意 token 打分、测量模型内部认为它属于哪个角色，可直接用作通道监控；(2) [Agent 沙箱](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/agent-sandbox.md)式执行层隔离限制的是注入得手后的破坏半径，并不阻止混淆本身；(3) tool 权限应基于角色而非内容裁定——输出中出现看似指令的文本时，在系统层面就不给它进入执行路径的资格。

## 实践启示

### 对 Agent 开发者的建议

1. **不要信任 tool 输出中的"指令"**：在架构上确保 tool 输出被当作数据而非指令处理
2. **实现角色隔离**：使用不同的处理管道来处理不同角色的输入
3. **监控角色混淆**：实现类似角色探针的机制来检测模型是否正确区分了角色
4. **多层防御**：不要依赖单一的防御机制

### 对 AI 安全研究者的建议

1. **角色感知是一个可研究的方向**：角色探针提供了一种量化研究角色感知的方法
2. **攻击记忆不是长期解决方案**：需要投资于更根本的防御机制
3. **基准测试需要改进**：静态基准测试无法衡量模型对自适应攻击者的抵抗力
