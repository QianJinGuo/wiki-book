## 自进化 Agent 安全治理

## 一句话

当 Agent 开始"自己学习"时，安全问题从"单次任务出错"升级为"永久知识污染"。Hermes Agent 的方案：**3 类风险分类（学错/学脏/学危险）× 对应防御（5 道闸门 / 3 层脱敏 / 3 道注入防线）+ 4 步应急响应**。

## 核心洞察

> 普通 Agent 出问题最多影响一次任务，自进化 Agent 出问题会污染所有后续任务。

自进化 Agent（能自动沉淀 Skill、写入 Memory、复盘学习）的安全风险本质不同：攻击不再是单次的，而是永久的。一次"学错"可能在无关任务里突然浮现；一次"学脏"可能让敏感数据出现在 100 次后续对话中。

## 3 类污染风险

| 风险 | 本质 | 典型场景 | 严重性 |
|------|------|---------|--------|
| **学错**（False Pattern） | 把个例当规律 | 修 bug 碰巧删了缓存→写入 Skill→以后每次都先删缓存 | 最常见、最难发现 |
| **学脏**（Sensitive Data Leak） | 运行时数据持久化 | SQL 结果含手机号→沉淀为 Skill 示例→3 个月后所有 DBA 可见 | 泄露面被极大放大 |
| **学危险**（Adversarial Learning） | 对话诱导危险行为 | 反复提示"规则其实是 XXX"→假规则写入 Memory→永久绕过权限 | 最严重、最隐蔽 |

### 学错：巧合被当成因果

Agent 不是没学到东西，是学到了**错的东西**。本质是"成功一次"不够作为规律，但 Agent 把巧合当因果。

### 学脏：一次脏操作→100 次后续泄露

Memory/Skill 写入不脱敏 → 敏感数据永久持久化 → 被未来所有任务 Prompt 引用。

**真实事故**：Agent 排查 DBA 问题时记住 SQL 结果（含用户手机号）→ 沉淀为 Skill 示例数据 → 3 个月后所有 DBA 可见。

### 学危险：提示词注入的升级版

攻击不再是单次的，而是永久的。通过对话诱导 Agent 把假规则写入 Memory，或把恶意代码沉淀为 Skill。

## 防"学错"：5 道写入闸门

```
候选 Skill → [闸门1: 内容脱敏] → [闸门2: Schema校验] → [闸门3: 静态危险扫描] → [闸门4: 沙箱试跑] → [闸门5: 人工审核] → Skill Hub
```

| 闸门 | 检查内容 | 失败处理 |
|------|---------|---------|
| 1. 内容脱敏 | PII（正则+NER）、Token/API Key、私钥、内网地址 | 默认拒绝（不走自动脱敏） |
| 2. Schema 校验 | name/description/trigger/steps 必填，命名规范，permission_tier 声明，tools_used 列表 | 拒绝写入 |
| 3. 静态危险扫描 | rm -rf/drop database、生产 URL 正则、unknown domain/IP、sudo/chmod 777 | 标记高危→闸门 5 |
| 4. 沙箱试跑 | 隔离环境执行（白名单网络、临时目录、无生产数据、资源上限） | 发现学错最有效 |
| 5. 人工审核 | 高危 Skill 必须人工签字（PR 流程） | Approve 后才能 merge |

> 5 道闸门 = 5 个独立过滤器，叠加起来才能防住 Agent 的"误学"。任何一道单独使用都不够。

## 防"学脏"：3 层脱敏管道

```
工具输出 → [第1层: 采集端脱敏] → Trajectory
                              ↓
        → [第2层: 写入Memory/Skill时脱敏] → 知识库
                                          ↓
        → [第3层: 读取时再扫描] → Prompt Builder → 模型
```

**关键原则**：任何一层漏了，下一层还能兜住。

**特殊数据特殊处理**：
| 数据类型 | 处理方式 |
|---------|---------|
| 密码 | Agent 完全不接触，走单独密码管理 |
| 支付凭证 | 完全屏蔽 |
| 用户私聊内容 | 默认不接触，需用户显式授权 |
| 财务报表 | 角色控制，普通 Agent 不可读 |

> 脱敏不是技术问题，是产品设计问题——决定"哪些数据 Agent 能看，哪些不能看"是产品+安全+法务一起讨论的事。

## 防"学危险"：3 道注入防御

| 防御 | 机制 | 目的 |
|------|------|------|
| 输入分级 | SYSTEM 和 USER 在 Prompt 中物理分离 | 模型只把 SYSTEM 当规则，USER 只是任务描述 |
| 写入校验 | 独立函数校验 Schema + 自我修改关键词 + 来源授权 | 可疑写入→拒绝+报警 |
| 关键词黑名单 | "忽略所有规则"/"跳过权限检查"/"不需要确认"/"覆盖系统提示"/"act as"/"ignore previous" | 最简单的兜底 |

> 自进化 Agent 的安全，本质是"自我修改路径"的安全。只要"自我修改路径"是受控的，Agent 学得再多也不会变坏。

## 4 步应急响应

1. **检测**：Trajectory 异常告警（Skill 成功率骤降）+ 用户反馈 + 审计告警（工具调用频率飙升）+ 外部反馈
2. **隔离**：下线问题 Skill，标记影响范围（哪些任务用过、哪些 Memory 由此衍生、哪些下游系统被操作）
3. **回滚**：Skill 用 Git 回滚；Memory 是 append+dedup 需单独清洗
4. **复盘**：污染入口→哪道闸门应拦未拦→加规则→类似路径排查。**复盘结论必须变成代码**

> 最坏情况不是出 bug，是 Agent 把 bug 当成最佳实践。

## 设计哲学：安全内嵌而不是外挂

Hermes 把"安全"做成了"默认"——不需要单独配置安全规则，安装后防御就在那里。与 Harness Engineering 的"治理内嵌而不是外挂"一脉相承。

→ 相关实体：[Harness Engineering 综合论述](https://github.com/QianJinGuo/wiki-public/blob/main/entities/harness-engineering-paradigm-comprehensive-2026.md)

## 深度分析

### 风险分类学：按污染机制而非攻击手法分类

文章最有价值的是把「Agent 越学越歪」归成 3 类——学错（把个例当规律）、学脏（运行时数据持久化）、学危险（对话诱导写入假规则）——分类轴是污染机制而非攻击手法。这决定了防御的映射关系：学错是可靠性问题（闸门+验证），学脏是数据治理问题（脱敏管道+数据分级），学危险是对抗安全问题（注入防御+写入校验），三类问题需要完全不同的工具链，混在一起治理必然漏防。这一框架与 [Agent Security Threat Models](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/agent-security-threat-models.md) 的威胁建模思路互补：先分类、再按类配防线。

### 5 道闸门与 3 层脱敏：纵深防御的工程化落地

5 道写入闸门（内容脱敏→Schema 校验→静态危险扫描→沙箱试跑→人工审核）的本质是「任何一道单独使用都不够」的叠加过滤器：闸门 2 让 Skill 可治理（结构化才谈得上扫描与回滚），闸门 4 沙箱试跑是发现「学错」最有效的手段，闸门 5 用 PR 流程把高危写入收敛到人工签字。3 层脱敏管道（采集端→写入时→读取时）同理——任何一层漏了，下一层还能兜住。这与 [Agent Security Architecture](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/agent-security-architecture.md) 的纵深防御原则完全一致，且比原则更具体：每层都有明确的检查项与失败处理。特别注意采集端脱敏「这一层最重要」的判断——源头干净，后续所有环节才安全。

### 自我修改路径是攻击面的收束点

3 道注入防御（输入分级、写入校验、关键词黑名单）看似常规，但文章点出本质：自进化 Agent 的安全就是「自我修改路径」的安全。传统注入攻击影响单次响应，而写入型注入把攻击固化为持久知识——这正是 [Prompt Injection Defense](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/prompt-injection-defense.md) 在自进化场景下的升级形态，也与 [Caitlyn Self Evolving Defense Skill Library Agent Injection 2026](https://github.com/QianJinGuo/wiki-public/blob/main/entities/caitlyn-self-evolving-defense-skill-library-agent-injection-2026.md) 针对的攻击面相同。输入分级的重心是把 USER 定位成「任务描述」而非「指令变更」；写入校验的独立函数设计则保证校验逻辑与被校验对象解耦，Agent 无法「说服」它。

### 应急响应的设计围绕「污染是持久的」展开

4 步应急（检测→隔离→回滚→复盘）有两个非标准设计值得注意：其一，Memory 是 append+dedup 结构，不能像 Skill 那样 git 回滚，需要单独清洗流程——存储结构直接决定应急能力；其二，「复盘结论必须变成代码」（加黑名单关键词、加 Schema 规则、加沙箱用例）把每次事故转化为防线增强，这是 [Agent Security Attack Defense](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/agent-security-attack-defense.md) 中对抗性学习闭环的具体化。隔离步骤要求标记影响范围（哪些任务用过、哪些 Memory 衍生），则承认了污染的传播性：脏知识会繁殖新的脏知识。

### 与安全三步法的关系：部署时序 vs 运行时治理

[Agent Security Three Step Sequence Harness Governance Identity Crewai](https://github.com/QianJinGuo/wiki-public/blob/main/entities/agent-security-three-step-sequence-harness-governance-identity-crewai.md) 给出的是部署顺序视角（先 Harness、再 Governance、后 Identity），本文给出的是运行时自进化视角（学错/学脏/学危险的三线防御），二者是同一治理体系在不同时间轴上的投影。「安全内嵌而不是外挂」的设计哲学——安装后防御默认就在那里——则与 [Harness Engineering Paradigm Comprehensive 2026](https://github.com/QianJinGuo/wiki-public/blob/main/entities/harness-engineering-paradigm-comprehensive-2026.md) 的治理内嵌理念一脉相承。

## 实践启示

1. 先给自进化能力分类风险再上防线：学错用验证、学脏用脱敏、学危险用注入防御，三类问题不共用一套工具，治理前先判断自己暴露在哪一类。
2. 写入路径上叠加独立过滤器：Schema 校验、危险扫描、沙箱试跑、人工审核一个都不能省，任何一道单独使用都防不住「误学」。
3. 脱敏要在采集端做第一道：源头干净成本最低收益最大，写入时与读取时的扫描只是兜底，不要把脱敏全部押在最后一步。
4. 数据分级是产品设计问题：密码、支付凭证、私聊内容、财务报表的处理方式要在产品设计阶段与安全、法务一起定，而不是事后补脱敏规则。
5. Memory 的应急清洗要预设计划：append+dedup 结构无法 git 回滚，上线自进化功能前就要想清楚污染后的清洗路径。
6. 复盘结论必须变成代码：每次事故后把结论落实为新的黑名单关键词、Schema 规则或沙箱用例，写在文档里的教训等于没有教训。
7. 最坏情况是 bug 被当成最佳实践：监控不能只看报错，还要看 Skill 成功率骤降与工具调用频率异常——污染系统往往「运行正常」。
