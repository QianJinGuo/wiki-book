# 高德导航Live模式：时空Agent架构——从「一次做对」到「变化后还能做对」

> 📊 Level ⭐⭐⭐ | 21.7KB

高德技术 2026-09-20 发布的驾车场景 Agent 架构深度解析。**导航 Live 模式 = 步行 AI 伴行（2026-04 发布，[前作架构解析，实体已于 2026-09-07 质量闭环归档](https://github.com/QianJinGuo/wiki-public/blob/main/entities/gaode-ai-companion-agent-architecture.md)）向驾车领域的延伸**：不另起架构，在同一骨架（Supervisor 驱动双内核 Agent [自研 Mobility + QwenPaw 通用 + OmniVista 多模态]、ReAct 推理引擎、Skill 动态注入、统一时空上下文体系）上做能力延展与模型强化。

**驾车场景三大新挑战**：①时空变化更快（每秒数十米前进，约束会改、候选点会失效、路线与途经点状态会变）→ 任务不是「一次做对」而是「变化后还能做对」；②任务时空跨度更广（短辄数分钟长辄天级以上，空间可达几千公里跨多行政区划）→ 需要可托付、可修改、可重复触发、被打断还能接回的长程能力；③交互更严苛（双手握方向盘，语音为核心通道，要求鲁棒[噪声/误发指令/路线变更/工具出错] + 极致低时延）。对应升级为四大能力：**说得准（高可信时空交互）、办得成（主动服务=用户记忆×时空长程任务）、变得了（变化中的自恢复）、响应快（极致低时延 Harness）**。

## 一、说得准：高可信时空交互

### POI-Explore：多维约束求解 → 可执行候选

核心性质变化：从**信息检索**变为**可执行动作候选生成**——驾车独有「可达性」层（路网方向/禁行规则/出入口/停车条件严格约束），输出不止「信息正确」还要「行动可执行」（能开进去、能停、不需反复掉头绕行）。基于高德海量 POI 数据库 + 预估到达用时工具，将可达性加入搜索与排序。

**可执行候选 = 对象匹配 ∧ 硬条件约束 ∧ 搜索中心正确 ∧ 到达代价可解释 ∧ 未在历史已搜索过的 POI 中**。6 类筛选（距离/品类/品牌/评分/营业状态/价格）× 5 类排序（距离/价格/评分/人气/综合最优）+「顺路」时空约束（基于路线偏离代价计算而非模型猜测）。约束求解原则：先满足「必须」再优化「更好」——对象/语义（召回别名宽、最终证据严）、时间（缺营业证据不能声称满足）、空间（超硬边界不下发）、数值（未知值不能视为已满足）、偏好（主观常识不能替代选择依据）、多轮/相对（无基线不编造「更贵/更近」，硬性排除已展示候选）。

**到达代价的三层计算空间**（同一个「附近」必须选对计算方式）：L1 近场合规（围绕搜索中心满足几何范围与对象约束，不等同真实算路）→ L2 路网/绕行证据（搜索中心 + 预估到达用时排序 + 绕行距离综合）→ L3 真实算路闭环（选中 POI 后最终算路成功才完成闭环）。候选漏斗五步：宽召回（Query 改写扩召回，品类别名不作真值）→ 按需补证 → 硬筛在前（半径与上轮候选先剔除）→ 模型核验（不满足/冲突/无法验证时返回未找到而非硬凑数量）→ 终态门禁（严格半径/品类冲突/去重/显式排序）。

### LightSearch：有限预算下的可靠信息获取

与 DeepSearch/DeepResearch 的分野：出行场景面临严苛时延 + 单日千万级请求，DeepSearch 框架成本与耗时均不可行。**LightSearch = Agent 做语义决策、工程系统执行有界检索、以证据充分性决定停止**的轻量链路，在有限时延/有限 token/有限注意力预算内判断「该搜什么、不该搜什么、证据够不够、什么时候停」。

四环节：**受控搜索规划**（search_type 是可执行检索约束而非关键词标签：强时效事实[新闻/天气/限行/油价，必须命中目标时间]/权威事实[至少一条一方或机构来源]/体验推荐[多来源一致]/内容消费[离线 RAG 优先]四类型族，非法降级 generic）→ **并发召回**（主查询/拆解交叉查询/权威查询三角色最多并发 3 路，单分支 8s，总预算 15s，分支失败隔离）→ **语义重排**（先去重分组再统一重排，不按返回顺序拼接）→ **证据门禁**（最多定向补搜 1 次且需保留至少 2s 预算，低置信度不强答）。资源按职责分层：一方与官方资源（政策/开放时间必须可追溯）、专业垂直资源（行情卡/气象）、开放互联网（体验推荐/交叉验证，不替代官方确认）、离线内容库（故事笑话，支持历史去重）；「权威」最终由真实返回 URL 的 domain 与正文共同判定，query 含「官网」不自动升级。

**证据门禁是价值锚点**：把「回答质量」从概率问题变成可控问题——模型输出边界由检索到的证据强度决定，而非语言流畅度。效果：任务完成度 **79.58%→90.42%（+10.84pp）**、满意度 **75.83%→85.62%（+9.79pp）**；线上 **90% 搜索任务 1 秒以内**获取。并行的收益是把主事实/权威源/交叉证据放同一轮完成，端到端时延接近最慢分支而非三链路之和。

### 近场空间探索：感知不走 LLM、沉默优于错报

「感知→探索→指引」三层递进，核心原则**不确定时不回答，回答必须有证据**。**近场感知**：「我在哪、旁边有什么」类事实问题直接调用逆地理编码引擎获取位置快照，LLM 不参与——近场感知是 Agent 的「睁开眼睛」不是「做一个决定」；原始 POI 列表经三层过滤（方向 ±90°/距离/类型[排除餐饮购物类商户，保留大厦/学校/公园/医院等稳定参照物]）产出四类结构化事实（当前区域/行政位置/详细位置/前向环境参照物），作为独立上下文块注入模型与导航上下文分离，确保「当前位置」信息来源唯一不被污染。**周边探索**三类工具：周边搜索（附近有什么）、沿路搜索（天然区分前方/后方）、详情+到达代价（怎么去）；同轮可组合指令下发与探索（「打开音乐并找个加油站」，指令下发前校验格式与参数）。

**多模态指路（沉默优于错报）**：基于 MLLM 空间推理的端到端视觉导航指令生成，从行车记录仪图像序列提取无坐标地标（类别/描述/方位/距离），视觉证据不足时主动沉默。针对传统导航三局限（2D 地图与 3D 现实认知鸿沟、连续岔路口「前方 50 米右转」失效、单向被动交互）。渐进式 MLLM 对齐框架（**已被 EMNLP 2026 接收**）：Stage I Multi-task SFT（地标提取分解为 6 辅助任务）→ Stage II Contrastive DPO（7 种对比对消除漏报/误接受/方位错误）→ Stage III NARF GRPO（Navigation-Aware Risk-averse Reward 三层奖励：Tier 1 FP-free 最高奖励、Tier 2 沉默温和惩罚、Tier 3 含假阳性惩罚性基底——Tier 2/3 之间**软边界**，真阳性足够多时 Tier 3 可超过沉默，避免硬边界导致**沉默崩塌**）。效果：离线 Benchmark Precision **92.29%（32B）** vs 通用 MLLM 基座 49.55%；线上 A/B 覆盖 4 城市约百万级用户，地标增强指令使出发确认延迟降低 **23.5%（7.54s→5.77s）**；训练后输出长度呈 U 型曲线，自适应场景复杂度无需人工阈值调参。

## 二、办得成：主动服务 = 用户记忆 × 时空长程任务

两类诉求分野：当下及时型（「找加油站」「带我回家」）是合格线；**延后/持续型**（「路过城市讲讲有意思的事」「每隔两个半小时提醒休息」「下个服务区前 1 公里提醒我」「每走 500 米提醒我」）才是出行 Agent 的价值高地。双视角统一建模为主动服务：用户视角是委托，Agent 视角可基于情境「先人一步」发起邀约。与代码智能体/智能客服/企业助手的长程任务相比，出行长程任务呈明显时间+空间双重跨度。

### 条件驱动长程任务：任务一等实体

范式从**请求驱动**（用户说一句，编排一次闭环）转向**条件驱动**：任务创建 → 条件持续监听 → 满足时主动播报 → 闭环/重置。五类触发条件覆盖绝大多数委托：路线前置距离触发（「服务区前 1 公里」）、地点到达触发（空间几何围栏）、相对时间触发、周期重复触发、条件重复触发（「每次快到地铁站提醒看末班车」）。**最关键工程决策：把任务做成「一等实体」**——生命周期跨一次甚至多次行程，支持自然语言二次修改与取消；不是一次性定时器，而是可被 Agent 检索、指代、推理和改写的对象，内部构建任务创建/更新/触发/挂起/销毁五个工具接入时空 ReAct 引擎。复合诉求自动组合（「去公司路上路过咖啡店提醒我」= 沿路线 POI 搜索 + 地点触发型长程任务，Agent 自动规划串联）——**能力可组合，而非一句话对应一个技能**，这是与「技能式语音助手」的本质差异。

### Agentic Memory：记忆要改变决策

延续步行阶段**双轴治理模型**：五层时空粒度（Step/Session/Goal/Navi/User，解决生命周期）× 四类记忆表征（稳定出行规律/明确诉求/情境事件/程序记忆）+ 检索机制（KV 精确检索 + 向量语义检索 + 置信度门控，目标「记得准、调得出、用得少、忘得掉」）。Live 模式将其接入用户可感知的**三条消费路径**：路线类明确诉求（「避开高速」→ 后续每次路线规划的约束项）、助手风格与称呼（→ 播报人格与表达策略）、稳定出行规律+程序记忆（→ Proactive 主动服务的发起判断）。对记忆只有一条要求：**不是「记下来给你看」，而是要改变系统后续决策**——只有被真实消费的记忆才算从历史记录沉淀为决策资产。

五环节闭环：写入判断（是否值得记/增/改/删）→ 双库沉淀（长期记忆存稳定偏好，导航事件存单次行程空间事实）→ 分层召回 → **地图回灌**（把记忆中的地点还原成地图可识别候选，交还搜索/算路工具）→ 行程巩固（行程结束后压缩有效交互，更新路线经验与偏好）。记忆不替代地图事实、不绕过当轮诉求，而是转成搜索条件/路线约束/主动发起条件：优先级为实时可行性与安全硬约束 > 当轮显式诉求 > 高置信记忆 > 低置信推断；命中冲突/过期/低置信时忽略或再次确认，「这次走高速」等新指令覆盖旧偏好。业务收益：记录必要性精度 **31/31=100%**，内容准确率 **29/31=93.55%**。

### Proactive 服务与触发时机裁决

链路：情境识别 → 主动邀约 → 一次授权 → 全程分点交付（长程任务在行程中逐个地点就近推送）。承接步行阶段「地理位置驱动的个性化导览」壁垒场景，形态本质变化：**从用户提问触发，扩展为 Agent 主动发起 + 用户单次授权 + 全程自动交付**。难点判断：**不在「能不能触发」，而在「该不该现在触发」**——沿用 Skill 系统 L3 层（与工具调用、导航状态强绑定的规则强制覆盖）同一思路，结合位置/导航状态/播报时机做触发时机裁决，关键路口、复杂路况、与导航播报冲突时抑制发声。产品三准则：**先邀约、再服务、随时可终止**。

## 三、变得了：变化中的自恢复

### 反事实驱动的 ReAct 推理强化

步行阶段 ReAct 优化解决的是**效率**（推理轮次/重复调用下降，「路径够不够短」）；其 RL 设计（Env 层结构性硬约束 + Pipeline 层 LLM Judge 轨迹评分）本质是**在给定工具调用轨迹上做评价**，回答不了「变化发生时能否发现、诊断并恢复」。引入**反事实推断 LLM 模型**，同时承担「干预者」与「裁判员」双角色：基于真实工具调用轨迹，在关键决策点构造**可观测、可验证、可恢复**的反事实变化。干预不是随机加噪，而是以真实轨迹为条件注入语义合理变化，覆盖四类场景：用户约束变化（中途追加/修改/放弃）、候选点失效（POI 关闭/不可达/被否决）、工具异常（空结果/超时/异常码）、路线及途经点状态变化（重算/增删/换序）。数据质量三重保障：规则校验 + 独立模型评审 + 人工审核（延续步行阶段多智能体交叉审核，相关成果已被 EMNLP 2026 接收），审核对象扩展到「干预之后是否可恢复、恢复得是否正确」。定向消除四类失败：**状态丢失、错误搜索、重复调用、不合理收口**。效果：最优反事实模型用户需求满足率 **87.0%（纯 SFT +12.1pp）**；反事实干预评测集上 **40.7%→83.1%**。

**范式转变：从「打分」到「出变化题」**——步行阶段在已有轨迹上打分（衡量「做得对不对」），Live 模式主动在考场上出变化题（先改变世界，再检验 Agent 能否恢复，衡量「变了之后还对不对」）。进一步印证步行阶段核心结论：**通用能力强不等于垂直场景好**，决策效率不会随模型规模自动涌现，只能从场景反馈中习得；反事实干预的价值在于把「场景反馈」从被动等待线上暴露变成**可批量、可控地主动生成**（高质量 Agent 训练数据生产）。

### 打断续播与导航融合：语音通道三方仲裁

语音通道同时存在三方发声源：用户语音、导航安全播报、Agent 内容播报。四机制：**语义级打断判断**（不以「有无声音」为准，区分噪声/回声/ASR 碎片与真实插话）、**无效打断恢复**（判为误打断后恢复原播报内容与状态，内容不丢失）、**按实际播放位置续播**（以真实播放进度为锚找自然分句续播点，不从头重念也不半句续读）、**与导航播报融合**（安全播报永远优先，让行后自然接回而非丢弃或全量重播）。步行阶段用首包时延（P50 2.3s vs 对照 4.9s）证明「答得快」，Live 模式用打断续播证明「说得完」——**托付的事被打断之后能接回来，用户才敢真的把事托付出去**。

## 四、响应快：极致低时延 Harness

优化对象从单次模型调用扩展到 Agent 全链路（时延预算下保质量 + 千万至亿级日调用成本约束，与 EvoRoute 等 Agent 模型路由研究的目标一致）。四个抓手：①模型侧领域 SFT + 在策略蒸馏提升小模型多轮执行可靠性；②架构侧延续**大小模型协同双内核**：小模型承担能力边界内高频任务，动态路由把需要更强能力的请求交大模型；③上下文侧建立面向实体、事件及时空关系的结构化表示，按任务需要选择相关信息，减少全量历史与超长 Prompt 依赖；④运行时架构协同。效果：Agent 首包时延 **P50 1.69s / P90 3.3s**，较上一阶段（P50 2.3s / P90 3.5s）分别优化 **610ms / 200ms**。

**OPD + SFT（Label-Anchored）**：反事实干预模型结合先进大模型生成高质量决策与恢复轨迹，但线上必须由响应快、成本可控的小模型承担。OPD（On-Policy Distillation，见 [OPD 实体](https://github.com/QianJinGuo/wiki-public/blob/main/entities/on-policy-distillation-vs-offline-distillation-loster.md)）负责开放式决策能力——不要求离线复刻教师完整答案，而是在**学生自身生成的工具调用轨迹**上引入教师纠偏，针对真实会遇到的错误状态持续改进，缩小训练分布与执行分布差距（适合多轮约束变化/工具异常/路线状态变化）；但拒答、工具协议等**确定性知识**用 Label-Anchored 机制走 SFT 强监督（前序字段生成错误后无法恢复的边界样本），开放式表达/工具选择/恢复路径继续 OPD——核心不是叠加两种 Loss，而是**按知识性质分配监督信号**。Agent 主 Loop 跨词表蒸馏用 Sparse BPM 与残差建模传递教师概率分布，控制计算存储成本同时保留对候选决策及不确定性的判断。

**大小协同**：不是平均分流，而是小模型承担大多数稳定任务、大模型留给少量真正需要更强推理与多轮修复的请求。四部分：难度前置判断（复杂组合/强历史依赖/多约束纠错直接进大模型）→ 小模型主执行 → 高置信升级（小模型执行关键工具前自判能否可靠完成，只有高把握失败时升级）→ 状态与预算守门（升级时继承原请求/对话/工具状态；限制升级比例，避免重复分流与重复调用）。**时空上下文检索**：不是越多越好，按当前任务加载最小必要事实——来源分层（当前请求/实时路线/历史对话/用户记忆/近场环境/长程任务）、事实优先级（当前请求优先，DriveContext 提供实时路线真值，历史只用于多轮承接，**记忆只补充不覆盖当前状态**）、三档加载（意图层只看路线骨架；执行与回复层加载当前道路和最近事件；完整路线详情按需读取）、隔离与校验（近场环境独立注入，普通对话与播客历史隔离，工具执行前校验权威途经点与最新状态）。

## 五、总结与展望

技术主线一句话：**把伴行 Agent 从「空间智能内核 + 行动引擎」升级为「时空智能内核 + 主动服务引擎」，从「一次做对」到「变化后还能做对」**。步行阶段展望的「用户个性化出行伙伴」落地为 Agentic Memory × 长程任务的组合。两个后续方向：①**世界模型从「训练期干预」走向「运行期预演」**——现在世界模型用于离线构造反事实训练数据，下一步在关键决策点做轻量运行期后果预演（「这一步之后世界会变成什么样」），构建 Agent 与世界模型协同进化体系；②**时空智能基座**——对现有基座模型做规模化的出行场景时空能力（时间/空间两维度深度理解与推理）连续预训练。
