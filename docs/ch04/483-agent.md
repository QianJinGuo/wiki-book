# Agent 自进化四齿飞轮：评测→记忆→落地→控制

> 腾讯技术工程（yannisyang、ethanytzhou）基于 Anthropic 递归自改进报告、斯坦福 CS329A 课程、EvoAgentX 等开源框架研读，提炼出「评测→记忆→落地→控制」四齿飞轮方法论——不是单个环节最佳实践，而是一个完整、可落地、经过验证的工程闭环。

## 核心洞察：自进化瓶颈在环节衔接

Agent 上线半年后仍会犯三个月前犯过的错、走三个月前走过的弯路——问题不在模型不够强，而在没有人给它搭一条从「做过」到「记住」到「变好」的路。评测、记忆、Self-Improve 三件事在多数团队被拆散着做：评测分数去了周报而非 Prompt/Skill 改进链路；记忆向量检索噪声太高反被干扰最后被默默关掉；Self-Improve 生成的 Skill 质量参差、无评测筛选、无版本回滚。

**自进化的瓶颈不是任何一个技术点，而是环节之间的衔接。** 评测信号必须流进记忆和 Skill 更新；更新后必须能被评测验证；验证结果必须反哺下一轮进化——链路断任何一环，飞轮都转不起来。

## 四齿飞轮结构

- **评测**是闭环的「眼睛」（感知哪里有问题）——评测可信度 > 系统复杂度；一个简单但评测可信的系统远好于复杂但评测失真的系统；错误的正反馈会让 Agent 加速开往悬崖
- **记忆**是闭环的「大脑」（积累可复用经验）——记忆系统核心不是存储能力而是治理能力：版本控制、主动遗忘、冲突解决、来源溯源这些「不性感」的治理能力才决定记忆是帮忙还是添乱
- **Self-Improve / 落地**是闭环的「手脚」（把经验变成实际改进）
- **人机协作**是闭环的「方向盘和刹车」（确保进化方向不跑偏）

## 深度分析

### 评测：从「上线前打分」升级为飞轮信号源

传统评测只做质量门控；自进化里评测多了方向指引和经验筛选两个新角色，评测信号因此直接流入记忆写入与 Skill 更新链路。评测打错分不再是「上线了个差版本」，而是 Agent 自信地学到错误经验、污染后续所有任务——错误的正反馈比没有反馈更可怕，这正是「评测可信度 > 复杂度」的底层逻辑。

七大难题分两类：信号质量问题（弱评估器系统性偏差、只评结果不评过程、粗粒度无法归因、开放式任务难量化）与新鲜度/成本问题（评测集漂移、预算公平性、成本限制迭代频率）。对策是评测手段分层组合（规则校验 → LLM-as-Judge → 人工抽样+元评测集）、评测集三分法（train/val/test 互不泄漏）、评估器也需被元评测集校准。Skill 这类产物还要过四层验证（对照实验、难度校准、轨迹追踪、路径验证）才能证明「真的有用」而非「碰巧存在」。

### 记忆：治理能力决定帮忙还是添乱

原文用 Git 类比点出核心转变：记忆价值不在存储而在治理——存 100 条低质记忆不如治理好 10 条。写入要「策展而非全存」（正信号触发、反例标记、三层晋升、非对称淘汰——淘汰速度是强化 2.4 倍）；存储要分层 + 生命周期管理（L0-L3、版本控制、主动遗忘、冲突解决、[来源溯源](https://github.com/QianJinGuo/wiki/blob/main/concepts/memory-source-provenance.md)）；读取要渐进披露 + 严格预算（默认只注入顶层 500-800 token、按需钻取）。

记忆污染是最危险失败模式——错误蔓延远快于修复；检索噪声与上下文预算分配是「加了记忆反而不如不加」的主因。反直觉发现：把记忆建模成文件系统、用 ls/grep/cat 检索比专用 API 更有效；符号化压缩（Mermaid 编码状态、日志外置）实测省 60%+ Token。

### 落地：把「改 Agent」工程化成 Agent CI/CD

自动化 ≠ 全自动：LLM 修复质量不可控、单点修复缺全局视角（修 A 破 B）、总结生成 Skill 的环节也需专门优化（小模型策展人优于冻结大模型）。自动化覆盖「生成候选 → 评测验证 → 门控筛选」，关键决策留人。

八环节——诊断归因 → 信号汇聚 → 生成候选 → 独立评测 → 安全门控 → 灰度发布 → 监控回流 → 经验沉淀——本质是把 CI/CD 搬到 Prompt/Skill/记忆上。要点：三路信号汇聚（诊断 + Playbook + Auto-Research）突破平台期；Diff 模式代替全文重写；多文件联动需 AST 签名验证；一切版本化；灰度 10%×7 天 + 自动回滚 + 失败样本回流。异步 Dreaming 补足跨会话系统性模式，最终仍由人拍板。

### 控制：分级自主与防止对齐漂移

人机协作是分级自主、渐进放权、动态升降级。五个节点永远留人：规则级记忆写入前、安全边界类更新确认、回归决策、冷启动种子、安全边界设定——程序不应有权改自己的权限配置。

审核疲劳是常见失败模式——「什么都弹审核，人三天后直接通过」比没有审核更危险。解法：门控滤掉 95% 低质变体、批量异步审核（做选择题）、渐进放权 + 自动降级。更深的坑是对齐漂移：评测奖励「详细」致 Agent 越变越啰嗦——每步过门控但方向在偏。门控保安全不保方向，需三层防护：方向性审计、方向性约束指标（输出长度/工具调用/拒答率）、评测集含意图对齐维度。

## 实践启示

1. **先擦亮眼睛再动手脚。** 搭自动化前先用 1-2 周设计高质量初始评测集，三分法 + 元评测集校准评估器；评测不可信的系统自动化程度越高错得越快。
2. **把记忆当治理系统。** 正信号写入 + 非对称淘汰 + 分层架构 + 版本控制/主动遗忘/来源溯源；读取默认只注入顶层，配严格 Token 预算。
3. **落地走「Agent CI/CD」。** 先把诊断归因与监控回流做扎实；修复一律 Diff 模式；一切版本化，出问题可定位、可回滚。
4. **人把关关键节点而非事事把控。** 五个「必须有人的节点」留给人；批量异步审核对抗审核疲劳，让人做选择题。
5. **从最小闭环起步。** 手动跑通 Phase 1（50-100 条 case + 手动闭环）再自动化；优先选真实业务指标、反馈延迟短的场景。
6. **为方向建立观测。** 月度方向性审计 + 输出长度/工具调用/拒答率指标 + 评测集含意图对齐维度，防对齐漂移。
