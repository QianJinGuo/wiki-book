# LongCat-2.5：把视觉当 token、把长程任务当训练题的 1.6T 智能体模型

> 📊 Level ⭐⭐⭐ | 17.9KB

## 基本盘

**1.6 万亿总参数、每 token 激活约 480 亿**的 MoE，在 LongCat-2.0 基础上强化两件事：**原生视觉理解**与**智能体编程**。训练侧在长序列数据里加入更多长程轨迹，并用**大规模长程强化学习**提升"复杂代码库开发、完整项目构建"这类端到端工程能力；数据合成、环境构建、**跨 Harness 混合训练**持续扩展；一个值得注意的做法是把**真实 Agent 的失败轨迹转化为可复现、可验证的训练任务**，针对短板补数据。

对比基线选了 GPT-5.5、GPT-5.6-Sol、Claude-Opus-4.8、Claude-Opus-5（正文表格以图片呈现，本条目只记录文中明确写出的结论与工程细节，不代录未在文字中出现的分数）。全部结果在 `enable_thinking=on`、`temperature=1.0`、`top_p=0.95` 下取得；带 `*` 的对比分数取自公开报告/博客/官方榜单，未带 `*` 为自测。

## 机制一：视觉信号当成"多层级离散 token"

目标很明确——**让视觉基元建模具备与语言建模类似的 token 级抽象**，使主干模型以统一 token 形式处理视觉与文本。三个设计凑成一套：

1. **离散原生分辨率的视觉 Transformer**：沿用 LongCat-Next 的方法，对语义对齐编码器（SAE）产生的**原生分辨率特征**应用**残差向量量化（RVQ）**，把视觉表示为多层级词表 token——用 RVQ 解决视觉离散化的信息瓶颈。
2. **离线视觉 token 预处理**：固定 tokenizer 允许**离线预计算并缓存视觉 token ID**，主干直接处理预分词序列——减少在线视觉计算与负载异构性，简化长序列打包/切分，改善分布式训练的负载均衡。
3. **原生视觉表示**：视觉码本 embedding 与主干**联合学习**；在平均激活约 3B 的较小 MoE 上验证，视觉与文本 embedding 在 t-SNE 上呈**交织分布**，说明两者在共享语义空间里融合。

这套设计的直接后果是"视觉 Coding"能力：创意设计、3D 等任务（文中演示包括实时流体模拟、3D 文物交互页、城市沙盘、微缩场景、中国风色彩科普页、活动邀请工具等）。

## 机制二：Agentic RL——先把"题"造对，再谈 scaling

**数据合成与环境构建**是自动化流水线：数据源涵盖 GitHub 公开仓库与内部真实代码任务；筛选后的 PR 与关联 issue 由 Agent 自动打标、合成可交互环境、生成可验证测试用例，并做 **fail-to-pass（F2P）与 pass-to-pass（P2P）** 校验。训练中再用实时 rollout 的轨迹与通过率做**二次打标筛选**，并基于**假阴/假阳分析**持续修正与扩充 F2P 用例，以提高对任务功能描述的覆盖率与验证信号准确性。

**异步训练**用 partial rollout 缓解长尾：每个 RL step 保持一定**过采样率**，凑齐批次后中断、保存未完成轨迹，下一采样阶段恢复；过采样率按任务通过率调整，并**过滤全对/全错的零梯度样本组**以保证有效梯度。

**陈旧性**是 partial rollout 的副作用——同一轨迹的 token 可能来自不同历史 checkpoint。两个应对：裁剪采样时与当前训练时的 logprob 差异；基于历史累计差异调整每个 token 的梯度贡献，限制陈旧性带来的梯度偏置；另有基础设施侧的训推一致性优化。

**reward hacking 治理**（这段最实在）：在任务环境中**断网、清除 git 历史与文件缓存**，并引入 **LLM judge 监督轨迹**以限制投机行为；输出行为上，对**重复思考与重复工具调用施加额外惩罚**，对"过度思考、长度增长过快"则通过**重新分配正样本中的 Reward** 抑制。

**混合训练与泛化**：模型在 RL 中可自主学习并适配近似任务与 Harness；冷启阶段只需覆盖少量 scaffold 用例，RL 阶段通过**跨多任务、跨 scaffold 混合训练**显著提高泛化并促进各项任务性能。

## 机制三：MOPD 专家组——把领域能力并进主线

沿用 LongCat-2.0 的专家组机制，分别优化 **Agent 能力、推理能力、交互体验**（多轮任务执行、单轮推理、细粒度指令遵循、不牺牲有用性的安全防御）。MOPD 中学生模型在各领域任务上**在线采样**，领域专家通过采样结果上的**全词表 KL 散度**训练学生。

两个工程细节：**①per-cut prefix**——先前工作把教师见过的轨迹拆成 per-turn prefix 作学生采样上下文；这里进一步把每轮教师回复按**固定长度**拆成 per-cut prefix，并把学生自采样最大长度限制为该值，处理单轮长回复中的分布偏移。**②同组共享 prefill**——同一教师轨迹的 prefix 分到一组送同一推理引擎，共享 prefill 计算与 KV cache；训练时以教师轨迹为树干、学生采样为分支建树，结合 **Tree Attention**，用**单次前传与反传**完成同组所有样本的 OPD 训练，避免教师轨迹上的冗余计算与存储。

## 机制四：国产算力上的长上下文训练

前提很硬：**单卡显存不足 80 GB**。系统围绕超节点做并行与显存优化：

- **并行组按超节点拓扑配置**：FSDP 与 EP 并行度都等于单超节点卡数、CP 不超过该卡数，使参数 AllGather、专家 token AllToAll、KV AllGather 都在超节点内高带宽互联域完成。
- **混合词表并行**：在 DP×CP 联合域内对基础词嵌入层、LM head、N-gram 嵌入层分片，降低显存占用。
- **MoonEP 动态专家复制**：仅当 EP 负载不均衡达阈值才启用，避免额外通信超过均衡收益，并防止路由 token 打爆接收端显存、通信操作打爆发送端显存。
- **提前图像 token 生成**：训练计算图不再包含视觉编码器，简化并行；利用已知图像 token 数量在打包打散时预估各模态负载比例，使各 DP rank 模态占比接近。
- **双重分片 FSDP**：参数在超节点内 FSDP 域分片，FP32 主权重与优化器状态经 HSDP 副本跨 FSDP 域再分片，兼顾参数通信效率与常驻显存。
- **扁平化缓冲区**：参数、梯度、优化器状态统一组织为连续缓冲，支持非均匀分片与 Muon 优化器分片；直接写权重梯度、复用临时缓冲，减少中间拷贝与峰值显存。
- **通信优化**：零拷贝 AllGather/ReduceScatter；EP 打包传输 token 与路由概率、基于 AIV 的实现缓解 AICPU 任务展开瓶颈；参数预取让 AllGather 与计算重叠；**ScMoE** 让 EP 通信与稠密分支计算重叠。
- **主机侧**：批量执行梯度操作、合并指标归约、CPU 绑核、NUMA 感知调度。

综合效果：**该 FSDP 配置在长序列 SFT 任务上的单卡吞吐较 DDP 基线提升 86%**。

## 机制五：训推 bitwise 一致

基于 IsoExec、GLM-5、XoRL 的工作，构建生产级训推一致性方案：**训练、Prefill、Decode 可独立选择并行配置，同时保持逐 token logprob 的 bitwise 一致**；两端统一采用 batch-invariant 算子并对齐框架计算逻辑、补齐 backward 支持；已在实验与生产任务中**默认启用**，作为算子与框架迭代的数值回归基准。

两个扩展：**TP**——用完整 K 维计算替代分段求和（训练侧保留权重分片，通过权重 All-Gather + 输入 AlltoAll 独立完成完整 K 维 GEMM，无需 Reduce-Scatter 求和；Prefill 沿用；Decode 把 `o_proj`/`fc2` 改 column-parallel，经输入 All-Gather + 完整 K 维 GEMM + 输出 AlltoAll，既避免每步聚合完整权重也避免跨卡数值求和）；**DCP**——在训练 forward 与推理 Prefill 中接入配套 sparse attention 算子，**复现指定 DCP 配置下 Decode 的 KV 分块与归约顺序**，对齐三者精度。

## 机制六：PD 分离与长上下文 KV 的三处优化

**缓存容量**：Prefill 用 QCP 按 token 分配计算、KVP 按页分散存储，避免 MLA 下 TP 切分带来的 KV 冗余；**HiCache** 在 KV 回迁显存后释放无其他引用的主存副本，减少两级缓存重复占用；并基于 Mooncake 重构权重管理与 Actor offload，为 HiCache 腾内存。

**跨层预取**：利用 **LSA** 奇数层复用前一偶数层 top-k 索引的特性，把奇数层完整 KV 卸载到主存、显存只留小容量工作缓存；偶数层产生索引后提前加载下一奇数层所需 KV 并与当前层后续计算重叠——**TPOT 无损的前提下 Decode KV 缓存容量接近翻倍**。

**容量感知调度**：Router 依据 L1+L2 缓存容量与请求 token 总量控制放行，并优先推进完成度较高的 Group，尽早凑齐训练批次、释放缓存——避免多条长轨迹交替推进时反复淘汰彼此前缀，引发**大规模重算雪崩**。该场景下 **P/D 实例配比 3:2 性能最优**。

## 机制七：W4A4 推理（1.6T MoE 的部署答案）

把**专家权重与激活同时量化到 4 bit**，用原生 INT4 矩阵乘单元计算。精度侧以 **FlatQuant 的可学习等价变换**为基础，进一步优化 MoE 量化精度，在已评测下游任务上**保持与量化前相当的表现**。

数据路径的关键一招是**专家共享的输入变换**：在 token 复制与分发**之前**完成量化，使同一份 INT4 表示贯穿专家通信与计算；把变换、尺度计算、量化、打包融合进专用算子，并结合权重布局与转置访问优化减少搬运与转换开销；系统层面按 prefill/decode 的执行特点优化计算与通信的流水重叠。

线上压测（相对 W8A8 INT8 基线）：**prefill 吞吐 +43.3%、decode 吞吐 +42.77%；TTFT -15.91%、TPOT -19.72%**；算子层面 **GMM 平均 1.73× 加速**。

## 深度分析

### 视觉"当 token"的真正收益在训练系统，而不只是模型效果

把视觉离散成多层级 token、离线预计算缓存，表面是模型设计，实质是**把视觉从"在线编码的异构负载"变成"可打包、可均衡的定长序列"**——于是长序列打包切分变简单、DP rank 间模态占比可控、训练计算图不含视觉编码器。**这是"为 infra 友好而设计模型"的典型**：多模态能力与训练效率在这里不是取舍，而是同一决策的两个结果。

### Agentic RL 的难点被拆成三个可独立治理的问题

**题的质量**（F2P/P2P + 假阴假阳反哺）、**梯度的有效性**（过采样率随通过率调整 + 过滤全对全错组 + 陈旧性裁剪）、**奖励的可信度**（断网/清历史/清缓存 + LLM judge + 重复与长度惩罚）。多数团队把它们混成"RL 不稳定"，这里则逐项给出机制——**能拆开治理，才能分别调参**。

### "失败轨迹转训练任务"是数据飞轮最实的一步

真实 Agent 的失败轨迹天然满足三个条件：**已复现、有上下文、有明确失败点**。把它们转成可验证任务，等于把线上噪声直接变成训练信号——这比"人工造题"更贴近分布，也比"只用通过样本"更能补短板。**与数据飞轮类文章的区别在于：这里给出的是构造流程（打标→环境→F2P 校验→二次筛选），不是概念图。**

### 训推 bitwise 一致是长程 RL 的隐形地基

partial rollout 让同一轨迹的 token 来自不同 checkpoint，如果训练与推理的数值路径不一致，"陈旧性校正"就建立在浮动误差上。LongCat-2.5 把 TP/DCP 的训推一致性做到 bitwise——**这不是性能优化，而是让 RL 的信用分配可解释的前提**。代价是要放弃一些"分段求和"这类性能技巧（用完整 K 维 GEMM 替代），属于典型的"用算力换确定性"。

### 国产卡上的每一个数字都是"约束驱动"的产物

80 GB 单卡显存、超节点拓扑、AICPU 展开瓶颈——这些约束直接决定了并行组配置、双重分片 FSDP、AIV 通信、MoonEP 阈值触发复制等设计。**86% 的 SFT 吞吐提升只对"这个配置 vs DDP"成立**，不能外推为架构优势；同理 W4A4 的 43% 提升是对 W8A8 基线、在线上压测场景下测得。读这类数据要连前提一起读。

### 1.6T + 48B 激活，是"能力上限"与"部署成本"的折中

总参数决定容量，激活参数决定每 token 成本。48B 激活配 W4A4 + PD 分离 + KV 分层，才让 1.6T 在线上可用；**模型规模竞赛的真正门槛不是训练，而是推理经济性**。

## 实践启示

1. **多模态要"为 infra 友好而设计"**：离散化 + 离线预分词能让视觉变成可打包的定长序列，训练效率与效果同时受益。

2. **把 Agentic RL 拆成三件事调**：题的质量（F2P/P2P、假阴假阳）、梯度有效性（过采样+零梯度过滤+陈旧性裁剪）、奖励可信度（环境隔离+judge+行为惩罚）。

3. **失败轨迹是最好的训练题**：已复现、有上下文、有明确失败点，转成可验证任务即可用。

4. **reward hacking 从环境下手**：断网、清 git 历史与文件缓存，比只在奖励函数上打补丁更根本。

5. **训推一致性是长程 RL 的地基**：追求 bitwise 一致，别让陈旧性校正建在数值噪声上。

6. **长上下文 KV 的容量靠"跨层结构"换**：利用奇数层复用偶数层索引的特性做卸载+预取，TPOT 无损把容量翻倍。

7. **调度要防重算雪崩**：按缓存容量与 token 总量放行、优先推进高完成度 Group，比单纯加机器有效。

8. **低比特推理的收益在"数据路径"**：量化前移（分发前完成）让一份 INT4 贯穿通信与计算，配合融合算子才能真正提速。

9. **读 benchmark 先读口径**：`enable_thinking=on`、`temperature=1.0`、`top_p=0.95`，带 `*` 的是他人公开分数——不同口径不可直接横比。
