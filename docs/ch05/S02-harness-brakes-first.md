# 先写刹车，再写循环：Harness 设计的六个决策点

> 🧭 综合·决策框架 | 信源 5 篇

<!-- syn-slug: harness-brakes-first -->

本章信源反复出现同一句告诫："先写刹车，再写循环。"但"刹车"具体在哪些位置落子？综合各信源，Harness 设计可以收敛为六个决策点，每个都有明确的默认答案与偏离条件。

## 决策点

**1. 循环还是工作流？** 默认用循环（模型自主决定下一步）；当任务步骤可枚举、顺序固定、合规要求可审计时，退回工作流。判断信号：任务描述里出现"每次都可能不一样"，用循环；出现"必须每一步都留痕"，用工作流。

**2. 验证器放在循环内还是循环外？** [核心模式梳理](005-harness-engineering)的答案是循环内做廉价校验（schema、lint、单测），循环外做昂贵验收（集成测试、人工 review）。两道都不可省——只做循环内校验的 Harness 在本章案例中最常见的死法是"每步都对，合起来是错的"。

**3. 工具权限分几级？** [Harness 架构拆解](../ch04/127-agent-harness)给出五级模型：L0 只读自动执行 → L4 直接拦截。默认从 L0/L1 自动放行、L2 Diff 确认、L3 人工审批起步；**不要为不同风险级部署独立 Agent 实例**，精细分级就是为此而存在的。

**4. 双循环还是单循环？** 快循环处理高频工具调用，慢循环每 3 步或出错时触发全局复盘——该设计的报告收益是任务成功率从 60% 提升至 90%+。偏离条件：任务短于 5 步时，慢循环是纯开销，单循环 + 结束时复盘即可。

**5. 上下文爆了怎么办？** 见第六章综合页《上下文装不下时怎么办》的完整决策树。Harness 层只需预先回答一件事：丢失细节的容忍度，由任务性质决定，不由预算决定。

**6. 成本护栏放在哪？** [KV Cache 成本迁移实践](071-deepseek-kv-cache-harness)的教训是护栏要在系统层（缓存策略、路由、预算熔断），不要在提示词里恳求模型省钱。[Model-Harness Fit](067-model-harness-fit-agent)进一步指出：脚手架要与模型档位匹配——给强模型配重刹车、给弱模型配轻刹车，是两种常见错配。

## 使用方式

这六个决策点的产出物本身就是一份 Harness 设计评审单。按 [半年实战](050-loop-engineering-claude-ship)的说法，团队评审一份 Harness 设计只需要回答这六题——答不出默认答案的题，就是设计里还没想清楚的部分。
