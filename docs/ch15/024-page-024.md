# 决策模型的三个可调旋钮：排序、校准、阈值

> 📊 Level ⭐⭐⭐⭐⭐ | 35.9KB

## 一句话结论

这篇把「决策模型能不能直接上生产」拆成三个可以分别处理的问题：**排序能力（PR 曲线）· 校准度（校准曲线）· 阈值位置（业务代价）**。核心判断是——**很多人接入决策模型后直接照搬 API 默认的 0.50 阈值、也不检验概率是否可靠，"结果把一大截性能白白留在了桌面上"**。而更深的一层来自作者的原创推导：**校准与排序是两件事**，**严格递增变换不改变 PR 曲线、只改变 Brier 的 Reliability 项**，**调阈值等价于在 logit 上加偏置**，**贝叶斯最优阈值是 `C_FP / (C_FP + C_FN)`——只有误报与漏报代价相等时才是 0.50**。

## 一、为什么不用生成式 Judge：两个瓶颈与三条假置信度路径

| 瓶颈 | 原文 |
|---|---|
| **生成开销大** | "哪怕我们最终只需要一个 `Pass` 或 `Fail` 的二元结论，自回归模型也必须逐个 token 把推理过程或 JSON 结构写出来" |
| **给不出连续、可信的置信度** | 三条路都不行（见下） |

**三条"看起来有置信度、其实没有"的路径**：

1. **直接输出 Pass/Fail**：等于"让模型在黑盒内部做了一次**不可见的硬截断**"——拿不到任何概率，既没法调误报/漏报比例，也没法识别灰区样本；
2. **让模型口头报 `{"score": 0.85}`**："本质上只是在**采样数字字符 token**。受预训练语料先验影响，生成的数字会高度扎堆在 **0.50、0.80、0.90** 等少数离散档位上，既不连续，也不代表真实的错误频率"；
3. **读答案 token 的 logprobs**："由于通用大模型普遍经历了多轮偏好对齐（RLHF）或 0/1 奖励的 GRPO 训练，它的词表 logits 早已被**强烈推尖**——输出概率动辄坍缩在 **0.999 或 0.001**，同样失去了灰区样本的校准度"。

**决策模型的谱系与机制**："从 **TypeSafe 的 Jev** 开始，随后 **Perplexity 的 Decider、Liquid 的 d1、Cloudflare 的 Clef 以及 OpenAI 的 Decisions API** 相继推出"；它们"**砍掉了自回归生成文本的循环，单次前向计算直接从决策头读出 logits，并映射为 0 到 1 之间的连续概率分数**"。

于是三件事终于可以拆开：**能排开好坏（PR）、数字能不能当概率信（校准）、阈值切在哪（业务取舍）**。

数据来自"一套**公寓租赁 Agent 系统**"，抽出 **100 条真实轨迹**（含完整对话历史与执行动作日志），任务是"找出包含错误的案例——比如**预订失败**，或者**本该转交人工客服却漏转**"。

| 模型 | 备注 |
|---|---|
| **TypeSafe Jev 1.13** | 使用适配 Jev 的结构化输入 |
| **Perplexity Decider 1.1 27B** | |
| **Liquid d1 / d1-ultra** | 两个档位 |
| **Cloudflare Clef Flash** | |
| **OpenAI Decisions** | 底层为 **GPT-6 Luna** |

两个维度：**性能**（对比人工逐条审阅的 `pass`/`fail` 真值，"在抓出错误的同时能不能少报假警"）与**成本**（按实际 token 与官方定价）；"这次实验暂不对比时延，因为时延很大程度上取决于实验控制之外的服务端因素"。

## 三、为什么默认 0.50 会坑人

**一个极端反例把问题讲透了**："假设某个模型给每一条真正的失败轨迹都打了 **0.40** 分，给每一条正常通过的轨迹都打了 **0.10** 分。你看，这个模型其实把正负样本分得一清二楚——只要我们把阈值设在 **0.30**，它就能做到 100% 完美分类；可如果沿用默认的 **0.50** 阈值，**它连一条错误都抓不出来**。"

所以"选择决策阈值的过程，本质上就是在权衡两个指标"：**Precision**（控制误报）与 **Recall**（控制漏报）。类比也很准：**"刑事审判对定罪设了极高的门槛，宁可漏判也不能冤枉无辜，这强调的是 Precision；而早期癌症筛查则宁可多做几次复查也要尽量少漏掉患者，这强调的是 Recall。"**

## 四、先立业务门槛，再谈优化

> "**千万不要脱离业务底线去盲目最大化 F1。**"

他的例子："假如我们要拿这个分类器去搭一套**自动化线上告警系统**，那我会要求 **Precision 和 Recall 都必须至少达到 80%**——只有这样，才能在尽量少发假警报骚扰团队的同时，抓住足够高比例的线上故障。"

于是图上"右上角'P ≥ 0.8 且 R ≥ 0.8'的矩形阴影区就是我们的合格线"，六个模型立刻分层：

| 结果 | 模型 |
|---|---|
| **进入合格区（3 个）** | **Perplexity Decider 1.1 27B** · **Liquid d1-ultra** · **OpenAI Decisions** |
| **未达标（3 个）** | **Jev 1.13** · **Liquid d1** · **Cloudflare Clef Flash**（"无论怎么调整阈值，都无法同时迈过双 80% 的门槛"） |

**注意这里第一个反直觉**：**概率校准最好的 Jev 1.13，反而没进合格区**（后文 3.1 解释）。而且"即便对留下的三个候选模型，它们各自的曲线也只是**有一小段**落在阴影区里"。

## 五、阈值调优：交叉验证 + 硬约束

方法上有两句前提很重要："调阈值只能选择既有 PR 曲线上的工作点，那么**自训时，我们就应在数据覆盖、训练目标和模型选择中提前考虑误报与漏报的要求**"；以及"**概率校准或阈值加权损失本身，都不能保证 P/R 达标**"。

具体做法：**"在训练数据上加上硬约束：只允许在同时满足 Precision ≥ 0.8 和 Recall ≥ 0.8 的阈值里挑选"**；未达标的三个"不加约束直接最大化 F1，用来展示调阈值本身能带来多大变化"；且"**为了防止在测试集上'看答案调参'导致过拟合，这一步必须使用交叉验证**"（分层五折，用训练折选阈值、剩余折测性能，模型间用同一套划分；**"如果没有合格阈值，就如实报告，而不是放宽任何一条要求"**）。

**发现**："入围的三个候选模型从 F1 调优中获得的提升幅度，**反而比被淘汰的 Liquid d1 和 Clef Flash 要小**"——因为后两者"默认阈值偏离最佳点太远，调完阈值后 F1 大涨，但依然够不到双 80% 线"。

**但调优仍不可省**："在实际业务里，哪怕 Precision 和 Recall 只有几个百分点的移动，也会直接牵动业务成本或用户体验。"而且"现实业务里 P 和 R 几乎不可能像 F1 假设的那样恰好等权"——看重 Precision 用 `F_β`（β<1），看重 Recall 用 β>1，"**换一个优化指标，选出来的最佳阈值和最终排序都会随之改变**"。

## 六、性能 vs 成本：帕累托前沿

| 模型 | 调优后 F1（5-fold CV） | 成本 / 100 次评测 | 定位 |
|---|---|---|---|
| **Perplexity Decider 1.1 27B** | **0.79** | **0.82 美分** | "合格候选中最便宜，守住双 80% 底线的极致性价比之选" |
| **Liquid d1-ultra** | **0.79~0.87** | **0.82~3.72 美分** | "中间档，且**原生概率校准极佳**" |
| **OpenAI Decisions（GPT-6 Luna）** | **0.87** | **3.72 美分** | "分类性能断层领先，但成本约为 Perplexity 的 **4.5 倍**" |

"连接这三个点的虚线就构成了候选池的**帕累托前沿**：对于我们想要的任何 F1 水平，这条线都能指出达到该性能的**最便宜模型**。"

## 七、概率能直接当置信度吗：Clef 的 8% vs 60%

判据很硬："如果模型报出 0.80，真的意味着'80% 的可能性有错'吗？要满足这个条件，在所有被模型打出 0.80 左右分数的轨迹里，**必须真的有大约 80% 包含错误**。"

**校准曲线**（每点约 20 条）：对角线上=严丝合缝；**上方=低估风险**；**下方=高估风险**。

| 模型 | 校准表现 |
|---|---|
| **Jev 1.13 / Liquid d1-ultra** | "**天生就已经校准得非常好**，几乎不需要调整" |
| **Clef Flash / Perplexity / Liquid d1** | "明显偏离对角线" |
| **最夸张** | **Clef Flash：某组轨迹平均预测失败概率约 8%，实际有 60% 包含错误** |

**Platt scaling**（在留出数据上拟合 S 型曲线）让 Perplexity、Liquid d1、Clef Flash "显著向对角线靠拢"。**但它不是万灵药**：

> "**Platt scaling 并不总是合身**……在我们的实验里，**OpenAI Decisions 的概率在套用这一版 Platt scaling 后反而略微变差了**。所以做完校准一定要用指标说话。"

## 八、四步迭代闭环

1. **定门槛筛模型**：打磨好 Judge Prompt 后，先按业务定下 P/R 最低线，直接淘汰达不到的；
2. **先调阈值再比性能**：交叉验证下调优，"认真思考该用什么权衡指标，**别仅仅因为本文用了 F1 就照搬 F1**"；
3. **按需检验并校准概率**："校准能帮上忙，但**必须用 Brier score 实测确认它确实带来了改善**"；
4. **综合权衡与持续迭代**：结合性能、成本、时延拍板；"**一旦后续优化了 Prompt，前面调好的阈值和校准映射都需要重新跑一遍**"。

另外两条工程建议：**"强烈建议为每一种具体的失效模式单独构建一个 Judge"**（把"预订失败"和"漏转人工"拆开），且"任务范围收窄、评判指令更具体之后，**我们预期不同模型之间的性能差距会大幅缩小**"；实践顺序是"**先从一个性能能达标的大模型开始跑通，然后再尝试换用更小、更便宜的模型**"。

## 九、原创推导：为什么"概率准"≠"分类好"

### 9.1 校准与排序是两件事

现象："**Jev 1.13 的预测概率几乎紧贴对角线，但在双 80% 筛选中却未能入围**；反倒是原始概率明显失准的 Perplexity 先过了门槛，随后补一步简单的 Platt scaling 就把概率也修准了。"

原因是模型输出的连续分数承担**两项不同任务**：

- **排序 / 区分能力**：把正负样本排开；
- **校准度**：如实报出每个分数对应的真实错误率。

用 **Murphy 分解**：`Brier = Reliability − Resolution + Uncertainty`。

**关键定理**：对所有样本施加同一个**严格递增变换**（温度缩放、斜率 > 0 的 Platt scaling），**样本之间的分数高低顺序完全不变**——"原分数在阈值 τ 下选出的告警集合，与新分数在阈值 τ' 下选出的集合是同一批样本"。

> "因此，在同一批数据上遍历所有阈值时，**严格递增变换不会改变 AUROC、整条 PR 曲线以及最优 F1**；同时由于可逆变换不改变信息划分，**总体 Resolution 也保持不变，Brier 分数的变化全部来自 Reliability**。"

**由此澄清一个常见误区**："**单纯把 logits 乘以一个放大系数，只是拉大了分数的数值跨度，并不会提高 AUROC 或改善 PR 曲线。**"

所以训练的第一要务是"让模型学到能够**区分正负样本的特征表示**（把真正含错的轨迹排到前面），在此基础上再保证输出概率与真实频率对齐"。

### 9.2 默认阈值失灵：先验基率偏移与代价结构

换到 log-odds 空间，"默认阈值 0.5 恰好对应 logit = 0"；Platt scaling 则是"在 logit 空间做了一次线性仿射变换"（斜率拉伸尺度、截距平移对数几率）。

**可精确推导的特例——先验基率偏移**："假设模型在训练分布上已经学到了准确的真实后验，到了下游评测集，正负类的特征生成机制没有变，唯独**正例出现的总体比例从 π 变成 π'**……由贝叶斯公式两边取对数几率，可以直接推出新分布下的真实后验 logit 整体**平移一个常数偏置**"。

> "哪怕模型的判别能力一点没变，只要下游业务的故障基率和训练数据不同，真实对数几率就会整体平移一个常数。**如果照搬原来的分数并死守 0.50 阈值，自然会出现系统性的漏报或误报。**"

**印证**："Jev 在多个基率各异的基准上**混合算 ECE 只有 0.047，但单拿每个基准出来算，中位 ECE 升到了 0.168**"——**混合指标会掩盖单场景的失准**。

**两个进一步结论**：

1. **调阈值 ≡ 加偏置**："把决策阈值定在 τ，等价于在 logit 上加偏置后再用 0.50 截断"——但**"调阈值只改变分类切分点，本身不等于把概率校准准了"**；
2. **业务代价决定最优阈值**：设误报代价 `C_FP`、漏报代价 `C_FN`，则**贝叶斯最优阈值为 `C_FP / (C_FP + C_FN)`**——"**只有误报与漏报代价完全相等时，最优阈值才是 0.50**"。

> "一套通用模型权重不可能预先写死所有下游业务的基率与代价结构，**部署时留出少量带标样本在交叉验证下调阈值、验校准，是必不可少的标准动作**。"

### 9.3 训练损失怎样塑造概率：严格正常评分规则

"只要 `p* ∈ (0,1)`，Brier 与交叉熵的条件期望损失的导数都在**预测值 = 真实后验**处唯一为零"——

> "**在模型容量足够、优化充分且训练分布与目标一致的理想条件下，最小化 Brier 或 CE 都会驱使模型如实报出真实后验概率。** 具有这一性质的评分规则，就叫做**严格正常评分规则（Strictly Proper Scoring Rules）**。"

**三种常见修改如何破坏它**：

| 修改 | 后果 |
|---|---|
| **标签平滑** | "**会把概率向 0.50 压缩**"——"真实高风险样本的概率会被系统性压低，低风险样本则被抬高" |
| **纯 0/1 奖励**（无 KL 等正则） | "**会把概率推向极端顶点**"——"只要正确率高于 0.5，梯度就一直把 p 往 1 推；低于 0.5 就往 0 推" |
| **套 GRPO 的组内标准差归一化** | **校准项被约掉**（见下） |

**RLCD 的正确形式**："如果把标量奖励设计为（求梯度时把奖励视为常数），那么策略梯度在期望上**恰好等价于 Brier 损失的负梯度**"。

**两个极易踩坑的细节**：

1. **有完整标签时无需绕道采样式 RL**："直接对 Brier 或 CE 求导就能拿到**零采样方差的精确梯度**；用采样 RL 估计同一个梯度只会平白引入动作采样方差"；
2. **组内标准差归一化会抵消校准作用**："如果照搬 GRPO，对同一道题采出的 G 个动作减去组内均值再除以组内标准差……由于该因子对同一题的 G 个采样是同一个正数，而标准化操作对**正仿射变换完全不变**，因子在分子分母中被直接约掉！归一化后的优势函数与纯 0/1 奖励完全相同，**原本用来锁住校准不动点的项就此失效，不动点再次坍缩到 0 或 1**。"

**这一条对做 RL 微调的人非常实用**：GRPO 的归一化是为"组内相对好坏"设计的，**它天生会抹掉绝对概率刻度**——想要校准，就不能用它的标准化形式。

### 9.4 业务卡死 P/R 下限时，训练阶段怎么发力

**第一步：把"双 80%"写成数学约束**——"当阈值取 τ 时，业务要求的 P ≥ 0.8 与 R ≥ 0.8 可以改写为关于真正例比例与假正例比例的**两个线性不等式**"。

两个常犯的概念混淆（值得单独抄）：

1. **"'P 和 R 都达到 80%'是跨样本的总体排序约束，绝不等于'把概率阈值设成 0.80'。"**
2. **挑 Checkpoint、做困难样本挖掘、调数据配比时，不能只盯整体平均 NLL / Brier**，而应在验证折上直接追踪**受约束工作点指标**——"在满足 P ≥ 0.8 的所有阈值中，模型能达到的最大 Recall（或最大 F1）是多少"。

**第二步：已知部署阈值区间时，用 Schervish 加权损失**

- **陷阱写法**："把指示函数直接换成 sigmoid 软决策"——"求导就会发现**导数的符号只取决于真实概率在阈值的哪一侧**……**它不仅没有校准阈值附近的概率，反而把概率强行推离了阈值**"；
- **正确写法**：**Schervish 定理**指出"任何二元正常评分规则都可以表示为不同阈值下代价敏感损失的**加权积分**（标准 Brier 对应均匀权重）"。于是"在目标阈值附近放一个**窄高斯峰**并叠加一个正的基础权重"——"**逐点期望损失的唯一最优点依然严格停在真实概率上**；同时，当预测分数落在目标阈值附近时，模型会对这一区域的**校准残差赋予更高的梯度权重**"。

**代价：误差搬家**。"当模型容量有限、不同输入共享参数时，提高阈值附近的权重，本质上是**把宝贵的拟合预算优先保给阈值附近，代价是其他非关键区域的校准误差可能变大**"。作者给了个极简构造例：两组等权样本真实失败率 **0.90 / 0.50**，但受表达能力限制预测被耦合——均匀权重 Brier 的最优解折中在 **0.70**（两组预测 0.85 / 0.55，各承担 0.05 偏差）；改用集中在 0.80 附近的权重后，第一组在阈值附近准到 **0.8015**，但第二组被拉低到 **0.5015**（偏差近 0.10），**整体校准误差反而上升**。

结论："Schervish 阈值加权是一个**把校准精度集中到刀刃上的工具，但它本身不能代替特征区分度的提升**。"

### 9.5 拆原子 Judge：共享前缀与 Fréchet–Boole 陷阱

**为什么要拆**："对于不生成 CoT、只做一次前向计算的决策模型来说"一个宽泛 Judge 相当于"要求它在固定层数内同时完成'检索各轮对话状态、核对多种业务规则、再做逻辑或（OR）汇总'"。拆成 N 个职责单一的原子判断（如"用户明确要求转人工时是否未调用转接接口"、"双方确认看房时间后是否未调用预订工具"、"报价是否与房源表冲突"）后，"每一道子题的判据就变得具体而局部，标注与归因也更加清晰"。

**成本问题**："按传统方式拆成 N 个独立 Judge 分别请求 API，同一段长轨迹要被**重复编码 N 次**，成本会直接翻 N 倍。"

**解法（共享前缀 + 题间隔离读出）**："长轨迹材料只需 **Prefill 一次**，随后把 N 个原子问题作为**互相隔离的分支**接在共享 KV 缓存后面并行读出"——"当轨迹上下文很长、而原子问题本身很短时，一次前向并行读出 N 个原子 Judge 的总计算成本**将非常接近单次调用**"。

**汇总陷阱（这一段最容易被忽略）**："很多人会本能地写出 `P(总) = 1 − ∏(1 − p_i)`。但请注意：**注意力掩码上的'题间隔离'只保证模型在回答第 i 题时偷看不到第 j 题的题面，绝不意味着真实世界里的失效事件在给定轨迹后是条件独立的！**"（例："Agent 一旦误解了用户的核心意图，可能在同一条轨迹里既报错价格、又漏调接口，两类错误高度正相关。"）

不知相关性时，"数学上只能框出 **Fréchet–Boole 上下界**"。两个原子各 **0.30** 的直观例子：

| 关系 | 真实并集概率 |
|---|---|
| **完全重合**（同一底层故障） | **0.30** |
| **相互独立** | **0.51** |
| **互斥** | **0.60** |

> "单靠'每个原子 Judge 各自校准得很好'，**并不能自动推出合成后的总失败概率也是校准的**。"

**两条消费路径**：

- **路径一（只做告警，不求总概率）**：每个失效模式单独调阈值，任一超阈就触发对应类别告警——"不仅能抓错，还能直接给出**细粒度错因标签**"；轨迹级统一验收整体 P/R；
- **路径二（要子项诊断 + 总风险概率）**：做一层轻量的**二次聚合校准**。

**二次聚合的两个做法**（前提先说清："N 个原子 Judge 是 **N 个各自独立的 Sigmoid 二分类器，而不是 Softmax 类别分布**……同一条轨迹完全可以同时犯多种错误，因此**子题概率之和完全可以大于 1**"）：

| | 做法 A（极简基线） | 做法 B（标准做法） |
|---|---|---|
| 做法 | 固定公式拍扁成标量（取 max，或按独立性算 `1 − ∏(1 − p_i)`）→ **一维 Platt scaling** | 保留 N 个子项分数 → **带正则的多变量逻辑回归** |
| 硬伤/优势 | ①**丢掉组合结构**："两项完全重合"与"两项真正独立"算出来都是 0.51，一维校准分不清谁触发的；②**只修刻度不改排序**："校准函数严格递增……遍历所有阈值画出来的整条 PR 曲线分毫未动" | ①区分"单项孤立存疑"与"多项并发报警"（(0.6,0.6) 与 (0.6,0) 拍扁都是 0.60）；②**自动给冗余/高噪 Judge 调权重**（"两题高度重合时压低各自系数以避免双重计分；纯噪声子题权重自动向 0 收缩"）；③**重学轨迹级排序，有机会抬高 PR 曲线** |

**天花板**："**第一层原子特征的覆盖度始终决定了上限**……如果某类错误根本不在已拆出的 N 个原子 Judge 之内……要突破这个天花板，就得回到错误分析闭环，**把漏网的失效模式补成第 N+1 个原子 Judge**。"

## 十、两个作者自陈未解的问题

1. **Thinking Decision Model 的必要性**："如果 20 轮轨迹里的错是'第 3 轮答应的折扣，到第 18 轮算总价时漏扣了'，或者要先算出两个日期差几天再判断是否违规，**不写中间步骤，小模型单靠一次前向很难算对**"——"要么得用代码把中间数字先算好塞进输入，要么还得退回带推理的模型"；
2. **阈值与校准的场景漂移**："等线上 Agent 修掉了几个高频 bug、或者换了一版 Prompt，错题的比例和分布一变，**原来锁死的阈值和校准映射就会偏掉**。线上怎么低成本发现分数漂了、隔多久需要补标数据重调一次，**目前还没有一个 auto 的解法**。"

## 深度分析

### "三个旋钮"是这篇最实用的抽象

生成式 Judge 把这些混在一个黑盒里：分数、概率、切分点全都由一次生成决定。决策模型把它们拆开之后，**每个旋钮有了独立的诊断工具**——排序看 **PR 曲线/AUROC**，校准看**校准曲线 + Brier**，阈值看**代价结构**。这个拆分让"评测器调优"从玄学变成了三个可分别验收的工程任务。**如果你只有一个指标（比如准确率），这三件事永远纠缠在一起。**

### "概率准 ≠ 分类好"这一条，纠正了一个普遍的直觉错误

Jev 1.13 校准近乎完美却进不了双 80%，Perplexity 校准很差却先进了门槛——这组反差说明**校准是在"已经排好的顺序上重新贴标签"，它改不了顺序本身**。数学上就是那句：严格递增变换不改变 PR 曲线。**所以任何"把概率修准"的努力，都不会让一个排不开样本的模型变得可用。** 这条对选型影响很大：先看 PR 能不能过业务线，再考虑校准。

### 贝叶斯最优阈值 `C_FP/(C_FP+C_FN)` 应该写进每个评测系统的配置

默认 0.5 之所以"看起来合理"，是因为它隐含假设**误报和漏报代价相等**——而这在真实业务里几乎从不成立。线上告警漏一次可能损失几十万，误报只是多一次人工确认；反过来内容审核误杀一次可能是公关事故，漏放一条只是延迟处理。**"阈值"本质是业务代价的函数，不是模型的性质。** 这也解释了为什么"一套通用权重写不死所有下游"——**代价结构是部署方的私有信息**。

### GRPO 归一化抹掉校准，是一个值得所有 RL 实践者记住的坑

这一条推导很干净：组内标准差是同一题的同一个正数，标准化对正仿射变换不变，于是**因子被约掉，优势函数退化成纯 0/1 奖励**，校准不动点从 `p*` 塌回 0/1。含义是：**GRPO 优化的是"组内相对好坏"，它天生不保留绝对概率刻度**。所以如果你的下游需要"0.8 真的是 80%"，就不能只用 GRPO 的标准化优势；要么回到有标签的监督（Brier/CE 的精确梯度），要么用 RLCD 那种带校准项的奖励，且**不要做组内标准化**。

### 从"1 个宽泛 Judge"到"N 个原子 Judge"，是一个可计算的重构

拆细的三重收益说得很实：判据更局部（单次前向的推理跨度下降）、归因更清晰（能给出错因标签）、成本可控（共享前缀预填 + 隔离读出，"总成本接近单次调用"）。但作者也把代价讲清了：**拆细引入了新的数学问题**——边际概率不能直接相乘。**Fréchet–Boole 那个 0.30/0.51/0.60 的例子，是全文最有教育意义的一个小实验**：同样两个"各自 0.3"的原子判断，合成后的总风险可能差一倍。

### 二次聚合器是"评测系统的元学习层"

做法 B（多变量逻辑回归）本质上是**用轨迹级标签学"怎么组合子判断"**：自动压冗余、自动降噪、重学排序。它的天花板也诚实——**看不到原始轨迹，只能看到 N 个分数**。这给了一个清晰的架构判断：**第一层决定上限（覆盖度），第二层决定利用率（组合）**。补 N+1 个原子 Judge 的收益，通常大于把聚合器调得更精。

### 它与"Skill/工具评测"那一族的关系

AWS Skill Eval 的三层（Invoked / Selection / Instruction）是**确定性 + Judge 混合**；这篇是**把 Judge 本身换成可校准的决策头**。两者可以叠：确定性的部分继续用断言，语义的部分用决策模型 + 校准 + 业务阈值。而"为每种失效模式单独建 Judge"这条，与 AWS 的"分层检查"、支付宝的"每个关键产物都有准出标准"是同一种**粒度细化**直觉。

## 实践启示

1. **先定业务门槛（P/R 双下限），再谈优化**——脱离底线的 F1 最大化没有意义。

2. **永远不要用 API 默认阈值**：0.5 隐含"误报=漏报代价"，现实中几乎不成立。

3. **阈值要用交叉验证调**，且只允许在训练折上满足约束的阈值入选；没有合格阈值就如实报告，别放宽要求。

4. **比模型前先调阈值**，否则你比的是"谁离默认点更近"，不是"谁更强"。

5. **按业务选权衡指标**：偏 Precision 用 `F_β`（β<1），偏 Recall 用 β>1——换指标会换排序。

6. **看帕累托前沿选型**：给定 F1 水平，找最便宜的模型；别只看单一最优。

7. **概率别直接当置信度**：先画校准曲线，再看 Brier；Platt scaling 要实测有效（可能反而变差）。

8. **混合 ECE 会骗人**：Jev 混合 0.047、单场景中位 0.168——**按场景分开算**。

9. **记住排序与校准是两件事**：递增变换不改 PR，只改 Brier 的 Reliability。

10. **别指望放大 logits 提升分类**：那只改变数值跨度。

11. **训练目标决定概率性质**：Brier/CE 是严格正常评分规则；标签平滑压向 0.5、纯 0/1 奖励推向 0/1。

12. **用 GRPO 就别指望校准**：组内标准化会把校准项约掉。

13. **已知部署阈值时用 Schervish 加权**（窄高斯峰），但要接受"误差搬家"，且它不能替代特征区分度。

14. **拆原子 Judge**：一题一判据，标注与归因都更清晰；用共享前缀预填 + 隔离读出控成本。

15. **别把边际概率当独立概率乘**：只能给 Fréchet–Boole 上下界；要总概率就做二次聚合。

16. **二次聚合保留全部子项**（多变量 LR），别先拍扁成一个标量。

17. **补原子 Judge 的收益通常大于调聚合器**：覆盖度决定上限。

18. **Prompt 一改，阈值与校准都要重跑**——它们是数据的函数，不是模型的常量。
