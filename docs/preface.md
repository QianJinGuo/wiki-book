# 序言

> 这本书在回答一个问题：当你把一个 LLM 接上工具、放手让它做事，怎样才不会在第一个真实任务里散架？

## 一道等式

全书的骨架是一道等式：

```
Agent = Model + Harness
```

模型决定能力的上限，Harness 决定生产的下限。过去两年，工程界的重心沿着这条等式迁移了三次——从 Prompt Engineering（模型听得懂吗），到 Context Engineering（信息给够了吗），再到 Harness Engineering（它能在真实执行中持续做对吗）。五篇二十章，就是沿着这条线铺开的一次完整旅程：先理解模型这半边（第一篇），再逐层搭起系统那半边（第二、三篇），然后深入模型自身的锻造与加速（第四篇），最后站到技术之外看全局（第五篇）。

## 三种读法

- **按路径读**：从[学习路径](PATH.md)进入，Level 0 到 Level 5，每级有作业和验收标准——适合想把 Agent 工程变成职业能力的人。
- **按难度读**：每个条目标注 ⭐ 到 ⭐⭐⭐⭐⭐ 五阶难度，每章开头的导航表告诉你每一阶有多少篇——适合按自己水平自由采摘的读者。
- **按问题读**：带着具体问题来（RAG 为什么拒答？多租户怎么隔离？），用搜索直达条目，每个条目都溯源到一手原文——适合把本书当参考书查的读者。

## 一部会自进化的书

这不是一本写完即冻结的书。全书 1,693 个编撰条目全部从一手文章炼取、逐条溯源、每日由自动管线收录新文并炼去糟粕；质量门禁把不达标的材料挡在书外。代价是：个别观点会随信源演化而过时——所以每个条目都留着通往原文的路，请把本书当作一张标注了难度与出处的地图，而不是替代品。

深度判断的立场写进每章的导读与收束：那是编撰者的综合，欢迎反驳。引语和数字属于原文作者；错误属于我们——发现问题请到 [GitHub](https://github.com/QianJinGuo/wiki-book) 提 issue。
