# PoS：用显式信念状态识别并打破 Belief Trapping

> 📊 Level ⭐⭐⭐⭐ | 23.9KB

## 核心命题：把"Agent 忙了很久却没做成事"变成可计算、可诊断、可干预的过程

南开大学、阿里云、清华大学提出 **Belief Trapping（信念受困）**：智能体持续与环境交互，但**与目标相关的信念演化已无法带来有意义的任务进展**——表现为原地重复、在若干状态间循环，或不断探索却没触及真正未解决的问题。论文《Beyond Memory: Harnessing Long-Horizon Agents with Explicit Belief States》（arXiv:2610.01415，github.com/luoyu100/PoS）的回答是 **PoS（Progression of States）**：持续维护显式信念状态，用 **Belief Health** 衡量任务进展，检测到受困后按受困模式与缺口类型实施 **Trapping-Aware Recovery**。

论文用 ALFWorld 的真实案例点题：把加热后的杯子放进柜子——智能体先把杯子放进微波炉再放进柜子，随后陷入"反复查看柜子"的循环，**无效行为重复 36 次直到耗尽行动预算，漏掉的是"加热"这一步**；使用完整交互历史的 Raw Trajectory 基线用完 50 步仍失败，**PoS 在 17 步内完成同一任务**。同类困境在 GUI Agent（反复点击而界面停在原处）与 Coding Agent（一遍遍读同一文件却不进入有效修改与验证）上重复出现，共同问题是：**系统能否在预算耗尽之前判断当前行动是否仍在推进关键要求**。

## 为什么"历史越来越长"不等于"当前状态越来越清楚"

长程任务中的信息会过时：杯子刚才在微波炉里、现在可能已被拿走；**一次工具调用表达"要做什么"，返回的观察才说明"实际发生了什么"**；前几轮看似合理的判断也可能被新证据推翻。完整轨迹保留顺序、记忆与压缩帮助筛选整理——它们提供证据基础，但每次选动作时智能体仍需把分散信息重新拼成对当前任务的理解，判断哪些结论继续成立、哪些已经失效。PoS 把这步**显式化**：这里的"信念"指智能体基于已有证据形成的当前理解（既有直接观察，也有仍待检验的推断），**可以被更新、被检查，也可能出错**。

## 机制一：把当前世界与剩余要求放进同一份状态

- **世界表示**：用**实体**（杯子、微波炉、柜子）、**状态**（杯子是否热、微波炉是否关闭）、**关系**（杯子位于哪里、由谁拿着）组织与任务相关的世界；状态与关系保留**来源、置信度与可用支持证据**以便后续核对。只保留会影响行动、结果判断与目标完成的信息——加热任务需要记住温度与位置，"单纯记录曾经操作过微波炉并不够"。
- **未解决要求分两类**：**信息缺口（Epistemic Gap）=还需要弄清楚的事**；**达成缺口（Achievement Gap）=还需要通过行动改变的事**。若没有证据确认杯子是否变热就需补充信息；若已知杯子未加热就需真正完成加热。该划分同时用于诊断：排查服务故障时"数据库等待还是 JVM 内部处理造成延迟"是信息缺口，**下一步应寻找能区分两种解释的证据，而不是继续收集与判断无关的日志**。
- **Active Gap**：面对多个未解决要求时选定一个当前优先处理的缺口；智能体仍能看到完整任务状态，但行动获得明确焦点，该缺口解决后再推进后续要求。

## 机制二：Belief Sentinel——写下来的状态要经得起证据检查

显式记录状态后还有一个隐忧：**这份状态本身也是模型生成的**，错误判断写进去会让后续决策持续沿错误前提展开。因此一次行动返回新观察后，PoS 先生成候选更新，再交给 **Belief Sentinel** 核对两件事：①**内部是否自洽**（同一个微波炉不能同时被记为打开和关闭）；②**更新是否得到交互证据支持**（只看到杯子被放入微波炉，不足以把"已经加热"写成确定事实）。发现问题后结合证据修正，**经过校验的状态才进入后续决策**；公开实现中若修复后仍未通过检查，则保留此前已提交的状态。这也为受困检测提供前提：**先核对状态变化是否可信，再判断这些变化是否构成进展**——但内部自洽、与观察相容并不保证任务在前进（智能体完全可能准确记住"杯子还没热"，然后继续查看柜子）。

## 机制三：Belief Health——把 Belief Trapping 变成可计算问题

**不能仅凭动作重复就认定受困**：相同工具的多次调用可能在收集不同证据；反过来每一步都换工具，也可能一直绕开关键问题。PoS 因此关注的是**未解决要求持续存在时，经过校验的信念是否仍在发生有助于任务的变化**：先为每次状态转移标记进展，再在**最近 K 次经过校验的转移**上观察三个互补信号——执行任务的单步进展（缩小当前缺口、获得必要信息，或推进一条合理的完成路径）、诊断任务中相关推断的置信度是否发生超过阈值的变化（**置信度降低也可能代表排除了错误解释，同样计入变化**），以及第三个推进/重复信号。

三者组合成可解释的启发式指标 **Belief Health（信念健康度）Hₜ**（E、A 分别为信息缺口与达成缺口，健康度越低受困信号越强）。组合原则：**持续未解决的要求**与**进展停滞或信念重复**共同出现时形成较强受困信号——内层 max 保留停滞与重复中较强的异常（避免一种明显迹象被较弱的稀释）、乘以缺口持续度把异常与长期未解决要求关联、外层 max 关注两类缺口中受阻更明显的一类。由此得到两个反直觉但关键的判断规则：**任务尚未完成本身不会单独触发受困判断**；**部分单步获得正向进展标签，也不能掩盖持续存在的状态循环**。论文的设置是**积累 8 次经过校验的转移后启动检测，当 Hₜ ≤ 0.25 时进入受困诊断**。

## 机制四：Trapping-Aware Recovery——把受困诊断变成行动约束

健康度回答"是否需要干预"，恢复机制回答"该改变哪段行为、恢复什么进展"。诊断拆成两个维度：**行为模式**（**Static** 世界状态局部不变 / **Cycle** 在先前出现过的状态间周期性循环 / **Drift** 世界状态虽变化但与当前缺口相关的部分没有推进；按此顺序判定，无法匹配时用通用恢复）与**被阻塞的缺口类型**（比较非空信息缺口与达成缺口的持续度，取更顽固的一类：前者需要能区分解释的新证据，后者需要真正改变任务状态）。**同一个"原地停滞"可能分别要求换一种调查方向，或执行一直被遗漏的动作**——模式约束负责打破无效行为，缺口约束负责明确下一步必须恢复的进展（原地停滞则抑制无效的"状态-动作"重复、循环则打破重复转移、偏离目标则重新对齐 Active Gap）。

**恢复约束作为额外条件交回原来的智能体**，由它继续选动作，当前 Active Gap 保持不变；每次新转移经校验后重新计算健康度，高于阈值即释放临时约束、仍然受困则更新诊断与约束——受困检测、约束生成与恢复后重新评估构成持续闭环。论文的 RCA-100 案例 t024 展示了这条链路：Kimi-K3 已发现 inventory 服务慢请求与垃圾回收活动升高同时出现，却无法区分"数据库等待"与"JVM 内部处理"；PoS 识别出"原地停滞＋信息缺口"，要求停止无效重复、寻找能区分两种解释的证据，智能体随后选择检查 CPU 活动；恢复过程中间仍经历三次低进展动作，之后 CPU 证据与已有垃圾回收观察共同促成信念修订。该次运行共 28 个动作，最终提交的 `inventory /memoryPressure` 同时匹配基准标注的故障实体与类型。

## 实验：四类任务、三个模型、12 组设置全胜

**设置**：ALFWorld 与 LOCA-Bench 要求多轮操作完成目标（134 / 525 案例，LOCA-Bench 汇总七种环境描述长度），RCA-100 与 ClinDiag 要求持续获取证据完成故障或医学诊断（103 / 604 案例）；基础模型 Qwen3.7-Plus、Kimi-K3、GLM-5.3，每个基础模型下 PoS 的执行、信念维护与校验组件使用同一模型；对照方法覆盖完整轨迹（Raw Trajectory）、ACON、PACE、HiAgent，以及显式维护任务状态的 LongHorizon-Harness；**PoS 无须为这些任务更新基础模型参数**。

**主结果**：PoS 在**全部 12 组"基准 × 模型"设置中取得文中比较方法里的最高整体指标**（ALFWorld、LOCA-Bench 为任务成功率，RCA-100 为**故障类型与实体联合准确率**，ClinDiag 为诊断准确率）。以 Qwen3.7-Plus 为例：ALFWorld 从最强对照 **72.39% → 88.81%（+16.42pp，相对 +22.68%）**；RCA-100 联合准确率 **28.16% → 38.83%（+10.67pp，相对 +37.89%）**——同时覆盖"让世界发生目标所需的改变"与"通过证据逐步明确判断"两种任务结构。

**消融与对照**：移除**一致性校验**后 ALFWorld **88.81% → 73.88%**、LOCA-Bench **56.38% → 44.57%**（说明状态更新可靠对需要频繁协调环境变化与新观察的执行任务尤其重要）；移除**受困诊断及其恢复**后 RCA-100 **38.83% → 33.98%**，三个模型在该基准降幅 **4.85-6.79pp**；保留检测但把针对性约束换成通用的"请尝试恢复"提示时，Qwen3.7-Plus 四个基准上 **PoS 的针对性恢复都更高**。受困模式分布与任务类型对应：ALFWorld 中**循环最常见**，RCA-100 中 **Drift 占 55.93%**，ClinDiag 中 **Static 占 78.25%**——"只让智能体'换个办法'，未必能说明它究竟应当换掉哪段行为、以及需要补齐什么"。

**长上下文压力**：LOCA-Bench 把环境描述从 8K 扩到 256K tokens，各方法总体下降，而 **PoS 在 96K-256K 区间相对稳定，256K 设置下三个模型分别比同设置最强对照高 10.67-16.00 个百分点**——与设计思路相符：每次收到新观察就更新现有任务状态、后续决策围绕当前条件展开，减少从长历史反复重建任务状态的需要。

**代价与边界**：RCA-100 / Qwen3.7-Plus（103 案例平均）中，PoS 把联合准确率从 Raw Trajectory 的 **24.27% 提升到 38.83%**，但**方法总 token 消耗达原始轨迹基线的 5.06 倍**；其中**执行智能体本身 token 消耗减少约 20.9%**，额外开销来自信念维护与 Sentinel——即"用额外推理投入换诊断准确率"。PoS 仍依赖基础模型理解证据的能力，**信念健康度用于识别进展停滞、并不直接验证最终答案**：即使状态内部一致且与已有观察相容，仍可能包含因领域知识不足形成的错误判断。作者给出的后续方向是更紧凑的**潜在世界状态表示**（减少反复生成文本的开销）与在状态更新中引入**领域知识检索**（帮助模型解释专业证据）。

## 深度分析

### 一、主张的位移：把"当前理解"当一等公民，而不是把"历史"当答案

记忆与上下文工程的隐含假设是"证据越多，决策越好"，于是投入集中在检索、排序、压缩、截断。PoS 换掉的是这个前提：证据是原料，决策用的是**结论**，而结论必须能被单独书写、单独核对、单独作废。世界表示的三要素（实体／状态／关系）配上三项元数据（来源／置信度／可用支持证据），实质上给每条结论发了一张"可证伪的户口"。这解释了为什么 Sentinel 不是可选的性能优化：结论一旦写进状态，就从"一句话"升级为"后续所有动作的前提"，错误会被复利放大，而修正成本随步数指数上升。相形之下，长上下文与检索式记忆都只有"再取一次"，没有"作废"这个动作——它们管理的是证据的可得性，不是结论的有效性。参见 [工作集与长期记忆](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/working-set-vs-long-term-memory.md) 与 [记忆来源溯源](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/memory-source-provenance.md)：前者区分"在手边"与"在库里"，后者让证据可追，但都不回答"这条结论现在还成立吗"。

### 二、信息缺口／达成缺口的二分，把 explore–exploit 张力变成了可诊断单位

"还需要弄清楚的事"与"还需要通过行动改变的事"看似只是分类，实际是把一个模糊的"没做完"拆成两种**性质不同的失败**：一种缺证据，一种缺动作。这个二分的诊断价值在 RCA-100 案例里最清楚——"数据库等待还是 JVM 内部处理"被判定为信息缺口，于是正确动作不是继续翻日志，而是去找**能区分两种解释**的证据。换句话说，缺口类型决定了"下一步该做什么才有信息量"，而不是"下一步该做什么才像在工作"。它同时给出一个反直觉的推论：面对信息缺口时，更多同类观测是负收益——这恰好是大多数 Agent 在长任务里耗尽预算的方式。Active Gap 则是这个二分的调度器：完整状态仍可见，但只有一个缺口拥有行动权，避免"同时推进五件事、五件都不动"。

### 三、受困是信念层的属性，动作层指标系统性失明

"重复"是最容易测的，也最容易误判：同一工具连调十次可能在收集十份不同证据；每步换工具也可能一路绕开关键问题。Belief Health 的构造因此不是"数重复"，而是**缺口持续度 × 信念停滞度**：内层取停滞与重复中更强者（防止一个明显信号被另一个弱信号稀释），乘上缺口持续度把异常绑定到"长期没解决的要求"，外层再对两类缺口取更顽固的一侧。由此得到两条工程上极重要的规则：**任务未完成本身不构成受困**（区分"难"与"卡"），**部分单步拿到正向进展也不能掩盖持续循环**。后者是对过程奖励式监控的直接反驳——用单步奖励之和当进度条，会被"看起来在动"的轨迹系统性骗过；它也让"步数预算""工具调用多样性"这类便宜指标失去正当性。代价是判据变贵：必须先有经过校验的状态转移序列，才能谈进展，这也是为什么三个信号只在**最近 K 次校验过的转移**上计算。

### 四、恢复是"约束注入"而非"重规划"，所以天花板由知识而非搜索决定

Trapping-Aware Recovery 不换模型、不重开任务、不重置 Active Gap，只把"改哪段行为＋补哪类缺口"作为额外条件交回原智能体。这是一个成本极低的设计：干预是一条临时约束，策略连续性完整保留，健康度回升即释放。它的有效性来自把"换个办法"这种空话替换成**行为模式 × 缺口类型**的二维定位——Static 抑制状态-动作重复，Cycle 打破重复转移，Drift 重新对齐 Active Gap；模式说"停什么"，缺口说"补什么"。但这个设计也划出了它的天花板：约束只作用于**行为**，不增加**知识**。ALFWorld 的"漏掉加热"能被修好，是因为该发现一旦被点名就能被发现；如果智能体根本不知道"这类服务慢可能源于 GC"，约束只能驱使它去找证据，找不到就仍在原地。这正好对上作者的边界声明——健康度识别停滞，不验证答案，领域知识不足仍会写进看似自洽的状态。而受困模式分布（RCA-100 中 Drift 占 55.93%、ClinDiag 中 Static 占 78.25%）说明"卡"的形态本身由任务结构决定，通用恢复提示必然打偏：只让智能体"换个办法"，说不清该换哪段行为、该补什么。

### 五、5.06× 的代价结构，与 256K 稳定性说明的同一件事

总 token 达原始轨迹的 5.06 倍，但执行智能体自身反而少花约 20.9%——新增开销几乎全部是"元认知税"：维护状态、跑 Sentinel、算健康度。这笔钱买到的不是"更会做事"，而是"更早判断自己没在做有用的事"：联合准确率 24.27% → 38.83%，绝对水平仍不到四成，说明它治的是"卡住"，不是"不懂"（参见 [上下文窗口经济学](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/context-window-economics.md)：这里被交易的是每步推理成本，换的是诊断准确率）。LOCA-Bench 从 8K 拉到 256K 时 PoS 在 96K–256K 区间相对稳定，三个模型在 256K 下领先同设置最强对照 10.67–16.00pp，这与"每次观察即更新状态、后续决策只看当前条件"的设计同构：状态是上下文的一种**有损但可核对的压缩**，压缩掉了重建成本，保留了可作废性。把它与 [长程 Agent 架构](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/long-running-agent-architecture.md) 的常见分层对照，PoS 补的是"进展判据"这一层——多数架构有记忆层、工具层、编排层，却没有一层能回答"我们还在往前走吗"；[工具使用推理](https://github.com/QianJinGuo/wiki-public/blob/main/concepts/tool-use-reasoning.md) 关注单次调用的选择质量，而这里关注的是**调用序列整体是否收敛**。作者给出的两个后续方向（潜在世界状态表示、状态更新中引入领域知识检索）恰好对应本节两个瓶颈：文本化世界模型的生成开销，以及知识缺口无法靠约束闭合。

## 实践启示

**1. 与其加长历史，不如加一本"待办＋证据账本"。** 每条状态写成三元组（实体／状态／关系），强制带来源、置信度、支持证据三列。落地时最容易漏的是"支持证据"：没有它，状态退化成模型的自由叙述，Sentinel 也就无事可查。账本要能被整体重写，而不是只追加——追加式日志会退化为"更长的历史"。

**2. 写入前过一道"自洽 ＋ 有据"双检。** 用同一模型做一次廉价复核即可（论文中执行、维护、校验共用同一模型）：①同一对象不能同时处于互斥状态；②每条更新必须能指向具体观察，"看到杯子被放进微波炉"不等于"已加热"。修复后仍不过检，就保留上一版已提交状态——宁可旧而可信，不要新而可疑。消融数据说明这道检查不是锦上添花：去掉它，ALFWorld 88.81% → 73.88%、LOCA-Bench 56.38% → 44.57%，在执行型任务里它才是主力。

**3. 监控从"动作统计"切到"缺口是否在缩小"。** 具体做法：给每次状态转移打进展标签（缩小当前缺口／获得必要证据／推进合理完成路径／无进展），只在最近 K 次**通过校验**的转移上判读，并要求先积累足够样本（论文用 8 次）再启用判定，阈值 0.25 属可调工程参数。三条禁令值得写进监控规范：不用"动作重复"单指标告警；不用单步正向奖励之和当进度条；不把"任务还没完成"当受困证据。

**4. 恢复提示必须点名"停什么＋补什么"。** 模板：`当前为 <Static|Cycle|Drift>，阻塞于 <信息缺口|达成缺口>：停止 <具体无效动作>，下一步必须产出能 <区分解释|改变任务状态> 的证据/动作`。论文的对照很干脆——保留检测、把针对性约束换成通用"请尝试恢复"，四个基准上针对性恢复全部更高。同时保留 Active Gap 不变、约束临时化、健康度回升即释放，避免把一次干预变成永久紧箍。

**5. 按任务结构分配预算与开关。** 执行型（环境可改、缺口多为达成缺口）优先保一致性校验；诊断型（缺口多为信息缺口）优先保受困诊断与恢复——去掉后者 RCA-100 掉 4.85–6.79pp。成本侧按 5× 总 token 预留元认知开销；成本敏感场景可只在长任务或高价值诊断上开，或降低校验/健康度计算频率换取成本，但要接受"发现更晚、浪费更多步"的交换。

**6. 交付前留一道"答案不由健康度背书"的关卡。** 健康度高只说明在推进，不说明推对了。对诊断类输出，额外做一次"结论 ↔ 证据"对齐检查，并显式标注哪些结论依赖领域常识而非本案证据——这正是 PoS 自己声明的薄弱面，也是接入检索或人工复核的位置。

**7. 同一套判据可以搬到人类流程。** 周会问"这周做了什么"得到的是动作统计；问"哪个未解决问题动了、动了多少、下一步要的是证据还是动作"得到的是健康度。缺口二分在这里同样好用：把"卡住"的议题先判成缺信息还是缺决策，再决定是调研还是拍板——大多数无效会议是把达成缺口当信息缺口反复讨论。
