# 腾讯 TGR：生成式推荐技术栈的三条路径——重塑排序、替换级联、推理增强

> 📊 Level ⭐⭐⭐⭐ | 22.1KB

## 总览：三条路径同时走，不做单选题

TGR（Tencent Generative Recommendation）面对的是工业推荐系统的三个结构性瓶颈：**DLRM 范式不具备 LLM 式 scaling law**（embedding 查表 + 人工交叉结构受内存带宽限制，加参数加算力后效果饱和）、**级联架构的目标割裂**（各级独立优化独立截断，上游截掉的 item 下游看不到，用户看到的却是一屏有序列表）、**协同信号的覆盖边界**（冷启动、长尾、意图模糊三类请求恰恰最需要推理，而共现模式只能匹配）。

作者把生成式改造分成两条路：**重塑**（保留级联，用生成式技术换掉各层模型）与**替换**（用单一生成模型直接输出 item 或整屏 slate）。团队的判断是**两者不互斥、短期并存**，按数据规模与成本选路——于是 GenRank 走重塑，GenRec 与 Reason 走替换。技术栈分三层：排序层（GenRank）、生成与推理层（GenRec / Reason / Memory）、基础层（Numerous-Torch、用户建模、多模态理解、SID 模型），共五个方向：TGR-SID（全场景统一语义 SID，也是共享解码空间）、GenRank、GenRec、Reason、Loop（多智能体自进化，研究中）。

## TGR-GenRank：CCFormer 用半算力打赢 HSTU

### 两条既有范式各有硬伤

**范式 A（DLRM）**：算力利用率高（交互骨干只处理压缩后的少量表示），但**序列先压缩后交叉**——细粒度序列信息、候选与历史行为的精细匹配在进入骨干前就丢了。**范式 B（统一 token 化 + attention，HSTU/ULTRA-HSTU/OneTrans）**：用户画像、行为序列、候选统一编码成一条 token 序列，attention 一次完成序列内与跨域交叉，**首次呈现可预测 scaling**（HSTU 扩到万亿参数、线上 A/B +12.4%），但 self-attention 对序列是 O(L²)，万级长序列在工业延迟预算下算不动，后续工作都在注意力上做减法。

### 三个机制

1. **特征域分离的交叉注意力**：把跨域交叉与序列内交互解耦，避免不同特征域在同一注意力里互相干扰。
2. **子空间相对时空位置编码**：把长序列划成相邻 m 个 token 的子序列，在子序列上分别计算相对时间与相对位置的参数矩阵并注入，**复杂度从 O(L²) 降到 O(Lm)**。
3. **层级序列压缩 + 长序列 token mixing**：用卷积式 token mixing 与层级压缩替代原生 self-attention，把长序列建模的成本压下来（训练加速 2.21× 的主要来源）。

### 数据

- 40 亿样本真实业务数据：**AUC 77.94% / GAUC 71.36%**，相对 HSTU（77.66% / 70.86%）分别 **+0.28 / +0.50 个百分点**（相对提升 1.01% / 2.40%）。
- **scaling 更强**：特征维度 128→512、序列长度 0.5K→2K 都持续提升，且**领先幅度随规模扩大**（ΔAUC 0.84%→1.22%，ΔGAUC →2.4% 左右）；每个维度下 GFLOPs 仅 HSTU 的三至六成。
- **0.5K 序列 ≈ HSTU 2K 序列**的效果；KuaiRec 上同结论（200 长度接近或超过对手更长序列）。
- 消融（真实业务集）：完整版 AUC/GAUC 77.94/71.36、训练加速 **2.21×**；去掉相对时空编码 GAUC→71.13；token mixing 换回 self-attention GAUC→71.21 且加速降到 1.41×；去掉 token mixing →71.02；去掉序列压缩 加速→1.29×。

## TGR-GenRec / BARGE：修 NTP 路线的两个结构性缺口

### 缺口一：Item Boundary Gap

推荐自回归把 item 编成多层语义 ID（SID），一个 item 是多个 token；展平成序列后**item 边界丢失**，模型不知道哪几个 token 属于同一件商品。

### 缺口二：Semantic Drift（更致命）

层级解码一旦某一层走岔，之后每层都只在错误子树里搜索，目标 item 被永久排除。量化很刺眼：第三层目标在 teacher forcing 下概率 **0.787、排名 7.4、准确率 80.5%**；自回归整体只剩 **0.015、119.5、1.6%**（概率掉到约 1/52）。按前缀拆开看——**前缀正确时准确率 77.0%，前缀出错只剩 0.6%，相差 128 倍**。

### 四个模块（都不改 NTP 骨架）

1. **OSQ-VAE**：正交旋转后一分为二，为每个 item 产出**互补的两套 SID**，双解码器并行。
2. **ICA Block（Item Context-Aware Attention）**：进 encoder 前用可学习 query 对同一 item 的 L 个 SID token 做 cross-attention pooling 得 item context，再以**门控残差**注回每个 token——实测门控强度处于中等区间，模型选择"补充"而非"覆盖"SID 信息。
3. **HPR Block（Hierarchical Path Reranking）**：用**全局路径一致性**重排局部 token 概率——用累计路径与 decoder 初始隐状态 h₀ 打分、逐层重排 beam；训练用 InfoNCE，正样本是 h₀ 与真值 item 的累计前缀，负样本含同批次其他路径、**NTP 高概率错误前缀**、已曝光未点击等业务负样本（针对 PROMISE 负样本太"容易"的问题）；推理分数 = 生成分数 + λ×路径匹配分数；每层 Top-N 扩展评分池但 beam 宽度不变，h₀ 每层只算一次。
4. **DPD（Dual-Path Decoding）**：两条通路共享 encoder、decoder 与 HPR 私有，item 空间 soft-OR 融合，任一通路高分即可恢复；两路**经验上真互补**——双路 Top-10 的 Jaccard 仅 0.172–0.183（前 10 名约 3 个重合），OR 命中中 **15.6%–24.3% 仅由单路贡献**。

一条反直觉的工程结论：**仅增加判别式结构容易与 decoder 概率同质化**，有效收益来自**额外监督**（曝光未点击、NTP 高概率错误前缀）与多目标信号；把 target 侧特征引进来要靠另一条结构——User–Item 双塔训练时用对比损失把 target 特征带进用户向量，推理时只需把用户向量以 soft prompt 注入 decoder 起始位置，这一步把 Hit@1 从 0.3749 提到 0.4088（+9.0%）。

### 数据

- 公开集全库评估（Beauty / Sports，对 TIGER、HSTU、COBRA、ActionPiece、APAO-pointwise）：BARGE 全部报告指标最佳；Beauty R@10 **0.0927**、N@10 0.0547；Sports R@10 0.0544、N@10 0.0308；Beauty R@10 相对最强列内基线 **+16.6%**、相对 TIGER **+43.1%**。
- 关键对照 **BARGE-base**：保留 ICA/HPR/DPD 但换回 TIGER 3 层码本，仍超过全部生成式基线（Beauty 0.0896、Sports 0.0513）——**证明结构模块收益不依赖特定码本、可跨数据集复现**，从而把"结构收益"与"码本收益"分开归因。
- 工业两场景 Hit@5/@10/@20/@50 全优：场景 1 Hit@5 **0.5459→0.6015（+10.2%）**，场景 2 **0.0835→0.0976（+16.9%）**（对比 OneRec）。
- 线上 A/B（小说推荐，两周、6% 流量，对照现网多阶段召回）：**CTR +0.60%、点击 UV +1.34%、总阅读时长 +1.70%**，三项统计显著；全量后保留的长期反转组显示提升幅度更大更稳。作为单路召回，**曝光采纳率 1.02%**（与图召回 1.03% 同处第一梯队）、**曝光后 CTR 9.93%** 为四路最高——说明带来的是现有通路未覆盖的增量。

## TGR-GenRec / HiGR：把生成单元从 item 升级为 slate

### 三个断层

item 级生成到 slate 级优化之间有三处断裂：**规划缺失**（逐 item 生成无法保证整屏的兼容性、多样性与位置效应）、**列表内相互影响**（item 之间不是独立事件）、**逐 token 目标与列表级偏好的错位**（生成概率不等于列表质量）。

### 三个设计

1. **PCRQ-VAE（前缀约束的 RQ tokenizer）**：不同于逐层累计的量化损失，对量化器前后的编码向量与重构向量构造**全局损失**，抵抗残差消失，迫使深层码本承载有效信息。消融给出精确的最优点：**只对前 D−1 层施加对比约束（prefix2）最优**——碰撞率 **2.37%**、集中度 93%、一致性 **66.47%**（较 RQ-VAE +10.7pp）；把约束延伸到叶子层（prefix3）会"身份坍缩"，碰撞率升高近 4 倍（0.0237→0.0873）。**前缀级约束是"语义层级"与"item 唯一身份"的平衡点。**
2. **HSD（层次化 slate 解码器）**：先规划整屏意图，再轻量解码 item；**深度分配 14 层规划 + 2 层生成**为最佳生产配置——相比 12:4 时延 **-26%**、NDCG@5 仅 -0.6%；继续给生成器加层效果持续下降（10+6 → 0.0621，8+8 → 0.0605），15+1 时延只再降一点但 NDCG@5 掉到 0.0623。**算力应主要投在"规划整屏意图"上。**
3. **ORPO listwise 对齐**：GRPO 的核心假设是"环境能对每次采样即时准确反馈"，而列表级推荐不满足；改用 listwise 的 ORPO 做多目标偏好对齐。效果：去掉 L_ILD 后准确性几乎不变（NDCG@5 0.0753→0.0755）但 ILD 0.62→0.59，说明该正则**在不牺牲准确性下提升列表内多样性**；对齐后 DPO 把 ILD 提到 0.57/0.60，**ORPO 达到最高 0.62/0.63**——"多样"作为显式对齐目标得到直接验证。

### 推理加速与数据

- 加速三件套：**beam 折叠进序列维**的 K/V 投影优化 + **Flash Attention**（减少 HBM↔SRAM 读写、突破显存带宽瓶颈）+ **KV cache**。
- 对比（同为 25M 参数，对 ListCVAE/BERT4Rec/SASRec/TIGER/HSTU/OneRec-25M）：工业数据 5 指标全超 OneRec-25M——**Impressions Hit@5 +15.9%、Effective Views Hit@5 +21.3%、NDCG@5 +21.2%**；KuaiRec NDCG@5 +5.2%。
- **scaling**：0.05B→2B 收敛 loss 下降、NDCG@5 上升；推理吞吐（万请求/分钟）vs recall@5 的曲线上，HiGR（含/不含 KV cache）都在 OneRec beam 解码的右上方——**吞吐高数倍且 recall 更高**。
- 已全流量三场景：场景 1 人均停留 +1.03%、人均观看 +1.22%、人均视频播放 +1.73%、人均请求 +1.57%；场景 2 CTR +0.68%、广告收入 +0.56%；场景 3 人均观看 +1.14%、人均播放 +0.88%——**且收益出现在推理成本下降的前提下**（推理 5×+、训练 2×+、成本 -60%）。

## TGR-Reason：把"思考"搬出请求路径

### 为什么现成方案放不进延迟预算

显式推理（OneRec-Think / OneReason）每请求多出数百 CoT token；隐式推理（ReaRec / STREAM-Rec）每请求多 K 步前向。**共同问题是推理容量与每请求计算绑定**——多想一步就为每个请求多付一步延迟；搬到离线也只是转移成本（推理结果随请求产出，每次曝光仍要算一次）。

### LatentRec：训练期展开，生成期不展开

- **连续思考模块 CTM**：用户历史经 LLM Encoder 得 h₀，CTM 迭代 K 次（h_k=h₀ 起），由 SID Decoder 输出完整 SID。
- **STS（Soft Token Selection）解决尺度不匹配**：hidden state 范数约 45、词表 embedding 约 3，**相差约 14 倍**，直接反馈会改变下一步输入的尺度与方向；STS 维护 64 个可学习向量（由词表 embedding 初始化），隐状态经 W_q 形成 query 对 token bank 做 softmax 加权，得到下一步输入。
- **PRL（Per-step Reasoning Loss）**：每个中间状态过同一个 LM head 预测**首层 SID**，各步 CE 平均，L = L_CE + 0.1·L_PRL，温度递减（T₁=3.5、T₂=1.0，早期软后期聚焦）。只监督首层是为避免把 latent 轨迹与固定解码路径耦合。
- **训练 K_train=2 / 生成 K_eval=0**：生成时跳过 CTM 展开，直接用训练中更新的共享 LoRA 与标准 SID 解码——**推理成本在训练期摊销**。规模很小：Qwen3-1.7B + LoRA rank 16 + 64 个 soft token（约 2.5M 参数，**新增参数 < 骨干 0.2%**），3 epoch、bs 64。

### TGR-Reason 系统：三层快慢协同

共享一个以 user_id 为键的 **Reason Store**：**Part A 在线（毫秒、只读）**按 user_id 点查记录、校验有效期与版本后以 token/特征注入 GenRec/GenRank；**Part B 近线（秒级、请求触发）**异步发事件，Reason Trigger Controller 判据决定算不算，准入任务进常驻 GPU 池攒小批计算，结果写 Redis 供后续请求；**Part C 离线（日级、吞吐优先）**扫日志与存储元数据识别待重算用户、弹性大批量池重生成，周级重训后把不兼容记录标为待重算并渐进重建。

落地两种方式：**离线召回**（Reason Store 的 topk_sid 经 SID 倒排映射到 item，过滤去重合规库存后进独立配额队列）与**在线生成**（topk_sid / cot_emb 经 GMR/DRI 注入 GenRec 的 Encoder-Decoder 解码，生成 SID 再映射 item），实现**服务时零推理 rollout**，线上 A/B 在新用户指标上显著提升。

## TGR-Loop：把演进本身交给多智能体（研究中）

最后的方向是**推荐系统的 Agentic 自进化**：在 ROI 约束下，让 LLM 多智能体在有限算力与线上流量预算内**自主提出、验证并沉淀模型改进**，把"离线迭代 + 小流量求证"连成可控、可审计的闭环。技术报告已公开（arXiv 2609.00986），未来三层探索：生成式推荐的 scaling 效率、推理原生的生成与 test-time 计算、Agentic 自进化。

## 深度分析

### 三条路径其实是"瓶颈定位表"

GenRank 打的是**算力效率**（同样效果用一半算力），GenRec 打的是**决策单元与目标的割裂**（逐 item→整屏），Reason 打的是**协同信号之外的"推断"**。作者没有说"生成式一定更好"，而是按"当前最痛的是哪一段"选工具——重塑还是替换取决于数据规模与成本。**这种"按瓶颈选范式"的分法，比"端到端 vs 级联"的立场之争有用得多。**

### 把"结构性缺口"量化，是这篇最有价值的方法论

Semantic Drift 那段数据（前缀正确 77.0% vs 出错 0.6%，**128 倍**；整体概率掉到 1/52）不是修辞，而是把一个"感觉会漂移"的问题变成**可测的失效边界**。有了这个量级，才能解释为什么 HPR 要按路径一致性重排 beam、为什么 DPD 要两条通路——**都是针对"前缀错了就全错"这一失效模式的结构解**。

### 判别式结构容易与生成概率同质化

"仅增加判别式结构容易与 decoder 概率同质化，有效收益来自额外监督"——这条经验对任何做"生成 + 重排"的团队都适用：**在同一个信号空间里再叠一层打分，往往只是把同一信息换了个形状**；真正带来增益的是**新信息**（曝光未点击、NTP 高概率错误前缀、target 侧特征）。

### BARGE-base 这个对照，是实验设计上的亮点

换回 TIGER 3 层码本、只保留结构模块，仍然全面超过生成式基线——**把"结构收益"与"码本收益"解耦**。多数论文只报"我们的完整方案更好"，读者无法判断哪一部分在起作用；这个对照直接回答了"如果沿用你原来的 tokenizer，你的结构还有用吗"。

### 深度分配 14+2 揭示了 slate 生成的算力结构

规划层要深、生成层要浅（12:4→14:2 时延 -26%、NDCG -0.6%；继续加深生成层反而变差）。含义很直接：**列表质量的决定权在"想清楚这一屏要什么"，而不是"逐 token 写得多精细"**。这条对做 agent 输出规划同样成立。

### Reason 的真正创新是"把推理变成可缓存资产"

LatentRec 在训练期展开、生成期不展开（K_train=2 / K_eval=0，新增参数 <0.2%），TGR-Reason 再把推理结果物化成 **reason tokens 存进以 user_id 为键的 Store**（在线只读、近线按需、离线兜底）。这解决了"推理容量与每请求计算绑定"的根本矛盾——**推理从"每次请求都要付的成本"变成"可以按新鲜度与预算调度的资产"**。

### 收益要按场景读，而不是加总

GenRank 给的是离线 AUC/GAUC 与训练加速；BARGE 给的是公开集 R@10 与小说场景 A/B（CTR +0.60% 等）；HiGR 给的是三个全流量场景的时长/收入指标，且**建立在推理成本下降 60% 的前提下**。这些数字量纲不同、基线不同，**不能相加，也不构成"整体提升 X%"**——但它们共同证明了一件事：三条路径都已在真实流量上跑通。

## 实践启示

1. **先定位瓶颈再选范式**：算力效率→重塑排序；决策单元割裂→替换级联；语义/推理缺口→推理增强。三者可并存。

2. **长序列用"子空间 + 压缩"，别硬扛 O(L²)**：子空间相对时空编码把 L² 降到 Lm，token mixing 替代原生注意力。

3. **层级 SID 的第一风险是前缀错误**：先把"前缀错则全错"量化，再用路径一致性重排 + 双通路解码兜底。

4. **想加结构收益，先加新的监督信号**：同空间的判别式叠加容易与生成概率同质化。

5. **做对照要能分离变量**：BARGE-base（换码本保结构）这类设计，比"完整方案 vs 基线"更有说服力。

6. **slate 生成把深度给规划层**：14 规划 + 2 生成是质量与时延的折中点。

7. **列表级对齐用 listwise 偏好方法**：GRPO 的"即时准确反馈"假设在推荐里不成立，ORPO 的多样性收益可测（ILD 0.62/0.63）。

8. **推理不要放进请求路径**：训练期展开、生成期跳过，再把结果物化成可缓存的 reason tokens，按新鲜度调度。

9. **每个收益都标清基线、口径与前提**（是否同参数、是否含成本下降），否则数字无法比较。
