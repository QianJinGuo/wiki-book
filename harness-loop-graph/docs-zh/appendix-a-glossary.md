# 附录 A 术语表

按拼音/字母序。术语后的括号内为英文原文。

**AGENTS.md / CLAUDE.md**：编码智能体的项目级指令文件，"写给 Agent 的架构文档"；实践中承担"免疫系统"角色——每次犯错追加一条规则。约 100 行当目录表是最佳实践。

**编排税（Orchestration Tax）**：并行 Agent 产出超过人类审查带宽导致的浪费。审查带宽是并行度的真正上限。

**闭环（Closed Loop）**：带验证门禁、停止条件、回滚与人工介入的循环；与开环（定时重跑、无反馈）相对。

**开环（Open Loop）**：无反馈的循环（如纯 cron 重跑）。Agent 会在循环中重复并自我确认错误，必然失败。

**蓝图模式（Blueprint）**：Stripe 实践——确定性节点"夹住"概率性 LLM 环节，Agent 最多尝试 N 轮（如 2 轮 CI），要么成功要么转人工。

**首次合理方案偏见（First Plausible Solution Bias）**：模型对第一个看似合理方案的固守——写完重读自己的代码"看起来 OK"就停。对策是退出前检查清单。

**CP 检查点（Checkpoint Summary）**：阶段结束时把上下文强制压缩为固定格式摘要（结论+关键信息+待关注事项）再传给下游，不传整段对话历史。

**上下文腐化（Context Rot）**：无关内容占窗口多数篇幅后决策质量系统性下降；经验阈值：填充率约 40%。

**生成-评估分离（Generator-Evaluator Separation）**：生成者与验收者必须是不同实例；模型自评系统性偏乐观。Evaluator 三形态：环境验证、确定性工具、独立模型。

**扇出/扇入（Fan-out / Fan-in）**：图编排中一个节点同时触发多个并行节点（扇出）、合并节点等待全部前驱（扇入）。

**Harness（驾驭层）**：环绕模型的完整控制基础设施——上下文供给、工具与权限、状态与记忆、可观测、人工治理。中心公式：`Agent = Model + Harness`。

**Harness 衰减（Harness Decay）**：模型升级后，旧 Harness 组件从资产变摩擦的现象（如 Opus 4.5→4.6 去掉 Sprint 分解省 38% 成本）。

**条件边（Conditional Edge）**：图编排中根据当前状态动态决定下一节点的边；路由函数应为纯函数。ReAct 的本质即条件边循环图。

**渐进式披露（Progressive Disclosure）**：默认只注入能力名称与描述，需要时才加载全文；上下文工程第一杠杆。

**JSONL Inbox**：子智能体通信协议——每个子智能体一个 JSONL 收件箱文件，追加写入，轮询消费。

**Loop Engineering（循环工程）**：构建驱动 Agent 自主循环的系统而非单个提示词。Loop = 触发 + 决策器 + 验证 + 预算 + 状态。层级：Loop > Harness > Context > Prompt。

**MVH（最小可行 Harness，Minimum Viable Harness）**：五件事起步——AGENTS.md、验证命令、feature_list.json、progress 文件、完成门禁。

**Pass@k / Pass^k**：k 次中至少一次成功（探索上限）/ k 次全部成功（上线回归能力）。生产决策看后者。

**Redo…（错误喂养规则库）**：Harness 运营闭环——AI 犯错→转化为规则/测试/约束→更新规则库→同类错误不再犯。

**Reducer**：图编排中状态字段的合并函数；节点返回增量片段，Reducer 合并成新快照；状态不可变。

**Shadow 验证（影子运行）**：新旧系统并行对照（生产实录：22,792 次调用、99.49% 一致）。过渡手段，非永久架构。

**Skills**：固化项目知识/操作模式的制品（SKILL.md）；程序性记忆的载体。作者格式，区别于 Plugin（分发格式）与 Bundle（部署格式）。

**Spec 文件驱动**：多智能体协作模式——Agent 间不直接对话，通过结构化文件交换信息；可追溯/可审计/可恢复/可解耦/可隔离。

**Sprint 契约（Sprint Contract）**：生成者与评估者在开工前协商"什么叫完成"的约定文件。

**Token 瘫痪（Token Paralysis）**：工具过多导致模型在选择工具上浪费注意力。对策：确定性编排器按需筛选（Stripe 500→15）。

**L1–L6 任务分级**：按可验证性划分的自主级别。L1/L2 可全自动；L3 抽查；L4 计划审批；L5 资金/身份动作级人审；L6 人主导。

**外循环（Outer Loop）**：跨会话的教训持久化——把对的教训、用对的颗粒度、写到对的地方（AGENTS.md、进度文件、规则库）。

**工作集（Working Set）**：当前决策真正需要的最小上下文集；供给链模型"总上下文→筛选→工作集→决策"的核心。

**三明治推理（Sandwich Reasoning）**：规划高推理 + 实现中推理 + 验证高推理（66.5%）优于全程高推理（53.9%）。

**三路检索融合**：BM25 + 向量 + 图检索用 RRF 融合；解决代码场景精确关键词被向量稀释的问题。

**主观线/主权（Sovereignty）**：不随模型进步消失的五件工作——意志注入、权限授予、环境供给、边界划定、治理审计。主权不可自生。

**状态机三要素**：State（数据快照）/ Node（执行动作并更新状态）/ Edge（决定走向）。图编排的本体。

**doom loop（死循环）**：Agent 在同一坏方案上反复微调不收敛。止血带四档：计数提醒→回滚→预算熔断→错误回写。

**fail-closed（默认拒绝）**：护栏规则引擎异常时默认拒绝而非放行。

**Factory Model（工厂模式）**：多循环协同产出软件的形态——需求/实现/审查/部署循环各司其职，确定性门禁传递制品。

**feature_list.json**：Anthropic 长程任务模式的核心工件——功能清单带 `passes: false/true` 状态，JSON 优于 Markdown。

**Git 检查点**：增量提交作为状态快照，失败可回滚——回滚机制的默认实现。

**hook**：智能体生命周期事件上的自动拦截（如 PostToolUse 检查）。"hook > 文档"：说明是请求别做，hook 是做不到。

**LLM-as-a-Verifier**：把模型裁判工程化——细粒度评分、K 次重复取期望、规范/输出/错误三因素分解；Terminal-Bench 2.0 平局率 27%→0%、准确率 86.4%。

**Markov Blanket 注入**：只注入与当前决策因果相关的上下文（对照：全量注入 143 条关系使误报率翻倍）。

**MCP（Model Context Protocol）**：Anthropic 2024 年底发布的模型-工具/数据连接协议。表征成本约为 CLI 的 32 倍，接入前先算 token 账。

**One-shot Syndrome**：长任务中会话上下文耗尽后，Agent 看到部分进展就提前宣布完成而不验证。

**Ralph Loop**：2025 年出现的结构化循环验证实践，/goal、/loop 等 2026 年产品化命令的前身。

**Salt Signatures**：Google 提出的模型层状态持续路线——调用工具前生成加密推理状态，传回对话恢复推理链路。与 Harness 层外部制品路线并行。

**WIP=1**：一次只做一个功能/一个 PR——最安全的默认并发度。
