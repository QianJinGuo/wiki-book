# 第 5 章 让循环持续：外循环、预算与编排税

!!! abstract "学习目标"
    - 掌握持续循环的六个必备组件与六个原语，并能在 Claude Code / Codex 中指出对应物；
    - 会做 loop 化的准入判断：重复频率 × 失败成本；
    - 理解外循环（跨会话状态记忆）为何是当前最大的价值洼地；
    - 正视编排税：你的审查带宽是并行度的真正上限。

第 3–4 章解决的是"一次任务怎么跑对"。但工程师的真实日子里，大量任务是**重复发生**的：CI 又红了、依赖又升级了、监控又报警了。Loop Engineering 的后半场，是让循环在无人值守下持续、安全、经济地运转。Boris Cherny 的"三个高度"模型给这场升级画了坐标（`topics/agent-harness-deep-dive-qa`）：

| 高度 | 模式 | 人的角色 |
|------|------|---------|
| 1 | 带自动补全的手写代码 | 仍在循环内 |
| 2 | 并行运行多个 Agent 会话 | 做决策和指挥 |
| 3 | 编写 Loop 替你 Prompt Agent | **只在循环卡住时介入** |

Anthropic 2026 年 6 月发布的《When AI builds itself》给了这三级台阶一个刻度：Claude 写的代码占其合并总量超过 80%；工程师日均代码合并量为 2024 年的 8 倍；开放式任务成功率从半年前的 26% 升至 76%。Boris Cherny 本人最近 30 天对 Claude Code 仓库的 259 个 PR 全部由 Claude Code 自己写的——他的工作是设计让 Claude Code 写代码的循环。

## 5.1 持续循环的六个必备组件

若飞在《Loop Engineering 工程现场》中给出的清单，是实践里最完整的一版（`entities/loop-engineering-feedback-control-system`）：

1. **自动触发**（cron、`/goal`、`/loop`）——循环不能依赖人按下回车；
2. **隔离工作区**（worktree、临时分支）——避免并发覆盖，烧坏了能整段丢弃；
3. **过程资产**（Skills、规则、模板）——不用每轮重新解释上下文；
4. **外部连接**（MCP、插件、CLI）——否则循环只能看本地文件；
5. **独立验证**（子智能体/审查者/测试）——避免"自写自审"的反馈缺失；
6. **状态记忆**（plan.md、issue、日志）——让下一轮能接上前一轮。

这套清单与 Addy Osmani 总结的 **Loop 六原语**一一对上，且同时映射到 Claude Code 与 Codex——说明它是循环本身的结构，而非某家工具的私有设计（`topics/agent-harness-deep-dive-qa`）：

| 原语 | 角色 | Claude Code | Codex |
|------|------|-------------|-------|
| Automations | 定时发现与分诊（循环的心跳） | `/loop` + hooks + GitHub Actions | Automations + `/goal` |
| Worktrees | 并行隔离 | git worktree + isolation | 内置 worktree per thread |
| Skills | 固化项目知识 | SKILL.md，隐式匹配 | SKILL.md，`$name` 调用 |
| Connectors | 连接外部工具 | MCP servers + Plugins | MCP Connectors + Plugins |
| Sub-agents | 制作与审查分离 | `.claude/agents/` + agent teams | `.codex/agents/` TOML |
| State | 跨会话记忆 | AGENTS.md / progress files | Markdown / Linear |

**一个真实循环的完整形状**（综合自一线实践）：

```
1. Automation 每天早上触发 → 调 $triage skill 扫描 issue/CI → 写入 progress.md（State）
2. 循环读 progress.md 取最高优先级任务
   → 派子智能体 A（实现者，快模型）在独立 worktree 工作
   → 完成后派子智能体 B（审查者，强模型）
   → 通过 → 开 PR + 关联 issue（Connector）；不通过 → 反馈写回，A 重试
3. /goal 判断："所有 P0 issue 关闭且 CI green" → 满足则终止并通知人；
   超过迭代上限则升级
4. 预算控制：最多 15 轮 / $5 / 300 秒
```

## 5.2 状态记忆：外循环的家

第 3 章说过，外循环（跨会话教训持久化）是价值洼地。它的机制核心是第 4 条与第 6 条组件的组合：**状态记忆必须外部化**——写在磁盘上（progress 文件、issue、Git 历史），不依赖任何一次会话的上下文。会话会结束，上下文会被清空，仓库不会遗忘。

第 9 章会展开状态记忆的完整设计（feature 清单、启动序列、检查点）。这里只强调一条纪律：**循环的每一轮开始时，恢复状态靠读文件，不靠模型回忆。** 没有状态记忆的循环会退化成"每轮独立运行"的无记忆重复——每轮都重新犯错。

## 5.3 预算：三维保险丝

持续循环的第一个杀手是成本失控。参考量级（`entities/loop-engineering-feedback-control-system`）：单智能体循环 5–20 万 token/次；舰队循环 50–200 万 token/次；每天定时的循环，一周就是数百万 token。**每个循环必须有三维预算上限：token 数量、时间长度、累计成本**——没有熔断器的电路不该通电。

预算设计的三个实务点：

- **三维上限取最小**：任一触顶即停，不要等三项全满；
- **分级预算**：低风险读/查用轻量配置，高风险写/执行才用完整验证链（`entities/harness-engineering` 的按风险分级策略）；
- **监控三指标**：成功率、回归率、token 效率。每月复盘，据此调循环频率与验证器严格度（`moc/loop-engineering` 的实践路径）。

YC 的 Garry Tan 提醒过另一个方向的失控：不要把 Agent 变成"富士康工厂"式的重复劳动机器——循环应该是"带反馈的智能循环"而非"机械重复的自动化"。判断一个循环是否健康，看它的验证门禁是越来越准，还是形同虚设。

## 5.4 编排税：审查带宽是并行度的真正上限

持续循环的第二个杀手更隐蔽：**人的审查带宽**。5 个并行 Agent 各开一个 PR，但你每小时只能认真审 1 个——另外 4 个在排队烧 token，这就是编排税（`topics/agent-harness-deep-dive-qa`）。

推论有三条：

1. **并行度 = 审查带宽 ÷ 单位产出审查成本**。想并行，先降单位审查成本（更好的验证器、更小的 PR、更高的自动化通过率），而不是先开更多会话。
2. **Stripe 的路线是先修路再跑车**：它能跑无人值守的 Minions（每周 1300+ PR），前提是多年建设的人类开发者基础设施——10 秒起的 devbox、300 万个测试。**为 Agent 做的最好准备，就是本来就该做好的工程实践。**
3. **等待很贵，纠正很便宜**（同一实录中的注意力经济学）：让人等 Agent 不如让 Agent 排队等人审；把人的注意力花在关键决策暂停（删库、扣费、发邮件）上。

## 5.5 什么任务值得 loop 化

不是所有重复任务都该上循环。准入判断只有一个乘法（`entities/loop-engineering-feedback-control-system`）：

> **重复频率 × 失败成本 > 阈值，才值得 loop 化。**

- 重复性高但失败成本低（每天清理日志）→ cron 就够，别上循环；
- 失败成本高但一次性（跨服务迁移）→ 上循环，但按项目制管理，结束后拆掉；
- 两者都高（CI 失败修复、依赖升级、监控响应）→ 循环的最佳主场。

**判断顺序的完整版**（把第 2 章的裁决接上）：确定性 API → 单次调用 → 薄循环 → 重 Harness。循环是工具箱里的一档，不是默认档。

## 5.6 从循环到工厂：下一层预告

层级图的最顶端是 Factory Model：让多个循环协同产出软件——需求循环、实现循环、审查循环、部署循环各司其职，确定性门禁在它们之间传递制品（`topics/agent-harness-deep-dive-qa`）。Stripe Minions 与 OpenAI 团队 5 个月约 100 万行代码的实践已经是它的雏形。再往前是递归自我改进——Anthropic 的数据显示 Claude 优化训练代码的加速比从 3 倍涨到 52 倍，"Claude 正在帮助训练下一个 Claude"。那是本书的终点站（第 13 章），也是需要提前设防的风险。

## 5.7 反模式

- **为"看起来高级"上舰队循环**。单循环没跑稳就上编排，把单份问题放大 N 份（第 11 章的完整判断标准）。
- **预算只设 token 一维**。时间与成本同样要设限；长循环最常见的爆炸是"每步都便宜、总数无上限"。
- **状态记忆靠对话历史**。跨会话恢复靠读文件；聊天记录是低质量记忆载体，丢"为什么"只留"说了什么"。
- **无人值守越过 L4**。循环自动化等级不得超过任务的可验证等级（第 2 章 L1–L6）；涉及资金、身份、外发的动作必须保留人工门禁。

## 5.8 本章小结

- 持续循环六组件：触发、隔离、过程资产、外部连接、独立验证、状态记忆；六原语在 Claude Code 与 Codex 中各有对应物。
- 准入判断是乘法：重复频率 × 失败成本；顺序是确定性 API → 单次调用 → 薄循环 → 重 Harness。
- 预算三维保险丝（token/时间/成本）+ 三指标监控（成功率/回归率/token 效率）。
- 编排税决定并行度上限；先修路（测试、门禁、devbox）再跑车。
- 外循环（状态记忆外部化）是当前投入产出比最高的一层。

## 5.9 练习

**动手**

1. 挑一个"重复频率 × 失败成本"都高的真实任务（推荐：依赖升级或 CI 修复），按 5.1 节六组件清单搭一个最小循环，跑一周。记录：成功率、回归率、token 消耗、你花的审查时间。
2. 给你的循环接入三维预算上限，并故意把上限调到极小值验证熔断路径——熔断不可测试的循环等于没有熔断。

**思辨**

1. 用"三个高度"自评：你现在的日常工作在第几级？升到下一级的第一块短板是什么——验证器、状态记忆还是审查带宽？
2. "为 Agent 做的最好准备，就是本来就该做好的工程实践"——这句话反过来读是什么？（如果你的测试套件烂到 Agent 都用不了，先修的是谁的债？）
