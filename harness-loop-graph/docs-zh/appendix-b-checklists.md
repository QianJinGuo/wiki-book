# 附录 B 检查清单合集

全书 7 张清单收口于此，可直接打印使用。出处见各清单末尾与附录 C。

## B1 最小可行 Harness：A 面（启动阶段）

从零到第一个可用的 Agent Harness：

- [ ] 写 AGENTS.md/CLAUDE.md（项目宪法：领域、技术栈、约定、危险操作清单，约 100 行以内）
- [ ] 写验证命令（"应该跑测试"→ completion 前检查测试结果）
- [ ] 建 feature_list.json（功能点 + `pending/in_progress/completed` 状态）
- [ ] 建 progress 文件（每次会话的进展记录）
- [ ] 设完成门禁（提交/PR 必须在验证通过状态下合并）
- [ ] 默认 WIP=1；工具先砍 80% 按需加回；从单智能体开始

> 心法：AGENTS.md 是软控制（"请求别做"），验证/权限/hook 是硬控制（"做不到"）。

## B2 最小可行 Harness：B 面（迭代阶段）

从"能用"到"不会炸"：

- [ ] 建立瓶颈三问习惯：症状在 Prompt 层（理解错）、Context 层（忘了）、还是 Harness 层（执行路径错）？
- [ ] 建立"错误→规则"管道：每个真实故障转化为一条规则/测试/约束
- [ ] 每次模型升级跑组件保质期检查（见 B6）
- [ ] 安全基线：部署前（权限沙箱 + 危险清单）、执行中（fail-closed 拦截）、输出后（审计日志）三层各至少一项
- [ ] 高风险场景（运维/金融/医疗）：全五层 + 人工审核节点 + 回滚 + 变更审计

## B3 循环上线检查单

每个要持续运转的循环：

- [ ] 验证门禁独立于生成器（不信模型自述）
- [ ] 四种停止路径已写明：通过 / 达成 / 超预算 / 回滚
- [ ] 三维预算上限：token / 时间 / 成本，任一触顶即停
- [ ] 回滚机制可用（Git 检查点），熔断路径实测过
- [ ] 状态记忆外部化（progress 文件 / issue / Git），新会话从文件恢复
- [ ] 隔离工作区（worktree / 临时分支）
- [ ] 准入判断：重复频率 × 失败成本 > 阈值；顺序：确定性 API → 单次调用 → 薄循环 → 重 Harness
- [ ] 监控三指标：成功率、回归率、token 效率；设月度复盘

## B4 模型迁移检查表

换模型（或升级版本）时逐项检查：

- [ ] 工具 Schema 兼容性（名称、参数格式）
- [ ] 引用/记忆标签格式一致性
- [ ] 系统提示结构是否需要调整（旧硬规则可能已被新模型内化——审计上下文责任归属）
- [ ] 历史对话是否 OOD（新模型对旧 transcript 的推理）
- [ ] Prompt 缓存清空；tokenizer 是否变化（全部缓存失效）
- [ ] 跑基准：20–50 个真实任务，模型轴 × 任务轴交叉，一次只改一个变量
- [ ] 监控四信号：任务做对？过程变差？旧失败回潮？高风险边界被碰？

> 技巧：派子智能体用另一个模型，而不是切换主对话模型。

## B5 POC → 生产（十项）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | Harness Dry Run 完成 | 虚拟需求走完全流程，修掉发现的门禁/参数/格式漏洞 |
| 2 | 质量门禁可程序化验证 | "CI 通过"拆成可判定布尔表达式 |
| 3 | 执行与评判角色分离 | 评审者发现过执行者遗漏的问题 |
| 4 | 上下文分层加载落地 | 常驻/触发/按需分层，填充率不超约 40% |
| 5 | 知识显性化启动 | 隐性约束（字段类型/超时降级/高频变更区）写入规范 |
| 6 | 度量框架已更新 | 追踪交付率与审查开销 |
| 7 | 外部依赖调用规范已记录 | 超时/重试/降级写入 Skills |
| 8 | 变更审计链已建立 | 每需求完整变更目录（summary/tasks/review） |
| 9 | 知识生命周期机制已设计 | draft/verified/proven 三级 + 自动衰减 |
| 10 | 团队角色已调整 | 有专人负责 Harness 维护 |

## B6 组件保质期检查（每次模型升级执行）

| 组件 | 编码的假设 | 检查方法 |
|------|-----------|---------|
| Context Reset | 模型有长上下文焦虑 | 开/关各跑一轮对比 |
| Sprint 契约 | 模型无法自拆任务 | 移除后看生成器是否迷失 |
| 激进压缩 | 模型被冗余上下文干扰 | 降低压缩强度看质量 |
| 工具格式化 | 模型不会用原始格式 | 原始 vs 格式化对照 |

方法：每次只移除一个组件。Build to Delete——没有删除计划的 Harness 是负债。

## B7 上 Harness 前四问

1. 这个短板**当前模型**还有吗？
2. 有没有更便宜的确定性替代？
3. 任务复用频次撑得起维护成本吗？
4. 删除条件现在就写了吗？

任何一问答不上来，先别建。
